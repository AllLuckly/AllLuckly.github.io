After a series of exercises, finding the correct editable version can become difficult. Organise three fictional design projects through names, groups, tags and explicit backups. Classification helps retrieval but does not replace verifiable source files.

## List projects and version purposes

Choose three owned projects and list draft, candidate and delivered states, including pending edits. Do not delete anything initially. Inspect which version retains text and layers and which is only an imported image. Identical appearances can hide different structures. Centre the review on confirmed editable originals rather than the prettiest preview.

## Name the project, purpose and revision

Use a project name, layout/use and revision, such as City Cover Portrait v2. Dates supplement rather than replace purpose. Avoid naming everything Final. Rename one selected work, verify it in the list and continue. Use private shorthand where appropriate, and check exported filenames separately because library names and external names may need independent maintenance.

## Use groups for projects and tags for attributes

Use the grouping and tagging controls available in the installed version, with groups for projects and a small vocabulary for attributes such as landscape or pending. Avoid duplicate synonyms. Verify actual filtering after applying them. Library classification does not alter drawing layers or create an external backup. Test one work before organising the rest.

## Reserve favourites for active sources

Favourite only the currently active editable source for each project, keeping the list short. Open every favourite to rule out same-name older versions. Review it after delivery. Favouriting does not create a copy or extra protection, and removing a favourite is distinct from deleting artwork. Verify deletion targets and backups separately.

## Export editable backups and reopen them

Explicitly export each core project as an editable VectorPaint file to a managed folder. Reimport one as an independent work and inspect text, layers and key objects. Preserve the original throughout. Verify classification metadata through actual recovery rather than assuming it travels with every format. Keep previews for identification, not as substitutes for source files.

## Rehearse finding the correct version

Close the current work and retrieve a named source using project and purpose only. Verify revision, wording and pending edits, then locate its matching external backup. No deletion or library reset is necessary. Simplify naming if retrieval depends on guessing thumbnails. Record the backup location, filename rule and last verified date for future use.

## Write a short project handoff note

For each project, identify its active editable source, used delivery output and last verified recovery file. Match real library and folder names. Retrieve them from the note without relying on thumbnail memory. List separate layout sources where needed. Update this managed record when changes occur; it documents verifiable version relationships rather than creating automatic synchronisation.

## Check scope before assuming a work is lost

Leave favourite/tag filters and inspect the full library before assuming loss. Open same-name works to verify structure before replacing anything. Preserve failing files and errors, then use a verified backup instead of guessing through reinstallation. Standardise a small vocabulary gradually. The result should identify the active source, past delivery and recovery location.
