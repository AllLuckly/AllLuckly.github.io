A game in Yearn's list means the app recognized an item it can list. Playing still requires a complete file, appropriate platform identification, necessary system files, and working runtime and input. Following this order preserves useful evidence more easily than repeatedly deleting the app.

## Describe the failure precisely first

Record where failure occurs: rejected during import, no entry afterward, returning to the list after tapping, persistent black screen, or a visible picture with unresponsive controls. These concern different stages. Add platform, extension, Yearn version, and device model to create a reproducible description first.

For example, 'import succeeded, listed as PS1, black screen on opening, pause menu still appears' is more useful than 'the game is broken.' Test on a retainable copy and back up important saves. Change one condition per round and record whether it helps instead of changing BIOS, filenames, and controller settings together and losing the cause.

## Start with file completeness

In system file management, confirm that the original downloads locally, has a plausible size, and is not an unextracted outer archive. For multi-file disc images, retain all references and companion tracks. A filename visible in the cloud differs from complete local contents.

Recheck the extension and actual platform. Renaming one extension to another is not conversion. For unclear sources or unknown internal content, return to your lawfully held originals rather than trying arbitrary extensions at random. Settings cannot easily compensate for an unreliable file foundation.

## Confirm platform identification in the library

Open the entry information and inspect its assigned platform. Generic extensions, especially BIN or ISO, may be used by several systems and do not prove a PS1 file. Compare the displayed platform with your file information before proceeding.

If the platform is clearly wrong, stop launch attempts and inspect the imported material and original format. Do not arbitrarily change the title to remove the wrong label; a title change does not change the underlying format. Keep the original and import record and report identification details if necessary instead of letting a wrong category distort later checks.

## Check required BIOS files separately

If the platform needs BIOS, inspect its state in Settings. For PS1, verify that your supplied system file has both a recognized name and correct contents. A correct name with wrong contents can still fail to launch. A Present status is not final proof of every game's compatibility.

Compare another lawfully usable game on the same platform that previously ran. If all games on that platform fail, inspect platform requirements first. If only one fails, revisit its structure, edition, and compatibility. Do not delete all platform data for one game's problem.

## Check pause and input after a picture appears

If the title screen appears but buttons do nothing, check whether the game is paused, demonstrating play, or waiting for a specific button. Try the virtual controller, then the physical one. If touch works but the controller does not, investigate pairing, recognition, and button response rather than reimporting the game.

If the picture freezes while the pause menu works, try resuming normally or exiting and reopening, and record where it happened. Reset restarts the current game session. Confirm recoverable progress before using it. When save state is uncertain, do not treat reset or force-quit as harmless routine controls.

## Use narrow comparisons for performance problems

If a game starts but picture and audio stutter, restore normal speed and check whether a high speed multiplier was enabled accidentally. Close unnecessary background load and keep temperature and power conditions suitable for normal use. Compare the same scene before and after rather than mistaking different level workloads for improvement.

Record whether the issue is limited to one platform or game. Platform support does not mean every title behaves identically on every device. Verify the basic process with stable content, then document individual compatibility problems. One failed title does not establish that the whole app is unusable.

## Common questions and a feedback checklist

**Will reimporting automatically repair saves?** Import mainly handles game files. Saves also involve separate files and associations. Before reimporting, keep external copies and existing progress so same-name replacement does not add variables. Investigate saves separately through loading and backup checks.

**Why does another emulator run it while this one fails?** Emulators can differ in cores, format handling, and version support. The comparison is informative but does not establish the specific cause. Platform, format, failure location, and reproducible steps are more useful than naming only the other app.

Summarize the result in four lines: environment, steps, expected result, and actual result, with necessary screenshots. Omit private directories, accounts, and game content itself; extensions and companion-file structure are enough. Record a successful change too, so similar files can be checked from a clearer starting point later.
