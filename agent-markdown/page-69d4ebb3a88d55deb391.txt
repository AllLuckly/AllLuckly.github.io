用同一份双事件ASS、两种颜色与百分秒时间表，对比k的瞬变和kf的扫色，按实际字幕路径观察并记录。

为自己的短片准备一条带两段英文歌词的 ASS 字幕，把两种颜色和每段时间固定，再比较瞬间变色的 `\k` 与逐步扫色的 `\kf`。字幕文件在外部编辑；云映用于在实际支持的外挂字幕路径下观察，不假设应用自带歌词制作器。

## 先保存视频、文字与对照条件

选一段至少十二秒的自有静景视频，将声音调到适合的音量并保留原文件与原有字幕。把下面的英文短句当演示文字：第一段 `Blue`，第二段 `sky`。两段各分配一百五十百分秒，合计三百百分秒，也就是三秒。文件中的第一条事件为一至四秒，第二条为六至九秒，中间有两秒空档以区分两次演示。这里的文字与时间是练习素材，不能据此推断任意歌曲的真实发音位置。

准备两个颜色相同但效果不同的事件。主要色为白色，次要色为黄色，描边黑色。ASS 样式中的颜色按透明度、蓝、绿、红排列，不要直接把网页 RGB 值放入对应位置。本练习不测精确色值；背景与设备显示可能改变看到的颜色。不要把播放器的快进、画面缩放或系统主题变化算作字幕的单变量变化。

## 保存包含两条事件的完整字幕文件

把下面内容保存为 UTF-8 纯文本 `karaoke-compare.ass`，保留节标题、样式字段和两条 Dialogue 行。每条事件的相对歌词计时从该事件开始，第一段和第二段前分别放相同的百分秒值；两条事件安排在不同的绝对时间；歌词标记的差别是事件一使用小写 `k`，事件二使用小写 `kf`。复制后检查花括号、反斜线与英文标点，重新打开确认文件确实以 `.ass` 结尾。

```
[Script Info]
ScriptType: v4.00+
PlayResX: 640
PlayResY: 360
ScaledBorderAndShadow: yes

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Default,Arial,40,&H00FFFFFF,&H0000FFFF,&H00000000,&H00000000,0,0,0,0,100,100,0,0,1,2,0,2,20,20,25,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:01.00,0:00:04.00,Default,,0,0,0,,{\k150}Blue {\k150}sky
Dialogue: 0,0:00:06.00,0:00:09.00,Default,,0,0,0,,{\kf150}Blue {\kf150}sky
```

## 把相对时间换成视频时间

先在纸上核第一条事件：`Blue` 从一秒开始，持续一点五秒；`sky` 从二点五秒开始，持续到四秒。第二条事件整体从六秒开始，因此对应六至七点五秒，以及七点五至九秒。各段时长与相对边界相同并不表示两种视觉效果相同；同样，视频绝对时刻六秒不是 `kf150` 的持续时间。第二段的起点来自前一段时长的累加，这里不使用其他会改变起点的特殊标签。

```
k:  Blue 1.00–2.50 s; sky 2.50–4.00 s; event ends 4.00 s
kf: Blue 6.00–7.50 s; sky 7.50–9.00 s; event ends 9.00 s
```

## 先预测瞬变，再预测扫色

Aegisub 的公开标签说明把 `\k` 描述为音节开始时从次要色立即切换到主要色；`\kf` 使用音节持续时间，从左向右逐步完成颜色过渡。第一条中，`Blue` 在第一段开始时切换，`sky` 在二点五秒附近切换；第二条中，`Blue` 在六至七点五秒期间扫色，`sky` 在七点五至九秒期间扫色。这里的左右指字幕文字的扫色方向，不是整个画面移动，也不是改变视频像素。

在表格旁标出 `k` 与 `kf` 的区别，大小写必须原样保留；不要把 `\k150` 改写为小数秒，也不要仅从两个标记的时间相等就推断两种动画完全一样。若字体、语言、字符方向或播放实现不同，可见结果可能不同；这个英语样本不能代表所有文字。

## 在实际字幕路径中播放并记录

先在云映中打开自有视频，再按已安装版本实际提供的路径关联保存好的 ASS。进入第一条事件的内部，观察两段文字何时转色；再进入第二条事件，观察是否出现逐步填色。回看前记录当前播放时间、文件名和字幕选择，避免将另一份同名字幕当成新文件。如果安装版没有可用的外挂关联路径，保留字幕和纸面时间表，标记应用播放待核，不虚构入口。

建议对照一秒、二点五秒、四秒与六秒、七点五秒、九秒附近的变化，但不同设备可能无法准确停在边界。逐帧测量需要另外具备可靠的取帧工具；普通暂停画面只作为观察，不记录成毫秒精度的实测。播放器内的颜色或样式覆盖可能影响判断，应先记录实际设置，再尝试恢复原设置比较。

## 用一个改动制作反例

另存一份副本，只把第二条事件的第一个 `\kf150` 改成 `\kf100`，保留后一个 `\kf150` 和六至九秒的事件区间。按累加规则，第一段改为六至七秒，第二段改为七至八点五秒，最后半秒仍在事件区间内。不要把这半秒自动写成新增的第三段，也不要断言所有渲染器对最后状态的显示完全相同。

比较时区分事件本身仍到九秒，与两段标记总时长变成二百五十百分秒。只调整一个标记后，第二段开始时刻也随之提前；这不是对第二段单独输入了一个新起点。如果想让两段仍各占一点五秒，恢复原始值并重新保存，而不是单纯延长事件结束时间。

## 遇到相同外观时逐项排查

两个事件看起来完全相同时，先核文件是否更新、应用是否选中这份外挂字幕、事件二是否确为 `\kf`，再看主要色与次要色是否不同。只看到普通文字时，记录播放器是否识别 ASS 样式及是否存在用户样式覆盖；不要通过安装未知字体或改变其他媒体库设置解决一个字幕样本问题。若看到反斜线原样出现在画面上，检查花括号与英文半角字符；若没有字幕，检查时间段、文件编码和关联对象。

某个引擎不呈现扫色并不能说明所有 ASS 文件都不支持；外部 Aegisub 的预览结果也不能代替云映中实际观察。保留原稿、修改稿和操作记录，条件不足就写“待核”，不要把纸面预测填成设备测试结果。

## 交付并恢复日常字幕

交付两份 ASS、两条三秒时间表、事件绝对时间和实际观看记录，注明播放器版本、使用的字幕来源与观察条件。能解释 `\k` 与 `\kf` 的不同，以及修改第一段时长为何会改变后续段落起点。完成练习后切回原字幕并保留源视频。此样本只建立两个标签的可复查比较，不承诺歌词同步、效果兼容或音频识别。
