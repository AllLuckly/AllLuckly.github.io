Use a self-made two-part short to compare Plex multi-episode naming, library entries and actual playback boundaries.

## Understand the server rule

Plex documents naming a single file covering consecutive episodes as sXXeYY-eZZ. Plex apps can list the episodes individually, but playing any represented episode plays the whole file. iCouldPlay publicly supports Plex, yet its entry count, seeking and playback behavior still require observation in the current client; Plex’s own app description is not a guarantee for a third-party client.

## Prepare an identifiable short

Create or use an authorized short copy with “Part one” clearly visible in the first portion and “Part two” in the second; note the second part’s start, for example 1 minute 20 seconds. Keep the original outside the test library. Ask an administrator for an isolated Plex shows library and test account. Without these conditions, study the rule but mark all server and iCouldPlay observations unperformed; do not touch real media.

## Name the multi-episode file

Place one short copy in Season 01 of fictional Practice Series (2030), for example Practice Series (2030) - s01e01-e02.mp4, using the extension that matches the file. Verify there is no destination collision and copy rather than move the original. The e01-e02 range identifies two episode numbers; the filename does not create a cut point inside the file.

## Scan and record web entries

Have the administrator scan the test library normally in the current Plex version and wait. Find the series and episodes one and two in Plex Web, recording entry count, titles and the associated file. A fictional show may not match remote metadata. If entries differ from expectation, inspect library type, hierarchy, episode-number spelling and scan status, including both episode numbers around the hyphen and the test-library root, before performing any bulk rematching on a real library.

## Verify the first entry

In Plex Web or a server-supported client, open episode one first and record actual starting position, first-part marker and total file duration. Play only the test portion needed to avoid changing another user’s real progress. If the second part appears first, check whether playback resumed an earlier test position before inspecting file contents; starting position and file content are different evidence.

## Check the whole file from the second entry

Return to the list and open episode two, recording start position, duration and whether both parts can be reached through seeking. Plex’s whole-file rule does not mean episode two necessarily starts at the second part. If the test account has prior progress, note it first, then use an actually available restart or seek control. Do not report manually seeking to part two as automatic server splitting. Record the initial seconds, manually return to the beginning for a few seconds, then seek to the second marker; this preserves evidence of both the initial state and the file’s two parts.

## Open entries separately in iCouldPlay

Connect iCouldPlay to the same Plex server and test account and enter the show, recording actual episode count and names. If both entries appear, open each and record opening, duration and the preset second-part time. If only one entry or no corresponding control appears, record the actual interface instead of inferring iCouldPlay behavior from Plex Web. Record position before switching so resume state does not obscure playback boundaries. If an entry appears to start at part two, record the displayed progress and return to the beginning to see whether part one is still present; do not infer a separate file from the opening alone.

## Separate labels, duration and start

Record episode names, each entry’s watch progress, the total duration of the shared source and the actual second-part start in separate columns. Two list items pointing to one video do not prove the media has been split into two files; the second part need not begin halfway through the total duration. Verify content using the pre-recorded visual marker rather than estimating boundaries from entry names.

## When independent playback is needed

If each episode must start independently, Plex recommends splitting the file into individual episodes. Preserve the original and edit project, export two authorized copies using an appropriate editing tool, and check boundaries, audio and subtitle timing. The administrator can then name them by individual episode number in a separate test directory and scan. iCouldPlay is not assumed to perform the editing or subtitle adjustments automatically. Open each split file to check the first ending and second beginning for omissions or duplicates; subtitles using the full-file timeline also need external review.

## Troubleshoot and clean up

If the web view lacks two entries, check filename and server scan; if iCouldPlay differs from the web, verify account, test library and actual interface. If start positions differ, record resume state and manual seeks rather than immediately declaring the file corrupt. The administrator cleans up test copies by agreement and confirms originals, real library and other accounts’ progress remain intact. If retaining samples, record their names, relative paths and initial test-account state so the administrator can restore or remove them later. Hide private server addresses and account information in shared notes. This guide claims no private-server or device test.
