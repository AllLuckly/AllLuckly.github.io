VoiceOver is Apple’s system screen reader. Its spoken focus, current Jianlai keyboard item and text committed to the host are different states. Observe under conditions you know how to restore; do not assume every third-party keyboard control has a complete label or present one observation as accessibility certification.

## Establish a safe prerequisite

Use your own iPhone and an ordinary note with the nonprivate practice phrase “花开了.” Confirm a safe way to return to your usual system operation and ensure bystanders will not hear sensitive material. If unfamiliar with VoiceOver gestures, read Apple’s introductory guide and practice with assistance from someone you trust; if independent restoration is uncertain, do not enable a new mode and mark later steps pending. Existing VoiceOver users need not disable their daily accessibility features or change preferences.

## Record system and keyboard baseline

Record confirmable VoiceOver enabled state, speaking rate, typing mode and shortcut, together with system, host and Jianlai versions; private accessibility preferences need not be shared. Confirm Jianlai was added and actually selected in an ordinary field. Preserve the original and use a separate empty practice copy, not a password field or a message that might be sent. If the host does not offer Jianlai, record the fact without weakening security.

## Establish a document baseline using your usual method

Under your familiar input conditions, use an available Chinese scheme to enter “花开了,” confirm any candidate and inspect the document. Record keyboard, actual actions and outcome. If candidates are not visible or distinguishable, use your usual reliable spoken or text-inspection method rather than requiring a visual check. When uncertain leave the result pending; key labels do not prove committed text. Keep an empty practice copy for the later trial.

## Enter the VoiceOver condition using a familiar method

If you already use VoiceOver, retain your current state. If it was off and you can safely enable and disable it, follow the Apple guidance available for your device and record the activation method; do not assume everyone uses the same shortcut. VoiceOver changes gesture meanings. Confirm how to exit before starting the trial. If the device differs from the instructions or restoration is unclear, stop and retain the original state and unfinished record.

## Observe spoken focus on keyboard items

In the second practice draft select an ordinary text field and confirm Jianlai is still active. Using a VoiceOver navigation method you know and the device actually supports, observe a few identifiable keyboard items. Record spoken labels, focus reachability and whether labels match visible items where relevant. Do not assume every key is labelled, a fixed navigation order or a particular accessibility action. If labels are absent or unclear or focus cannot reach an item, record device and screen; do not repeatedly activate unknown controls to manufacture a pass.

## Separate confirmation actions from document text

When target controls can be identified reliably, enter the same phrase using an actually available method. Record what was spoken, the action taken, whether candidates appeared and the final document text. Hearing a key name does not prove activation, and activation does not prove correct final text. Pause and mark candidate handling pending if unclear. Preserve a mismatch before retrying in a fresh copy; do not infer the user’s intent.

## Compare and troubleshoot separate observations

Compare baseline and VoiceOver conditions across focus reachability, understandable labels, identifiable confirmation actions and retained target text. System speech, candidates and document text are different evidence. For a difference, first check the actually selected keyboard, ordinary field focus, VoiceOver typing mode and host feedback, changing one condition at a time. If speech is too quiet, use your normal method to check output and volume; do not weaken other security protections.

## Restore and report a limited scope

If candidates appear, record whether the list is reachable and whether the spoken item is candidate text, number or other host content. Do not choose based on a guessed order. If the target cannot be identified reliably, end that trial and distinguish “list found” from “selection completed.” On a later retry you may first confirm your usual operating method with Apple’s system keyboard or a familiar assistive tool, then observe Jianlai separately. The control keyboard’s outcome is not a Jianlai test. Record the actual keyboard and host in each trial.

Restore the original VoiceOver state, typing mode, speaking rate, shortcuts, usual keyboard and volume. An originally enabled feature stays enabled. Confirm the original and both practice results are accessible. Deliver nonprivate versions, steps, actual labels, actions, text and pending checks, making clear when there is only one sample. One reachable control does not establish full accessibility conformance. No physical speech or accessibility test is claimed.

Record the date and recheck after version updates instead of carrying forward an old conclusion.
