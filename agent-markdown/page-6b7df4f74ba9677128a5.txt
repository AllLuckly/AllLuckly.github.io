Distinguish user progress, client display and actual reading with a test comic.

English translation of the [Chinese original](<https://allluckly.cn/guides/manyue-komga-two-user-progress-server-client-observation/>), translated on 2026-11-23. Original publication dates, attribution, code and version notes are retained.

When two accounts see the same comic, record each user’s progress separately before observing the actual Manyue+ display.

## Separate users from devices

Komga documents reading progress separately for each user. Two devices using one account are a different experiment from one device switching accounts. Web progress also does not guarantee Manyue+ will read or write that value. Record server and client states separately with authorized test accounts and a test book; do not assert an unobserved sync mechanism.

## Prepare two authorized test users

The administrator confirms that test accounts A and B both have access to one self-made comic in an isolated test library, and that each account holder consents to viewing test records. Prepare at least five pages and record first, third and last markers. Do not use another person’s real history or ask for passwords or tokens. Without a second authorized account, mark the cross-account comparison not performed.

## Record both initial states

Each account holder opens the same test book separately in the Komga web interface and records the visible unread, in-progress or read status and position. Verify the displayed account when signing out or switching; write aliases A and B and times on paper. If A was already read and B unread, preserve that baseline instead of resetting production records. If one user cannot see the book, have the administrator check existing access without expanding production permissions.

## Read once as account A

Account A opens the test book on the web, goes to page three and exits the reader normally. Back on the book page record the progress bar, read state or other indicator actually available in that version and the time. Do not assume exit immediately saves or displays an exact page number. If A was already read before the test, ask the administrator for a safely recoverable dedicated test state rather than overwriting real history.

## Inspect account B

B’s holder opens the same server and test book under their own account and records whether its web state remains consistent with its baseline. Komga describes separate progress per user, but mistaken account identity, book identity or an unrefreshed interface can affect an actual observation. If A and B show the same state, do not immediately declare isolation broken; verify account, book and time one by one.

## Inspect A in Manyue+

Use A’s authorized account in the Manyue+ Komga source, confirm server and test-book identity, open the book and record the displayed or entered page position. Report only what appears. Starting at page one neither proves server progress was lost nor establishes bidirectional synchronization. If no page number is shown, describe the position using self-made page markers.

## Inspect B in Manyue+

B’s holder opens the same test book with their own account on an appropriate separate device or permitted session, recording app position and time. Do not ask anyone to disclose a password. Skip and mark unperformed if switching cannot be done safely or may affect production sessions. Compare web A, web B, app A and app B in four rows rather than merging accounts.

## Understand manual marking

Komga web can mark a book or series read or unread. This changes the selected account’s state and is not proof every page was examined. Do not apply it to production works for this exercise. If a test-account holder explicitly agrees, record the original state, change only the test book and inspect web A, web B and Manyue+ separately. Do not run the optional step without a safe way to restore state.

## Investigate differences and identity

If web A has progress but Manyue+ A opens at page one, compare server, account, test book, app version and time first. Record actual states; one difference does not establish cache behavior, synchronization direction or a defect. If B cannot see the test book, check existing library access. Exclude private addresses, authentication details and unauthorized pages from administrator or support reports.

## Align the four observations in time

For each account prepare web and Manyue+ rows containing server alias, account alias, test-book marker, time, read state and visible page position. Record A’s page-three action as a separate event. If the app was opened before that action, do not directly compare its old screen with the later web state. Re-enter using each interface’s actual controls, note the time and then compare. Refresh alone is not proof that synchronization was triggered.

On a shared device, close the reading session normally before switching and ensure both account holders understand the switch. Do not clear saved system credentials or alter other sources. If the app cannot safely distinguish two sessions, use separate devices or skip B’s app step. Per-user server storage is documented; when the app reads, writes back or resolves conflicts requires separate observation of the installed version.

## Restore and hand off

The administrator and account holders handle test records according to the initial backup and test policy. If a safe restoration method is unknown, retain the test data as pending instead of resetting production progress. Summarize four observations with times, page markers and unperformed steps. This public-documentation guide claims no private-server connection or physical-device test.
