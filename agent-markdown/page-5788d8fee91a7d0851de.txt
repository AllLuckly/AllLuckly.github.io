Use an isolated test account to distinguish server Want to Read status, full completion and client observations after cleanup.

## Understand the cleanup scope

Kavita’s tasks documentation says cleanup removes fully read series from users’ Want to Read lists as part of automatically run cleanup tasks, without requiring a manual trigger. This concerns server-user list state, not deletion of comic files, and does not guarantee an identically named entry in Manyue+. Actual task timing and client display must be observed separately.

## Prepare an isolated test account

Use only a test server you administer, a normal test account and a self-made short comic you may read. Confirm library access and preserve the original file and existing account state. Do not use another person’s actual reading list or clear a database or delete production content to speed the test. If state cannot be restored or task effects on others are uncertain, stop at read-only observation and consult the administrator.

## Establish list and progress baselines

Find the series in Kavita’s web interface as the test user and record identity, chapter count, Want to Read state and visible progress. Add only your test series using the available interface and note the time; do not repeat if already listed. Series completion differs from a single chapter. Identify all accessible chapters first, and do not call the series fully read if some are missing or inaccessible.

## Observe the Manyue+ entry point

In Manyue+ connect to the same server and test account. Check whether the current connection exposes the server’s Want to Read list and record directory, item and visible state. If no entry exists, mark it unavailable or unobserved; do not automatically equate the app’s own read-later list with Kavita’s Want to Read. Confirm the self-made series identity to avoid same-name or other-account confusion.

## Complete controlled reading

Read each chapter of the authorized test series using the actual interface and record whether each is shown complete and when. If reading in Manyue+, return to the server web interface to check that account’s series progress. Whether the client synchronizes progress depends on the actual connection and version; do not assume it. If any chapter remains incomplete or the server shows unread material, do not conclude that the series is fully read.

## Wait rather than repeatedly triggering

Record when the server first shows the series fully read, then observe any administrator-visible task state for automatic cleanup. The documentation does not promise a fixed time for this exercise. Mark it pending if not yet run; do not repeatedly change progress, restart the server or force a global cleanup to obtain a result. If task state is unavailable, record it as not visible rather than inventing a run time.

## Check server results first

In the test user’s web interface separately check whether the series still exists, reading is complete and Want to Read still contains it. Removal after cleanup is consistent with the documented rule; verify files and the library independently. If it remains in the list, check full completion, task execution and account identity. A pending state is not a failure.

## Then observe Manyue+

Return to the same account and connection in Manyue+ and reopen the relevant directory if the interface permits. Record visibility of the series or list item. If the server list changed while a client entry remains, first verify that the entry actually corresponds to the server list, the account matches and the page was reopened. Do not assert cache or a separate list as the cause without evidence. If no entry exists, retain the server result and mark client verification incomplete.

## Restore and document

After testing, restore the test account’s prior state through available controls and preserve original media and other users’ lists and progress; involve the administrator if restoration effects are uncertain. Record server and app versions, test series, chapter completion, visible task state, list changes and skipped steps. Remove private addresses and credentials before sharing. This guide relies on public documentation and does not claim private-server or device testing.

## Separate list changes from files

Record whether the series remains in the server library, an authorized chapter opens, the server Want to Read list contains it and which entry Manyue+ shows. Removal from a list establishes only a membership change, not file deletion; a remaining file does not prove a cleanup task ran. Tie each conclusion to an observation and leave the execution cause unknown if logs or task state are unavailable.

## Preserve completion conditions and timing

If chapters are added later, the server’s full-completion state can change with the series or progress. Record chapter count, each chapter state and inspection time. Unsynchronized client progress, restricted chapters or a pending task can produce different results. Observe only your own sample and do not change real users’ progress to force consistency. If all chapter states cannot be confirmed, stop and mark the test incomplete.
