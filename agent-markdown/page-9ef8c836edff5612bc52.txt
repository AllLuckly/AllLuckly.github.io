## Fix three documents and their reading order

Externally prepare original preface.xhtml, chapter.xhtml and glossary.xhtml documents. Declare spine order preface, chapter, glossary and record package and navigation paths instead of substituting filename order. Without an editable EPUB, use labelled structure cards and state no container was generated. Name the later PDF report separately rather than claim a reader fully parsed the original package. ManYue’s task is legible report reading and return.

## Give contents and landmarks separate purposes

Contents can list browsable chapter links, while landmarks identify key entries such as body start, contents or glossary; they are not meant to repeat the entire contents list. Record purposes and actual items separately rather than demand equal counts. Human-readable labels and semantic types have different roles: a label saying body does not prove bodymatter markup. Missing landmarks do not mean missing documents, and a landmark alone does not establish spine membership.

## Follow the body landmark to its fragment

The body entry targets `chapter.xhtml#start`, with an actual start identifier in that chapter. Resolve the file against the navigation base, then verify the fragment; text after the hash is not a new extension. A document-only target does not establish a specific paragraph landing. A body-start entry leaves the preface in the spine: one navigation jump is not deletion or editing. A listed link also does not guarantee every reader chooses the same initial-reading strategy.

## Change landmark order without changing the spine

Make control B changing only landmark display order to glossary then body start, while retaining preface/chapter/glossary spine order. Verify resources and spine unchanged, so first landmark does not make glossary the default first chapter. Interfaces may expose some landmarks or present them differently; record observations, not assumed compatibility. Change only landmark order rather than also reorder the spine or rename files, which would obscure the responsible layer.

## Check semantic type and target identity together

The specification restricts repeated identical landmark types targeting the same resource or fragment; duplicating bodymatter is not a way to pad navigation. Audit type, file, fragment and readable label together. A glossary label targeting the preface is a mismatch, not a colour problem. Entries may address different positions in a resource subject to actual rules; do not impose one link per file universally. Inspect original structure and edit copies externally, without assuming an in-app navigation editor.

## Read a four-column PDF report

Externally make a short PDF covering documents, spine, A/B landmarks and target checks, with original markers and date. Open through an available ManYue PDF path and enlarge filenames, hashes, fragments and arrows, returning to each row. Report links or visible labels do not demonstrate native EPUB navigation. Printed or rasterised reports can change text selectability, so record their representation separately. Visible text does not prove XML structure, and untested original-package paths remain unperformed.

## Check missing fragments and deletion assumptions

Opening a file without the intended landing calls for checking fragment existence, case and edition, not treating resource access as precise-location success. If starting at body hides the preface, inspect spine and source before alleging deletion. A report omitting landmarks may reflect tool scope, not absence. Share original documents and minimal structure without private-library credentials. Preserve packages and reports rather than run an unknown bulk navigation repairer.

## Reopen and verify both orders

Reopen the report at the same marker and reconstruct spine and A/B landmark orders without conclusions. Trace the body fragment, glossary label and four-field identities, explaining why entry changes do not rewrite the spine or delete a preface. Recheck added documents, fragments and order after package changes rather than edit only a report title. Deliver an auditable navigation record with unperformed reader paths explicit, not claims of automatic EPUB repair, uniform landmark display or exhaustive device interaction testing.
