English translation of the [Chinese original](<https://allluckly.cn/guides/icouldplay-two-sample-average-filter-gain-frequency/>), translated on 2026-11-19. Original publication dates, attribution, code and version notes are retained.

Averaging two adjacent audio samples is a simple filter. Halving each sample independently is uniform gain. Both operations contain a factor of one half, but their frequency behavior differs. Start with original discrete sequences and only then observe externally produced sources in iCouldPlay; the app is not assumed to contain this filter.

## Define averaging and a separate gain control

Fix the rate at 8 kHz. Define y as the current plus previous input sample divided by two, and a separate control v as the current sample divided by two. Start indices at zero and state that sinusoidal gains are steady-state results. For a finite clip, define its preceding sample as zero rather than silently wrapping the end. Retain distinct input, processing and export records. No undocumented two-point filter button is required in iCouldPlay. If existing external tools cannot perform it, complete the sequences and mark processing and playback unperformed; renaming one original does not create different treatments.

```text
y[n] = (x[n] + x[n-1]) / 2
v[n] = x[n] / 2
Fs = 8000
```

## Check unity gain with a constant input

For a sustained input of 0.2, averaging remains 0.2 once both samples are within the constant region; uniform halving gives 0.1. This disproves equivalence. With a zero preceding sample, a finite clip begins at 0.1 and reaches 0.2 on the next sample. Keep that boundary separate from steady-state gain. A constant is a mathematical DC input, not material to play through speakers for an extended test. Do not use audibility to decide whether DC is preserved; equations, sample inspection and listening have different scopes.

## Calculate gain at each frequency

For a sine or cosine at f, steady-state amplitude gain is abs(cos(pi\*f/Fs)). At 8 kHz this is approximately 0.923880 at 1 kHz, 0.707107 at 2 kHz and zero at 4 kHz. Uniform halving gives 0.5 throughout. For input amplitude 0.2, the first two averaged amplitudes are approximately 0.184776 and 0.141421; gain is not an instantaneous sample. At 4 kHz use the alternating signs of a cosine, avoiding a zero-phase sine whose sampled values are already all zero and therefore cannot demonstrate filtering.

```text
steady_amplitude_gain(f) = abs(cos(pi*f/Fs))
```

## Calculate alternating samples and an impulse boundary

For a sustained sequence alternating 0.2 and -0.2, adjacent pairs sum to zero; uniform halving still alternates 0.1 and -0.1. In a separate calculation, let only input n=0 equal one and all other values, including the preceding sample, equal zero. Averaging produces 0.5 at n=0 and n=1, then zero; halving gives 0.5 only at n=0. Label indices and do not describe the two output values as soundtracks. This checks adjacency and finite-start conditions. Unit amplitude is mathematical, not a request to play a full-scale impulse.

```text
input impulse:  [1,   0,   0, 0]
average output: [0.5, 0.5, 0, 0]
half output:    [0.5, 0,   0, 0]
preceding input sample = 0
```

## Do not hide delay by removing the first output

Between zero and half the sample rate, where gain is nonzero, the average also has half a sample of phase delay: 62.5 microseconds at 8 kHz. This does not mean storing samples at fractional indices or aligning every transient by deleting half a number; output values remain on integer sample positions. Phase is not normally readable where the 4 kHz gain vanishes. Keep gain and phase conditions separate. Deleting the first whole sample to force a visual match introduces another time shift and changes boundaries.

With trusted tools, title owned exports original, adjacent average and uniform half-gain, retaining soundtrack parameters. Confirm externally that the audio processing was applied before selecting videos in iCouldPlay. Keep normal speed, soundtrack position and output settings fixed and compare briefly at comfortable volume. Calculated gains are not measured device values. Comparing only originals cannot establish filtering, and similar posters do not establish file identity. Restore the original source for normal viewing rather than leaving an unidentified processed copy selected.

## Check prior samples, phase and rate for mismatches

If both operations always match, check whether the previous sample was incorrectly replaced with zero or only a coincidental input was tested. For a silent 4 kHz case, first ensure the input was not already all zero. Check whether external tools used a longer window, normalized again or changed rate. At 16 kHz, a 2 kHz tone no longer has the gain 0.707107 from this example. Record corrections and identities without changing player engines to hide production differences. Without sample inspection, do not infer an exact 62.5-microsecond delay from listening.
