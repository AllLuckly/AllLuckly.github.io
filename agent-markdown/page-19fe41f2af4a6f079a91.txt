Use a bilingual test card to inspect missing glyphs, wrapping and font availability, separating editable text, outlined copies and image previews.

English translation of the [Chinese original](<https://allluckly.cn/guides/vectorpaint-font-fallback-proof/>), translated on 2026-10-26. Original publication dates, attribution, code and version notes are retained.

Text can change on another device because of font availability or glyph coverage. Build a bilingual test card and compare the original, vector export and image preview. Matching font names or file extensions alone do not prove identical appearance.

## Prepare representative test characters

Prepare a Chinese title, English subtitle, date, numeric units and punctuation representative of the project. Test relevant Chinese and special glyphs rather than a few Latin letters alone. On a 900 by 600 pixel canvas, separate text groups with ample width. Record font, size and environment, starting with a system-font baseline before testing the intended font.

## Distinguish missing glyphs from overflow

Inspect boxes, blanks or style-changing individual glyphs separately from wrapping and clipping. Check the actual text for copy omissions. A listed font need not cover every required character. Compare a problematic character with a known covering font and record its position. Preserve the original text because outlines are not a convenient source for restoring it.

## Separate editable and appearance-fixed versions

Save editable text, then outline only an independent delivery copy where needed. Check its appearance and changed object structure. Keep dates, prices and changing names editable in the source. Outlines preserve current glyph geometry without supplying the font file. Agree on future text editing and font requirements before choosing delivery versions.

## Use an image preview as a visual reference

Export a sufficiently sized PNG from the checked original as an appearance reference. It is not editable text but helps reveal vector rendering substitutions. Compare equally sized views for title endings, numbers, punctuation and line spacing. Label the reference clearly and inspect small semantic details rather than relying on similar thumbnails.

## Reopen in the actual target environment

Open the exact delivery file in its intended environment and inspect glyphs, wrapping, alignment and weight. Results apply to the tested environment only. Locate a difference using the PNG reference, then inspect object type and any mixed-font characters. Change fonts and text widths separately. Name the checked final version distinctly from earlier tests.

## Regenerate every affected output after editing

Update the editable original first, then regenerate outlined delivery and image reference. Maintain a version list and reopen each file. Newly introduced characters need fresh coverage and width checks. Read both languages independently, including dates, units and letter case, so visual consistency does not conceal incorrect wording.

## Test the complete chain with a date edit

Change one date in the editable source, regenerate outlines and PNG, and verify the same new date in all three. Add a previously untested punctuation mark and recheck coverage and wrapping. If delivery remains stale, inspect source and paths before blaming fonts. Keep tests separate and list only reopened, checked files for delivery, retaining editable text for future changes.

## Retain a minimal card when differences persist

Check hidden layers, text-on-path and small labels for untreated text. Isolate one problematic group and compare text, outlines and raster output. Unexpected heaviness may come from duplicate objects. Prefer existing legitimately available fonts over untrusted same-name downloads. Retain the test card and environment record for future comparisons.
