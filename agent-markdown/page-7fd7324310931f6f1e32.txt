用四条自制 ASS 对照字幕核对换行条件，保留大小写与实际渲染记录。

ASS 字幕中的 `\N`、`\n` 与 `\h` 长得很像，作用却不能按大小写忽略处理。本课在同一段短片上比较四条原创字幕，先读源码，再在云映记录实际文字和行数。你将得到一份能够回退的字幕副本与条件清楚的断行记录，而不是通过把所有反斜线删除来“修好”文件。

## 一、选择短片，建立普通文字对照

选择至少十五秒的自有短片，优先使用背景相对稳定、没有烧录字幕的练习副本。在云映先顺播到末尾附近，确认视频路径本身可用，再记录来源与时长。电脑上用纯文本编辑器创建 UTF-8 文件，文件名保留 .ass 扩展名；不要用会把引号与反斜线自动美化的排版软件。另在笔记中写下普通句子“North gate”和数字单位“12 km”，作为之后核字的参照。加载字幕使用你安装版本已有的字幕入口，若无法加载就记录文件阶段的结果，不把电脑编辑完成写成真机显示成功。整个练习保留原片与原字幕，所有修改都落在副本。

## 二、保存完整练习文件，保留四条差异

下方是原创练习文件，四条字幕分别出现，不需要同时抢占屏幕。先完整复制，再检查四条开始结束时间及默认样式名一致。Arial 只是样式中的字体请求，设备未安装时可能使用替代字体，因此本课不以字形是否完全相同判断成功。最值得核对的是第一条的大写 N、第二条的小写 n、第三条额外的换行模式标记，以及第四条数字与单位之间的硬空格。不要先把四行统一改写成两行普通文本，否则就失去对照条件；文本编辑器显示出的源码行数也不是播放器最终可见的字幕行数。

```
[Script Info]
ScriptType: v4.00+
PlayResX: 640

WrapStyle: 0

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Default,Arial,24,&H00FFFFFF,&H000000FF,&H00000000,&H00000000,0,0,0,0,100,100,0,0,1,1,0,2,20,20,20,1
```

## 三、先写规范预期，再写实际观察

依据[Aegisub ASS 特殊字符说明](<https://aegisub.org/docs/latest/ass_tags/>)，`\N` 不受换行模式限制而强制换行，`\n` 仅在模式2强制换行、其他模式替换为普通空格，`\h` 是不换行硬空格。给四条记录先填源码条件，再留一个独立的“当前播放器实际显示”栏。不要直接把规范预期复制进观察栏，也不要因为课文写了预期就宣称自己看过结果。第三条的 `\q2` 放在覆盖标记花括号内，普通断行符则放在正文里，两种位置不能混淆。检查时逐字符保留大小写，不使用全文忽略大小写替换；一个不经意的小写转换就可能把原本要比较的两条变成同一条件。

## 四、从每条之前顺播，核字后数行

从零秒开始顺播，第一条出现时先确认 North 与 gate 两个词都在，再记录它们处于几行。继续用同样方法看第二、第三条，最后确认第四条的数字、单位及其间空白。暂停可用于读清文字，但结束后仍应恢复顺播，检查字幕不是一直留在屏幕上。每条记录至少包含时间、完整文字、可见行数和异常符号，不只填“正常”两个字。若第一条显示两行、第二条一行而第三条两行，记录这组观察即可，不把当前结果扩张成云映在任意设备和字号下都一模一样。若结果不同，保留原始观察，下一步再定位条件。

## 五、硬空格的检查需要控制宽度条件

第四条短句在宽画面上往往只有一行，因此“一行显示”本身不能证明你已测出硬空格效果。先核源码确实是 `12\hkm`，再用副本与普通空格版 `12 km` 对照，保持同一视频、方向和字幕设置。只有在实际可用的显示条件下出现换行差异，才记录该差异；不要为凑结果声称应用提供了本来没看到的字幕框宽度输入。若两版都不换行，结果就是本轮没有形成能区分的宽度条件。保留这个结果仍然有价值，因为它避免把缺少对照的顺利显示误说成全面测试，也让下次改变设备方向后有条件继续复核。

## 六、只修改一个条件，保存命名清楚的副本

需要继续查问题时，给原文件、普通文字版和单项修改版分别命名，并在笔记写每份只改变了什么。比如把第三条的模式标记移除属于一个条件变化，而同时换字体、改屏幕方向和改时间不利于解释。每次重新选择字幕后，核对文件名并从条目前顺播，确认不是仍在看旧轨道。若安装版本提供字幕外观设置，可以记录真实选项与当前值，再做一次单项对照；没有该入口时就使用文件副本，不把外部 ASS 编辑命令写成应用内按钮。最终应能从笔记还原每一步修改，而不是只剩一份叫 final 的文件却不知道它与原稿差在哪里。

## 七、问题排查：字面反斜线与缺字

如果屏幕直接显示反斜线和 N，先检查文件是否被当作普通文本字幕、格式头是否完整，或编辑时把一个反斜线写成了两个。若整条不出现，检查时间范围和选择的轨道，再回看 Events 的字段顺序，不先责怪换行规则。若数字与单位都出现但中文说明中的字符不见，字体覆盖与字符编码也是独立问题，不应靠改变 `\h` 来解决。出现两个字幕叠在一起时先排除烧录字幕与内嵌轨道同时显示。保存异常文件用于复查，不反复覆盖原稿；无法确定的渲染行为记录为当前兼容性待查，不宣传已完成全部 ASS 样式验证。

## 八、完成检查与可读备用版

最终检查四条记录都有实际执行状态：已观察、未加载或条件不足都应写明。核对大小写没有被整理工具改动，源码与可见文字的差异都有对应时间，硬空格没有被误解释成固定像素宽度。把规范说明、自己的观察和未确认部分分开保存；本文给出的是任务与预期边界，没有替你执行设备实测。最后再加载普通文字备用版，从头顺播到十二秒以后，确认至少有一份可以清楚读取的字幕，同时保留完整 ASS 原稿用于后续复核。这样你既能继续观看，也能在未来环境变化时知道该重查哪一个条件。
