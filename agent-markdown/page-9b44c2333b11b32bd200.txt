An order-four Latin square has 1–4 once per row and column. Use only that rule, without Sudoku subgrid restrictions. Build one complete static answer, then deliberately alter a row to inspect column conflicts. The app supplies text/grid layout, not unique-solution generation, hints or a solving program.

## State the row/column rule without importing Sudoku

Create an 800 by 800 pixel canvas with sixteen cells, rows A–D top to bottom and columns 1–4 left to right. Each row/column contains 1–4 exactly once. Do not check 2×2 boxes or call a filled grid uniquely solvable. Put the rule beside an evenly weighted grid without bold middle lines suggesting Sudoku boxes. Distinguish headers from entries. Count sixteen empty cells and exclude a duplicate outer row before adding text.

## Save a complete row-checkable source

Use rows 1234,2341,3412,4123 and save them externally rather than guessing missing numbers from a screenshot. Each row contains one set in shifted order; inspect rows and then columns. Row 2/column 2 is 3, not 2 because its indices match. Keep one text size/bounds and black-on-light appearance, without colour encoding correctness. Save the full answer before making blanks so the only source cannot be lost through deletion.

## Centre text without changing numerical identity

Use one text object per cell, centred against references without dragging headers inside. Change copied content before positional checks so aligned copies do not retain one number. Optical adjustment for narrow 1 must not alter spacing. Hide headers to read sixteen entries, then restore coordinate identification. Row grouping may aid selection, but exclude neighbouring lines when moving. Text does not update numerically from changed coordinates; every rearrangement needs the master list.

## Check row and column sets independently

Check complete nonrepeating 1–4 sets in four rows, then independently in four columns: 1234,2341,3412,4123. Row success is not column success. A sum of 10 is insufficient: 1144 also sums to 10 but lacks 2/3. Track seen-value sets manually without assuming a Latin-square validator. Only rows/columns matter; repeated 2 in the top-left 2×2 is not an error here. Do not add a subgrid condition afterward and reject the source.

## Swap two values within one row to reveal column failures

In a copy, swap the first two entries of row one to 2134. The row remains complete, but column one becomes 2234 and column two 1341, repeating 2 and 1 respectively. Record both conflicts; unchanged row sum does not mean unchanged validity. Columns three/four and other rows remain fixed, isolating effects. Restore or separately name the error example. This motivates two-direction audits, not unique-solution or automatic-error-detection claims.

## Separate blank exercises from answer versions

For practice, save a copy and hide a few entries with their coordinates recorded. Blank is not zero or a fifth symbol. Without uniqueness analysis, call the full grid a reference completion, not the only solution. Match exercise/answer IDs rather than pairing a different arrangement as uniquely correct. Colour hints are manual annotations, not software advice. Retrieve the original from the exercise before sharing; Sudoku-like appearance does not impose unwritten box/diagonal rules.

## Inspect sixteen cells and rule text after export

Save blank exercise, full completion and swap test. Read actual-size exported numbers with strokes clear of text. Check monochrome and changed backgrounds; white cell fills are not holes. Name order-four Latin square, exercise/answer and revision and confirm row one is restored. Retain row/column lists for editable delivery and recheck glyphs/positions after font changes. ## Still inspect columns when the grid looks complete

For repeated row values, check unchanged copied text before colour edits. Correct rows with two wrong columns suggest an in-row swap. If sixteen objects include headers, hide outside labels and recount entries. Mismatched blanks/answers need coordinates/revisions, not guessed filler. Recheck sixteen cells, four rows, four columns and explicit rules against the list. Neat numerical layout alone does not establish constraints; the exercise should explain them.
