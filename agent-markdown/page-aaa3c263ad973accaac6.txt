Place the same owned JPEG in a CBZ and compare selected areas, ICC evidence and device conditions in ManYue and a system viewer.

## Select an original JPEG safe to share

Choose an ordinary JPEG comic page you created or are authorized to use. Include identifiable solid-color areas, skin tones or a gray reference, and keep the original file and editable project. Record name, byte size, pixel dimensions, export time and origin. These identify a candidate but do not individually establish byte-for-byte equality. Do not substitute a screenshot or social-app copy: transmission may recompress or process profiles. Use a shareable original page for any public feedback, not a private or unauthorized book.

## Check for a confirmable embedded profile

Use an existing trusted image-information tool to inspect whether the JPEG contains an ICC profile, its name and the reporting tool version; save the observation. With no suitable tool or no displayed information, record unknown instead of assuming sRGB because the image looks normal. ICC describes embedded profiles as information for interpreting associated color data, but embedding does not guarantee every viewer uses it. A filename suffix alone does not establish a profile, and a wide-gamut screen does not establish a wide-gamut source. No ManYue profile-viewing, selection or color-management toggle is assumed.

## Prepare a one-page CBZ from the same file

Copy the original JPEG into a new practice folder with a clear page name such as 001.jpg; retain the independent original. With an existing archive tool, place that JPEG in a ZIP and name the practice archive .cbz. Include only material you are authorized to handle. Check the archive listing has one page image, extract it to a separate temporary location and compare byte digests with the prepackaged copy. Without a digest tool, mark equality unverified: matching names or sizes is insufficient. A matching digest supports equality of the compared file bytes. A different digest only establishes a byte difference: profile or other metadata, image data, or both may differ. It does not alone establish a visible difference. Do not re-export, screenshot or recolor during packaging, which would mix conversion with the viewer comparison.

## Record a reference on the same device

Open the prepackaged JPEG through an existing system image-viewing entry on the iPhone or iPad. Confirm the same picture, orientation and observation areas. Record device, system version, time, brightness and any color-temperature, appearance or accessibility display settings you can actually identify. For comparison keep the same device, orientation and lighting where practical, and wait for loading. This system view is a reference observation, not an instrument-calibrated color value or a guarantee of the author’s or printer’s intended appearance.

## Import into ManYue and locate the same picture

Use an actually visible local-import entry in ManYue for the CBZ, confirm the sample appears and open its single page. Locate the same color patch, gray region or figure, keeping zoom and orientation as similar as practical. Distinguish image content from the surrounding reader background. If import fails, the actual file is unsupported or only a thumbnail appears without an opened page, record the stage and visible message; do not guess what color transform the app performed. Leave import or reading observations incomplete if not done.

## Record actual differences in specified regions

Compare whether gray areas remain distinguishable and whether a red or skin-tone region shows an obvious directional change, then return once to the system reference. Record what was actually observed in each viewer instead of pre-filling normal or wrong. A visible difference, no obvious difference and unable to judge are distinct outcomes. The views occur at different times; visual adaptation, zoom, surrounding background and system settings can affect impressions. A screenshot can itself undergo color processing, so its pixels are not direct screen measurements. Retain only necessary shareable areas and file identity.

## Troubleshoot file, environment and entry in order

If both views look unusual, check the source file and export in the editing tool first. If only the ManYue page differs, verify the inspected archive and page were actually imported, then exit and reopen. If a difference depends on one viewing condition, hold other conditions fixed, change just that condition and record its prior value and restoration. A missing ICC field, unverified archive-byte equality or incomplete page load leaves cause undetermined. Do not delete the original profile, recolor the real book or generalize one sample to all files.

## Deliver reproducible scope and restored conditions

Reopen both the sample and reference and record file or archive identity, profile report, app and system versions, observation areas, display conditions, both results and untested items. Restore settings actually changed for the exercise, retaining the original and editable project. This single-page JPEG exercise complements the PDF color-card lesson: it compares an archived image with the same source in a system viewer and checks whether ICC information is confirmable. It does not test PDF color algorithms, every profile format or professional calibration. Without device observation, deliver only prepared materials and pending steps.
