Use trusted external tools to repack images from an owned CBR into ZIP-based CBZ, then check the first, middle and last pages in Book Isle.

## Confirm format scope and preserve the original

Book Isle’s public description lists CBR for import, management, filtering and synchronization and recommends conversion to CBZ for reading. Successful import does not establish direct CBR reading. Choose a short authorized CBR and retain the original and an independent backup. Record filename, size, expected page count and first and last page markers. Do not upload private scans to an unknown conversion website.

## Extract images from a copy

Create a separate test directory on the computer and open a CBR copy with a trusted tool that supports that archive. Inspect the actual contents and destination first. Stop for a password, corruption or unsupported format; do not guess passwords or overwrite files. Record image count and subdirectories and check first, middle and last pages open. Preserve non-image metadata initially rather than deleting it indiscriminately.

## Establish page order and create a ZIP

View the images by filename and compare numbers with content. If 1, 10 and 2 are ambiguous, plan uniform-width names on test copies such as 001, 002 and 010, then check cover and blank pages. Leave original images and CBR unchanged. Use a trusted tool to create a real ZIP archive containing the needed pages and inspect its internal hierarchy and count. Merely renaming a RAR file to CBZ does not convert it.

## Name and import into Book Isle

For a ZIP copy confirmed to open, change its extension to .cbz following the system prompt; retain the original ZIP copy and CBR. Choose that CBZ using the file-import method actually offered by Book Isle, wait for completion and record feedback. If the device asks to confirm the extension change, first establish that the contents really are ZIP; stop if uncertain rather than overwriting existing files.

## Compare page count and reader display

Open the imported result and compare cover, first, middle and last pages, count and orientation of wide images with the earlier record. A shelf entry or cover does not establish that every image was read correctly. If ordering differs, inspect filenames, archive hierarchy and page ledger in the test package. Change one condition at a time and repack a copy rather than repeatedly overwriting the original.

## Record results and protect the source

Record tool and app versions, redacted CBR and CBZ names, page counts, import feedback and untested items. Confirm that CBR, original images and final CBZ remain available. If extraction fails or unfamiliar files occur, preserve the state and consult tool documentation rather than claiming conversion. Extraction and repacking use external tools; no built-in Book Isle converter or physical-device test is claimed.

## Make a page-order ledger first

Suppose the source archive contains a cover, three body pages and a blank page. Record original filename, visual marker and intended CBZ position instead of only a total. Blank pages can serve layout purposes, so decide explicitly whether to retain them; for this comparison preserving them is preferable. If names sort as 1, 10, 2, inspect each page before deciding whether test copies should use three-digit numbers. Do not infer order from numbers alone.

If non-image files such as `ComicInfo.xml` exist, record them and understand that they may contain title or page-order data. Readers may handle metadata differently. Do not automatically count it as a comic page or overwrite and delete the original to force a matching count. If metadata must change, consult the relevant format and tool documentation and keep an unchanged archive. This exercise does not promise Book Isle uses every metadata field.

## Inspect the real ZIP contents on Mac

Apple’s file guidance describes compressing files or folders into ZIP through Finder. Select the needed images and retained material in the test directory, use the current Finder compress command and wait for completion. Open a ZIP copy in a separate location and inspect file count, hierarchy and order; an extension alone does not prove the contents are correct. Compressing the folder itself and selecting its contents can produce different nesting, so inspect the actual extraction.

If extensions are hidden, follow system help to inspect the real filename before renaming. If the result has a double extension such as `.cbz.zip`, verify the actual name and file type rather than repeatedly guessing. Retain the initial ZIP for comparison. If your computer cannot extract CBR, choose a trusted compatible tool or ask the source provider. Finder’s ability to handle ZIP does not promise it can open every CBR.

## Use observed results to decide what to keep

If the imported page count exceeds the ledger, inspect the ZIP for extra images, duplicate folders or covers. If a page is missing, check whether its image is in the archive and opens on the computer. System-generated auxiliary files and reader handling can affect outcomes, so inspect actual contents rather than assuming a cause. If the image itself is unclear, return to the source scan; repacking cannot recover an edge missing in the original capture.

Keep the original CBR and images after accepting the new CBZ, particularly when the original has notes or other material not shown by Book Isle. Before cleaning the temporary directory, confirm retained locations and backups; do not remove the only copy. If organization, extraction or import was incomplete, record that and the actual prompt. Separately checking source files and the app shelf distinguishes file conversion from reading position. Record completion time and actual tool version for later review.
