Compare two authorized versions in a Kodi movie library, keeping server default, iCouldPlay display and playback observations distinct.

English translation of the [Chinese original](<https://allluckly.cn/guides/icouldplay-kodi-movie-versions-default-client-observation/>), translated on 2026-11-21. Original publication dates, attribution, code and version notes are retained.

Compare two versions of an authorized movie in an existing Kodi library. Record the relationship visible on the Kodi server, then inspect what iCouldPlay actually displays and plays. This exercise does not assume iCouldPlay exposes Kodi’s version selector.

## Prepare two identifiable authorized versions

Use two authorized copies of one film, such as a normal edit and a shorter edit you made yourself. Preserve the originals separately. In an existing Kodi movie library, choose two versions already associated with the same movie. If your Kodi installation or library does not provide version grouping, record the unmet prerequisite and consult Kodi’s documentation; do not move, rename or delete files in bulk just to make an example. Privately record both file locations, durations and a distinctive opening or ending for each.

## Establish the server-side facts first

On the Kodi device you manage, open the movie information and observe the entry and any actual version relationship. Kodi documents grouping multiple movie versions beneath a parent entry, with one default; that does not establish the same interface for every library, TV episode or client. Record the installed Kodi version, title, visible labels, default if identified, and whether each version plays in Kodi itself. If labels are absent, record that you did not observe them instead of inferring a group from filenames.

## Prepare identifying observations

Play the first few seconds or another known differing segment of each copy and record the image, player time and duration. For illustration, one short version might show a blue title at 00:12 while a longer version shows white; use differences actually present in your own material. Record the time displayed by the player rather than estimating it from another edit. If the copies look identical, a title or poster alone cannot establish which file played. Find a verifiable difference or leave identity pending.

## Inspect the same source in iCouldPlay

Open the already configured and authorized Kodi source in iCouldPlay. Confirm that the server and movie library match the Kodi device inspected above, then find the same movie. Record whether you see one card, several cards, version labels or no movie. Try a version selector only if it is actually visible. Kodi’s server-side grouping does not prove that iCouldPlay exposes a selector; presentation can vary by app version and server configuration. If the movie is absent, check the source, library, login and list refresh state and retain the actual feedback.

To avoid confusing a server entry with a same-named local copy, record the source name, library containing the card and the actual access path before observing. If the client does not expose the path, mark it unavailable rather than guessing from a filename. Enter through the same Kodi source for each comparison and note whether you reopened the movie entry. Even with identical posters this identifies whether to investigate the source first or continue checking images and duration.

## Record the initial playback result

Without changing server settings, open the item iCouldPlay actually displays. Observe the duration and the identifying scene recorded above, keeping the displayed time and image in your notes. If they agree with Kodi’s current default, record that this sample is consistent with the default; one observation does not establish a universal selection rule. If the image agrees but the duration differs, investigate whether the result is a trailer, transcoded copy or another file before assigning an identity based on title.

## Compare the other version only if offered

If iCouldPlay actually offers distinct versions, select the other item without deleting or overwriting the originals and repeat the same checks: duration, image at the same time and whether playback begins. If only one entry is offered, record that no selector was found and stop this comparison; opening an unrelated same-named file from another source is not a successful selection test. Do not alter Kodi’s default or server settings to manufacture the expected outcome. If the user already intends to adjust the server, back up and record its original configuration independently, then distinguish server changes from the client selection.

## Investigate differences and protect the library

If Kodi plays the movie but iCouldPlay lacks the entry, check the connected server, account, selected library, current list and network, then ask the administrator about service status. Do not publish private server addresses or passwords. If an item is listed but fails to play, retain the actual error, source and file identity and compare Kodi’s local result with iCouldPlay’s result. A visible list does not establish access to the underlying media path. If only one entry is displayed, describe the observation instead of declaring a file lost or a defect proven.

## Deliver a two-sided comparison record

Keep the identifying marks for both files, Kodi version and default state, entries visible in iCouldPlay, observed playback and unfinished checks. Confirm that original files and the existing library remain available, and close playback when finished. Remove private accounts and paths before sharing. If the second version cannot be identified, mark it pending. This repeatable observation is not a compatibility test for every Kodi release, network, media format or iCouldPlay version.
