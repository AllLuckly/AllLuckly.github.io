Compare visible regions, page boundaries and observed Book Isle display using authorized PDF copies.

## Understand two page boundaries

A PDF MediaBox defines page medium boundaries; CropBox defines the intended visible region and normally defaults to MediaBox if absent. Missing visible edge content does not by itself mean the original page object was removed or that Book Isle caused it. Inspect only self-made or authorized copies, and do not recover another person’s hidden private content.

## Create a simple test page

Create an owned one-page PDF in an editable tool with “center” in the middle and distinct short markers near all four edges; save an original and a test copy. Use non-private text so the test cannot expose previously cropped personal information. Record page size, filename and expected marker positions for a consistent comparison.

## Inspect original boundaries

In a trusted PDF tool inspect the sample’s MediaBox and CropBox and record values and tool version. Page boundaries can be inherited through the page tree, and a tool may display resolved inherited values. Do not infer a boundary is absent merely because a field is not directly present on one page object. If inspection is unavailable, record unknown.

## Save a cropped comparison copy

Using a trusted tool, create a second copy of the owned test page with a smaller visible region that retains the center and some edge markers; record the crop. Do not overwrite the original or assume cropping physically deletes objects outside the visible area. If the tool regenerates pages instead of adjusting a visible boundary, record its method rather than conflating the mechanisms.

## Verify in the source tool

Open the original and cropped copy separately in the PDF authoring tool. Record which edge markers are visible, the page order and filenames. If results differ from expectations, check that saving succeeded, the intended page was selected and the crop lies within the page. Do not proceed to alter real files until the test sample is understood.

## Import and identify copies

Import the original and cropped test copy using Book Isle’s available method, identifying each through title or distinctive page content. Record device, app version and reading layout. If entries merge or import fails, retain the actual message rather than deleting the normal library. If filenames are not displayed, use the identifiable test content rather than guessing.

## Compare each edge under matching conditions

With the same device orientation and reading layout, record visibility of the center, top, bottom, left and right markers in both copies. If zoom is actually available, record and match its state; do not assume a control exists. Separate visible-region differences from zoom or screen clipping rather than drawing a conclusion from one screenshot.

## Cross-check the page display

If Book Isle differs from the authoring tool, first verify identical file, page, orientation and zoom, then inspect the same copy in another trusted PDF reader. Record visible regions and tool versions without treating any one tool’s behavior as automatically authoritative. If every tool misses the same edge, inspect the copy’s page bounds and generation method.

## Do not use cropping as redaction

Data outside a visible region can remain in the PDF, so cropping is not reliable permanent removal or privacy redaction. For sensitive documents, follow a trusted tool’s proper redaction process and verify the resulting copy. Do not expand bounds to inspect another person’s hidden information. This exercise uses self-made non-sensitive samples.

## Record and roll back

Record each file’s boundary values, visible markers, reading environment, comparison tools and unperformed steps. Make later changes only to owned test copies and identify one before deciding whether to remove it; retain the original and backup. Omit private paths and accounts from shared reports. This guide claims no device or private-library test.

## Separate viewport from page

A screen’s reading viewport may show only part of the current page, especially after zooming; the screen edge is not the PDF page boundary. Confirm the current page and zoom state in the available interface, then see whether actual supported controls allow moving around the page. If unavailable or unperformed, record unknown rather than automatically calling off-screen content cropped.

## Recheck provenance of both files

Record the generating tool, save time and page count for the original and cropped copy and verify filenames before opening. If both tests show the same page, first check whether the same file was selected twice, then compare with the samples in the editing tool. Whether the app merges copies must be observed; do not alter real library files to force a difference.

## State the scope of conclusions

Keep “content not visible in the current view” separate from “object absent from the file” in the test table; if only the former was observed, mark the latter unknown. Technical bounds apply only to pages inspected, not automatically to a whole multi-page document. For additional pages, record sequence and boundaries separately rather than substituting page one for the whole book.

## Check a multi-page sample

For an additional self-made two-page file, change only the second page copy’s visible boundary and use different labels on each page. Inspect each in the source tool, then find the corresponding page in Book Isle and record its edge markers. Repeat separately if page order or zoom changed; a normal first page does not prove the entire file.
