Create a minimal WebVTT file for a personal clip and verify format, selection and three cue locations.

English translation of the [Chinese original](<https://allluckly.cn/guides/icouldplay-make-webvtt-practice/>), translated on 2026-10-27. Original publication dates, attribution, code and version notes are retained.

Start captioning a personal demonstration with three verifiable cues. iCouldPlay publicly lists external VTT support. Create text outside the player, placing cues near the beginning, middle and end. This workflow does not require automatic speech recognition or treat the player as a subtitle editor.

## Choose three events in the clip

Use a known working personal video and record visible opening, movement and ending events. Allow a few seconds per cue without overlap. Write your own descriptions and keep the first test small rather than beginning with dozens of lines or commercial dialogue.

Watch the original completely and fix this edition for the test. Later cuts require new timing checks. Keep its name and event times together so matching filenames alone do not determine which captions belong to which edit.

## Understand the minimal structure

Create plain text beginning with WEBVTT and a blank line. Each cue has start time, arrow, end time and text, with blank separation between cues. Keep time formats consistent and end after start. Leave colours, positioning and complex tags out initially.

See the [W3C WebVTT description](<https://www.w3.org/TR/webvtt1/>) for the header, timing and cue groups. The following times are examples to replace with your actual events, without implying dialogue exists at these positions. A readable text file still needs content and timing verification.

```text
WEBVTT

00:00:02.000 --> 00:00:04.000
Opening card

00:00:20.000 --> 00:00:23.000
Move the object

00:00:45.000 --> 00:00:48.000
Ending card
```

## Save actual plain-text subtitles

Save UTF-8 plain text with a VTT extension, ruling out an extra TXT suffix. Reopen it and inspect header and arrows. Renaming rich text or a document cannot convert its internal structure into parseable subtitles.

Keep captions beside the corresponding video copy under clear edition names. Matching names do not guarantee matching timing. Download cloud files first and retain an editable original, naming revisions so you know which file the player loaded.

## Select the file during playback

Open the same video and use available subtitle-management or external-import controls. Verify this file is selected rather than disabled or an older one. Follow visible controls; for an unavailable entry point, record the playback path instead of repeatedly renaming extensions.

Play from shortly before the first cue and watch its appearance and disappearance. No words before its interval does not establish failure. If absent throughout, inspect syntax, saved format and selection before comparing playback paths or re-encoding video.

## Verify middle and ending independently

Compare all three events and distinguish a constant offset from sudden displacement after a cut. For this self-authored sample, correct your recorded cue times before masking mistakes with global offsets, keeping the file independently understandable.

Load clearly named revisions and confirm the selected version before repeating the same scene. Avoid simultaneous font, video and timing changes. A cue beyond the video's ending cannot appear; check edit selection and minute-second confusion first.

## Add Chinese text and recheck

After basic English cues work, create a copy with short Chinese text but unchanged intervals. Inspect UTF-8 for garbling and character/font coverage for isolated boxes. Start with ordinary characters without resetting every style control for one display difference.

For two lines, keep cues short and break at natural phrases, checking actual viewing size. Displayability does not establish adequate reading time. These are editing choices, without promising identical complex positioning or web styling across engines; test additions individually after basic text works.

## Preserve the verified pairing

Record video, caption file, events and results, then reopen playback. Check both video and captions independently offline, beyond previously loaded pictures. Keep caption originals externally; saved selection is not file backup or proof of suitability for every similarly named cut.

Completion means three cues appear and end near intended events, editable originals remain available and every timestamp has a visible reference. Extend gradually and repeat three-location checks, preserving this minimal file as a baseline rather than substituting someone else's complete subtitle for understanding your own timeline.
