A comic book cover and series cover can come from different images. Separate naming and objects before observing the server and Manyue+.

## Separate book and series covers

Komga documents that a custom book poster uses the same base name as the book file, while series artwork belongs in the series directory under supported names such as cover, default, folder, series or poster. These target different objects and cannot be swapped just because names look similar. Whether Manyue+ shows each position is a separate observation for the installed version.

## Prepare two self-made images

In an isolated test series the administrator prepares an authorized Book 10.cbz copy and two self-made images: a blue B for the book and a yellow S for the series, with no private information. Record first-page marker, page count and image dimensions. Keep originals and a server backup; do not change production comics or existing covers.

## Check real format and names

Prepare a copy of B as Book 10.jpg and S as cover.jpg outside the test series directory. The administrator checks the target directory containing Book 10.cbz and first verifies that neither filename already exists there; stop rather than overwrite an existing file. Confirm the images open and are genuinely JPEG, since changing an extension does not convert format. Komga also supports PNG, WebP and other documented formats, but use the format actually prepared.

## Record the server baseline

Before placing images, scan and inspect the server web interface, recording series cover, book cover and identity. Komga says analysis can use a book’s first page as default artwork, so an existing baseline image does not prove the test image imported. Connect web and Manyue+ to the same account and library, noting list, detail and first-page locations without assuming the client provides two distinct image regions.

## Refresh and inspect web roles

After recording the baseline, the administrator places the two checked copies alongside Book 10.cbz in the test series directory, refreshes test-series or book metadata under the current library options and version, then waits for completion. Inspect whether the web series position shows S and the book position B, recording each actual image and time. If unchanged, check local-artwork import options, location, name and refresh target first; do not repeatedly scan production libraries or overwrite files.

## Check the same book in Manyue+

Using the same server account, find the test series and Book 10 in Manyue+ and inspect list and detail positions the app actually provides. Record where blue B and yellow S appear. If only one image or no separate series cover is offered, mark unavailable or not observed rather than assuming the app must copy the web layout. Verify the first-page marker and page count to rule out another similarly named edition.

## Compare priority and visibility

If the web shows B but the app still shows an older image, that establishes different observations at those times only. Check book identity, account, server, normal page re-entry and time. If caching or the refresh mechanism is unverified, mark it unknown. If S is absent, inspect the server’s selected series artwork and configuration; merely placing a file does not guarantee immediate replacement of the current choice.

## Understand multiple-poster scope

Komga supports numbered book poster names such as Book 10-1.jpg and Book 10-2.png. This does not imply that a client exposes a selector or that several files are required. This exercise uses one book poster and one series poster. Skip an additional selection test without suitable images. Do not mistake Book 10-1.jpg for a second comic or cover.jpg for the book’s first page.

## Preserve files and check reading

Open the same test comic’s first and last pages on web and in Manyue+ to confirm added artwork did not replace CBZ content. Correct artwork does not prove all pages are readable, and readable pages do not prove both covers updated. Do not delete, repackage or rename the originals during checks. If there is a problem, the administrator inspects the test copy and original and records the failure stage.

## Map files to objects

Make three rows: Book 10.cbz is content, Book 10.jpg is the custom poster matching that book base name, and cover.jpg is series artwork in the series folder. Record actual sizes, image markers and modification times separately; do not infer contents from extensions or publicly share test paths. If a name contains extra spaces or case differences, ask the administrator to compare the actual filesystem with the documented naming rules.

After refreshing, inspect series and book details separately on the web, noting exact positions, then visit corresponding Manyue+ views. Layouts can differ, so establish whether a view represents the series or the book. A yellow series image in a list does not prove the blue book poster failed. If a view has no artwork region, mark that cell inapplicable rather than failed.

Without a recorded pre-image baseline, a later picture cannot automatically be attributed to this change. Re-establish before and after records on test copies without repeated deletion or overwriting. Where the source of a selected server or client image remains uncertain, record unknown and ask an authorized administrator to inspect it.

## Restore and hand off

The administrator removes only newly added test images or retains the isolated library by agreement, then verifies production files, prior covers and backups are intact. Never delete a pre-existing same-named image. Record filename, object, refresh scope, web and Manyue+ display, readability and unperformed steps; omit private addresses and tokens. This public-documentation guide claims no private-server or physical-device test.
