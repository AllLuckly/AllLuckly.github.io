Compare authorized recordings across two personal servers by source, account, metadata and audible cue.

English translation of the [Chinese original](<https://allluckly.cn/guides/diaodiao-fnos-audiostation-same-track-two-server-sources/>), translated on 2026-11-21. Original publication dates, attribution, code and version notes are retained.

The public release notes for 调调 1.0.4 describe connection and library-browsing improvements for Feiniu Music (FN Connect) and Synology Audio Station. When titles match across services, establish each source and recording before comparing playback; matching names do not establish synchronization.

## Prepare two independently authorized sources

Use only Feiniu Music and Audio Station services you manage or are authorized to access. Prepare an authorized recording on each. The two may be copies of one master or distinct self-recorded clips with the same title and different opening markers; write down which arrangement you chose. Record non-sensitive service aliases, account permissions and expected title while keeping the original files. If you have only one service, establish that side’s baseline and mark the other pending. Do not use strangers’ public servers or credentials to complete the comparison.

## Make separate source identity cards

From each server’s own administration interface or a trusted file source, record title, artist, album, duration and an audible opening cue. If both derive from one master, matching duration alone does not prove byte identity. If byte equality matters, hash authorized copies outside the server and record the method. If recordings differ, preserve their distinct cues for listening. Do not put tokens, passwords, internal addresses or private library inventories in public notes.

## Identify the first source

Within your authorized network and account, open the existing Feiniu Music connection in 调调 and browse or search using actual visible controls. Verify service alias and account before comparing title, artist and duration. If a connection must be created, use your own known service details and the actual interface; do not assume both services use identical ports or forms. If an item is missing, record directory and search conditions without changing server permissions or deleting the library.

## Play and record the first source

Select the identified item and play briefly at an appropriate volume. Record player title, audible cue, output and connection source. Mark “visible in server list,” “selected by user” and “audio heard” as separate observations. Visibility does not mean downloaded or played. If playback interrupts or audio cannot be identified, preserve the actual symptom and time instead of recording success. Stop the test while preserving the previous queue; do not write to a shared server.

## Recheck identity after switching services

Use the actual interface to switch to Audio Station. Confirm alias and account again before finding the same-title item. Do not reuse assumptions about the first service’s path, credentials or folders: the services may index different locations. Check the same fields, play a short portion and record the second cue. If the first source still appears, inspect current source and loading state; the title alone does not prove a successful switch. If controls differ, record the screen and stop at what you can verify.

## Build a two-column result table

For each service record type, non-sensitive alias, account permission, title, duration, audible cue, playback result and pending items. Similar sound establishes similarity only for the heard portion. Record byte equality separately only if source hashes were actually compared. Same-title items with different sound are an observation, not automatically a synchronization failure. A locally imported copy and server item are also separate objects; do not infer automatic server-file updates.

## Troubleshoot connection, indexing and playback separately

If a connection fails, check the appropriate service, your permissions and network reachability. Do not disable a firewall or expose the service to the internet as a default repair. When connected but missing an item, inspect that service’s own index and account visibility. When visible but silent, check output, player state and authorized readability of the source file. Change one condition at a time, record before and after, and give the server administrator a credential-free error description if necessary.

## Restore and state limits

If you created a test recording or temporary connection, identify its ownership before removing only your own disposable item; leave it in place when uncertain. Do not remove existing accounts or assume observed metadata is licensed for public sharing. Note whether the two identity cards represent copies of one recording or distinct same-title recordings. Permissions and networks can change, so date the observations.

Stop test playback and restore output, volume and queue. Preserve the servers and others’ favorites. Keep the sanitized two-column table and pending checks. Release notes do not guarantee every server version, authentication method or network environment; no private-server or physical-device test is claimed.
