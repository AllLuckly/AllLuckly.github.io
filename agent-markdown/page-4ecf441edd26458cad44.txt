开启并验证书屿应用锁，理解系统身份验证、失败重试和关闭流程，同时区分 App 访问保护与导出文件、NAS 权限。

私人书架里可能放着未公开的工作资料、个人笔记和阅读记录。书屿的应用锁使用系统 Face ID、Touch ID 或设备密码进行验证。本篇演示怎样开启、检查重新进入时的保护，以及它与文件备份、服务器权限之间的区别。

## 开始前确认设备验证可用

先在系统设置中确认设备已经配置密码，并按设备能力启用 Face ID 或 Touch ID。书屿调用的是系统身份验证，不需要你另外为应用创建一套未知密码。若系统验证本身不可用，应先完成系统设置，再开启应用锁，避免把设备配置问题误认为书架文件异常。

练习前记住自己能够正常解锁设备，也确认重要资料有独立保存方式。不要通过删除应用来试验“能否绕开锁”，因为删除可能移除本地内容。应用锁的目标是在使用界面上增加访问验证，不是替代系统设备保护或所有数据备份策略。

## 在设置里开启应用锁

打开书屿「设置」，进入「隐私与安全」相关区域，找到「应用锁」。开启时会触发系统验证，按照屏幕提示完成。验证成功后回到设置，检查状态是否显示已开启；取消或验证失败时，不要只凭自己点过开关就认定保护已经生效。

如果提示先启用 Face ID、Touch ID 或设备密码，回系统设置处理，再重新操作。不同设备使用的验证方式可能不同，带 Touch ID 的设备不应寻找 Face ID 专属按钮。完成开启后，先保持这一本练习书在书架中，后续检查不需要触碰真正敏感的文档。

## 检查离开与重新进入的表现

回到系统主屏幕，再打开书屿，观察是否出现验证或“私有书库已锁定”提示。完成验证后，应能回到书架或之前的使用界面。第一次可以取消验证，确认书籍内容没有因此直接露出，再通过「解锁」重新尝试。

也可以在应用切换器中观察预览是否被保护界面遮挡，然后回到 App 验证。这个动作的目的是确认你日常切换应用时的实际表现，不需要拍摄私人内容，也不要因为一次系统动画短暂变化就推断所有场景都具备完全相同的保护。以当前设备与版本的可见行为作为检查依据。

## 认识失败重试与关闭流程

验证失败后，按页面「解锁」再次调用系统验证。系统可能根据设备状态要求密码或暂时限制生物识别，跟随系统提示即可。不要把 NAS 登录密码、Apple 账户密码和设备解锁密码混在一起：它们服务于不同系统，书屿应用锁并不要求你把服务器密码填到这个界面。

若确实需要关闭应用锁，应先解锁进入设置，再关闭并完成要求的验证。关闭后检查状态是否变为未开启，再重新进入一次确认。这是一个可恢复的设置变化，适合在把设备交给自己管理的其他使用场景前检查，但不应该让陌生人代为输入你的设备密码。

## 文件导出后要按目的地管理

应用锁保护书屿界面的访问，不会自动给已经导出到「文件」或相册的笔记、卡片和电子书加上同样的锁。若你把书摘卡片保存到相册，之后从相册打开它，使用的是相册自己的访问方式。分享到其他 App 的内容也应按那个 App 的规则管理。

因此处理私人笔记时，可以先确认导出目标是否合适，再保存。工作资料需要长期留档，就选自己明确管理的位置，并用清楚的文件名区别私人版与可分享版。不要因为书屿有应用锁，就把所有导出内容默认视为已经加密或不会被其他设备同步。

## 服务器与设备分别保护

书屿中的应用锁不会替 NAS 关闭访客权限，也不会修改 WebDAV、SMB 或 Calibre 的账号设置。服务器仍需要自己的访问控制；设备本身也应使用系统密码。两者共同服务于私人书库，却不能互相代替。远程连接信息变更时，仍应到对应连接设置核对。

如果你在两台设备使用书屿，应分别检查每台设备的锁状态与系统验证配置，不要假定同步阅读记录就自动完成了设备保护设置。换新手机后先确认本地书架、同步与文件可用，再设置应用锁并按本篇步骤检查，能更清楚地知道每一步是否完成。

## 常见问题

**不开 Face ID 能用应用锁吗？** 当前实现使用系统设备所有者验证，设备密码或 Touch ID 可能参与可用方式。具体取决于设备能力和系统配置；如果页面提示无法开启，先按提示建立可用的系统验证。

**忘记设备密码后能让书屿找回吗？** 应用锁依赖系统验证，书屿没有替系统恢复密码的入口。应走设备本身的官方恢复方式，并注意这些流程对本地数据的影响。不要把卸载重装当成无损恢复方法。

**开启应用锁是否表示所有电子书都已加密？** 不能这样推断。应用访问验证、文件存储保护、服务器传输与导出文件的保护是不同层次。开启应用锁后，进入书屿需要验证；你导出到其他位置的文件仍由目标位置管理，若需要单独加密，应使用相应的文件保护工具。
