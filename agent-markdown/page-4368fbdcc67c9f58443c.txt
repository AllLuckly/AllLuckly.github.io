Practise price columns, long item names, categories and update checks with a fictional café menu, keeping text editable.

English translation of the [Chinese original](<https://allluckly.cn/guides/vectorpaint-cafe-menu/>), translated on 2026-10-26. Original publication dates, attribution, code and version notes are retained.

A menu should make names, choices and prices easy to find. Use six fictional drinks to design a static café menu with consistent columns and spacing. Example prices are exercises; the app does not become an ordering or calculation system.

## Prepare an auditable content list

List six names, sizes, short descriptions and example prices, including one long name and one drink with two sizes. Divide them into classic coffee and caffeine-free groups. On an 800 by 1100 pixel canvas, reserve title, menu and footer areas. Standardise currency and units. For a real shop, approve the content first and use that list as the revision reference.

## Give names and prices separate columns

Create separate editable objects for names and prices. Right-align prices against a consistent edge instead of using spaces, whose widths change with fonts. Set outer margins, reserve a price column and give the remaining width to names. Check the selection before aligning so category headings do not move too. Establish one working row before duplicating it.

## Associate descriptions with the correct item

Place smaller descriptions below their names with the same starting edge. Keep sizes near the prices they describe. Choose one consistent rule for dual-size items, whether an extra row or stacked prices. Replace every field after duplication, including empty descriptions that might retain old copy. Hide prices temporarily to confirm the names and descriptions identify each drink clearly.

## Express categories through spacing

Use consistent spacing within groups and larger gaps between groups. Keep category headings subordinate to the main title. If using rules, standardise their length and colour and separate them from text. Inspect the content without decoration. When a long description adds height, move subsequent items down together instead of shifting only its price and risking an incorrect association.

## Handle long names and footer information

Break long names at natural phrases and keep the second line clear of prices. Move descriptive flavour wording into the description before shrinking one item disproportionately. Use confirmed wording for temperature, allergens or pricing conditions, and separate footer notes clearly. Do not imply unverified food attributes through icons. Test the hardest row with the longest description and widest price.

## Audit content before appearance

Save the editable original and content list. Read each exported name, size and price before judging alignment and colour; incorrect content can look perfectly neat. After a price change, inspect related sizes too. Check the smallest text at the real display distance rather than relying on phone zoom. Include revision and applicable date in filenames to prevent obsolete menus returning to use.

## Rehearse a price revision

Change only two size prices for one drink in a copy and locate them from the source list. Confirm they remain easy to select. Include repeated prices in footer or package wording in the revision checklist. Compare exports row by row for unintended changes elsewhere. Archive the old version clearly. This rehearsal reveals layouts that look good but make routine updates error-prone.

## Diagnose misplaced prices

For one shifted price, inspect that object’s alignment and bounds before redistributing the menu. For a whole uneven column, check common alignment and stray spaces. Unexpected exported wrapping may come from unavailable fonts; keep editable text and check a separate appearance-fixed copy. If a description crowds the next item, enlarge its row or shorten it rather than pushing headings to the page edge.
