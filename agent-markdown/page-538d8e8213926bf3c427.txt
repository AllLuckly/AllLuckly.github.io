## 1. Identify the two copies being compared

Choose an owned or authorized clip with a clear sample identifier near its opening. Label the existing complete computer file A and a complete copy obtained from a source you manage B. Record acquisition date, source path and size. Partial playback cache is not a complete B, and a transcoded copy should not be treated as the same byte representation as the original. ## 3. Read validators within their actual scope

[RFC 9110’s validator definitions](<https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8>) describe an ETag as an opaque server-assigned validator. W/ marks a weak form. An ETag need not use a particular hash algorithm, and a modification date is not a locally computed file digest. These are invented teaching cards, not an observed download result. Preserve case, quotes and W/ and label the fields accurately, without guessing an implementation from their appearance. Label them as a server validator and server-declared modification date, not MD5 or device capture time.

```
ETag: "sample-a"
ETag: W/"sample-a"
Last-Modified: Tue, 10 Nov 2026 00:00:00 GMT
```

## 4. Compute the same digest for complete files

Once A and B are fully downloaded, locally available and no longer being written, compute SHA-256 for each on the computer. These macOS commands use exercise filenames: first copy or rename the files into your own exercise directory and ensure that they identify your actual copies and keep quotes around paths containing spaces. Record the full output and time. Matching digests support byte identity for these complete copies. A mismatch establishes a byte difference, not necessarily a visible content difference or a quality ranking. Container metadata, transcoding or other file rewriting can change a digest.

```
shasum -a 256 "sample-A.mp4"
shasum -a 256 "sample-B.mp4"
```

## 5. Return to iCouldPlay for visible identity checks

Open A and B as separate exercise files. Check the opening identifier, one clear action in the middle and an ending marker. Confirm the source name after every switch and play into each checkpoint rather than relying on thumbnails or a resume position. If hashes differ while these checkpoints match, say only that no content difference was found at the observed points. Do not claim frame-by-frame equality. A remote URL that changes over time also requires an observation time; a later player request may not retrieve the same representation as B.

## 6. Keep different conclusions in different columns

Add separate columns for response validators, complete file bytes and viewed content. Identical tag text from different servers or representation conditions is not a cross-server file identity proof. Different hashes with matching openings should remain “different bytes” and “matching observed opening” in separate columns. An absent modification date does not make an otherwise complete playable file corrupt. Conversely, an attractive title and update date do not establish a complete download. Try the invented field cards as classification practice, then enter the actual A/B findings. Mark comparisons you did not perform as unchecked.

## 7. Troubleshoot incomplete or different representations

If a digest changes between runs, check whether downloading, synchronization or another program is still modifying the file. Retry after it stabilizes rather than attributing remote changes to the player. If delivery involves content coding or another quality representation, identify exactly which saved bytes are being compared; an HTTP coding label is not a video codec. A file of only a few kilobytes or a login response calls for download identity checks, not renaming it MP4. Preserve the response status and retrieve the clip through its normal authorized entry. For stale content, preserve source, time and validators for investigation. Clearing app data is not required, and do not assume the cache is necessarily on the device.

Another reader should be able to identify which layer of sameness was checked and which remains unknown. Add a row for later source updates instead of replacing this result. The outcome is traceable version checking, not hash guessing from an ETag’s shape or a universal integrity guarantee from one successful playback.
