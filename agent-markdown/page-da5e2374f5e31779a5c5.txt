A Calibre library consists of metadata and actual files; copying metadata.db alone does not copy all books. If you already connect Calibre to Book Isle, first distinguish Content Server access from database-directory access, then validate one book after a computer or NAS move. These are separate connection paths.

## Identify your current connection method

Content Server exposes books through a running service; database access depends on metadata.db and its matching structure. Inspect the connection type you originally added and record its server address or library directory. A database filesystem path does not belong in a server URL field merely because both use Calibre.

If the old method worked, focus on migration changes rather than changing methods too. Record one familiar title, author, format and quotation as a sample. Preserve important readable notes and original files before moving the only source and losing its relationship to existing records.

## Confirm the moved library through Calibre itself

Open the moved library normally in Calibre and inspect books, covers and actual reading files. Prefer its supported library-management process rather than manually changing managed author folders or book IDs. Tidy-looking directories do not prove database paths changed consistently.

Open both an EPUB and PDF from the management side to rule out metadata-only preservation. If Calibre itself cannot find them, repair the source before rebuilding Book Isle connections. A client cannot reconstruct missing text or covers from a catalogue record alone.

## Verify database and files moved together

For database access, confirm metadata.db belongs to this moved library rather than a separate old backup. Check that its author and book folders came too. A copied database may show titles while files remain inaccessible; this is a metadata-file relationship problem, not necessarily a search query issue.

When exposing the directory through existing WebDAV or SMB access, inspect the full structure from the shared root. The account needs read access to actual book subdirectories; readable top-level metadata does not establish that. Preserve real paths containing spaces or Chinese characters instead of guessing simplified replacements.

## For Content Server, verify the running endpoint

Confirm the new machine's service is running, selects the right library and preserves intended account permissions. Use actual address, port, domain and proxy path rather than the computer's filesystem location. A sleeping computer or stopped service can make the catalogue temporarily unreachable and should be checked at the source.

Browse with the same account in an external client before comparing Book Isle listing and retrieval. Login does not establish access to every library, and listing does not validate acquisition URLs. For a proxy subpath, verify both catalogue and download rather than relying on an accessible service homepage.

## Read one sample in Book Isle

Use available connection editing or browsing to enter the new location and find the recorded sample. Check author and format, then download or open it and inspect beginning, middle and end. Reopen offline after downloading to distinguish a readable local copy from catalogue metadata or temporarily loaded pages.

If metadata appears but retrieval fails, investigate shared paths and read permissions. If a retrieved file will not open, compare the same file with Calibre's copy. Recording the failure stage prevents unnecessary database-path edits from disrupting parts that already worked.

## Compare old records and companion formats

For matching titles after migration, compare edition, identity and format before merging or deleting. Existing local copies can still work while new-path copies need separate checks. Verify progress and notes through chapters and quotations, not titles or percentages alone, particularly when the source edition changed too.

For multiple formats, choose the primary one and establish that companions really exist. An EPUB entry in the database does not prove the file reached its new location. Before cleaning old directories, trace important formats and preserve notes; unchanged shelf-card counts cannot justify removing originals.

## Keep the migration inventory for future use

Record connection type, new endpoint or shared root, sample, checked formats and date, managing passwords elsewhere. Mark large files still being copied as outstanding rather than presenting limited sample success as individual verification of the whole collection.

Reopen the app and check one earlier import and one newly retrieved book. Understanding source library, database, server endpoint and local-copy relationships is more useful than repeated scans. Follow the same order on a future move instead of guessing from a cover that opens no text.
