Older and newer seasons of a long show may live on different disks or Kodi video sources. Separate folders do not necessarily mean two shows, and a single poster does not prove every episode is indexed. Check the existing server library first, then what iCouldPlay actually displays and plays.

## Confirm the prerequisites

Use a Kodi library you manage or are explicitly authorized to inspect. Choose a show with episodes already in two source folders; there is no need to move, copy or rename files for this guide. If you have no such library, mark the prerequisite unmet instead of treating the example as your result. Preserve backups, record an administrator contact and inspection time, and use nonprivate aliases for directories, servers and accounts.

## List the original items in both sources

In an authorized file manager inspect source A and source B. Record each show folder name, season folder, sample filenames and actual season and episode numbers. For example A might contain season 1 episodes 1 and 2, and B season 2 episodes 1 and 2; this is illustrative, so enter your own files. Use a row per season and episode. Matching folder names do not prove matching content, and the same episode number in different seasons is not automatically a duplicate. Mark unreadable folders unknown.

## Check show name and sources in Kodi

With the administrator's permission inspect the existing Kodi TV library. Record show name, year, season count and whether each sample episode appears, and compare each against both file lists. Kodi's official documentation recommends identical TV show folder names across split sources; slight differences can identify different shows. When using NFO files, the documentation also advises using the same NFO in each split show folder. Observe only: do not automatically edit folders or trigger scraping. Kodi versions, providers and configuration vary, so the actual library remains the authority for its result.

## Check whether both sides refer to one work

If Kodi shows two show cards, inspect both titles, years and season lists against the file inventory. Even matching posters do not establish identity; remakes or different works with the same title must not simply be merged. If there is one card, open its seasons and verify the A and B sample episodes individually. If information or access is insufficient, mark the row pending rather than assuming the server merged it successfully.

## Check the visible result in iCouldPlay

Open the already configured and authorized Kodi source in iCouldPlay and confirm it is the same server. Find the show through the library entry the app actually provides and record card count, visible name and season/episode list. Entrances and presentation can vary with version, account and server state. If iCouldPlay does not expose file paths or disks, record those as invisible; do not claim that the client has identified split folders or attribute Kodi maintenance controls to iCouldPlay.

## Compare playback of two samples

Select an authorized episode from A and one from B. First check each opening picture and sound in a trusted reference player. Then open the corresponding visible episodes in iCouldPlay and record whether listed, whether playback starts and whether the opening matches. An opening segment does not prove the whole episode is intact. If sound is absent, record picture, audio track and output device separately instead of blaming split-folder recognition. If an item is missing or will not play, preserve the error and time without changing permissions or overwriting data.

## Compare and investigate missing episodes

Create a sanitized table with season/episode in each source folder, presence in Kodi, presence in iCouldPlay and observed playback. If a file exists but is absent from Kodi, ask an authorized person to check source access, folder names and numbering, then the scraper and library state. Do not clean or rescan the entire server without understanding the consequences. If Kodi shows an item but iCouldPlay does not, verify the app's current entry and connection under the same account and server, and record the difference for an administrator. An old poster alone does not prove a cache failure.

If both sources list the same season and episode number, first determine whether they are the same episode, different versions or a naming error. Duration and opening scenes are only supporting clues; never delete either copy based on filename. One visible app item does not prove the server holds only one file. Leave inaccessible files pending so lack of permission is not mistaken for nonexistence.

Number each source separately and record specific season/episode and observation time. If the server goes offline or a disk is unavailable, record its access state and add a new row after an administrator restores it. The same poster in two observations does not establish the same source was reached. Inspect folders only with permission; do not try another person’s account when access is denied.

## Finish the record and preserve the library

Deliver both source inventories, server and app observations, two observed samples and unresolved questions, omitting private paths and credentials. Confirm you have not moved files, changed NFOs or altered library configuration. The example claims no private Kodi-server or physical-device testing. Renaming or maintaining a library requires a separate backup and assessment by an authorized administrator.
