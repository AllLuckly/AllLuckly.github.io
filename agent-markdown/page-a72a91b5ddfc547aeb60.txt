对照普通变体与独立关键帧入口，核必须字段、相对地址及不能迁移的音频字幕属性。

主清单里的关键帧入口与普通变体看起来都写带宽，却采用不同的目标地址位置。本课用一份原创六行清单练习逐标签建表，并追踪它真正指向的子清单；没有真实关键帧资源时只完成审核，不让占位文本假装能生成缩略图或实现云映快速预览。

## 准备普通播放和关键帧两类证据

先从自己的短片留下普通播放清单资料，再给外部打包工具的关键帧清单另取名字。只在确有输出时记录它们的真实路径、媒体字节与工具报告，不能把普通视频删掉几行标签就称关键帧资源。此次纸面例子把普通目标叫main/video.m3u8，关键帧目标叫trick/iframes.m3u8。这里trick是自选目录名，不是操作云映的菜单指令；两份资料也不因名字相近自动共享时间轴，需保留生成来源与同一片源身份。

## 先认目标地址属于哪一种标签

普通EXT-X-STREAM-INF把随后的一条URI行作为目标，EXT-X-I-FRAME-STREAM-INF则是独立标签，目标由自己的URI属性给出。先在表里为两种标签各列一行，分别标下一行和属性内，不按距离最近就乱认归属。一个带I-FRAME的长名字不代表它继承下面main/video.m3u8，也不把两条声明合并成同一个流。抄写时保留大小写、连字符与引号，比较的是标签语法，不是屏幕折行后的视觉行数；很长的一行换到下一屏仍是同一标签。

## 核六行样本的必填字段

在样本中关键帧入口含BANDWIDTH与URI，普通入口随后才接main/video.m3u8。关键帧所指的媒体清单必须有EXT-X-I-FRAMES-ONLY；当前主清单没展示那份子文件，因此这项应记需要打开子清单验证，不能凭目录名判已满足。版本四是本练习给定声明，不说写得更高就能修好缺资源。带宽单位是比特每秒，八万不是八万字节每秒，且普通一百六十万与关键帧八万描述不同可播资源，不能拿数值较小推断整片质量变差。

```
#EXTM3U
#EXT-X-VERSION:4
#EXT-X-I-FRAME-STREAM-INF:BANDWIDTH=80000,URI="trick/iframes.m3u8",CODECS="avc1.4d401f"
#EXT-X-STREAM-INF:BANDWIDTH=1600000,CODECS="avc1.4d401f,mp4a.40.2"
main/video.m3u8
# child trick/iframes.m3u8 must contain EXT-X-I-FRAMES-ONLY
```

## 还原两个不同的子清单位置

约定主清单位于https://media.example.invalid/lesson/master.m3u8，两个目标应分别进入lesson/main与lesson/trick目录，而非接在master.m3u8后。将URI属性的引号去掉后再作网址解释，但原清单中仍保留引号。纸面地址采用无效保留域名，不发送访问；自己的真实来源需要记录最终响应与重定向基址，不能让旧目录笔记替代实际资源。两条路径各只登记一次，同时注明它是普通还是关键帧入口，避免后来抽查时误播普通流并把结果归给关键帧。

## 不要搬入被排除的关联属性

RFC对这个关键帧标签不定义FRAME-RATE、AUDIO、SUBTITLES与CLOSED-CAPTIONS这些普通变体属性。另存故障副本给关键帧行加AUDIO=”voice”，在审核表指出它不属于这类标签的定义，再删除该项恢复原文；不要为保留错误项新编一个voice音频组。这个差异不证明所有关键帧资源一定没有任何声音字节，也不代表云映应该出现某个特定错误提示。文法范围与具体文件内容分开核，未知播放器如何容错就记未知，不用容错成功反过来改写规范。

## 在真实片源记录普通播放和预览观察

把外部核清的真实主清单交给云映已有来源入口，先检查普通播放的片源、动作与声音是否正确。若安装版确有预览或相关选择，记录实际出现的画面与时间位置，不能把手指拖动后看见一帧直接等同播放器读取了这条关键帧URI；取证仍要结合你控制的资源报告。没有预览控件时只核普通播放，关键帧子文件的语法审核另记完成。不要通过反复改码率名或画面尺寸，伪造一个实际上没有提供关键帧媒体的服务。

## 按缺字段、错归属和子文件分开排障

关键帧行没有URI就先补审核所需的真实目标，不能把下一行移近一点当修复；子文件缺I-FRAMES-ONLY则回外部打包资料核身份，不直接对任意媒体清单强行加标签。普通流能播而预览未知时分别保存两项结果，不删正常入口。每次只改一个副本条件，重数两类声明与两条唯一目标；引号没闭合时先修属性边界再看路径。实际服务器返回HTML登录页也不属于关键帧媒体，先解决授权或地址，不把收到二百状态码当内容正确。

## 重开后交付入口关系和未验证项

保留原六行样本、故障差异、两条还原路径以及真实子清单的核查位置，重开笔记确认普通与关键帧行没有互换。若重新打开云映，只重复自己实际具备的来源与控件检查，确认文件身份后再评价结果。验收能够指出关键帧URI来自哪一属性、哪些属性不能照搬、子清单还需什么标记，并清楚标出预览是否实测。没有真实预览结果时不要写已经生成缩略图、已经支持任意拖动或所有关键帧编码都兼容，纸面审核与观看保持各自边界。
