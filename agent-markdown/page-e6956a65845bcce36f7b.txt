When using iCouldPlay with a Jellyfin movie library, distinguish a disc folder from a regular video file before checking subtitle selection at each layer.

## Separate the three objects

A Jellyfin movie library may contain regular video files, VIDEO\_TS folders or BDMV folders. A disc folder, its VOB files and a separate MKV are different objects. This exercise compares the server entry and availability of external tracks; it does not assume the app can open any folder as a media file. Jellyfin documents that VIDEO\_TS and BDMV do not support multiple versions, multiple parts or external subtitle and audio tracks. That does not mean internal disc tracks necessarily fail, or that iCouldPlay exposes every server option.

## Prepare reversible samples

Choose a short video you created or are authorized to use and a short subtitle you made yourself. Ask the administrator to prepare an identifiable VIDEO\_TS folder in a separate test library and a lawfully obtained single-file copy of the same content for comparison. This guide does not instruct bypassing disc protection. Record duration, picture content, language and filenames. Without a comparison copy or authorization, read the guide and mark the test not performed. Leave the production library and originals intact.

## Write predictions and limits

Create five columns: sample, server entry, external subtitle availability, corresponding iCouldPlay choice and actual playback. The documented prediction for external tracks in the VIDEO\_TS group is unsupported. Mark the single-file group as pending because format, naming, server settings, permissions and client all affect the result. Do not prefill it as successful, or claim identical codec, quality or subtitle content based on file extensions.

## Check the server directory hierarchy

Ask the administrator to inspect the test library and confirm that the movie folder contains a VIDEO\_TS folder rather than numbering its VOB files as separate films. The actual structure should match the Jellyfin example and the legitimate source. Place the self-made subtitle in the administrator-approved test location for observation, without modifying protected disc content or the production library. Give the comparison single file its own movie folder and matching name so two test entries are not accidentally combined. Record relative hierarchy, not the private server path.

## Confirm matching content first

Open both test entries in the server web interface and compare title, opening image and duration. Mark any edit differences before diagnosing subtitle timing. For a short sample, choose an obvious visual event, note its time and content, then check the other entry at the same position. Similar filenames alone cannot establish identical content.

## Compare subtitle choices on the web

Have the administrator update the test library using the normal procedure, wait for scanning to finish and refresh the web interface. Open playback options for each entry and record the actual subtitle choices and languages. If the VIDEO\_TS group does not show an external subtitle, note that the observation matches the documentation. If a choice appears, establish whether it is internal to the disc instead of assuming it is an external file. Observe the single-file group too. If its subtitle is absent, inspect server recognition, language labels and permissions before changing production configuration.

## Check the same entries in iCouldPlay

Connect iCouldPlay to the same authorized Jellyfin account. Confirm server, test library and identity of both entries. Open each short clip and inspect subtitle or audio controls actually offered by the installed app. Record visible choices, selection and screen result. If a control is absent, mark it unavailable or not observed; do not assume the client presents all server capabilities. Follow the installed interface and avoid changing several playback settings at once.

## Investigate differences without overwriting samples

If web and app show different entry counts, first check the account, library and completion of scanning. If entries appear but playback cannot start, record whether failure occurs in listing, opening or playback instead of automatically attributing it to the external-track limitation. If a single-file subtitle appears out of sync, check that it corresponds to the same clip and edit. Preserve originals and disc content. Change one test condition at a time and record before and after.

## Finish the check and clean up

A useful result distinguishes both sample types and both observation points, marking each cell successful, failed, unavailable or not performed; it does not require both samples to offer external subtitles. Share sanitized findings with the administrator, excluding passwords, tokens and private URLs. Ask the administrator to remove test copies under the normal cleanup procedure after verifying that production content and originals remain accessible. Retain uncertain items as pending. This guide is based on public documentation and does not claim a private-server connection or physical-device test.

## Review the observation timeline

Check observation times after filling the table. A web result before server scanning completes cannot be compared directly with a client result afterward. Record different networks too. If conditions cannot be matched, list that as a limitation rather than attributing the difference to a feature. On a retry, preserve the earlier row and add a new one so the administrator can see the changed conditions and results.
