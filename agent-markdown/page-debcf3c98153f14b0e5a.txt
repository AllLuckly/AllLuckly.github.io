## Understand whitespace and wrapping

W3C CSS Text describes white-space as controlling whitespace collapsing and soft wrapping: normal generally collapses consecutive whitespace and allows wrapping; pre preserves whitespace and forced breaks; pre-wrap preserves whitespace and allows wrapping. The specification does not guarantee Book Isle applies every declaration in a book. Record source spaces, CSS and screen display separately.

## Prepare an authorized short sample

Choose an EPUB you made or the publisher permits you to inspect, ideally containing self-written text, recognizable consecutive spaces and an explicit line break. Record file version, source, expected display and original location, preserving a backup. Do not publish copyrighted text. If internal inspection is not permitted, observe the screen only and mark source inspection unperformed.

## Record the initial reading view

Open the target section in Book Isle and locate the self-made marker. Record current font size, device orientation, line starts and ends and approximate whitespace positions. If consecutive spaces are not visible, do not immediately conclude they are absent from the source; style, width or reader behavior can matter. If the section cannot be found, check file completeness and contents before changing anything; preserve notes.

## Inspect source and applicable style

Only with permission and suitable tools, inspect the EPUB copy’s target XHTML and referenced CSS. Record spaces and line breaks in the target text, relevant selectors and white-space values. A section can reference multiple stylesheets or inherit overridden values. Normal, pre and pre-wrap are different declarations; a filename or single search hit does not establish the final applied value. Mark source inspection skipped without permission.

## Change one reading condition

If Book Isle offers the control, change only font size or device orientation, keeping the same file and passage. Find the marker again and record screen wrap and visible whitespace. Available width can affect soft wrapping without changing characters in the file. Mark missing controls unavailable and do not install unknown tools or modify system security settings.

## Compare explicit and automatic breaks

Using authorized source inspection or publisher information, separately record intentionally authored breaks and wrapping caused by screen width. Without structural evidence, two screens alone do not prove that a particular break came from a line-break element or CSS. Check continuity before and after the passage; a changed line position alone does not prove missing or duplicated text.

## Bound copy and search conclusions

If Book Isle actually permits selection, copying or searching, privately record the result and compare it with the authorized sample; do not publish restricted text. Copy behavior can depend on the app, operating system and destination editor, and visible spaces do not automatically prove the source file changed. Mark unavailable or uncertain steps untested without bypass tools.

## Use an independent control and troubleshoot

Where permitted, open the same copy in a trusted reader and record version, width, size and display. Different fonts and reading areas affect wrapping, so a difference alone does not prove an app defect. If the sample is absent, first check file, section path and access; if only whitespace differs, inspect style scope and reading conditions, changing one variable at a time.

## Restore and document

Restore original font size and orientation and confirm originals, bookmarks and notes remain. Record source inspection, CSS declarations, both displays, copy or search results and skipped steps separately; remove private paths and restricted text before sharing. This guide relies on public standards and app information, claims no device test and does not guarantee a CSS value is implemented by Book Isle.

## Compare two self-made formats

If the publisher provides two authorized self-made passages, one ordinary paragraph and one preserving explicit whitespace, record structure, style and screen output separately. Their text length and position can differ, so identify markers and expectations first. Without a permitted control, retain the single observation and never rewrite the sole original to manufacture an experiment.

## Separate source lines from forced breaks

A source line break visible in an XHTML editor can participate as ordinary whitespace; forced breaks may instead come from elements or applicable CSS. Only source and style evidence supports a specific structural claim. Do not assume an editor line ending must become a screen break. Record original markers, actual elements and reader display without deleting blank lines to repair an unconfirmed issue.

## Note spaces and tabs

Consecutive spaces and tabs are whitespace, but visible width and handling depend on style and layout. If an authorized sample contains tabs, record character type in the copy; do not infer a precise number of spaces from approximate screen width. Pasted text may also look different in its destination. Record source, Book Isle display and paste result as three distinct stages.

## Keep a reproducible record

Tabulate publisher expectation, source declaration, both reading conditions and observed wrapping separately, marking unknown or skipped items. Screen size, font and app settings may all affect layout, so preserve these conditions. For an unexplained difference, share a self-made example and concise record with an authorized maintainer, not private EPUBs, credentials or substantial unauthorized text.

A self-made section can place the same string A, three consecutive U+0020 spaces, B in separate paragraphs styled normal and pre. CSS specifies that normal collapses consecutive whitespace while pre preserves it. Observe A-to-B spacing in Book Isle and verify the respective rules target the paragraphs.
