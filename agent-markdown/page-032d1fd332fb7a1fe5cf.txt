Observe Kavita OPDS title icons and Manyue display at two reading positions in one authorized chapter.

## Separate the information

Kavita’s OPDS documentation describes an optional user setting that encodes progress icons in item titles, with symbols for unread, progress ranges and completed reading. A title symbol is a server-provided hint, not part of the chapter file, and cannot alone prove Manyue restored an exact page. Observe the actual display and reading position without assuming the client preserves or interprets every symbol.

## Prepare an authorized sample

Ask the administrator to confirm test-server version and account access. Choose a small authorized chapter with a known page count, and record the current reading progress and relevant user settings. Without permission or a safe way to restore existing progress, use a paper exercise. Do not change another user’s account, delete history or share an OPDS URL containing a key. Keep comics, server and account under user control.

## Understand documented symbols

Kavita documents an empty circle for no progress, partially filled circles for ranges up to 25%, up to 50% and higher progress, and a filled circle for completed. Symbols and thresholds describe the server documentation; display depends on version, configuration and account. Do not call them built-in Manyue progress icons. Record documented expectations separately from what appears on the device.

## Inspect the server option

The account holder checks the OPDS progress-icon option in the user settings actually offered by Kavita and records its initial state. The user decides whether to enable it; mark unavailable if interface or permissions differ. Do not change unrelated server options or rotate an API key. If no icon appears after enabling, first inspect the corresponding feed and cache instead of declaring the app broken.

## Make the first observation

Find the test chapter in the Kavita web interface and record its current progress and the title actually shown in the OPDS catalog. Do not copy a private URL or key into notes. Mark no progress only if the chapter is truly unread; otherwise use the existing state. Record symbol presence, shape and visible chapter name separately, including an absent symbol.

## Open the same catalog in Manyue

Use the currently offered Kavita or OPDS connection in Manyue with the same authorized account, checking server, source and chapter identity. Ordinary OPDS acquisition and page streaming are different; if the source only exposes a whole-file link the client cannot read directly, record that limitation rather than calling it a login failure. Observe the list title before opening.

## Record an intermediate position

If the chapter can be opened lawfully, inspect its page count and choose an intermediate page that is easy to find again. Record page number or image marker, then return normally to the list. Do not guess a percentage from a drag. If only a visible page number is known and the server’s calculation is unclear, record that limitation. Skip if existing progress is important or cannot safely be restored.

## Refresh server and client separately

Check the test account’s current progress and OPDS title in Kavita, then refresh or re-enter the same directory using controls actually available in Manyue. Record time, title and symbol for each observation. Do not assume instant synchronization: list cache, server settings and supported sync behavior can matter. If no refresh control exists, mark unavailable rather than inventing one.

## Compare icon and actual page

Tabulate server progress, OPDS title icon, Manyue list text and actual reopened page separately. An icon represents a documented range, not one unique page; up to 25% contains many possible positions. If Manyue omits an icon while the chapter is readable, record a title-presentation difference. If the page is not restored, record that separately rather than merging the observations.

## Troubleshoot and restore safely

For a difference, first verify the same account, chapter, icon option, feed and recorded times, then inspect refresh conditions one at a time. Do not change multiple permissions or clear all history. Restore reversible options and test progress from the baseline where possible, otherwise record the limitation. Redact account and OPDS key when sharing. No private Kavita connection or device test is claimed.

## Check boundaries without inventing percentages

If the server actually displays 25% or 50% for the test account, record value, icon and time, then compare with the documented inclusive boundary. If only a page number is visible, do not divide by the total and present that as the server calculation: cover pages, contents or rounding may change the result. Do not repeatedly overwrite real progress to hit a threshold; a safe test copy and baseline matter more than producing a particular symbol.

## Separate completion and progress range

The documentation lists the completed icon separately from partially filled range icons. A position near the end does not necessarily mean the account is marked complete. Record visible position, server state and OPDS title separately. If the final page is missing or cannot be opened, leave completion unknown rather than altering a database or simulating requests to manufacture an outcome.
