Yearn Settings includes iCloud save sync. First aim to confirm cloud availability and completed file handling, then check whether a second device recognizes the same progress. A completed Sync indicator and actually continuing the game are separate results requiring separate checks.

## Prepare a local checkpoint before syncing

On the primary device, choose a practice game, create a manual save state, and record the slot, time and scene. Save through the game's own menu too if it has one. Verify loading locally before syncing. Without a verified local record, later problems are difficult to attribute to saving or the cloud.

Before preparing another device, keep the original ROM and its version details. Sync handles save-related data; do not assume that ROMs, BIOS files, covers and every setting have also been transferred. Running the same content on a second device still requires your own legally obtained files and the necessary environment.

## Check system and app cloud status

Confirm that the device is signed into the Apple Account you intend to use and that iCloud is available. The saves section of Yearn Settings includes an iCloud Sync switch. Enable it, then check the status area for unavailable, waiting or error messages.

If Manual Sync is unavailable, address the account, network and cloud availability according to the current status. Repeatedly toggling switches is not a useful new test. Resolve insufficient iCloud storage in system settings too. Record the error description when troubleshooting; public feedback does not need your email address, account identifiers or personal cloud-drive contents.

## Start one manual sync and wait

Once the local record is established, run manual sync and wait until the in-progress state ends. Check the last sync time or any error afterward. Avoid saving competing progress on both devices during the process. Let one finish before checking the other so that older and newer data remain distinguishable.

Do not delete local saves or move app folders during sync, or repeatedly change networks to hurry it along. If the operation fails, retain the records and error message, confirm network and cloud availability, then retry once. Success means that sync process ended; it does not automatically prove that another device can correctly recognize every game's records.

## Confirm matching material on the second device first

Install the appropriate app version on the second device, import the same ROM you retained, and prepare any required BIOS. The same game name does not mean identical files: region, revision and patches may differ. If the material does not match, stop and compare it rather than testing by overwriting cloud records.

Enable sync under the same account and wait for completion. Open the target game and inspect both its save-state list and in-game records. Compare the scene noted on the primary device instead of merely looking for a timestamp. Only loading into the expected location verifies continuation for that particular combination.

## When sync completes but no record appears

Keep the primary device as the reliable source, rather than alternating between two devices to create competing latest progress. An empty list may involve either file transfer or the association between a game and its saves. Compare app versions and game material on both devices before checking sync status. Reimporting adds variables, so retaining the current state can make diagnosis easier.

Record both devices' app versions, game filenames, sync status, visible slots and actual loading results. Before further file operations, make an independent backup and ask support to assess this information. Do not guess internal identifiers and rename save files, or delete content that still works on the original device.

## Sync and backup have different roles

Sync generally brings two ends toward the same state, while a backup should retain a historical copy you can identify. Even with sync enabled, back up important progress separately before migration, updates or major cleanup. When both devices can write data, a newer timestamp alone cannot tell you which record is most valuable.

Use a fixed sequence: save and verify on the primary device, complete sync, load and check on the second, then decide which device to continue using. If loading on the second has not passed, retain the first device's files and settings rather than rushing to uninstall the original app.

## Common questions and completion criteria

**Does iCloud sync automatically transfer game ROMs?** No. This entry concerns save-related data. Prepare and check game files and BIOS files separately. A healthy cloud status does not mean the second device already has everything required to run the game.

**If sync fails, can I switch it off and delete the local records first?** Do not use deletion to troubleshoot a network problem. Retain the local source that still loads, check the account, storage space and network, and address the reported error.

Finishing this guide does not require an immediate successful migration. It requires clear facts: which record exists on the primary device, whether the cloud operation completed, and whether the second device recognized and loaded it. Keep the original device if the last step fails, so an unverified sync does not become your only source of progress.

## Record a clear migration status

Keep three separate notes: the primary device loads correctly, the sync process completed, and the second device's loading result. If the last check has not passed, retain the primary device as the current source and do not overwrite its usable progress. Even if you return days later, you will know the exact stage reached rather than merely remembering that you once tapped Sync.
