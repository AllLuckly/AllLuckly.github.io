Check same-title authorized EPUB samples using package identifiers and distinctive chapters.

## Set the comparison scope

Two EPUBs can display the same title while containing different text or editions. EPUB metadata includes titles and identifiers; the package unique-identifier attribute identifies its primary identifier. This structure does not guarantee Book Isle displays that field or prove two files are the same edition. Record title, package identifier and actual content separately.

## Prepare two safe samples

Create short authorized A and B books in an EPUB editor with the same title, distinct opening sentences and distinguishable filenames. Keep each independent test package’s own identifier. Do not alter purchased protected books or someone else’s work. Back up originals and record how samples were made to avoid confusing them with everyday reading.

## Follow the primary identifier reference

Inspect each package document: find the metadata item referenced by the package unique-identifier attribute and record that item’s value. The attribute names the item’s ID; it is not itself the identifier value. If an editor displays identifiers through an interface, retain the filename and relevant record without assuming the client uses it as a deduplication key.

## Build comparison fields

For A and B list the displayed title, primary package identifier, chapter opening, filename and generation time. Add known revision information if available, but do not treat a filename, ISBN, internal identifier and shelf card as one field. Whether identifiers match or differ, evaluate provenance and content too; neither result alone proves completeness.

## Validate both EPUBs

Validate each sample separately with the editor or EPUBCheck, retaining each report and confirming chapters open without missing resources. Correct only an authorized working copy, save separately and revalidate. Do not damage package structure merely to force different identifiers. Without editable samples, retain the table and mark import and observations unperformed.

## Import A and verify content

Use the import method actually available in Book Isle for A, confirm the shelf opens the intended title, then check A’s distinctive opening sentence. Record the message, selected file and visible book information. Follow the interface shown. If import fails, first inspect file integrity and permissions rather than clearing the shelf or overwriting an original.

## Import B and observe behavior

Import B in the same way and observe whether the app actually displays a new entry, reports an existing item or behaves differently; do not assume which. If B opens, verify its opening sentence and record the entry point. If both samples cannot be retained, stop and record the result rather than deleting everyday books to force the experiment.

## Check differences hidden by the title

Same-title shelf cards can be hard to distinguish. In your own record use filenames, opening sentences and edition notes. Use renaming or notes only if the actual app interface offers them; changing a displayed label is not the same as changing EPUB metadata. Compare the same location in each book so different reading positions do not mislead you.

## Diagnose a mismatch

If the opened text differs from expectations, verify the selected import file, distinctive opening, editor identifier and generation time, then identify the currently open Book Isle entry. Correct one condition at a time and record results; do not infer that the app deduplicates by a particular field. If source files are identical, consult the creator’s edition information first.

## Retain edition records and privacy

The result table includes both identifiers, opening sentences, import results, actual visible entries and unperformed steps; use a new row for another device. Remove private paths, accounts and unauthorized book text before sharing. Identify test entries before deciding whether to remove them, and retain originals and backups. This guide claims no device test.

## Compare a copy of the same edition

You can also copy file A within a personal test directory, confirm the copy contains the same data and give it another filename. Record that it is a file copy of the same publication, unlike independent sample B. A changed filename alone does not establish a new edition. If you import the copy, report the app’s actual behavior and preserve earlier records.

## Check provenance and edition notes

For real books, copyright pages, publisher information and purchase or acquisition records may provide edition clues. Check publisher, revision date and content you may lawfully view. If evidence is incomplete, mark the version unknown rather than inventing a version number. Even identical identifiers can occur in files altered by different sources, so assess provenance carefully. If records exist for only one edition, mark the other source unknown until evidence is available.

## Check the actual entry separately

If same-title samples are difficult to distinguish on the shelf, record each selected file location and import response, then open the visible item and check its distinctive beginning. If reading resumes elsewhere, use any available contents control to return to the beginning. If you cannot find it, record unknown rather than inferring identity from the most recent import time.
