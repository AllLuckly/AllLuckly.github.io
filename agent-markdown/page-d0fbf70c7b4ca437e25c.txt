Compare two owned books from the same catalog across listing, search and acquisition, using actual pagination evidence where available.

## Prepare early and later samples in one catalog

Choose an authorized private OPDS library. In its existing management or browsing entry, record catalog identity, account permissions, sort and filter conditions. Select owned book A near the start of the listing and owned book B later in the same order; record each title, author and format rather than identifying them by title alone. Preserve originals and local notes, and hide account details, sensitive URL parameters and book text in screenshots. Without a suitable library or permission, record preparation only instead of exposing a server for a test.

## Identify where counts and filters come from

Determine whether a server count refers to the entire library, current category or search result, and record the time. If additions, deletions or sorting change a listing, two observations need not represent one snapshot; avoid modifying the library during a short comparison. If no reliable total is available, record only confirmed A, B and catalog scope, not a guessed expected count. Accounts may see different authorized subsets. Verify the same identity used by Book Isle on the server; an administrator’s count cannot automatically substitute for a normal account’s.

## Locate the same entry in Book Isle

Use the existing OPDS connection to enter the same library, category and visible filters in Book Isle. Find A and inspect its title, author and format. Then look for B using whatever scrolling, loading or other navigation is actually available. If no continuation control is evident, record the visible list and final entry; do not assume a fixed button or interaction. If the first view contains only part of the results, confirm the same category and ordering before calling B lost.

## Inspect pagination information only when applicable

If the service actually supplies OPDS 1.2 and you are authorized and have an existing tool to inspect its response, read the current feed’s entries and rel=next link without modifying it, recording the check time. The specification permits paginating large acquisition feeds; next points to a subsequent catalog document, not a page of book text or necessarily a directly readable file. Record the actual presence and target scope. A continuation link may be relative or carry a server-generated cursor; interpret it against the actual document location and service documentation rather than assuming that incrementing a page number yields a valid address. Do not share authorization-bearing links or repeatedly request an entire private catalog during comparison. If the document, next link or protocol version cannot be confirmed, mark unknown. Do not assume this optional structure exists or claim Book Isle uses a particular pagination algorithm.

## Separate search, listing and book acquisition

If B is not yet visible in the long listing and this catalog actually offers search, search its definite title or author and verify the edition. Search results have their own scope and do not establish that the original listing fully loaded. Open B’s details, use an actual available acquisition entry for the intended EPUB or PDF and inspect beginning and end; a cover or preview link is not a downloaded book. B may be found via search but not the current listing, or missing on the server itself. Record those outcomes separately without guessing a client-side filter.

## Fix conditions before diagnosing duplicates or blanks

For repeated titles, inspect author, edition and actual entry identity: same-title translations or editions can be separate books, while two positions may refer to one record. For an empty continuation, record network, account, filter and last visible entry. Change one condition at a time rather than deleting the connection, rebuilding the library or modifying originals. Note if server data changed during checking, since results then do not share a static snapshot. A title or screenshot alone cannot establish the cause of duplicates or blanks.

## Protect addresses and existing reading data

When comparing service documents, do not put token-bearing URLs, credentials or private directories in public feedback; preserve only a redacted structure sufficient to explain the layers. Catalog browsing and private sync are different features, so diagnosing a list does not require clearing WebDAV sync data. Keep downloaded local books and notes independently. An unreachable server does not itself establish that a local file disappeared. If an operation’s scope is unclear, stop and consult existing documentation or the service provider.

## Reopen and deliver bounded findings

Re-enter the same category and recheck actual listing, search and acquisition results for A and B, recording time and account scope. Deliver a comparison of server A/B, Book Isle listing A/B, available search result, actual opened book, any next-document evidence and untested items. Leave unperformed server inspection, continuation or download incomplete. A small sample can locate a difference but cannot establish complete coverage of every item in a large library or compatibility with every OPDS server.
