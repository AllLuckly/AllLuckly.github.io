Use four fictional objects to compare shared nodes, branch rotation and actual reconnection without assuming line length represents time.

English translation of the [Chinese original](<https://allluckly.cn/guides/manyue-rooted-tree-tip-node-relationship/>), translated on 2026-11-10. Original publication dates, attribution, code and version notes are retained.

A tree on a comic science page can resemble a left-to-right queue without ranking advancement or dates. This task reads an explicitly rooted simplified relationship tree using four fictional objects. Organisation charts and decision trees follow other conventions, so a tree-like shape alone does not justify the same interpretation. ManYue does not infer relationships automatically.

## Identify the tree’s purpose and root

Record work, edition, chapter, page position and caption. Confirm that the diagram presents a relationship hypothesis and identifies a root. Without a root, do not assign ancestry to the leftmost or lowest node. Note whether tip labels denote species, samples or fictional objects; one name must not alternate between an individual and a whole group. Our four original tips A, B, C, D are illustrative, not a real classification. Describe root, internal nodes and tips separately, retaining full connections before enlarging labels. A crop that removes the root cannot support an equally definite interpretation.

## Record connections as a traceable structure

Our original structure has root R branching to nodes N and M; N branches to A/B, and M to C/D. Write these stated connections before discussing relative relationship. Node letters are external note identifiers, not an app-created tree object. Trace each tip to its immediate fork; crossing lines without a connection mark must not automatically become a node. Follow the real diagram’s conventions when different. If balloons or cropping obscure a connection, mark it unresolved rather than inventing a hidden branch because two tips are physically close.

## Compare shared nodes rather than screen distance

A and B meet at N, whereas A and C meet only back at R. In this rooted example, A/B therefore share the more recent common fork; C/D similarly share M. Preserve both traced paths instead of saying A/B are closer because the screen distance is shorter. Bending, zoom and label placement may change geometry without changing connections. Tip A is not B’s ancestor: both are tips. A shared internal node represents an inferred common-ancestor position; do not substitute a current tip for that node or infer age from label size.

## Rotate branches without reconnecting them

Make a manual control swapping A/B under N and moving the entire M group to the other side while retaining every original attachment. Trace again: A/B still meet at N and C/D at M, so changed tip order does not change relationships. Draw this on paper or in external notes, not through an invented ManYue tree-rotation button. Cutting A’s branch and attaching it to M would change topology rather than rotate it. Record the two operations separately instead of using “position never matters” to conceal an actual change in connections.

## Do not read branch length as time without a scale

If the caption specifies branching relationships only, a long branch does not automatically mean more elapsed time, more change or greater advancement. Some trees scale length to time, others to inferred change; consult this diagram’s scale and definition. Record scale presence, quantity name and unit, marking absent encoding or unspecified meaning explicitly. A tip drawn farther from the root is not an evolutionary endpoint. For fictional objects, compare only stated connections, without importing real species’ ages, superiority or adaptation. This reading exercise does not validate scientific classifications.

## Handle multiple branches and unresolved parts separately

If a node directly has three branches, do not insert two ordered binary forks yourself. The source may mean unresolved relationships or use another convention; read its caption first. Separate explicit structure from unknown order instead of pairing nearby labels merely to fit the A/B example. An absent object need not be extinct or nonexistent; the sampled set may differ. If trees on two pages differ, check object set, question and edition before declaring contradiction from left/right order. Record the precise node at which a real difference occurs.

## Troubleshoot obscured lines and proximity mistakes

For overlapping lines, enlarge junctions and the legend, then trace every tip in the full diagram instead of guessing locally. If the source is too blurred to resolve a connection, mark that edge uncertain; a search result cannot replace graphical evidence. Manually record descendant-tip sets, such as N containing A/B and M containing C/D, to spot a missed branch. These sets must follow visible connections, not invent them backwards. A cropped label remains an unknown object rather than a name supplied by sequence. Personal screenshots should retain source location, and sharing must stay within permitted material.

## Exit and return to review node relationships and limits

Exit the reader and return to the original. Locate R, N, M before retracing the shared nodes for A/B and A/C without consulting your conclusion. Check that the rotation control did not reconnect an edge and that any length interpretation has scale support. Save six items: diagram identity, root/object set, connections, shared nodes, scale conditions and unknowns. Completion means another reader can reconstruct relationships and identify unsupported inferences, not rank advancement from tip proximity. If the picture is not a relationship tree, stop applying these rules and read its own declared classification or process meaning instead.
