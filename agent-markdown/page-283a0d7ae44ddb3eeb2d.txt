Sound while typing may be Jianlai's piano feedback or spoken typing feedback from iPhone accessibility. Hearing sound alone does not make them the same feature. Apple says system typing feedback can speak characters or words, but the behaviour of a third-party keyboard and host must be observed separately. Use fictional letters to compare body text, piano sounds and system speech without assuming every device produces both sounds.

## Prepare the environment and practice text

In a safe place where brief sound is acceptable, open an ordinary test note without private information. Confirm Jianlai is enabled in system keyboards and choose an actually visible English input mode. The practice text is “CAT”, three letters that are not a real contact, password or message. Set comfortable volume. If sound is unavailable or inappropriate, mark sound not tested while still checking text. Do not record or share the voices of people nearby; there is no need to upload the exercise anywhere.

## Record original feedback settings

Record the current Jianlai piano-sound state, relevant system typing-feedback settings, output destination and device version. Apple's public instructions place typing feedback in accessibility reading settings, with labels varying by system version and language. Inspect only the needed options; do not change account, security or unrelated settings. Restore all temporary changes afterwards; if the original state is uncertain, do not start a comparison requiring that change. The system may offer separate options for characters, words, autocorrection or predictions; the actual names and count depend on the device. This exercise compares character speech only and does not need other options enabled merely to produce sound. List each actual change separately for restoration.

## Establish the text baseline

On a blank line use Jianlai to enter C, A and T in order. Confirm committed text is exactly “CAT” without extra spaces or replacements. Record keyboard layout, actual keys and whether each character was committed; an unconfirmed candidate is not body text. Do not infer actual pitch from a promotional screenshot or equate taps automatically with final character count. If the host autocorrects a letter, record the change first and then correct a copy through the interface.

## Observe Jianlai piano sound separately

If the current version exposes an identifiable piano-sound switch and you choose to change it temporarily, enable and confirm it through the actual interface. If the entry cannot be confirmed, mark the round not tested. Keep system typing speech at its original state, type “CAT” again and separately record body text, heard piano sound, heard speech or uncertainty. This round describes only the current combination. If system speech was already enabled, not all sound can be attributed to piano. If both overlap and cannot be distinguished, pause rather than declaring either feature broken; change one condition for another round only if you choose to and have recorded its original state.

## Inspect system typing feedback

Apple says typing feedback can speak characters or words, with actual entries and available options varying by system. If you are willing to change a known original state temporarily, enable character speech through the actual system settings, then return to the same test note and keyboard. If the control is absent, the third-party keyboard produces no feedback, or you prefer not to change it, record not tested or not heard. Do not install unknown software for the exercise or describe this system setting as a built-in Jianlai feature.

## Compare feedback during typing

Enter C, A and T one by one again with short pauses. For each, separately record committed text, possible piano sound, possible spoken character and uncertainty. Do not assume a key triggers both sounds or use pitch as a substitute for character checking; system and keyboard audio may overlap. If hard to distinguish, mark uncertain rather than raising volume to an uncomfortable level. If necessary change only one known setting at a time and record its before-and-after values.

## Distinguish typing feedback from Speak Selection

Character speech is feedback during input; selecting the completed line and using system Speak Selection afterwards is a separate action. To compare the latter, first complete and confirm the text, select the line and use the system menu actually available. Skip if no entry appears. Do not write the sounds from both stages as one event or revise the earlier body observation based on speech. Even hearing a character name does not remove the need to inspect the committed text.

## Troubleshoot and record outcomes

Inspect current keyboard, host, output destination, piano switch and system typing-feedback state, changing only one condition at a time. If text is correct but no sound is heard, record the behaviour of that combination rather than declaring the keyboard or device faulty. If sound occurs but text is wrong, preserve separate conclusions. Keep four columns: committed text, piano observation, system-speech observation and unconfirmed items. Do not record private material or tests that were not performed.

## Restore settings and finish

Restore all piano and system typing-feedback settings changed in this exercise from the starting record, and check the output destination. Do not guess if an original value was unknown. Keep or delete the test note as you prefer. This guide uses public Apple and Jianlai information, does not claim step-by-step tests on a personal device, and does not promise that every third-party keyboard supplies system typing speech.
