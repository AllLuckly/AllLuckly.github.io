On a shared device, the saved position may reflect the last use rather than each viewer. Use a disposable sample and two personal position notes to test retrieval after a handover. This assumes no multi-user profiles, independent viewing identities or automatic protection against sync overwrites, and does not require sharing server credentials. Make content identity and personal progress explicit within existing permissions and features.

## Choose a sample both may view

Use self-made or permitted material both viewers may access, without private photos, sensitive speech or restricted server content. Start with one device and source, not cross-device sync. Record filename, duration and recognizable opening so each viewer selects the same edition. Include several distinguishable positions. When permission is unclear, use already permitted local material rather than borrowing credentials or expanding access to complete the exercise.

## Use consistent fields for each position note

Create ordinary A and B notes containing sample identity, stop time, content anchor, remaining passage and date. Use displayed media time rather than elapsed viewing minutes, especially at increased speed. Existing personal notes suffice without searching for assumed in-app features. Simple agreed labels are enough; complete names or private identity details are unnecessary. Consistent fields expose missing edition identity or timing basis.

## Viewer A should test retrieval first

A pauses at a clear first position, confirms picture and sound stop, records time and an anchor, then leaves and returns through the same entry. Allow context for approximate seeking rather than claiming frame accuracy. Establish retrieval before handing to B. If it fails, correct notes or file identity before two viewers have changed progress. No history deletion, cache clearing or library rebuild is needed to establish this small-sample method.

## Record the shared state after viewer B uses it

B opens the same sample, stops elsewhere and writes a separate note. Record the app’s actual shared position without implying A viewed that far. Seeking to the end is not completed viewing and should not be used merely to change a card label. Note any synchronization condition without assuming per-person storage. Each viewer can have different goals and remaining material; one shared player record need not represent both.

## A returns from the personal note

When A returns, confirm the edition and consult A’s note instead of accepting the current resume point. Seek before the anchor and verify context before continuing. Landing at B’s point may simply mean the personal note was not used, not that A’s note disappeared. This explicitly separates app progress from external personal records without proving independent-user support. Update A’s note after retrieval without overwriting B’s.

## Check captions, tracks and speed too

Viewers may also differ in language, captions or speed. Record relevant preferences and check actual state on return without assuming they bind automatically to a personal note. Before changes, ensure the other viewer has recorded what matters. Do not alter server-wide language or library watched state to simplify a handover. Respect the current entry’s scope, and record unavailable settings without requiring purchases or new accounts for this exercise.

## Keep access scope unchanged

A position note needs identity and retrieval information, not passwords, full authorization links or private directories. A-only material does not become B-accessible because of a note; substitute permitted content. Respect existing downloaded content and history without clearing another person’s records. Any sending remains the person’s decision about recipient and scope; this exercise sends nothing. Clear records do not require public disclosure or wider access.

## Test two handovers and restore the viewing state

Have both viewers leave, hand over and retrieve once, checking identity, position, language and remaining content. Remove irrelevant note fields while retaining edition and anchor. Recheck a small sample for another work or source rather than generalizing to all multi-device scenarios. Restore the device’s formal viewing position and settings, cleaning only disposable test material. The result is two explicit notes and a reproducible procedure for a shared resume entry.
