用自制中性灰说明片核两种中点与八位取整，不把截图或播放器亮度当色彩转换报告。

黑白之间的中点取决于在哪个数值空间里计算。本课外部准备两种中性灰与原始换算账，再在云映读取同一说明片；所算的是声明的sRGB传递函数，不把它套到所有HDR或影片编码，也不承诺屏幕亮度能按纸面比例直接测出。

## 固定同一sRGB中性灰任务

在自己的外部图像工程中约定RGB三通道相等、数值归一到零至一，黑为零、白为一。A卡按编码信号的中点取0.5，B卡按线性光的中点取0.5；二者名称不能都只写百分之五十灰而丢掉空间。原始工程、色彩标记和换算表分别保留，不从一张来路未知的截图猜sRGB。此处没有透明度混合层，也没有拍摄曝光变化，先固定这两个条件，避免把昨天的预乘颜色问题或相机自动曝光误当本次传递函数区别。

## 把编码与解码方向分开列出

用C表示sRGB编码分量、L表示线性分量。对本课正值范围，C不超过0.04045时L=C除12.92，否则L=((C+0.055)/1.055)的2.4次方。反向在L不超过0.0031308时C=12.92L，否则C=1.055乘L的十二分之五次方再减0.055。把两段条件与方向都写完整，不能只记一个幂指数便把所有值直接平方；这也是为什么信号中点与线性光中点要分别计算。公式在外部核，云映不被假定提供公式输入或逐像素读取工具。

## 分别计算两种中点的对应值

A卡C为0.5，代入非线性解码分支得到L约0.214041；B卡L为0.5，代入反向编码得到C约0.735357。三通道都采用同一数值，所以仍是中性灰，不通过改变某一通道去让图变亮。黑白两端往返仍回零与一，是另一项边界检查。保留六位小数供阅读，原始计算多保留精度；不能把0.214直接称视觉亮度百分比，也不说B在所有观看条件下必定感觉恰好亮一倍。这个模型描述数值表示，感知和设备输出另有条件。

```
declared neutral sRGB model: R=G=B; no alpha compositing
decode(C)=C/12.92 if C<=0.04045 else ((C+0.055)/1.055)^2.4
encode(L)=12.92*L if L<=0.0031308 else 1.055*L^(5/12)-0.055
A: C=0.5 -> L=0.2140411405; nearest 8-bit C=128
B: L=0.5 -> C=0.7353569831; nearest 8-bit C=188
decode(128/255)=0.2158605001
decode(188/255)=0.5028864580
```

## 将八位取整误差另做一栏

若外部制图选择八位编码，将C乘二百五十五再四舍五入，A约为128，B约为188。这里乘的是编码值C，不是把线性0.5直接填成B的128。取整之后128除255并不精确等于0.5，188除255也不等于0.735357；把它们重新解码得到约0.215861和0.502886，作为量化后的另两个值。原始实数与八位近似各列一行，不能用量化后的小偏差宣布反向公式矛盾，也不擅自改白端上限来凑出精确中点。

## 外部制作带身份的说明短片

制作黑、白、A、B四块并写清编码与线性标签，再放进自己能够导出的短片，至少让两块中点同时出现一段可读时间。保留图像工作空间和导出转换记录；如果视频导出经过另一传递函数、矩阵或有损压缩，不要求解码后的每个整数仍等于原图128或188。成片里的数字是烧入说明，不是云映测得的像素读数。使用已知可读的封装先验身份，未真正导出的项目记待做，不把纸面等式当成已存在的测试视频文件。

## 云映观看时保持同一输出条件

通过实际可用文件来源打开说明片，先核四块名称、同屏顺序与原始资料对应，再保持亮度、显示模式、画面适应方式和输出设备一致。只记录A与B是否能区分及字幕是否可读，不拖播放器亮度去把A调成B后宣称转换完成。若换到另一显示路径，另建一行条件；界面主题变暗也不等于影片编码改变。没有量测工具就不写精确亮度、色差或校准通过，截图中的数值仍要回原图和导出记录验证，不以截图替代全部色彩管理链。

## 先查方向和空间再查实际画面

若B也被填128，先查是否把线性值当编码值；若得到负数或超过一，核输入范围、指数和编解码方向；若只有成片不同，回外部导出记录查空间与压缩，不能统称播放器颜色坏了。每次只修一个故障副本条件，保留正确公式与两张原卡作参照。不把这份sRGB换算直接套给PQ、HLG或任意未标识影片，也不把代码值较大理解为拍摄曝光已增加；数值模型、素材处理与观看观察应始终能分开回查。

## 重开交付两个中点和导出条件

保存两种中点、八位近似、往返结果和说明片身份，重开先核C与L栏没有互换。实际重开云映时再核同一片源与同一输出，未执行观看便只交计算和准备清单。验收能解释为何0.5编码对应约0.214线性、线性0.5为何要编码成约0.735，以及128与188只是八位近似。恢复日常显示设置，保留未知转换环节，不声称内置sRGB编辑、HDR测量、屏幕专业校准或所有影片都采用同一种传递函数。
