Collections and read lists can both organize comics, but one groups series and the other individual books. Map members before comparing web and Manyue+.

## Identify members of each container

Komga Collections group series; Read Lists group individual books. Both can relate objects across libraries, but at different levels. Adding a series to a collection is not the same as adding one of its books to a read list. Compare server web behavior with actual Manyue+ entry points using self-made samples, without assuming the client supports every management feature.

## Prepare two series and three books

In an isolated test library, the administrator prepares self-made Alpha books A1 and A2 and Beta book B1, with distinct first-page markers. Record each filename, page count and series. Use a test account authorized for both series, retain originals and existing lists, and stop at paper planning if permission or backup is unavailable. Do not use another person’s production collection.

## Draw the object relationships

On paper write that the collection candidate members are series Alpha and Beta, while read-list candidates are books A2 and B1. Count two series and two books, then note that A1 belongs to Alpha but was not individually added to the test read list. Series name, book name and first-page marker should identify each object; matching titles alone do not prove two entries are the same book.

## Create a test collection

An authorized person creates an identifiable temporary Komga collection on the web and adds test series Alpha and Beta using the current interface. Open collection details and record series names, each book count and time. Komga says a collection can contain series across libraries; if the test books are in one library, do not claim cross-library access was tested. Leave production collections unchanged.

## Create a test read list

Separately create a temporary read list containing only A2 and B1. Open details and record each book’s series, volume, first-page marker and time. Confirm A1 was not individually added. If A1 appears, check for misselection or a different list before taking any action; do not delete the source file. Seeing A2 in a read list does not mean the entire Alpha series is a member.

## Check both web entry points

On Komga web, open the test collection and read list separately: inspect series objects in collection details and book objects in list details. From Alpha series details, inspect its collection association; from A2 book details, inspect its read-list association. Use the interface actually present in that version. Mark unavailable or unperformed controls rather than changing production data to force them to appear.

## Observe actual Manyue+ support

Connect Manyue+ to the same server and account and inspect whether the installed version offers collection or read-list entries. If visible, record names, members and object levels separately, then open A2 or B1 to check its first page. If absent, mark unavailable or not observed; do not assume every Komga web feature exists in the client. Finding a book in a regular series list does not prove its collection or read list synchronized.

## Investigate missing members

If web shows B1 and Manyue+ does not, compare account, source, series, book identity and observation time first. Existing library or content restrictions may affect visibility. Ask the administrator to check existing permissions without expanding production access. Record web and client separately; one difference does not establish a sync, cache or server defect.

## Separate membership removal and file deletion

Removing a series from a collection or a book from a read list changes a relationship; deleting media files is another action. Komga says deleting an entire collection or read list does not delete its items or media files, but this does not authorize deleting production objects. Keep the test relationships by default. For cleanup, only an authorized person may handle confirmed test objects under administrator policy; do not click book or file deletion.

## Check the scope of a cross-library observation

Komga permits collection and read-list members from different libraries, but this exercise does not require a second library. If an authorized separate test library already exists, an administrator can additionally record each object’s source and the account’s existing access. Without it, mark cross-library work not performed rather than reporting a single-library test as a cross-library pass. A missing member may reflect existing restrictions; verify them without asking to remove safeguards.

Keep the units distinct: the collection contains two series, Alpha with two books and Beta with one; the read list contains two books. Equal counts do not establish identical membership. Verify Alpha, Beta, A2 and B1 individually, and whether A1 is accessible only through its series. If the client does not expose relationships, leave them unknown instead of inferring them from the normal shelf.

Test objects should be clearly named apart from production objects. Before cleanup the administrator confirms the selection is the temporary collection or list and rechecks that all three test files exist. Pause and preserve the record if identity is uncertain.

## Record and restore

List two collection series, two read-list books, each web entry point, actual Manyue+ controls and reading results. Record A1’s read-list membership separately. The administrator handles temporary objects under normal policy and confirms three source files and production collections remain unchanged. Exclude private server addresses, accounts and unauthorized comic content before sharing. This public-documentation guide claims no private-server connection or physical-device test.
