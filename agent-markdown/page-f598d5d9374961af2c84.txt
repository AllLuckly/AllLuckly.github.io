Use one owned comic to check local reading, WebDAV state sync and server libraries against the published membership scope.

## Write three tasks as separate outcomes

Choose one owned short comic as a common sample and list three distinct tasks: opening the imported local file, synchronizing one reading state to another device, and browsing an authorized LANraragi server. Reserve device, entry point, time and result fields for each. They may concern one work but are different features: opening a file does not prove a server is connected, and a server listing does not prove progress synchronized. This is a check of current entitlement and observed behavior, not an instruction to purchase, change a subscription or create a server.

## Map each task to the public feature description

The official listing checked on 20 November 2026 lists iCloud sync, WebDAV sync, cloud-storage import and SMB under Pro. Ultra includes Pro and lists server libraries, image enhancement and batch features. Match the action you need to the description; do not collapse WebDAV sync, SMB file access and the LANraragi server library into one switch. The listing is public scope, not proof of a particular account’s current entitlement, region or device state. Offerings and prices may change; consult the current purchase page and app explanations for decisions.

## Identify the sample and installed state

Record the app version if confirmable, the device and the local sample’s title, chapter, page count or a recognizable image. Keep a recoverable original rather than testing the only important copy. Open an already imported sample through an actual local entry, inspect the first, middle and last pages, then leave and locate it again. If only a remote listing exists or import has not finished, mark the local task incomplete. A cover during loading does not prove the entire book can be read offline; do not uninstall the app to provoke an entitlement message.

## Synchronize one record only when available

If the appropriate Pro or Ultra entitlement, a configured WebDAV sync destination and a second device are available, leave a definite page position or practice marker on the first device. Exit reading and follow the actual visible sync flow. Record the destination and feedback, then check the same work and marker or page position on the second device. Where actually available, an existing iCloud sync flow is another option. Record the selected service, account identity and result separately, without assuming the two sync mechanisms merge automatically; this exercise does not require switching the service currently in use. Sync data and comic files are different objects: if state appears but text does not open, check whether the matching file is available there. With no second device, sync setup or entitlement, record this task as untested without manufacturing conflicts or overwriting existing records.

## Check the server library, not a similarly named sync address

If an authorized LANraragi server and the relevant server-library entitlement already exist, identify the actual server via the existing connection, enter its listing through the current interface and open the first and last pages of one test archive. Service address, account, visible listing, readable content and download are distinct checks; preserve feedback at the point of failure. Do not enter the WebDAV sync directory as a server address, expose a private server or create an account for this exercise. Without server conditions, mark it untested: local reading success does not establish Ultra server access.

## Identify the task and actual state when prompted

If an entitlement prompt appears, record whether it occurred in sync, SMB access or the server-library entry, then inspect what the app and Apple subscription account actually show. Public descriptions, regions and purchasable offerings can change. For inconsistent states preserve time, region and message, then use official support without guessing billing or restoration outcomes. Avoid cycling accounts, reinstalling or clearing data: these change the conditions and may affect unsaved material. The exercise requires no disclosure or transmission of credentials.

## Distinguish untested from failed

Without membership, another device, an authorized server or network, mark the dependent task untested. An attempted operation with a visible error is a failure with recorded feedback. Neither can be substituted by success in another task. If a local comic fails, inspect format, original, import and device storage; if only server login fails, inspect that connection rather than altering the local file. Change one condition at a time and recheck the same sample, so changing network, address and file together does not obscure the cause.

## Deliver three results and next actions

Keep three result columns: whether the local sample opened, whether synchronized state appeared on the destination, and whether the server library actually listed and opened the intended archive. Mark each pass, fail or untested with a next action. One success does not validate every format, account or server. Before resuming normal reading, confirm the original comic and existing records remain, and handle the practice marker according to your own preference. Retain the public version description separately from current prices, entitlement display and actual operations, and recheck the app and store when needed.
