Select one authorized comic in an existing cloud drive and check directory, import outcome and local copy in stages.

## Prepare one authorized cloud sample

Choose one small owned or authorized CBZ comic in a cloud drive you actually use and can access, preserving an independent original. Record title, edition, filename, size, recognizable first and last pages and directory. For same-named editions, distinguish their paths and contents; a similar cover does not establish identity. Public App Store screenshots show cloud-drive import and a Baidu Netdisk browser, while the listing places cloud-storage import under Pro. Actual providers, account state and current purchase options depend on the installed version and region; this exercise does not require buying membership.

## Confirm account, folder and file in the drive

Through the drive’s normal entry, confirm the current account can see the intended folder and that the sample is accessible to it. A share link or someone else’s screenshot does not establish the same access as a personal-drive directory; follow the provider’s actual authorization conditions for shared material. Record account and directory identity, not passwords or access tokens. A cloud filename and cover do not prove the comic has been fully copied onto an iPhone or iPad. Without an accessible sample, retain the preparation record and mark import untested.

## Identify the entry actually available in ManYue

Open the cloud-storage or drive-import entry actually visible in ManYue. Check whether it lists the drive you use and whether an entitlement or authorization prompt appears. Baidu Netdisk in the official screenshot is an example, not a promise of identical providers or permissions for every region, account or system. If sign-in or authorization is required, follow the app and provider’s instructions as currently shown; do not paste credentials into notes or feedback. If an entry, entitlement or authorization is unavailable, record the state and pause instead of switching to an unknown source or reinstalling to evade it.

## Navigate the actual folder and verify the edition

Follow folders actually shown in the cloud browser and confirm the root, parent folder and target filename. Use list-layout or refresh controls only if they appear, recording the directory before and after. An icon, sort position or home-screen location is not path identity. For same-named files compare folder, size and edition information, returning to the drive’s own entry if needed. An empty listing does not necessarily mean deletion: account, authorization scope, network or folder may differ. Record actual feedback separately.

## Check selection scope and processing outcome

Select the verified comic and follow any download or import flow actually presented. Observe destination shelf, progress, completion or failure messages where visible, leaving absent fields unknown. Cloud browsing, transfer, app processing and a shelf entry are separate stages: neither a click nor a cover proves all have completed. If interrupted or failed, retain the original and visible error and first check the same file and connection. Do not import an entire directory merely to test, or repeatedly select several same-named versions and obscure the result.

## Open first, middle and last pages on the shelf

Find the actual imported work, verify name and recognizable markers, then inspect first, middle and last pages for the intended edition. If only the cover appears, one page is still loading or no shelf entry is found, record location and message separately; a working cloud listing does not establish a complete device copy. Leave the reader and locate the same work again on the local shelf. If the interface only offers remote opening or no local copy can be confirmed, mark local completion unknown rather than assuming every chapter was automatically downloaded.

## Test offline only when practical

After transfer has actually ended and other tasks will not be disrupted, optionally disconnect temporarily and open the first and last pages from the previously confirmed local entry, then restore the original network state. Success shows only that the checked pages were readable at that time, not that every book or chapter was saved. On failure, check whether a remote entry was opened, transfer completed and device storage is available. If offline testing or a local entry is unavailable, mark untested. Do not delete the cloud original or revoke account authorization to manufacture a failure.

## Keep both sources and the failure scope

Deliver redacted drive and account identity, folder and edition, actual ManYue entry, transfer outcome, shelf item, first/middle/last page and offline results, leaving unperformed steps untested. For example, if only folder browsing was performed, leave transfer and offline results blank or untested rather than copying a cloud-side success message. Preserve cloud original and local copy separately; for a same-named revision recheck content and edition. One import is not continuous two-way synchronization or a complete backup. For feedback provide a self-created sample, version and failure stage, not private comics, tokens or an entire drive directory. Restore network settings changed for testing and confirm the original remains locatable.
