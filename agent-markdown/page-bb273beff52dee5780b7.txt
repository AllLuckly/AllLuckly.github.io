用无提交动作的本地 HTML 比较字段、键盘布局和实际输入。

同一套键盘在普通文字、邮箱和网址输入框中可能显示不同键面，因为网页会向系统提供字段类型提示；宿主、系统和第三方键盘是否采用提示，需要实际观察。本课用不发送数据的本地 HTML 小样本，比较键来在三种字段里的可见布局与正文，不预设键来一定切换特定键位。

## 准备不联网的练习文件

使用自己已有的纯文本编辑器新建一个 UTF-8 文件 `fields.html`，粘贴下面的完整内容并保存。文件没有表单提交按钮、脚本、远程资源或网络地址，不需要创建账户。它只包含三个带标签的输入框；示例地址使用保留域名 `example.com`，只是文本，不用于发信或访问。不要把真实邮箱、密码或工作地址输入这个练习。

```
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>输入框练习</title>
<label>普通文字 <input type="text" autocomplete="off"></label><br>
<label>邮箱 <input type="email" autocomplete="off"></label><br>
<label>网址 <input type="url" autocomplete="off"></label>
</html>
```

HTML 标准定义不同的输入类型，但字段类型不保证键盘每次一定显示某个键，也不代表内容已经通过验证。这里不提交表单、不测试网页的安全性或发送邮件。确认扩展名不是 `.html.txt`；若当前设备无法以可交互网页方式打开本地文件，可用自己控制的离线测试环境打开，无法安全实现就记录待核，不把文件上传到未知网站。

## 明确样本和观察表

在纸上准备三行样本：普通框输入 `tea`，邮箱框输入 `a@example.com`，网址框输入 `https://example.com/`。这三行没有真实身份。为每轮记录宿主和系统、当前键盘、字段类型、可见键位、正文结果以及未完成项。普通框在第一行，邮箱与网址各一行，避免把某次字段焦点或键盘切换混在一起。

先在支持打开该本地页面的浏览器或已知安全的网页预览中显示三个标签。确认三个字段均可点入、页面没有提交动作，也没有连接陌生网站。若系统预览不允许输入、页面被当作纯文字显示或运行环境不明，就停止；不要通过把真实资料填到公共测试站来替代本地练习。

## 建立普通字段基线

点入“普通文字”框，用系统提供的切换方式选择键来，确认真实显示的键盘。输入 `tea`，检查三个小写字母确实在第一个框中，记下键面是否显示字母、符号入口和回车键的可见文字。这个结果只说明当前浏览器与当前键盘的一次输入；候选区中出现内容不等于已经写入字段。

如果第三方键盘未出现，先检查系统键盘列表、当前焦点和浏览器是否允许该输入方式。系统可能对某些字段或情形使用不同键盘；不要为了测试关闭安全功能或删除已装键盘。此时保留基线未完成，不能用系统键盘的样子冒充键来。

## 核对邮箱字段

点入“邮箱”框，观察实际当前键盘是否仍为键来、`@` 是否可见、是否需要切换键面，以及回车键有何标识；记录真实情况而非预填预期。输入虚构的 `a@example.com`，逐字符核对小写字母、一个 @、一个点和域名。不点击链接、不发送邮件；即使浏览器提供格式提示，也不把提示当作地址存在或可以收信的证明。

如果系统切换了键盘，或键来沿用普通布局但可以经符号入口输入 @，都如实记录。HTML 的邮箱字段可以影响宿主对键盘的提示，但具体布局由系统和实际输入法决定；没有专门邮箱布局不等于内容无法输入。若输入失败，检查焦点和已选键盘后再记录，不能单凭页面字段类型判断应用缺陷。

## 核对网址字段

点入“网址”框，记录当前键盘、斜杠和冒号如何输入，以及可见回车标签。输入 `https://example.com/`，逐项核协议后的冒号、两枚斜杠、域名中的点和末尾斜杠。不要执行跳转或测试真实网站；该字符串作为文本即可。若宿主自动改写大小写或标点，记录前后差异，不把自动处理归因于键来。

与邮箱框比较时，先确认两次确实选中了同一键盘和设备方向。字段改变和同时更换主题、系统版本或浏览器会使对照失去可解释性；需要比较另一个浏览器时另起一轮。即使键面相同，也应分别检查三个字段的实际文本，因为用户任务及所需字符不同。

## 排查并保护已有设置

若目标字符找不到，先确认布局和符号入口，再用键盘实际可用方式输入；不要假定某个截图中的位置适用于全部设备。若正文不符，检查是否残留候选、自动替换或焦点在另一框。若页面在本地打不开，核文件扩展名与编辑器保存格式；不需要关闭浏览器保护或授予额外权限。每次只改变一个已理解条件，保留实际错误而不是清空重试历史。

如果做系统键盘对照，用新的记录标明键盘已经改变；某个系统键盘有专用布局不证明键来必须完全一致。无论哪种键盘，都不把浏览器显示的字段有效性提示当作真实账户验证。需要向开发者反馈时，可提供该无隐私 HTML、版本与可见反馈，不提供私人输入或截图中的个人信息。

## 保存观察并结束

交付三行观察表和本地测试文件，包含字段类型、键盘身份、所需字符的输入方式、最终文本以及未测试项。清除练习框或删除本地样本由用户决定；恢复日常键盘与显示设置。本文依据公开资料设计实验，没有声称在特定浏览器、键来或设备中实测布局兼容性。
