English translation of the [Chinese original](<https://allluckly.cn/guides/jianlai-ios-zoom-magnified-viewport-keyboard-input/>), translated on 2026-11-21. Original publication dates, attribution, code and version notes are retained.

System accessibility Zoom can magnify the screen, but the visible viewport, Jianlai’s actual layout and committed document text require separate observations. Use a nonprivate practice sentence and restore the original settings. Screen magnification is a system feature, not a Jianlai-specific function or a claim of medical benefit.

## Prepare an ordinary input environment

Create a practice copy in an ordinary note you control, with the target “午后读书.” Record device, system, host and visible Jianlai version. Confirm Jianlai is added and actually selected in the field. Preserve the original; do not use a password field or private message. If someone else manages the device and accessibility changes are not permitted, record the baseline only and leave the viewport comparison pending.

## Record the existing Zoom state

In system accessibility settings inspect whether Zoom is already enabled and record the mode and options you can confirm. Different viewport forms and system interfaces exist. Do not change complex settings without knowing how to restore them. If Zoom is already part of daily accessibility use, you need not turn it off merely to create an “off” baseline: preserve it and record the actual state. Stop if safe restoration is unclear; do not erase system settings.

## Establish the currently visible baseline

Under the current Zoom condition separately observe key labels, candidate area and host text, recording visible extent and legibility. Enter “午后读书,” confirm using the actual scheme and record all four committed characters and input position. Distinguish the key’s actual interface location from its magnified presentation. Seeing only part of the screen does not establish that other keys were deleted. If normal input already fails, mark it pending rather than using magnification to hide the problem.

## Observe Zoom under reversible conditions

Only after recording original settings and understanding the device’s actual operation, enable or adjust Zoom according to Apple’s guide and the onscreen instructions. Record the viewport mode, any confirmable level or value and gestures. Do not assume identical default gestures, levels or viewport size on all devices. Observe the magnified center and visible edge, then move the viewport to inspect earlier keys and candidates. If a gesture conflicts with input, stop and restore the original state rather than repeatedly triggering accidental input.

## Enter the sentence again and inspect the document

In the same host begin a new practice line, verify Jianlai remains selected and enter the same sentence. Record visible keys, whether candidates appear, user confirmation and committed host text separately. Verify both lines read “午后读书”; magnified key appearance alone is not success. Preserve a first mismatch before correcting another copy. System Zoom does not guarantee particular touch positions, candidates or glyph changes in all apps.

## Build an observation table rather than inferring layout changes

Use baseline and Zoom columns, each recording setting, visible key range, candidates, entered text and viewport movement. If a key is temporarily outside the magnified view, move the view before searching; do not immediately write that the layout lacks the key. If the keyboard layout was also manually switched, list that as a separate condition. When comparison cannot be completed, state why rather than inferring unseen areas from a screenshot.

## Troubleshoot by layer and restore

If full-screen and window modes are available, record the one actually used; both are not required in a single input trial. A second independent comparison may use the other available mode only if restoration is possible. Record what each viewport covers, whether it must move and whether focus remains in the practice field. A candidate temporarily covered by a lens is not proof no candidate exists; if moving the view still cannot establish it, mark evidence insufficient. Neither mode objectively measures touch area or proves suitability for everyone.

If magnification fails, inspect accessibility state and device gestures. If magnification works but input differs, check focus, selected keyboard, candidate confirmation and host text. For legibility alone, record font, background and light separately. Change one condition per retry. Restore the original Zoom state, mode and usual keyboard. If it was originally enabled, restore that enabled state rather than always turning it off. Confirm ordinary operation and retain existing notes.

## Deliver the record and limits

Keep nonprivate text, system and host versions, baseline and Zoom conditions, viewport movement, input results and pending checks. Behavior varies with device, mode, host and keyboard version. One observation cannot prove touch target sizes or universal accessibility compatibility. This exercise uses Apple’s accessibility guidance and public Jianlai information; no physical Zoom or accessibility acceptance test is claimed.
