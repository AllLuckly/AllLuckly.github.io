A self-made video can appear in local storage, NAS and a media server. Similar pictures after switching do not establish the same file, record or caption state. The public iCouldPlay 1.1.1 release mentions source-switching improvements. Use two sources that already play successfully to check a small, explainable round trip. Cross-source progress merging is not assumed, and you need not upload private media to a new service merely to obtain two entries.

## Choose two independently working sources

Prepare sources A and B, such as an authorized local copy and your NAS folder, and verify playback independently. Use a self-made short clip with a clear beginning, two anchors and a recognizable ending to avoid affecting real films. Record names, durations and any transcoding; where useful, follow the existing digest guide for accessible copies. Resolve an independently failing source before the switching exercise. These two entries are comparisons, not proof of a shared server identity or database record.

## Record an independent baseline for each source

For each source, note its name, file/item identifier, stop time, content anchor, audio, captions and speed. Use file time rather than elapsed watching time, which seeking and speed can change. Mark a missing setting as unavailable instead of inventing identical menus across all routes. Ordinary private notes suffice without an assumed automatic state-export feature. Use matching fields for A and B but record each actual state independently, rather than copying desired shared preferences from one card to the other.

## Pause A and leave playback explicitly

Open the sample through A, pause at the first anchor, verify that sound and picture stop, and record file time. Return to the source or library using the current interface without rapidly opening several entries or competing playback windows. If a route retains playback on leaving, use its visible pause/stop control and record the difference rather than assuming universal background behavior. Preserve the exit sequence and use the same route on the return trip so differing exit actions do not confound the comparison.

## Verify B’s file before accepting a resume point

Switch to B and inspect its source and file information before opening. Compare any resume prompt with B’s baseline rather than expecting A’s time because titles match. Play briefly to verify content. If an edition adds an introduction or removes material, use content anchors instead of equating identical timestamps with scenes. Pause at the second anchor and update B while preserving A’s card. This records behavior: matching times alone do not establish a general cross-source progress-merging mechanism.

## Check captions, audio and speed individually

On B, compare spoken language, available captions and speed with its baseline and your current needs. Similar caption names with mismatching content call for edition and caption-source checks before timing adjustments. Track lists can differ by source; an absent track is not automatically a lost selection. Record whether it is offered. Change one preference at a time and review a short passage. One retained size setting does not establish universal cross-source settings synchronization. Update B’s card to distinguish retained values from manual changes.

## Return to A and compare its record

Pause and leave B by the same sequence, reopen the item through A’s original entry, and compare identity, anchor and settings with A’s card. If B’s time appears, check for selecting B accidentally or two entries pointing to one record. Restoring A’s older position is likewise specific to this observation. For manual return, seek a few seconds before the anchor and play forward rather than claiming frame precision. Record the returned state before resets or deletions remove evidence about the source relationship.

## Reduce an anomaly to one round trip

For inconsistent results, reduce the test to A pause, B open/pause and A return, keeping device, network and sample fixed. Record displayed source and content time at every step without changing server accounts or involving another device’s sync. A difference appearing only after account changes must retain that condition. For a stale list after returning, use available return/refresh controls and keep messages rather than clearing the library. Share sanitized steps and two state cards for support without real server links or secrets.

## Restore everyday viewing and state the scope

Restore the everyday source and viewing position, and date the cards with the app version. Different cuts do not share interchangeable times. A local/NAS comparison does not cover Kodi, Plex or every object store. Keep useful entry-choice observations, including whether a source suits offline viewing or still needs a network, but verify offline capability separately. The result is a clear identity/state-check sequence, not an inference that source-switching improvements automatically unify all media and personal progress.
