## Prepare a source and fixed conditions for the curved edge

Use an owned still-scene clip at least ten seconds long, preserving footage, normal subtitles and display conditions. Fix a 640 × 360 script, position (120,140), p1, zero baseline offset, both scales 100 and no border/shadow; white fill is easier to see on dark footage. A curved upper edge and straight lower closure form a visible filled region. Calculations concern points on the upper curve, not the filled shape’s centre. Script position is not a device-pixel assertion. Keep prepared parameters and observations separate rather than substitute player zoom for a control-point change.

## Name the start, two controls and endpoint

Name current point P0 = (0,60), first control P1 = (0,0), second control P2 = (120,0) and endpoint P3 = (120,60). The m command places the pen at P0; b then supplies P1, P2 and P3, without repeating P0 as its first pair. Aegisub describes departure towards P1 and arrival at P3 from P2’s direction. Controls shape the curve rather than impose successive polyline vertices. Replacing b with three l segments is different geometry. Label all four roles before mistaking a control for the start or omitting the endpoint.

## Define the paper curve with cubic weights

Externally define the standard cubic model for t from 0 to 1. Its four weights are (1-t) cubed, 3(1-t) squared times t, 3(1-t) times t squared and t cubed. Multiply P0 through P3 respectively and add componentwise to obtain B(t). Non-negative weights sum to one; t = 0/1 returns P0/P3. This t is a geometric parameter, not playback seconds. One-half is neither two seconds nor partial drawing halfway through an event. Each event displays a static whole shape; parameter samples check the model without claiming an in-app sweep feature.

```
B(t) = (1-t)^3 P0 + 3(1-t)^2 t P1 + 3(1-t)t^2 P2 + t^3 P3
0 <= t <= 1; t is a GEOMETRIC PARAMETER, NOT playback time
P0=(0,60), P1=(0,0), P2=(120,0), P3=(120,60)
```

## Calculate endpoints, parameter midpoint and wrong substitutes

At t = one-half, weights 1, 3, 3 and 1 divided by 8 give (60,15). The controls’ average (60,0) and endpoint-chord midpoint (60,60) are not this parameter midpoint. Quarter/three-quarter samples are (18.75,26.25) and (101.25,26.25), consistent with symmetry. These are local coordinates, not screen-picked measurements. Although both control Y values are zero, this curve does not pass through those controls; its minimum local Y is 15. Expanding Y gives 60 - 180t + 180t squared, or 180(t - one-half) squared + 15. Thus the minimum is established, not guessed from a single midpoint calculation. Equal parameter steps do not guarantee equal arc lengths; the quarter-parameter point is not automatically a quarter-distance point. Neither the control polygon nor the filled region’s centroid substitutes for B(t).

```
Original LOCAL curve:
B(0)    = (0,60)
B(1/4)  = (18.75,26.25)
B(1/2)  = (60,15)
B(3/4)  = (101.25,26.25)
B(1)    = (120,60)
Control average = (60,0); endpoint-chord midpoint = (60,60)
```

## Check fixed endpoints after changing only the first control Y

The second event changes only P1 to (0,30), leaving P0/P2/P3 fixed. At the same midpoint weights, Y increases by (3/8) × 30 = 11.25, giving B(1/2) = (60,26.25), while endpoints remain (0,60) and (120,60). Their horizontal separation stays 120; a deformed curve does not imply a larger endpoint distance. Shape changes without endpoint movement do not imply uniform translation. The modified curve is no longer left-right symmetric; its half-parameter point is not automatically a new extremum. Keep that one-value control. Also changing P3 destroys the fixed-endpoint comparison; restore by returning P1 Y to zero.

```
Modified P1=(0,30), all other points fixed:
B(0)   = (0,60)
B(1/2) = (60,26.25)
B(1)   = (120,60)
Midpoint Y change = (3/8)*30 = 11.25
```
