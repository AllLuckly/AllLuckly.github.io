Check chapter groups, subsection destinations and observed navigation in a self-made EPUB.

## Understand the hierarchy

An EPUB navigation document can express chapters and subsections with nested ordered lists. Check labels, levels and each link’s actual destination separately. Observe how a reading system presents the hierarchy; file structure alone does not establish that Book Isle has an expand or collapse control.

## Make a chapter with two subsections

Use an editable EPUB you are authorized to modify. Write one chapter with two distinct subsection headings and opening sentences, and save a separate test copy while retaining the original. For example, use “Section one: seeds” and “Section two: sprouting” with your own text. Do not modify protected purchases or publish private library content.

## Record content targets

In the editor inspect the file and fragment identifier of each subsection. Confirm each target exists and identifiers are not duplicated within the same document. Record the chapter’s relative path, both targets and opening sentences. Similar subsection labels do not imply the same target; repair an invalid target in the authorized copy first.

## Check parent-child structure

Inspect the toc list in the navigation document: place the chapter at the parent level and its two subsections in the child list with their respective targets. EPUB permits an unlinked grouping label when it has a child list; a linked parent can also have children. Ensure labels contain recognizable text and do not record a pure grouping label as necessarily clickable.

## Validate links and order

Resolve each relative path and fragment from the navigation file and verify each section reaches its own target. The specification recommends contents references follow spine and in-document order; this sample follows the text. Run EPUBCheck or the editor’s checks, retain the report and keep the sample separate from the original.

## Identify the sample in Book Isle

Open the sample using the file import method actually available in Book Isle and confirm title and opening text. Record app version, device and display layout. If import fails, preserve the message and check file and permissions rather than clearing the shelf or overwriting the original. If no applicable interface exists, mark subsequent actions unperformed.

## Observe the contents presentation

Open the contents actually offered by the app and record whether the chapter and both sections appear, their relative hierarchy and whether any expansion offered by the interface is needed. If sections do not appear, record what is visible and available. Do not generalize support or lack of support for a particular depth without sufficient testing.

## Check destinations individually

Select the first and second sections if actually clickable, recording the heading and opening sentence reached, then return using the available interface. Record if an item has no click target, fails to respond or reaches only the chapter beginning. A manually searched passage does not prove a contents link worked. For an approximate landing, note the visible heading and context.

## Troubleshoot the wrong subsection

First inspect the navigation links’ complete relative paths, fragment spelling and content targets, including whether both accidentally point to one location. Confirm the newly imported sample rather than an old copy is open. Correct one error, save and validate again, then repeat both selections and retain the earlier result. Do not attribute one observation directly to the app.

## Compare linked and grouping parents

For a further check, prepare authorized copies with a chapter-linked parent in one and a grouping-only parent in the other while keeping the children the same. Validate both and record filenames and structural differences; observe only behavior available in the interface. A grouping label without a destination does not invalidate its subsection links.

## Record results and keep backups

The table includes label, level, expected file and fragment, actual destination text, available action and reasons for unperformed steps. Use a separate row for each device or version and do not publish private paths or copyrighted text. Identify the test book before deciding whether to remove it; retain the original and report. No device test is claimed.

## Record context around the landing

A fragment need not place its heading exactly against the top edge of the screen. Use distinct short sentences before and after each section heading, and record the visible heading, surrounding text and chapter to avoid misclassifying a normal contextual display. If only the chapter opening appears, continue observing but do not count manually reading to the section as a direct link arrival.

## Compare both records after retesting

After correcting a link, validate the working copy again, import it under a different filename and repeat both subsection selections in the same order. Record the targets and results for old and new copies. Note any change in reading layout. If the new entry is not found, stop and confirm the import message and title rather than clearing all reading history. Include the validation tool version and date so the sample can be checked later.

## Check relative contents paths

Record the directories containing the navigation document and chapter, then resolve both links from the navigation file, checking filename case and target fragments. If labels look correct but destinations do not, inspect links before rewriting the chapter. Keep the older copy and validation report to compare whether a single correction changes the actual landing.
