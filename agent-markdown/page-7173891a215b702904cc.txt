A small pronunciation annotation can be attached to a character or flattened into ordinary text. Visible pinyin alone does not establish ruby rendering. Prepare a minimal external VTT and compare annotated and plain versions in iCouldPlay. Use your own text without automatic pronunciation generation or a promise of identical support across engines.

## Define the character and exercise scope

Prepare a self-made clip at least ten seconds long, using a stationary paper card if desired. Record that 行 has the row/line reading háng in this exercise. You supply the reading; the player neither disambiguates it nor establishes real speech. Preserve the original and regular captions under separate names. Without recording facilities, finish the paper structure and control files while leaving playback untested. Reading this code is not observing ruby on a phone. Check the character in a trusted text tool.

## Nest base and annotation inside one cue

Save this original example as UTF-8 plain text with a .vtt extension, excluding fences. One cue lasts from second one to six. Put the base inside ruby and the annotation inside its nested rt, closing inner then outer tags. Retain the accented pinyin. This adds neither another cue nor an audio track or timing interval. Reopen the saved text and check brackets, closing tags and the blank line rather than trusting apparent editor completion.

```
WEBVTT

00:01.000 --> 00:06.000
<ruby>行<rt>háng</rt></ruby>
```

## Check structure without assuming a screen position

Use the [W3C WebVTT ruby-span definition](<https://www.w3.org/TR/webvtt1/>) to distinguish base and annotation roles. Moving rt outside ruby changes the structure. Add no webpage CSS or script and do not treat a browser style as a guarantee for iCouldPlay. Sketch parent/child relationships externally without learning the full parser algorithm. Record normative structure separately from device rendering, leaving unobserved position, size and colour blank rather than assuming one placement for every language.

## Play from before the cue and record separate outcomes

Select the practice caption through the actual iCouldPlay entry and play from before second one until after six. First record whether the base appears, then annotation presence and relative placement. Record a base alone, flattened text, layered display or exposed tags as observed. Keep video, orientation and speed fixed instead of changing sources to force expectations. For missing controls or loading errors, retain entry and message without immediately blaming ruby or inventing a manual engine menu.

## Make a base-only control with unchanged timing

Save a copy replacing the entire markup with 行 alone while retaining header, interval, encoding and extension. Select and play each separately; similar list names do not prove switching. If the control lacks the base too, check selection and character rendering first. If only the annotated version differs, limit the finding to these files and this path. Removing pronunciation loses information, so the control is not semantically equivalent. Keep the sole original intact.

## Separate character and markup problems

A missing-glyph box and exposed rt tags are different observations. For the former, inspect saved characters, a known readable character and font path; for the latter inspect nesting and caption handling. One screenshot does not diagnose the cause. Do not delete the characters and keep only pinyin to claim a repair, and do not download or install unknown fonts. For lost accents, inspect the saved source first. Correct a source error in a copy while retaining the old value rather than calling editing damage a playback translation error.

## Verify an explicit-text alternative if pronunciation must be visible

If visible pinyin is required, separately test explicit text such as 行（háng） on the same video for completeness and reading load. This is parenthetical text, not ruby layout or a universal device guarantee. Do not apply this alternative directly to production captions whose author supplied no reading. Interpreting polyphonic characters also requires reliable context. Give the alternative a new name and record changed structure, retained information and untested devices. A successful exercise does not imply automatic annotation of arbitrary films.

## Reopen and verify all three file identities

Reopen the video, identify annotated, base-only or parenthetical selection, and play again from before the interval. Retain source character, supplied reading, structure, observed rendering, control differences and unknowns with filename and date. Restore regular captions and keep the three files and original separately. Completion separates authored information from actual rendering, without universal character disambiguation or a claim that publishing this lesson constitutes physical-device testing.
