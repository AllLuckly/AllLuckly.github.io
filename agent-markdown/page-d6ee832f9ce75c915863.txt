Compare Apple Notes document formatting with Jianlai key-label appearance, recording characters, host style and keyboard settings separately.

## Prepare a non-private practice note

Open Apple Notes on your iPhone or iPad and create a separate test note with “海边计划 ABC。”; preserve existing documents and avoid passwords or account data. Record OS, whether Notes and Jianlai versions can be identified, and the current Jianlai theme and visible font setting. Jianlai’s listing describes keyboard font appearance; Apple Notes offers document styles such as headings and bold. Their scopes must be observed independently: key-label styling is not automatically document formatting.

## Enter the original sentence with Jianlai

Select Jianlai in an ordinary Notes body field and type the sentence manually. Check Chinese, English, spaces and punctuation, preserving the first line. Observe keys, candidates and body text without changing a font or document style yet. If candidates do not appear, record them absent; if Jianlai is missing, check system keyboard selection and field focus. Keep the committed text clear and separately saved. A keycap’s visible glyph does not prove the document saved that font.

## Change only the Notes document style

Copy the practice sentence to another line in the same note. Following Apple’s guidance and the actual Notes formatting controls, select the second line and apply one recognizable style such as bold. Record selection range and style. If the selection is unclear, cancel and reselect rather than changing an entire existing document. If the control is unavailable for this system or account, mark the trial unperformed. Notes handles its formatting; the bold button is not a Jianlai text-editing feature. If Notes uses the first line as the note title, create both comparison lines in the body so the title’s paragraph style does not confound the test. Record visible changes inside and outside the selection, preserving the original sentence.

## Check content, body appearance and keys separately

Compare characters, spaces and punctuation in both lines; observe any visible style difference and whether Jianlai key labels changed after the host action. Different appearance does not prove different characters, and equal text does not prove identical formatting. If both lines changed, inspect selection and paragraph scope while preserving the original result. If the style cannot be distinguished, mark it unobserved rather than treating a button tap as proof of success.

## Try one reversible Jianlai appearance separately

With both note lines and the original theme preserved, if the installed Jianlai offers an identifiable and reversible font or key-label option, change only that option and return to the same note. Observe keys and candidates, then inspect the two existing document lines. If no clear option is available, mark the trial unperformed. Do not import an unfamiliar font, remove a theme or simultaneously change system text size. A listing’s font customization does not establish that every font is applied to host text.

## Check new input under the changed appearance

While retaining that one keyboard appearance, type the same sentence on another line and compare key labels, candidate visibility and committed characters. Preserve the two existing lines and their styles. If new text inherits the current Notes style, record the actual host display; do not infer that the keyboard font was embedded in the document. If a new line inherits an unwanted host style, record it first and then correct the practice copy with Notes’ actual formatting controls rather than changing the keyboard theme. Changed keys with unchanged body text, or body text inheriting bold, must be interpreted under the observed conditions rather than generalized to all apps or fonts.

## Troubleshoot selection, host and keyboard separately

If bold is not visible, inspect the Notes selection, chosen style and actual display. For incorrect text, inspect cursor, candidate selection and whether the intended line was edited. If keys did not change, verify the actual Jianlai theme and saved appearance option rather than removing the keyboard or clearing data. When host style and keyboard appearance changed together, restore the baseline and change one condition per trial. Unknown selection, font or style remains insufficient evidence, not a universal incompatibility claim.

## Restore the theme and deliver the record

Restore the recorded Jianlai appearance, save or retain the practice note and verify existing notes and backup remain. The user may decide what to do with the practice draft. Keep target text, two document styles, key/candidate observations, single-option appearance comparison and unfinished checks. Apple documents Notes formatting and the Jianlai listing describes appearance customization; their interaction depends on actual device and host. No physical font, formatting or cross-app compatibility test is claimed.
