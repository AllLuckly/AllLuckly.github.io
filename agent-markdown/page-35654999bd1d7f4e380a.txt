Compare the first and subsequent catalog pages with actual works in an authorized library.

## Identify what is paginated

Kavita documents pagination for its OPDS feeds. This concerns server catalog lists, not comic image pages, and does not promise identical navigation controls in every client. Use an authorized personal Kavita library and a connection Manyue actually supports. If there are too few items or no subsequent page, record that rather than downloading unknown comics to increase the count.

## Prepare a safe test catalog

Ask the administrator to select an authorized test series with enough distinguishable items to trigger pagination on that server. Do not change other users’ permissions or a production library. Record Kavita version, test account identity in non-sensitive form, feed type and public series name without private addresses, credentials or OPDS keys. Without a test environment, use a paper plan and mark it unperformed.

## Establish a server baseline

Locate the same series or catalog in Kavita’s actual interface. Record total count if shown, recognizable first and last names, and sorting. Choose two or three authorized anchor items and record volume or chapter names. Feed types can sort differently. If no total is shown, do not infer a complete count from one screen.

## Connect to the same account and feed

Use an existing Kavita or OPDS connection in Manyue and verify server, account and library match the baseline, then open the same series or catalog. The user handles any user-specific authentication privately. On connection failure, inspect authorization and network rather than resetting accounts. If the matching feed or connection is unavailable, mark incomplete instead of substituting another source.

## Record the first catalog page

On the first Manyue catalog page record visible series or chapter names, first and last items, loading state and time. If a Continue From alias appears, note separately which underlying chapter it refers to. Do not equate screen capacity with server page size or immediately count an alias as a new comic. Record the actual next-page entry; if absent, say not observed.

## Open an available next page

Use a next page, more or continue-loading entry only if the current interface displays one. If scrolling triggers loading, follow the observed behavior rather than assuming a fixed button. Wait for loading and record the first and last new items and any error. If no entry appears, first confirm that the feed actually has a next page; otherwise mark the client entry unavailable or not observed.

## Check duplicates and omissions

Compare chapter names, volume numbers and baseline anchors at the page boundary for omissions or repetition. A Continue From alias can point to the same underlying file and is not necessarily a duplicate import; count a genuinely distinct work by identity. If items or sorting change during testing, preserve both times and establish a fresh baseline rather than labeling dynamic change a pagination defect.

## Open one authorized item

Select an authorized chapter from later results and record its title and position before using Manyue’s available opening method. A listed page does not guarantee page-streaming resources; if only a whole-file link is offered and cannot be read directly, distinguish list visibility from acquisition. After viewing one page, return and observe the catalog and position.

## Troubleshoot without clearing data

For a failed later page, record network, error, account, server feed and failure stage separately. Confirm server availability with the administrator, then retry once under the same conditions. Do not publish authentication links, reinstall or delete history first. If the server view has items but Manyue cannot open a later page, describe that specific version and observation, not all OPDS clients.

## Preserve records and existing state

Keep feed name, anchors, first and later entries, alias assessment, open and return results, and incomplete steps. The test reads already authorized content and does not require deleting comics or modifying another account. Restore any changed view filter using the initial record. The author used public documentation and does not claim a private-server connection or device test.

## Build a boundary ledger

Record names, volume numbers and positions of the last two identifiable entries on the first page and the first two in the next batch. If the boundary repeats a title, check for an alias, changed sorting or repeated display, and confirm the same feed and account. Matching titles do not establish identical files, and matching covers alone do not prove duplicated pagination.

## Separate catalog pages and comic pages

A row in a catalog is a selectable item; a page after opening a comic is content. Even if both are called pages, record the catalog batch and the page within the comic separately, including whether it was actually opened. If the interface reloads the first batch after returning, record that position change rather than claiming a comic page was deleted. This helps an administrator inspect the appropriate layer.
