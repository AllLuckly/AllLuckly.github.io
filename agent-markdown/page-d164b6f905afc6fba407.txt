An ebook cover can appear in the resource manifest, an in-book page and a shelf. Separate these before comparing actual display.

## Separate three cover locations

An EPUB manifest can identify a cover image with the cover-image property. W3C recommends it when a cover exists, but the property is optional. The first in-book page may contain cover content, while the Book Isle shelf thumbnail is an app interface; these need not use the same resource. The specification does not guarantee how Book Isle creates a thumbnail. Record each separately without editing the publication.

## Prepare an authorized sample

Choose an EPUB you created or are authorized to inspect, preserve the original, and record title, edition, source and shelf cover. If similarly named editions exist, distinguish them by contents and copyright page. Without internal-inspection rights, a suitable tool or with a protected file, observe shelf and first page only and mark manifest inspection unperformed.

## Create distinguishable references

On paper note main colors, title position and a recognizable marker on the shelf cover. Open the book to its cover or first page and record the same features. Similar-looking pictures do not prove identical files; different words can reflect edition or layout. Use self-made aliases for private material and do not upload unauthorized cover images.

## Optionally inspect the EPUB manifest

An authorized owner inspects the package manifest read-only in an isolated EPUB copy, looking for a resource item whose properties include cover-image. Record whether found, media type, relative filename and whether the target opens. If the optional property is absent, record not found rather than declaring the EPUB damaged. Do not edit the package or repackage the sole original.

## Compare resource and in-book page

If a cover resource is found, the authorized owner opens a copy in a normal viewer and records colors and markers, then compares the in-book first page. That page may be a separate XHTML document, include an image or contain other content; its position alone does not identify it as the manifest cover image. Mark an unreadable resource pending rather than guessing its contents.

## Observe shelf and content in Book Isle

Open the same edition in Book Isle and record the shelf thumbnail, in-book cover page and first visible contents or body position. If an image is too small, use any viewing control actually offered; do not assume zoom exists. Existing reading progress can mean reopening away from page one. Do not clear production progress to force a first import.

## Bound the conclusion

A visually matching resource image and shelf thumbnail establish a visual match in this observation, not that the app used cover-image to generate the thumbnail. Different shelf and in-book covers do not automatically establish corruption; user-edited artwork or distinct resources may be involved. Confirm file and entry identity first and leave uninspected image sources unknown.

## Investigate missing pictures

If an in-book cover or shelf thumbnail is absent, first confirm the file opens, title and edition match, image resource exists and the network or local-copy state is understood. Compare the same authorized file in a reliable reader and record software versions and location. One difference cannot establish cache behavior, format support or import error. Do not delete the book, repackage it or overwrite production artwork to complete the check.

## Separate artwork and text reading

Test the in-book cover, chapter contents and a body passage independently. A successful cover does not prove the book is complete; a missing cover does not establish unreadable body text. Record titles or self-made markers and precise failure locations. An authorized user may separately inspect any assistive description; visual artwork and text alternatives are distinct items.

## Build a three-location cover ledger

Give the manifest resource, in-book cover page and shelf thumbnail separate rows with confirmed source, color and text markers, observation time and unknowns. Only an owner who actually inspected the manifest can record cover-image found or absent; otherwise mark unperformed. If the user manually changed shelf artwork, record that history rather than attributing the thumbnail directly to the EPUB resource.

If a manifest target exists but a viewer cannot open it, check media type, actual format and the package document location used to resolve its relative path. Do not infer encoding from extension alone or overwrite the original with a similarly named web image. Follow the publication license for protected files; without permission leave the result unknown.

For the in-book page, confirm it is a content-sequence cover rather than an independent shelf thumbnail. Turning to the copyright page, contents and chapter one can establish sequence; record each target. A different order is not necessarily a defect. If multiple portrait, landscape or size variants exist, list confirmed resources rather than treating similar colors as proof of one file.

A report saying “shelf shows A, in-book page shows B” is easier to reproduce than a generic “cover is wrong.” Supply authorized edition, location and time without the whole book or account. State explicitly if resource inspection was not performed, so the recipient does not assume a source was identified.

## Restore and hand off

Preserve the original EPUB, shelf artwork and notes. The owner handles an isolated copy according to normal policy. Record resource property, resource image, in-book page, shelf thumbnail, body text and unperformed steps separately. Share only sanitized version and steps, not private paths or restricted images. Based on public W3C specifications, this guide claims no physical-device test.
