Observe EPUB light and dark color declarations, device preferences and actual reading results with an authorized sample.

## Understand the preference declaration

W3C Media Queries defines prefers-color-scheme as a preference for a light or dark page theme; the preference may come from the operating system or user agent. Its presence in a stylesheet does not guarantee Book Isle reads it or that all book text and images adapt automatically. Record user settings, reader themes, book styles and actual display separately.

## Prepare an authorized sample

Choose an EPUB you created or the publisher permits you to inspect, ideally with a short black-and-white passage and a self-made image, and documentation of whether it contains the relevant media query. Preserve the original and backup and record title, file edition and source. Do not unpack another person’s protected book. If internal inspection is not permitted, compare visible output only and mark structure inspection skipped.

## Establish the first observation

Open the same test section in Book Isle and record actual device appearance and app reading-theme settings, text and background colors and image edges. Record a heading or self-made short marker to return to the same location; mark unavailable settings unknown. A dark-looking screen alone does not prove that a CSS rule ran. Device brightness and page background color are different settings.

## Inspect stylesheets and scope

Only when permitted and equipped, inspect CSS referenced by the target section in a copy. Record whether prefers-color-scheme exists, the light or dark condition and affected selectors. A chapter can reference multiple stylesheets or include other rules, so finding one term does not prove it controls the whole book. Preserve actual relative paths and distinguish file contents from publisher statements; do not alter the original to force a result.

## Change one visible condition

Using controls actually provided by the device and Book Isle, change only one of device appearance or app reading theme while keeping the file and section unchanged. Reopen the same location and record text, background, image and settings. Mark missing controls unavailable. Do not change font size, brightness and several theme settings simultaneously, because the resulting difference could not be attributed to one condition.

## Separate image and text behavior

Compare legibility of text against the page background, then inspect whether the self-made image has a fixed light background, transparent area or dark border. An image need not change with text color, and transparent areas can reveal the page beneath. A light rectangle does not alone prove a theme change failed. Record image content and CSS declarations separately without inferring which rule the app used from appearance.

## Observe accessibility needs separately

If the user needs larger text or a system contrast feature, record the original setting and perform a separate observation using available controls. Accessibility settings and the book’s CSS are not a single variable; mark them untested if unused or uncertain. If text is hard to read, restore the original setting and pause rather than requiring prolonged use of an unsuitable color scheme.

## Troubleshoot without guessing

If the device setting changes but Book Isle does not, verify the same chapter, saved control and the app’s own theme before drawing conclusions. An absent CSS declaration cannot explain the result. Another trusted reader can serve as an independent control, but its display does not prove equivalent support in Book Isle. Change one condition at a time, record unknown causes and do not install unknown software or change security settings.

## Restore settings and save the findings

Restore original device, Book Isle and assistive settings and confirm the original file, bookmarks and notes remain. Record sample version, whether the style exists, both settings and visible colors, image background and skipped steps; remove private paths and unauthorized content before sharing. This guide relies on public standards and app information, claims no device test and does not guarantee support for this CSS media query.

## Separate declarations from display

Use one column for the stylesheet condition, selector and color values and another for text and background observed in Book Isle. Matching colors do not prove the declaration ran because another rule or app theme could produce a similar result; different colors can also involve selector scope, inheritance or overrides. If the source cannot be established, record a color change with its cause unknown rather than presenting inference as a verified app capability.

## Keep an independent control

If the publisher supplies another authorized test copy explicitly lacking the media query, compare the same self-made passage while keeping device and app settings fixed. Identify each file carefully; other differences between copies may still prevent a causal conclusion. Skip without a permitted control and never edit the only original.

## Record readability rather than ranking preferences

Light and dark are appearance preferences; comfort also depends on lighting, text size, individual vision and display. Record whether this sample is legible to you without claiming one theme suits everyone. More precise contrast analysis requires an authorized copy and appropriate tools. Keep personal accessibility settings private and restore them afterward.

## A reproducible self-made sample

A self-made sample can give selector p black text #000000 on white #ffffff, with a prefers-color-scheme: dark rule for the same p specifying white text #ffffff on black #000000. Record both declarations and the app’s actual display, then compare after changing one appearance condition. These are format examples, not proof Book Isle applies the query; record an app-enforced theme or unavailable switch as observed.
