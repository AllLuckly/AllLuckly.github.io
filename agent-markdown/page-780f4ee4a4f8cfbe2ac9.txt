Server playback type and the iCouldPlay viewing experience are separate observations. Record both using one clip and clear conditions.

## Separate four server results

Jellyfin distinguishes Direct Play, Remux, Direct Stream and Transcode. Its transcoding documentation describes file delivery without transcoding, a container change with both streams preserved, audio transcoding with video preserved, and video transcoding respectively. The server dashboard can display the playback type for a session. Use the current server documentation and do not infer the type from smooth iCouldPlay video or a filename extension.

## Prepare an authorized short clip

Choose a self-made or authorized short video in an administrator-approved test library. Record a film alias, duration, dimensions, video codec, audio codec and container; mark fields unknown if tools or permission are unavailable. A label in a player is not the complete source structure. Do not change a production library or other users’ settings to force transcoding.

## Record device and conditions

Connect iCouldPlay to the authorized Jellyfin server and confirm server, account, network and test film. The administrator prepares a signed-in session with dashboard access. Make four columns: time, selected audio or subtitles, server playback type, and iCouldPlay picture and sound. Use aliases and do not share private addresses, tokens or other users’ viewing records. Without dashboard permission, mark server type not performed.

## Run one baseline playback

Open the clip in iCouldPlay, verify picture and sound, and record selected audio, subtitle state and start time. Ask the administrator to identify this exact session on the server dashboard and record its displayed playback type and time. Labels and location can vary by release. If the session cannot be identified as yours, mark unknown instead of using another person’s session. Afterward stop only your own test playback.

## Understand each label’s limits

If the server reports Direct Play, its documentation describes untranscoded file delivery. Remux changes container while preserving both audio and video streams; Direct Stream transcodes audio but preserves video; Transcode means the video stream is transcoded. Output codec, quality and hardware use still require separate checks. Do not describe Direct Stream as a completely unchanged file, or infer sufficient bandwidth from the label.

## Change one playback condition

If the test film includes multiple authorized audio tracks, record the current option and switch only to another track while keeping device, network and clip fixed. Ask the administrator to observe the session again and record server type and actual sound. Skip when no second track exists. The type may stay the same or change; do not prefill a change or insist on triggering transcoding. Do not alter hardware acceleration, permissions or bitrate settings.

## Compare subtitles separately

Restore the baseline audio. If subtitles are available, change only subtitle selection and observe the same clip and server type. Subtitle format, client capability and server processing can affect the result; do not assert that subtitles always burn in or force video transcoding. Mark inapplicable if there are no subtitles or iCouldPlay offers no control. Restore the initial choice before another comparison.

## Check picture, sound and time

Choose one recognizable picture near the start and one in the middle. At each, record smoothness, matching sound and whether subtitles appear. A server type does not guarantee audio or synchronization quality; normal picture does not prove Direct Play. For buffering, record time, network and actual symptom instead of concluding that server hardware is insufficient from one observation.

## Investigate session and label differences

If dashboard and app observations differ, first confirm server, account, device and time. Stop the old session, reopen the same clip and ask the administrator to inspect the corresponding new record. Do not expose another user’s connection information. Names can vary by version; the administrator can consult current documentation. When evidence is insufficient, retain the original label and mark it pending. Do not weaken security to obtain a desired label.

## Make comparison conditions reproducible

Include the same clip alias, device, network and selections in every row. For example, row one uses original audio without subtitles; row two selects another audio track without subtitles; row three restores the original audio and selects a subtitle. After each session starts, the administrator records the dashboard wording observed at that time rather than copying a prior label. If the session has not appeared, mark waiting or unknown. Record start and observation times so an ended session is not mistaken for the new one.

Identical labels across conditions are still useful observations: they indicate the server displayed the same type during this test, not that audio content or stream codecs were identical. If an explanation is displayed, ask the administrator to remove any private paths before recording a minimal summary.

## Restore and hand off

Restore original audio and subtitle choices, stop the test playback and confirm production content is unchanged. The record should include each condition, the dashboard’s original wording, iCouldPlay picture and sound, and steps not performed, excluding addresses and credentials. Based on public documentation, this guide claims no private-server connection, physical-device test or transcoding performance test, and does not guarantee arbitrary codec support.
