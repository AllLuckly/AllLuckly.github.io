Use an already confirmed compatible personal service and retain evidence of the connection and library identity.

## 1. Establish compatibility and authorised access

Prepare a personal music service you manage or are authorised to access, confirming compatibility from its documentation or the installed app’s support information. 调调 publishes compatible-server access, not a universal protocol/brand list. An arbitrary webpage, cloud share link or network directory is not automatically its service address. Without a confirmed compatible existing service, retain preparation as pending and continue local importing instead of inventing success. This task neither deploys a new server nor requires opening an external port.

## 2. Prepare two library reference tracks

Through your existing authorised access, choose two identifiable tracks A/B and record library, title, artist, edition and audible clues. A small reference suffices without exporting a private catalogue. State any account-specific collection scope so inaccessible material is not mislabelled as lost music. These tracks identify the intended account/library, not universal compatibility or completed playback. Preserve server and source files; deleting music is unnecessary to prove a connection.

## 3. Verify the complete service address

Obtain the current address from trusted service information and check scheme, host, required port and path. Preserve the original string privately. A different path or port may identify another endpoint even under a familiar domain. This tutorial supplies no universal example address or guessed server type. Keep credentials separate from ordinary notes and public feedback. Respect the service’s required network environment instead of disabling protection or bypassing certificate warnings merely to retrieve a page.

## 4. Use only the installed connection flow

Open the identifiable personal-server/source connection flow. If types are offered, select only the one matching your verified compatible service. Follow real field names and requirements rather than an invented protocol menu, token field or save button. Verify the address, provide authorised account information as requested, submit once and observe feedback. Unclear fields or unmatched types remain unresolved. Another player connecting does not prove 调调 accepted the service, and repeated guesses across unknown types are not a sound setup method.

## 5. Check the library after connection feedback

After connection/loading feedback, verify source name and account scope, then browse for A/B. A success notice, a track list and the intended library are different evidence. Familiar titles alone do not establish the correct account. For an edition mismatch, compare artist, duration and collection before editing server tags. If only one track appears, retain the other as pending and inspect accessible scope. Do not invent synchronisation or treat a server listing as a file stored locally.

## 6. Open one track within the identified source

Open A from the identified server source, compare player identity and sound, then return to locate it again. This checks browse-to-open provenance, not a universal cache/download mechanism or offline readiness. Record browsing and playback separately if only the first succeeds. A playing through another entry is not this path’s success. Use comfortable volume and one source at a time. Unobserved later playback or access on another device remains pending.

## 7. Diagnose address, authentication and scope separately

For no service response, inspect address and required network. For explicit account failure, check authorised access. For the wrong library after connection, inspect source/account scope. For one silent track, inspect track/output separately. These are not all unsupported-server failures, and theme changes or deleting local songs do not diagnose them. Change one known condition, preserve exact errors and exclude credentials from public records. Unknown compatibility remains pending rather than a claim of a newly supported protocol or every personal service.

## 8. Deliver a minimal connection record

Preserve the service and local collection. Save service identity, compatibility evidence, access scope, feedback, two browse checks and one opening result. Keep address/account details privately and share only redacted descriptions. Explain which authorised library was connected and what actually occurred, rather than relying on a login screenshot. Recheck changed addresses, account scope or versions. No completed private-server/device test or unverified service, download or cross-device synchronisation capability is claimed.
