## 先约定三列与非空字段

另建一份练习笔记，列名固定item、count、note，下面两条记录用pencil与folder。每行三个非空字段，字段里不放制表符或换行，备注只用普通英文词。先写纸面顺序与字符约定，不从真实通讯录复制数据。宿主选能保存普通文本的现有工具，记录它是否把Tab用于移焦而非插字；没有插入制表符能力时，字段先分行草拟，随后交给自己已有的文本工具组合，不编造键来的专用TSV键。每个记录的数量是十进制文字，列顺序在整个练习中保持一致。

## 把可见标记稿与真实字符稿分开

下方第一份是说明稿，尖括号包住的TAB只是三个字母加两枚括号，并不是分隔符。第二份代码块实际含制表符，可作自己的对照副本。先用键来输入列名和词句，再用宿主真实入口完成分隔；若用复制的对照稿，应写明复制而非手输。不要把屏幕上同宽空白当证据，字体、制表位和窗口宽度都会改变外观。保存后从头到尾读三行，确认没有把代码围栏、注释标题或多余空白行一起写入数据文件。再次另存后，做一次字符替换验证：只在说明稿把TAB三个字母改成GAP，正文里的两枚尖括号仍在；它继续是说明文字，不会改变真实稿。这个动作有助于认清可见标签与控制字符的层次，不能把标签改名后的截图当作分隔符已经从文件中移除。真实稿若需要改分隔方式，应另建文件，并重新记录每行字符及导入规则。

```
item<TAB>count<TAB>note
pencil<TAB>12<TAB>ready
folder<TAB>3<TAB>archived
```

```
item	count	note
pencil	12	ready
folder	3	archived
```

## 逐行数分隔符再数列

按IANA登记的这类简单TSV约定，一行是一条记录，列间由制表符隔开，各行字段数相同。本例每行应有两个真正制表符，因此拆开后三列；首行是列名而不是第三条物品记录。若编辑器能显示不可见字符，打开后核两处Tab标记；若没有，就将自己的副本交给现有支持按制表符分列的工具，记录得到几列。两种检查都不能用肉眼数空白宽度替代，四个空格即便刚好对齐，仍是四个空格，不会自动成为一个Tab。

## 用键来只改数量字段

回到普通编辑框，确认当前为键来，把folder这一行的3改成4，保留前后制表符和备注archived。先点进数字附近，按宿主实际光标操作选中单个3；选区若越过Tab，先取消重新定位，不直接键入覆盖整段。输入后沿该行从左到右核folder、4、archived，再复查另两行未动。软换行只与窗口有关，不能为了让三列都留在一屏删掉分隔符。记录此次是否出现候选替换或宿主自动修正，实际没有发生时不要为了展示排查而制造故障。

## 另存空格反例验证分列条件

从修改后的合格副本另存一份反例，只把folder与4之间的一枚Tab替换成四个普通空格，其他字符完全保留。可见外观也许接近，但按Tab拆分后这一行只剩两个字段，第一字段包含folder加空格加4。把正常稿与反例的原始字符、字段数分别写下，不凭预期填入实际导入结果。这个反例只检查分隔方式，不说明所有表格工具都不能识别空格；目标工具若启用了自动猜分隔符，先把该条件记录下来，再固定明确的Tab规则重查。

## 交接到目标时先保留文字

如果目标是自己已有的表格工具，新建空白练习表，把合格副本按制表符导入或粘贴，并核列名是否各占一列、pencil与folder是否各占一行。第一列按文字保留，数量列的显示和实际值另外检查；本课不要求把数字转换成公式。不要把整个笔记连同说明段落一起导入，也不要把练习表粘进正式财务文件。目标没有分列能力时仅保存原始稿和字段检查，交接一栏写未完成，不能因为笔记看上去三列就填成功。

## 按字符、宿主与导入规则排查

全部挤到一格时先查是否真的有Tab以及目标是否采用Tab分列；若变成更多行，检查字段里是否混入真实换行。按Tab跳到别的控件，说明本次宿主把按键作为导航，不等于键来丢了字符。出现全角数字或被替换的英文词时，回到该字段用当前输入模式逐字符修复，并保留问题副本。每次只改变一个条件，别同时换键盘、导入工具和文件编码。无法显示不可见字符时明确证据不足，不从一张截图推断文件内制表符的数量。

## 重开交付可复查的三行稿

关闭再打开保存副本，重新核每行两个Tab、三个字段以及folder数量4。交付合格稿、空格反例和目标导入记录，注明设备、键来版本、宿主名称及分隔符插入方式。恢复日常笔记时仅关闭练习，不删除原始材料。最终能够说明字段文字由何处录入、制表符由何处进入、哪一步实际验证分列，比只留一张整齐截图更有用；若传输工具改写了空白，接收端仍需从原始字符重新检查，之前通过不保证以后每次交接都保持相同。
