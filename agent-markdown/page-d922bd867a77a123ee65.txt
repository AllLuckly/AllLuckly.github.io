System Dark Mode changes many interfaces, but does not establish that every third-party keyboard theme follows it. Jianlai offers themes and backgrounds. Keep one theme fixed and, only if desired and the original settings can be restored, compare light and dark system appearances while observing the host page, keyboard background and key labels separately.

## Record the current state

On your iPhone inspect the current light or dark appearance, whether automatic switching is enabled and its visible schedule. Record the original state; use the wording shown on your system. Apple describes selecting Dark Mode in Settings or Control Center, with paths that vary by version. If a user depends on an automatic schedule but cannot establish how to restore it, or prefers not to change it, observe the current state only and skip the comparison.

Confirm Jianlai is installed and select a familiar, readable theme, recording the name actually shown by the app. If no name is identifiable, describe it without inventing one. Record system and app versions, device and host. Do not change the background photo, font, key colors or permissions. Prepare a non-private ordinary note and table; do not test in a password field or important form.

## Establish a baseline with one theme

In comfortable, stable indoor lighting, open the note and show Jianlai, confirming that it is Jianlai rather than the system keyboard. Enter a short practice sentence and verify it appears in the body. Record system appearance, theme name, host background, keyboard background, and whether key letters and candidate area are legible. Mark uncertainty instead of writing expected colors as observations.

Keep device orientation, theme and host fixed. Brightness, automatic brightness, Night Shift and ambient lighting can affect subjective appearance. This exercise does not require disabling necessary features or measuring contrast, but visible conditions should be recorded so a brightness change is not mistaken for a theme change. If the theme contains a private photo, describe color and readability without sharing a screenshot.

## Optionally switch system appearance

If the original setting and restoration method are known, and the user wants to compare, use the current system control to select the other appearance: dark if the original was light, or light if it was dark. Automatic schedules and temporary switching vary by version; do not assume a schedule is permanently disabled. Restore the original settings afterwards. Skip the round if changing it would interfere with visual needs.

Return to the same note and field and show Jianlai. Confirm keyboard identity and theme, then separately inspect the host background, keyboard background, letters, candidate text and visible boundaries. Record “darker”, “lighter”, “no visible change” or “uncertain” per element rather than assigning one result to the entire screen. Enter the same short sentence and verify body text; appearance alone does not establish input success.

## Distinguish observations

If the host changed but the Jianlai theme did not visibly change, record both facts. A fixed theme may display by its own design, so one observation does not establish a fault. If both change, color alone does not establish Jianlai’s internal setting mechanism. If the system keyboard replaced Jianlai, record the identity change rather than attributing its colors to Jianlai.

If text is hard to read in one state, inspect the recorded theme, brightness, ambient light and whether Jianlai is active. Change only a condition the user is comfortable changing and record a separate round. Do not keep increasing brightness through discomfort or reset all themes. Return to a comfortable original state and mark unclear observations incomplete; visual comfort differs by person.

## Restore system and keyboard

In system settings restore the original light or dark choice and any automatic state and schedule. If restoration is unclear or the original record is incomplete, stop and check rather than guessing at unrelated display settings. Return to the note and confirm Jianlai’s theme, orientation and normal input. Restore the original theme by your known method if needed. Reopen the practice note to verify its text remains.

Compile the table: original settings, whether the alternate round was done, actual changes by interface layer, readability, input result and restoration. Automatic switching, brightness and theme are separate conditions; record any uncontrolled ones. A single subjective impression is not a contrast measurement or evidence that all versions support automatic themes.

## Troubleshoot and state limits

If Jianlai is absent after switching, check the field, active input method and system list. If the theme differs from expectation, compare the recorded theme and current appearance before considering any app removal or background deletion. Address one condition at a time and retain non-sensitive steps. System documentation establishes light and dark settings, not that Jianlai follows them on every screen. This exercise does not claim a device test.

For another theme, host or system version, create a fresh table and record observations again rather than copying old results. Ensure the user can comfortably continue using the device before deciding whether to keep the practice note.
