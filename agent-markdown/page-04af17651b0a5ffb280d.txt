Trace a file from provider selection through importing and actual playback.

## 1. Fix one track before a batch

Start with one prepared, authorised small sample. Preserve its original and record its full filename, provider and opening sound. Selecting one track first separates importing from playback. If you previously tried the same content, mark that history: duplicate-content handling could otherwise look like a missed selection. This exercise does not require an empty library. Preserve existing music and recognise the sample by its recorded identity rather than deleting older tracks to make the list look cleaner.

## 2. Open the provider through the visible import flow

Find the file-import entry in your installed version. Official screenshots show “从文件导入”; identify the actual wording and placement you see. In the picker, recognise the current provider and folder before choosing a similarly named recent item. Wait for iCloud Drive or other provider content to become readable. This is a system file-selection flow: a webpage share URL is not a selected local audio file, and account passwords do not belong in track names. If the content is unavailable, return to its source rather than creating empty placeholder files repeatedly.

## 3. Verify the selection before confirming

Select the file that matches your preparation record, then check extension, size and selected count. Multiselect is a published capability, but use one file in this first control instead of also testing a large batch. A picker preview can help identify content; it does not prove that 调调 imported it. Confirm once and wait for visible progress, a result or an error before continuing. Record the time and actual feedback externally. Without a visible progress indication, record only the available state instead of inventing a background percentage or submitting the same selection repeatedly.

## 4. Identify the imported library item

Return to the visible local-music or library entry and find the imported track. The list may prioritise metadata title over filename, so compare both rather than guessing from alphabetical position. Check artist, album and available artwork against the sample. Missing fields remain unprovided; do not invent an artist to complete the record. If duplicate content is reported, look for an existing copy of that audio. Skipping a duplicate is not automatically corruption, and importing an identical file ten times is unnecessary to manufacture additional entries.

## 5. Verify the selected track by listening

Open the item and listen for its opening anchor. Check that pause and resume affect this track and that the displayed title matches its sound. Use a comfortable volume rather than maximum volume for acceptance. If duration differs from the original, retain the discrepancy and check whether you chose another edition before editing anything. Artwork proves only that some displayable information exists. Listen at a later recognisable point too; any action you did not perform remains pending instead of being filled in from the expected result.

## 6. Leave playback and reopen the same item

Leave the player, return to the library and select the same track again. Verify the item’s identity and replay its opening. This tests whether the imported item can be found again; it does not require a promised exact resume position. Record any resume difference separately from file existence. Do not delete the app or clear system storage to simulate reopening, because that changes the storage conditions. Preserve the track and its original so that offline readiness or metadata checks can follow.

## 7. Locate failure within three stages

If the picker does not show the file, first check provider availability and permission state. If selection is followed by import failure, check format, size, protection and readability. If an item exists but will not play, record its identity and audio state. These are three different failure positions, with different next actions. When comparing a small known-working file, change only the sample rather than resetting the whole library. Retain exact errors, provenance and version; do not upload a private collection or attribute a local-file problem to an untested server.

## 8. Save the complete import result

Save the preselection identity, selected count, actual import feedback, library information, two audible anchors and reopening result. The record should let you find both the original and imported item, and show which actions were actually performed; an artwork screenshot alone is insufficient. If the original is protected or unreadable, preserve that failed result and choose a suitable sample rather than mark the task passed. Later batches can reuse this method, but still require count and result checks. One successful single-track import is not universal file compatibility.
