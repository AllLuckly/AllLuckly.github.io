After entering tasks with Jianlai, supported versions of Apple Notes can turn paragraphs into an interactive checklist. Notes manages the checked state and the keyboard enters the words; this differs from typing square brackets in plain text. Create three fictional tasks and inspect text, actual check state and copying separately, without assuming every destination preserves an interactive state.

## Prepare safe practice

Create a blank test note in Notes on iPhone. Confirm Jianlai is enabled in system keyboards and select an input language actually visible. Use fictional tasks rather than passwords, real addresses or an unbacked-up work list. Record system version, Notes account and Jianlai layout. If you use several accounts, inspect where the new note actually lives and work only within this test. The guide does not require enabling synchronization or treat a note on one device as proof it reached another. If the note is not editable, use a new editable note. Apple says the first line becomes the title, so enter “Practice checklist”, add a newline and check that the title was committed.

## Enter three separate tasks

Use Jianlai to enter “Sort paper”, “Check cup” and “Put away pen”, each in its own actual paragraph. Observe candidates and confirm the final words so autocorrection does not silently change an item. Visual wrapping caused by screen width is not a new item; if the tasks remain in one paragraph, insert actual newlines using the available host controls. Check each verb and object, and do not count unconfirmed candidates as committed text. If entering character by character, confirm each candidate before continuing; if committing a whole word, inspect the final text too. Record the entry method to help separate input differences from checklist formatting.

## Keep an unformatted baseline

Use the system's available selection and copy controls to copy the three lines to another test note without private information. Confirm all three appear in the same order. A screenshot is only visual reference and is not an editable text copy. Do not overwrite personal notes. If copying cannot be completed, mark the baseline step not tested and stop the later comparison. This copy checks characters; it does not establish that all accounts synchronize between devices.

## Create a checklist in Notes

Return to the first test note, select the three lines using the current interface, and use the checklist control actually visible. Apple describes checklists as a Notes formatting feature. If that control is absent in the current system or account, record incomplete; typing “\[ \]” is not the creation of an interactive control. Confirm each line corresponds to an identifiable checklist item and that an incorrect selection did not remove text.

## Check the middle item only

Use the actual check control on “Check cup” and observe its state change, then verify the first and last tasks remain in their prior states. Do not type a letter or checkmark into the text as a substitute for the interface state. If tapping gives no feedback, verify you touched the checklist control rather than body text or candidates; if still uncertain, record unknown. A system setting may reorder checklist items, so record the observed order rather than assuming every device behaves alike.

## Check content and state

Compare each current item with the baseline: all three task texts should remain identifiable, and the middle item's state is whatever the current interface actually shows. If order changes, identify tasks by their text rather than screen row number; do not automatically treat the second row as the original middle task. Before acting again, record each item's words, state and current location. Mark unconfirmed state unknown instead of guessing from colour or a promotional screenshot.

## Edit one task's body

Place the insertion point at the end of “Put away pen” and use Jianlai to add “ case”, producing “Put away pen case”. Confirm the edit landed in the intended item and neither other task nor its checked state changed unintentionally. If cursor position is unclear, cancel and place it again. If the item rather than its text is selected, observe the host's feedback before typing. Keyboard theme, candidates and the host's checklist control are different layers; keycap appearance alone cannot establish body state.

## Copy to another note and observe

Select the content containing the three items and use the system's offered copy and paste controls to paste into a new test note. Separately check the copied text, item order and checked state, allowing any to be unknown or different. Do not assume every host or paste method preserves interactivity. Treat this as an observation copy and retain the source checklist. If the paste is incomplete, inspect the selection and host feedback rather than repeatedly overwriting the baseline.

## Restore and record

If you want the original state back, find “Check cup” in the source checklist and use its actual control to uncheck it, then compare text and starting record. You may instead retain the test result. Record outcomes and reasons for any unexecuted steps for text entry, checklist creation, checking, body editing and copying. Afterwards keep or delete the test notes as you choose and restore the previous keyboard selection. This guide uses Apple's public information and does not claim a step-by-step test on a particular device.
