## 一、为三条素材先做声音身份

在应用外制作三份自己拥有的短录音，开头分别读曲一、曲二、曲十，长度可设为十二、十四、十六秒，保留未编辑母本。每条都要真正包含各自的声音，不用同一录音改三个文件名冒充三个曲目。为工作副本采用下方文件名，把声音标签和实际导出时长另列，不能根据文件名倒推内容已经正确。没有完成录制和导出就将准备栏留空，本文没有提供可下载的成品音频。原有音乐库和日常播放安排保留，本轮只用三份明确的练习材料，避免让真正的专辑因为测试被重命名或重新编码。

```
take-1.mp3
take-2.mp3
take-10.mp3
```

## 二、在外部记录标题专辑与曲号

用自己已有且能读回标签的工具，为三份副本写同一练习专辑与歌手，标题分别写叶片甲、叶片乙、叶片丙，曲号依次为一、二、十。先保存，再用工具重新读取，确认这些是音频里的资料，而非只改了文件夹。若用MP3的ID3标签，曲号字段可对应TRCK；来源规范说明字段语义，不等于调调一定显示每种字段。不要把总曲数写成三后又将第十曲当越界故障，本课仅选三个编号位置，没有构造完整十曲专辑。查不到曲号就记未核实，不能让一份看起来整齐的外部表替代真实标签。

## 三、先分字面排列与数字次序

按下方文件名做一张纸面控制，逐字符排列可以得到一、十、二所对应的顺序，而按外部曲号的数值则是一、二、十。两种排序使用的比较依据不同，不能看到十排在二前面便说音频损坏。这个控制只说明这些给定字符串与数字的关系，不预测文件提供方或调调会选哪种规则，也不把标题甲乙丙偷换为曲号。为三份资料各画一条对应线，让文件名、标题、曲号和开头声音保持同一行。之后任何视图只显示其中部分字段时，仍能回到这张身份表核对。

```
lexical: take-1.mp3, take-10.mp3, take-2.mp3
numeric track positions: 1, 2, 10
```

## 四、导入后记录真实资料库位置

在调调按已公开的文件导入方式选择三份工作副本，逐条记录反馈，再以声音和可见标题核库中条目。实际顺序是什么就照实写，当前没有曲号或专辑排序入口时不寻找虚构按钮；列表没有显示曲号也不能反推标签已被删掉。若某条被跳过，先核是否误选已有音频或收到重复提示，不通过删旧收藏强行凑三个新条目。三份实际内容不同能帮助区分，但公开资料没有披露重复比对算法，因此仍要保存每次反馈。只有确实可识别的条目才进入后面的队列安排，未确认项留在待核栏。

## 五、用当前可用队列排出一二十

将曲一设为当前曲，再按当前版本实际提供的队列能力安排曲二、曲十。目标是声音顺序一、二、十，并不是要求资料库先改变排序。确认普通顺序播放条件，避免循环或随机让结果失去比较依据；若不能恢复自己的原设置，先记清当前状态，不继续操作未知菜单。队列中标题若显示叶片文字，就沿外部身份表认对应录音，不按所在行号猜曲号。当前界面不提供某种拖动或插队动作时，使用实际存在的加入方式，必要时重新建立这份练习安排，但不宣称有未观察到的自动按号排队功能。

## 六、自然经过两次切换听回身份

从曲一开头顺播，依次听到三条录音的开头标签，并在每次自然切换后核当前标题。不要连续点下一首再把手动跳转说成自然按序播放；需要跳转确认身份时另开一栏。曲二应出现在曲十之前，这个关系由声音和当前条目共同证明，而不是外部表里已经排好就算通过。实际导出时长与初始计划不同可以照实修正身份表，不据几秒差异宣称应用把编号读错。遇到无声先核暂停、出口与原件，不直接用曲号排序解释所有故障。未守候到的切换只记待听，不补填两次都通过。

## 七、用一十二错排定位哪层改变

若听回成一、十、二，先比实际队列是否照文件名顺手加入，再查标题与声音是否配错，最后回外部工具核曲号。不要同时改标签、改文件名和换播放模式，否则无法指出哪一步造成变化。资料库字面排列、队列次序和文件里的曲号是三层证据，其中一层正确不能替另两层验收。如果只缺曲十，优先查是否真正导入成功，不把编号十视为系统不支持两位数的证明。保留第一轮结果，再只修实际错误的安排并听回需要的边界；外部原件不为迎合当前列表而永久改名，原专辑资料始终保存。

## 八、恢复日常安排并交付四列账

退出练习队列前保存三份文件名、标题、曲号和声音身份，另附资料库实际顺序与一二十队列的真实结果。按当前可见方式恢复日常播放，未能恢复的末态明确写出，不为了清场删除收藏。重新打开练习条目能再次认出身份才填写重开通过，尚未做就留空。最终应能说明文件名排序为何可能不同于数字曲序，以及调调实际队列凭哪段声音验收；不把这三个样本扩大成全部专辑标签或所有排序规则的认证。下次换标签工具、文件格式或应用版本，重新核字段映射与可用入口，不照搬本轮显示位置。
