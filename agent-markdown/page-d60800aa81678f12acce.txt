A WebDAV service can expose different scopes to different accounts. 调调 1.0.4’s public release notes mention improved WebDAV connection and browsing, but permissions are determined by the service administrator. Compare two already authorized accounts without broadening access or resetting the service.

## Prepare two authorized accesses

Use a service you manage or are permitted to access, with two existing accounts A and B authorized for this comparison. Ask the administrator which folders each may read. Do not obtain another person’s password or create a higher-privilege account. With only one account or unclear authorization, observe that side and leave the other incomplete. Prepare an owned recording both may read and, only with explicit permission, one directory for comparison. Preserve original files.

## Write a credential-free expectation card

Use “Account A,” “Account B” and “Service A” as local aliases. Do not publish real accounts, passwords, tokens or complete private addresses. Record the administrator-confirmed read scopes and common recording’s name and audible cue. Roles may have different user roots: seeing one fewer level does not automatically mean a missing file. The card describes authorization, not guaranteed behavior. Preserve mismatches and ask the administrator.

## Establish the service and original file

Using the service’s own management interface or an authorized client, confirm the recording exists, each account’s readable scope and that both entries address the same service. Record sanitized directory aliases, duration and a recognizable opening. A server file list does not establish successful playback in 调调. If permission or directory identity cannot be confirmed, do not guess paths or repeatedly attempt login. This exercise reads authorized content; it does not require changing ACLs, files, indexes or server configuration.

## Observe Account A

Open the configured WebDAV source in 调调 and confirm it is Account A. If the interface does not show the identity, use your own secure connection record; stop if still uncertain. Record visible starting folder, common recording’s presence, title and duration. Play briefly using an available entry and identify the sound. Keep list visibility, user selection and audible result separate. Preserve sanitized failure feedback without changing permissions.

## Observe Account B independently

Use a method the app actually provides and you are authorized to use to open or switch to Account B’s source. Do not assume the app saves two identical server addresses simultaneously or provides a particular switch button. If connections cannot be safely distinguished, leave B pending instead of overwriting or deleting existing accounts. Once B is identified, record starting folder, common track and actual playback as for A. Describe what the screen and authorized scope actually show.

## Compare the common item and scope differences

Use two columns for account alias, visible root, listing of the common track, audible result and administrator-confirmed scope. If a folder appears for A but not B, first determine whether B is authorized. A difference alone does not prove a service or app defect. If both show a same-title track, use duration and sound cue to identify it; a matching title does not prove identical underlying bytes. Equal list counts do not prove equal members, so check the small set needed for this exercise.

## Handle errors and protect accounts

If the administrator says the accounts see different virtual roots, use the common recording as a reference and record A’s “Music/Test” and B’s actual visible path separately on a private card; do not require identical display paths. Only administrator confirmation can establish that the paths address the same server resource. Matching title and duration are clues. If mapping cannot be verified, mark it pending while retaining the two separate list and sound observations. Use sanitized folder aliases when sharing.

If both connect but only one shows the common item, first check current account, user root, hierarchy and index. If one cannot connect, inspect authorization, network and service feedback separately. Keep errors credential-free for the administrator. Do not broaden permissions, weaken security or expose the service publicly. Change one condition at a time, distinguishing account switching from folder selection. If cached identity cannot be established, leave the result pending.

## Restore and deliver

Stop playback and restore the usual source, output, volume and queue without deleting server material or other users’ connections. Keep the sanitized expectation card, both observations, identity reasoning and pending checks. Different read scopes are not a permission-configuration recommendation and do not guarantee a particular 调调 account-switching interface. No private-server or physical-device test is claimed.
