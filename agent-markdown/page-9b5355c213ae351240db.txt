When two owned recordings share a title, recognizing that title does not establish that the intended version was selected. Build an identifiable baseline and record the request, system feedback, actual track and sound separately.

## Prepare two owned recordings with the same title

Prepare two authorized recordings, such as your own voice saying “mountain version” and “lakeside version.” Give both the display title “Weekend Notes,” but use distinct artist or album fields. Record file names, durations and audible opening markers. Keep original files separately, import each into 调调 and confirm both play manually. If duplicate-content detection skips a file, check whether the actual content differs; do not damage files or delete originals to force a second entry. If only one imports, leave the same-title comparison pending.

## Establish system and public capability boundaries

The public release notes for 调调 1.0.4 describe Siri playback of music from a personal library. Whether Siri is enabled, language, account and available actions vary by device; use only settings actually visible. This exercise does not require private contacts, music-account passwords or weaker security settings. Choose a suitable environment so other people’s voices and private content do not enter the request. Do not assume a fixed Siri phrase, an in-app voice button or support for arbitrary natural language.

## Identify both versions manually

Find both same-title records in the app. Compare title, artist, album and duration, then play several seconds at low volume to confirm each opening marker. Record the visible details and sound. A shared title does not establish file identity. Stop playback and retain the existing queue and output state. If metadata is absent, use only actually distinguishable duration or audio; stop if identity is still uncertain.

## Define the target of one spoken request

Choose one target and write down its title and distinguishing artist or album. Use the Siri activation method available on the device to request playback in 调调, adjusting wording according to actual system feedback while making one clear request at a time. Do not read or operate a phone or vehicle display while driving. If the system asks a follow-up or does not recognize the app, record what it actually says rather than inventing an option.

## Separate recognition, choice and audible result

Record the words actually recognized in Siri’s visual or spoken feedback. Note whether it asks about same-title items and whether the user makes a manual selection. Return to 调调 and inspect title, artist, album, playback position and state; listen briefly and compare the marker with the target. A recognized title without playback, the other version playing, and success after a manual choice are different results. If a success message appears but sound cannot be identified, leave sound pending.

## Compare requests without changing several conditions

Repeat for the other recording on the same device, in the same quiet environment and through the same output, retaining both requests and responses. A separate title-only trial can show whether the system asks, chooses or cannot decide. Lack of a follow-up is not automatically an error: previous choices or other rules may apply. Do not infer the system’s internal algorithm. If recognition language or library content changes, record a new condition rather than comparing directly.

## Troubleshoot at the correct layer

First play a known recording through the same speaker or headphones to distinguish output from track selection. Check the current media destination and volume and restore the trial state. Record when the output changes: a playback indicator alone cannot establish which device produced the sound. If multiple devices can respond to Siri, identify which accepted the request. Nearby audio alone does not prove 调调 opened on the intended phone.

If Siri does not respond, inspect ordinary Siri operation and network. If a request is recognized but 调调 does not open, check installed version, app availability and actual system feedback. If the app opens to the wrong track, inspect metadata, recording identity and user choice. A local file does not prove that Siri requests work offline. Change one condition at a time, retain failed observations and do not reinstall or clear the library as a first step. If the result remains unclear, keep it as pending.

## Restore and deliver the record

Restore the prior queue, volume and output. Decide whether to keep the test recordings; before deleting any test item, confirm the original files are safe. Deliver both identity cards, the nonprivate request or summary, system feedback, manual actions, audible marker and pending items. One success does not establish support across all languages, devices or acoustic conditions. No physical Siri test is claimed.
