## Separate text from styling

An EPUB chapter can reference a CSS stylesheet in the package. Its text, style rules and the reader’s own display settings are separate layers. Unexpected spacing or color does not by itself mean text is missing. This exercise compares paths, resources and observed display in a self-made authorized sample; it does not assume Book Isle has a CSS editor.

## Create two identifiable paragraphs

In an EPUB editor create a test book with a distinctive title and two short paragraphs; apply an easy-to-recognize spacing or weight rule to the second. Use text and fonts you authored or are authorized to use. Save a separate copy to protect an everyday book, and record the title and opening sentence of each paragraph for later content checks.

## Check stylesheet and manifest

Inspect the chapter and CSS files in the editor and record their relative locations within the EPUB. The package manifest should list the resources; check the stylesheet exists with the appropriate media type and that the chapter refers to that copy, not a same-named older file. A file existing on your computer does not prove it is included in the EPUB.

## Resolve relative references

A relative stylesheet reference resolves from the chapter that references it, not from the desktop or an arbitrary folder. Use the editor’s link inspection and check directory names, case and extension. If the chapter and stylesheet occupy different directories, use the path matching the actual structure; do not add parent-directory segments without checking.

## Inspect dependencies of the stylesheet

If the stylesheet references packaged images or permitted fonts, inspect those references and manifest entries separately; an existing CSS file does not prove its dependencies are present. To avoid font licensing and availability distractions, use paragraph spacing for the first sample. Record network conditions if external resources are involved; an online file is not automatically part of an offline package.

## Validate and save the test copy

Run the editor’s EPUB check or EPUBCheck, resolve reported missing resources, links and package problems, and save a separate test copy. Keep the time, report and filename together and retain the initial original. Passing validation means the checks found no corresponding issue; it does not guarantee every reader applies every style rule.

## Import and identify the book

Use Book Isle’s currently available file import method and verify the title and both opening sentences to avoid opening an old version. Record device, app version and whether reader text or theme settings are in use. Follow the interface actually shown; if import fails, preserve the error instead of first deleting the library or replacing the original.

## Compare text and spacing

In the same reading environment check both paragraphs sentence by sentence, then observe whether the second paragraph’s style is distinguishable. Even if they look identical, record text completeness and visual appearance separately; a reader may apply user preferences or limit some styles. Do not claim Book Isle supports a particular CSS rule without an actual observation.

## Recheck offline

To assess whether packaged resources are sufficient, first ensure import is complete, temporarily disconnect the device using its actual controls, reopen the sample in Book Isle and compare the paragraphs. Avoid disrupting other work and restore the previous network afterward; if disconnection is impractical, mark it unperformed. Visible offline text does not prove that every font, image and link was checked.

## Change one condition at a time

For an unexpected style, correct one path or missing resource in an authorized working copy, validate it, save under a distinct filename and repeat the same observation. Avoid changing theme, font size, text and path together, or the cause will be unclear. If the client retains an older entry, verify which copy is open. Keep before-and-after reports for rollback.

## Keep reviewable evidence

Record sample name, relative chapter and style paths, validation, text completeness, visual differences, network state and unfinished steps. Use a new row for another device instead of generalizing one observation to every version. Share only owned short text and reports without private details. Retain the original and backup. This guide does not claim a device or private-library test.

## Separate missing files from overrides

Formatting can still differ when the path exists and validation passes: for example, a reader’s preferences may override some book styles, or the chosen rule may not be rendered in the current environment. Keep the same test copy and font size and record the active theme. If actual settings are available, change and restore them one at a time. Do not invent a Book Isle control or edit the original on this basis.

## Cross-check with another tool

Viewing the same copy’s text and resource report in another trusted EPUB tool can help distinguish packaging errors from different rendering. First check that the filename and contents match, then record each tool’s display conditions. One reader showing a style does not prove another must apply it identically. If reports disagree, retain the exact messages and tool versions for further checks.
