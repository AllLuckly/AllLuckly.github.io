An answer page may be marked as auxiliary content. Check the publication and access path, then observe actual reading in Book Isle.

## Locate auxiliary content

In an EPUB 3.3 spine, the itemref linear attribute distinguishes primary reading order from auxiliary content. Omission defaults to yes; no marks supplementary content accessible out of sequence. The specification allows different reader presentations, including at the spine position or later. Whether sequential reading encounters an answer page alone cannot establish a Book Isle defect.

## Choose an authorized sample

Select an EPUB you created or are authorized to inspect, preferably with an exercise, answers and a link from question to answer. Preserve the original. Record title, edition, question number and a self-made answer marker without sharing long copyrighted passages. Without a suitable sample, read the workflow and mark it not performed rather than editing a real book.

## Record question and answer identity

On paper record exercise chapter, question number, a short question marker, answer chapter and answer marker, confirming the same edition. For similar questions verify chapter and number to avoid mistaking a neighboring answer. Answer correctness and solution reasoning are separate checks; this exercise concerns location, accessibility and return path.

## Optionally inspect the spine

An authorized owner copies the EPUB and uses a familiar tool to inspect its package manifest and spine read-only. Find the answer document item and match its itemref idref. Record whether linear is no, yes or absent. The standard defaults an omitted value to yes; if mapping or file cannot be confirmed, mark unknown. Do not edit the original, process protected files without authorization or infer order from a filename.

## Read sequentially in Book Isle

Import the authorized copy and use the current Book Isle controls to turn pages from the exercise. Record whether the answer appears, the next chapter is reached or another result occurs. If the book was read previously, record existing progress rather than clearing it. Font and scrolling can change screen positions and are not the sole evidence of answer existence. Mark unperformed if the chapter cannot be found.

## Open the answer from the question

Return to the test question and activate an answer link if actually present. Record destination title, question number and answer marker. If the link or usable action is absent, mark unavailable or not observed. First check whether the answer is accessible through contents or sequential reading; one missing entry point does not establish missing content. Inspect the destination rather than recording only the click.

## Check the return path

If the answer has a return link or the app offers a visible back action, use the actual interface and check that it returns near the original question. Otherwise use contents, search or a previously recorded personal location. Do not assume every reader has a popup or back button. Record question number and position before and after; returning to a different exercise in the same chapter is not the same result.

## Separate specification hints and app behavior

For linear=no, showing the answer during page turns or deferring it can both be among the specification’s permitted presentations. Focus on actual access and correct targets. The specification requires a way to access nonlinear content, but a link in the file does not guarantee the current client supports it. Record file link, Book Isle link and sequential reading separately.

## Investigate a missing answer

Check edition, question number, contents and the known answer marker first. An authorized person can inspect whether the target exists in a copy. If another reliable reader opens it and Book Isle does not, record both versions and actual steps without inferring a cause from one comparison. Do not delete the book or notes or repackage the sole original. Invisibility does not establish that the author provided no answer.

## Inspect links and sequence separately

Use four rows for question location, link target, answer content and return position, marking whether each came from file inspection or Book Isle observation. If a file link exists but cannot be activated in the current interface, keep both facts instead of saying no link exists. If only contents navigation reaches the answer, record that route and target rather than calling it an in-text link.

During sequential reading record the first heading after the exercise so a short answer page is not overlooked. If you pass it, return to the same question number and recheck. Different readers may present the same sample in different orders; record versions and observations. The auxiliary-content hint does not guarantee a particular popup, note style or skipping behavior.

If the sample answer is an image, a failed text search does not prove it is missing; use visible markers and content. Mark illegible images pending rather than guessing. Confirm any new bookmark or note belongs to the test copy so existing notes are not overwritten. The owner may retain the copy for a later check of the same question.

## Record results and preserve the original

Include sample identity, linear inspection, whether sequential reading encountered the answer, link target, return path and unperformed steps. Restore original reading settings and preserve the book and notes. The owner decides whether to retain the isolated copy. Based on public specifications, this guide claims no device test or guaranteed Book Isle popup behavior.
