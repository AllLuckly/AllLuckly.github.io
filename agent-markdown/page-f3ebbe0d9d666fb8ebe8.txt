Use two red and one blue hypothetical balls to check conditional branch probabilities, path products and their sum.

## Define the experiment

Suppose a bag contains two red balls and one blue ball. Draw two balls in sequence without replacement: the first is not returned. Use R for red and B for blue, and assume each remaining ball is equally likely on each draw. This is a practice model, not a real experiment. OpenStax demonstrates multiplying branch probabilities along a path; this exercise calculates a smaller example independently.

## List the first branches

The first draw is red with probability 2/3 and blue with probability 1/3; these add to 1. Record both on scratch paper and leave space for remaining counts. Do not keep denominator 3 for the second draw before considering what was removed. The root represents the state before drawing, not a red or blue ball.

## Calculate branches after red

If the first draw is R, one red and one blue remain, two in total. Therefore the second draw is R with probability 1/2 and B with probability 1/2. Write both beside the R node and verify they sum to 1. These fractions are conditional on the first red draw, not independent draws from the original bag.

## Calculate branches after blue

If the first draw is B, the only blue ball has been removed and two red balls remain. The second draw is therefore R with probability 2/2=1 and B with probability 0/2=0. You may keep the zero-probability B branch explicitly labeled 0 to show BB is impossible; do not depict it as having positive probability. The conditional probabilities still sum to 1.

## Set up a canvas and tree layout

Create a landscape VectorPaint document, for example 1800 by 1100 pixels, and save an editable original. Place the root on the left, the first R and B nodes above and below in the middle, and leave space on the right for four second-draw outcomes. Use available object or layer controls to separate lines, nodes, fractions and outcomes. Actual labels may vary. Make the two draw stages visually distinct.

## Draw the first branches

Connect the root to first-draw R and B and label the lines R 2/3 and B 1/3. Both begin at the same root; position text near its line without covering the junction. Arrows, if used, point left to right. Add a first-draw heading so probabilities are not mistaken for counts. Color may help, but letters and fractions must remain clear in monochrome.

## Draw second-draw branches

From the first R node connect to RR and RB, labeling each branch 1/2. From the first B node connect to BR and BB, labeling them 1 and 0. Mark BB impossible or clearly explain its zero probability. Keep all four endpoints tied to their parent paths without ambiguous crossing lines. Increase canvas space or row spacing rather than deleting conditional information.

## Calculate the four path probabilities

Multiply along each path: RR is (2/3)×(1/2)=1/3, RB is (2/3)×(1/2)=1/3, BR is (1/3)×1=1/3, and BB is (1/3)×0=0. Put each result beside its endpoint. Do not add branch probabilities to obtain a path probability. Each second factor depends on the first result, so BR’s second factor is not 1/2.

## Check completeness and order

The four ordered outcomes are mutually exclusive and cover this model, with total probability 1/3+1/3+1/3+0=1. Trace RB and BR separately: the former is red then blue, the latter blue then red. Their values happen to match but their orders differ. For the event “one red and one blue,” add RB and BR to obtain 2/3; do not include RR.

## Explain the zero branch and assumptions

State beside the diagram “equally likely, without replacement; initially two red and one blue,” and explain that BB is zero because no blue ball remains after the first blue draw. Zero probability differs from missing data; it is impossible in this model. With replacement, the second probabilities must be recalculated, not merely relabeled. Provide a text alternative listing branches and results without dependence on color.

## Troubleshoot, save and export

If every second branch says 2/3 or 1/3, check whether the first ball was removed. If outcomes do not sum to 1, check branch sums at each node and path multiplication separately. Save the editable original and use an available export control to create a separate SVG or PNG. Reopen it to check fractions, the zero branch and endpoint results for clipping; return to the original to verify editable nodes and labels. Mark unperformed device steps as pending.

## Verify with distinguishable balls

Temporarily label the two red balls R1 and R2 and the blue one B in scratch work. The six equally likely ordered pairs are R1R2, R1B, R2R1, R2B, BR1 and BR2. Two correspond to RR, two to RB, two to BR and none to BB, giving 2/6, 2/6, 2/6 and 0, consistent with the tree. This verification depends on the model’s equally-likely assumption. Labels do not change color or require real balls to be numbered. Include the list in a note or text alternative if readers need to check each outcome.

## Check path and conditional labels

Point from the root through first-draw R to second-draw B and read 2/3 and 1/2, confirming that moved lines do not accidentally connect to BR. Likewise trace root through B to second-draw R and read 1/3 and 1. Hide fractions temporarily: outcome names should remain traceable along lines. Restore text without covering the fork. If the zero-probability BB branch is gray, retain explicit “0” and “impossible” labels because gray might also mean missing information. State whether replacement occurs in the title or note so readers do not apply a different experiment’s conditional probabilities.
