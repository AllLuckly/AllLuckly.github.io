Inspect members of a self-made comic archive and compare pages actually shown in ManYue before attributing an extra page to the reader.

## Prepare three original sample pages

Make three images you own or may use, visibly marked 01, 02 and 03. Preserve the originals and existing comics; do not use a private photo library or restricted comic for a public example. Confirm that each image opens individually in a system image viewer. Record filenames, pixel dimensions and the number visible in each image, treating filename and picture content as separate facts.

## Distinguish images from metadata entries

A CBZ is commonly a ZIP archive named for comic use. Its members can include images as well as system-created hidden entries or directories. An entry’s presence does not necessarily make it a reader page: packaging tools, platforms and readers may differ. Classify image files, directories and nonimage files by name before using a member count as a readable page count.

## Make a clean control archive

In a working-copy folder on a computer, place only the three checked images with filenames ordered 01, 02 and 03, then create a ZIP copy using the system’s compression feature. Inspect the list before and after compression. Renaming the extension to .cbz changes the name, not the images, and does not guarantee compatibility with every compression method. Keep the original ZIP and image copies and do not overwrite an existing library.

## Inspect actual archive members

Use a familiar archive tool to view member names and paths without first extracting unknown files. Record the three actual image entries, directories and any \_\_MACOSX directory or dot-prefixed entries. If the tool hides entries, mark them unconfirmed rather than inventing them. Python’s official zipfile documentation explains archive member lists, but the list is not ManYue’s page sequence and does not by itself prove an entry is displayed.

## Import the copy and record each page

Import the self-made CBZ working copy using an entry actually visible in the installed ManYue version, preserving source identity and import feedback. Open and inspect each page in the available reading mode. Record 01, 02, 03 and any additional visible page. If the app uses one sample as a cover, identify which one rather than automatically counting a fourth page. A loading state, placeholder or list item is not automatically a page. Inspect full images and mark any unviewed portion unchecked.

## Compare evidence for extra or missing pages

Compare the reading sequence with the archive member list item by item. An extra page may reflect an additional image, duplicate cover, directory contents or display behavior. First inspect corresponding image content in a system viewer; a hidden filename alone does not establish the cause. For a missing page, check the original image, its actual presence in the archive and whether the imported item is the inspected copy. Change one condition at a time and preserve the first result.

## Make a one-variable control in a copy

If an extra member is actually identified, make a new working copy and remove only that positively identified nonimage entry or duplicate image, then repackage and import it separately. Never modify the only original archive. Stop if the entry’s role is unknown rather than deleting a directory wholesale. Compare member lists and visible sequences before and after; record whether entry count, displayed pages or both changed. One result applies only to the two samples.

## Check file identity and import feedback

When the two covers look alike, distinguish the packages in your own notes with different filenames and creation times, and check which was opened using actual app information. If no path or size is visible, mark identity unconfirmed; shelf order is not proof. If the app recognizes a repeat import as the same item, record its real feedback and consult the existing import guide rather than deleting other comics to force a new entry.

## Make a repeatable member-versus-page table

Give each self-made image a row with its relative archive path, number drawn in the picture, external viewing result and position observed in ManYue. Add a separate row for any nonimage member actually shown; write “not observed” if none is visible instead of filling in a presumed system entry. For example, if the archive lists 01.png, 02.png and 03.png but reading appears to show 01, 02, 03, 03, first inspect whether an additional image actually duplicates the content, then check the imported file’s identity. A list without duplicate images does not immediately prove the app duplicated a page: exclude a different opened copy and actual dual-page or continuous-layout behavior. Hold layout fixed and record one page-turn action and both screens. If a nonimage entry cannot be identified safely, stop, retain the original archive and do not remove an entire system directory.

## Check the original after import

After reading, return to the original file location and confirm it was not replaced. If cleaning up a comparison archive, handle only your own working copy and first identify which file is retained. Shelf thumbnail order does not establish that a disk file changed.

## Preserve originals and deliver an observation table

Record device and app versions, redacted names of the two copies, member classifications, page sequences, the one changed variable and unknowns. If feedback is needed, share only the self-made sample and necessary redacted steps, not another person’s comic. Confirm the original images and comics remain; remove only your own test copies if desired. The exercise follows public format and app information and claims no actual hidden-entry or reader compatibility test.
