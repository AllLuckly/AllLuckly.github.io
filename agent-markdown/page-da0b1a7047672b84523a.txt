Thicker edges may reflect outlines rather than a larger or stretched font. Prepare three ASS controls with wide horizontal, wide vertical and reset uniform borders, then observe iCouldPlay. Values request style widths; font shape/rendering still affect visible edges. Keep source conditions separate from observations.

## Fix a fourteen-second source and comparable glyphs

Retain an owned clip at least fourteen seconds long and prior subtitles. Use one requested font, size 36 and identical wording, varying borders only. Font naming does not prove installation; record known font/fallback status. Fix640×360 script dimensions and the scaled-border declaration, plus orientation/fitting, rather than change video proportions simultaneously.

## Save all three events and the scaling declaration

Save complete UTF-8 border-axis.ass with ScaledBorderAndShadow: yes. Events occupy1–4,5–8 and9–12 seconds, retaining position, text and zero shadow. Border requests are(8,2),(2,8), then(8,2) followed by uniform bord3. Preserve ordering and the same style name: a different style would obscure the later override. This is authored input, not a device-test log.

## Read the axes and their target first

xbord and ybord request horizontal/vertical outline widths, not text scale. Record(8,2) versus(2,8); equal sums do not imply equal presentation. Keep shadow zero so directional shadow is not mistaken for an outline. Record white fill and black outline independently. Colour changes alone do not verify width; inspect values, glyphs and actual presentation.

## Use the later uniform border as an override control

The third event’s later bord3 sets both axes to 3; it neither adds3 nor merely edits the base style. Record final(3,3). Placing bord before the directional overrides would instead leave final(8,2). Order is evidence. Save any reordered experiment separately rather than mix both sequences in the original and lose the selected condition.

## Use an idealised contour box on paper

For an invented100×40 fill bounding box, an ideal two-sided expansion gives116×44 for(8,2),104×56 for(2,8), and106×46 for(3,3). This checks adding each margin twice, not a real font measurement. Corners, antialiasing and scaling affect visible bounds. Paper box areas do not establish additional phone pixels. Also compare uniform bord0 with xbord0 alone:on paper, the former resets both axes while the latter leaves the unchanged vertical width. With shadow already zero, do not mistake shadow for a remaining outline. Fill remains a separate component.

## Observe the edge controls sequentially

Load through the available subtitle path and play beyond twelve seconds. Record unchanged fill wording, distinguishable outline differences and gaps. Pausing may help, but different screenshot scales defeat width comparison. Separate readable text from absent border effects. An editor preview is not an iCouldPlay observation; retain output dimensions and pending items.

## Separate clipping, boldness and border diagnosis

For one missing edge, inspect display clipping or clip tags before blaming ybord. Thicker fill calls for Bold/b overrides; a larger whole line calls for font size or scale. Change these classes separately and retain source/copy/failure. Return to the three-event baseline. One font cannot certify every outline style or renderer.
