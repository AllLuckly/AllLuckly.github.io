> "Many developers automatically reach for Alamofire whenever they need network requests. I am not saying it is a bad library, but it is a third-party dependency: you must learn its usage and add its code. Why not try NSURLSession? NSURLConnection used to be inconvenient, which made third-party libraries attractive, but NSURLSession is now easy to use. Why not spend the time you would use learning Alamofire on NSURLSession instead? A third-party library may offer helpful enhancements for json processing, but sometimes all we need are get, put, post, and delete requests, plus downloading, uploading, and resumable downloads. NSURLSession is already sufficient for those."

The simplest call

```

if let url = NSURL(string: "https://httpbin.org/get") {

    NSURLSession.sharedSession().dataTaskWithURL(url){ data, response, error in

    //...

}.resume()

}

```

Take a url, use the default session to process it, and receive the desired data.

> Calling resume(): NSURLSession does not start by default. You must explicitly call resume() before the request begins.

NSURLSession does not perform requests itself; it creates tasks to make network requests. One NSURLSession can create several tasks, which share cache and cookie data. Let us look at the task types it can create.

- NSURLSessionDataTask: This is the DataTask created in our first example. It mainly retrieves simple server data, such as JSON. In fact, it is not limited to fetching data; it can modify or create data too, using put or post.
- NSURLSessionDownloadTask: This task primarily downloads files. It provides more support for large-file requests, including download progress and resuming interrupted downloads.
- NSURLSessionUploadTask: The counterpart to a download task, this task mainly sends file data to a server.

Is NSURLSession available only through NSURLSession.sharedSession()? No. NSURLSession is powerful and highly configurable.

### NSURLSessionConfiguration

We can also create an NSURLSession through NSURLSessionConfiguration. There are three configuration types to choose from.

- defaultSessionConfiguration — Uses shared cache and cookie information. This is the default configuration behavior of NSURLSessionConfiguration.
- ephemeralSessionConfiguration — Does not store cache, cookie, or authentication information. It is effectively a private session; in a browser product, it corresponds to private browsing mode.
- backgroundSessionConfiguration — This configuration allows network operations to continue when your application moves to the background.

Let us try creating a task.

```
//定义一个默认的session
lazy var defaultSession = NSURLSession(configuration: NSURLSessionConfiguration.defaultSessionConfiguration())
//获取data的task
var dataTask:NSURLSessionDataTask?

/**
任务
*/
func doTask(){
    guard let url = NSURL(string: "http://your.url") else { return }
    dataTask = defaultSession.dataTaskWithURL(url)
    dataTask?.resume()
}
```

This example is much like the simple one above, except that we create our own session and separate the steps.

Let us see how to configure it.

```
func doTask2(){
    let configuration = NSURLSessionConfiguration.defaultSessionConfiguration()
    configuration.timeoutIntervalForRequest = 10 //超时时间
    configuration.requestCachePolicy = .UseProtocolCachePolicy //缓存策略
    configuration.HTTPAdditionalHeaders = ["Content-Type":"application/json"] //header 配置

    //更多配置详见官方文档...

    let defaultSession2 = NSURLSession(configuration:configuration)
    //获取data的task
    var dataTask:NSURLSessionDataTask?

    guard let url = NSURL(string: "http://your.url") else { return }
    let request = NSMutableURLRequest(URL: url)
    request.HTTPMethod = "get" //post put delete 等
    //还有很多可以设置  更多设置 详细 command + 点击 NSMutableURLRequest  就可以看到了

    dataTask = defaultSession2.dataTaskWithRequest(request, completionHandler: { (data, response, error) -> Void in

    //操作数据

    })

    dataTask?.resume() //开启任务
}
```

We can configure the configuration and request objects to achieve the behavior we want.

Request operations are task-based. A task can also be cancelled.

What about downloading?

```

lazy var downloadsSession:NSURLSession = {
    let configuration = NSURLSessionConfiguration.defaultSessionConfiguration()

    //delegateQueue设置为nil session会自己创建一个串行的队列
    return NSURLSession(configuration: configuration, delegate: self, delegateQueue: nil)
}()
下载创建session和普通的请求差不多，我们这里添加了代理就可以拿到下载进度

func doDownload(){
    guard let url = NSURL(string: "http://your.download.url") else { return }
    let downloadTask = downloadsSession.downloadTaskWithURL(url)
    downloadTask.resume()
}

```

You can also cancel during a download by calling task.cancel() directly.

If you need to pause it,

```
task.cancelByProducingResumeData { data in
    if data != nil {
        //将data保存本地 或者 内存 
    }
}
```

Resume the download.

```
//resumeData 为上次保存的data
task = downloadsSession.downloadTaskWithResumeData(resumeData)

task.resume()
```
