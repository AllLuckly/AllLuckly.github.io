Use an original comic page to record controls actually focused by the system reader separately from image content.

## Prepare a recoverable test environment

Use a one-page comic you made with “Sample 01” at the center and distinct corner shapes, keeping the original image. Record device, system and ManYue versions. Open the sample in the usual mode first and identify the visible way back to the shelf. VoiceOver gestures differ from ordinary touch; if unfamiliar, read Apple’s guide, arrange help from someone familiar with it and ensure you know how to exit.

## Record a baseline in the ordinary display

Before changing system accessibility settings, verify sample page, chapter, display layout and one actual visible non-destructive reader control. Record the visual label and location. Do not test by deleting, purchasing or editing a library. If no clear control is visible, record not observed. Words drawn into the sample are image pixels and are not automatically selectable system text.

## Practice gestures in the system practice area first

With the user’s consent to changing accessibility settings, follow Apple’s guidance to enable VoiceOver and open its practice area. If the user does not regularly use VoiceOver, try a single-finger movement, tap and double tap in the system practice area. It explains gestures without requiring unknown actions in a comic library. Record the actual way in and out; consult the system instructions if the device version differs. Open the original sample only after the user can return to the Home Screen independently or with identified assistance. If exit is unreliable or the user does not want to change accessibility settings, end the test with the ordinary-mode baseline. Do not require biometric setup, password removal or privacy changes for a demonstration.

## Enter the app and inspect focus

After practice, enter the app and confirm that the enabled VoiceOver sound and gestures still work. Move focus through items and record actual names spoken for the shelf, reader or menu controls. Record missing labels, inaccessible focus and uncertain order. One readable control does not establish that the whole app meets an accessibility standard, and focus order can differ across versions.

## Activate one clearly identified control

Only when VoiceOver clearly names a non-destructive control and its effect is understood, activate it once using the current system interaction and record spoken name, action and page change. Stop if focus is unclear or an action could alter the library; do not repeatedly activate it. Observe opening a reader menu, closing it and turning a page separately. If a control is unavailable, do not substitute a visual tap and call the VoiceOver check successful.

## Distinguish control labels from text inside the comic image

Within what the system actually permits, move focus to the comic image and record what is spoken, whether it is identified only as an image and whether another description appears. Do not assume all dialogue is recognized or treat image recognition as author-provided alternative text. Keep system speech, visually visible “Sample 01” and your own written notes separate. Mark image content not observed when it is not spoken.

## Verify return and original position

Use an actually identifiable return action to reach the shelf, then reopen the same sample and check title, page marker and position. If another person had to help, record that assistance rather than claiming independent completion. If the return control cannot receive focus, retain the result and use a known safe exit; do not delete the app or reset system settings to resolve one focus issue.

## Keep an observation record for each focus target

Use a table for focus sequence, actual spoken name, identifiable visual location, feedback after one activation and assistance needed. If the system says only “button,” record that word and context without inventing a label. If a label is spoken but activation has no effect, record two separate outcomes. Text in the comic image may serve as a manual comparison, but do not require the user to read the image or assume recognition is accurate. Use only the original sample for any screenshot and exclude notifications and private shelf content. If speech is muted or routed to another device, record the output condition before deciding that nothing was spoken.

## Check the restoration path before finishing

Before restoring, confirm the user can still operate the system using a known method. If assistance from someone familiar with VoiceOver is needed, let the user decide and record it. Reopen the sample afterward only to confirm the original book and bookmark remain; do not count the ordinary-touch result as a VoiceOver result.

Use the safe sample to identify focus first. Stop public recording if system speech contains private information; the record contains practice material only.

If the sample remains on the shelf but its source image is absent from the expected location, check source and backup separately; a thumbnail does not prove the original file is present.

## Restore settings and retain observations

Restore VoiceOver, volume and other user settings according to the initial record, and confirm the original sample and reading records remain. Record device and versions, actual spoken focus labels, each action, whether image content was spoken and steps requiring help. Mark unperformed behavior untested and use only the self-made page in feedback. This exercise follows Apple system guidance and claims no physical-device VoiceOver test or accessibility certification for ManYue.
