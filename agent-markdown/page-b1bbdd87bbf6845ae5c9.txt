Unreadable buttons in a screen recording are not necessarily recoverable through enlargement or a different engine. Create a text sample without private information and compare pre-recording content, the actual movie and iCouldPlay display. Locate where legibility changes without assuming OCR, super-resolution or automatic sharpening. Use a short clip and retain the original and repeatable conditions instead of processing a whole course for one menu.

## Create three non-private text samples

In an existing editor or presentation tool, write three original lines at large, medium and small sizes, each with words, digits and confusable punctuation. Labels suffice without claiming uniform system-font dimensions across devices. Leave margins and ensure the captured region contains no notifications, accounts or private chats. Keep the original text separately as a reference rather than guessing afterward. No downloaded sample or third-party low-resolution course is needed, so the actual source wording remains known.

## Fix the captured area and retain the movie

Record static text for a short interval, then move a pointer or scroll a little to compare static and moving legibility. Use existing recording tools, checking all lines and edges afterward without changing security permissions. Record device, orientation, reported file dimensions and any compression/sharing; mark unavailable information unknown. Preserve the initial movie and name compressed or trimmed versions separately. If text is already unreadable before capture, enlarge it there rather than asking playback to restore information never clearly recorded.

## Read the actual movie before import

Play the actual movie through a known working route. Without the reference note, transcribe each line and mark uncertainty, then compare confusable letters, digits and punctuation. Knowing the answer is not proof of seeing it clearly. Record orientation and viewing size; this is a sample comparison, not a precise vision test. If the movie already contains blurred blocks, retain that observation. A newly recorded larger-text sample may improve the task but does not repair the old file.

## Keep the same copy and framing in iCouldPlay

Import the verified copy, confirming name, duration and opening action, and begin with the complete frame visible. Do not substitute a messaging-app compression or crop to one line. Read large, medium and small lines in the same order, recording agreement and viewing-size differences. Resolve orientation/framing differences first. Let controls or captions clear normally when they cover text rather than interpreting an interface overlay as missing source letters.

## Change viewing size alone

Where supported, rotate to a suitable landscape view or compare an offered larger display while holding other conditions fixed. If zoom/crop exists, record hidden edges; do not assume arbitrary zoom otherwise. Enlargement may reveal existing shapes but cannot invent source detail, so judge through transcription without consulting answers first. Return to the whole frame and verify labels, column headings and values together rather than interpreting one cropped enlarged number.

## Separate static and scrolling text

Compare the same letters in static and moving sections: do they become difficult only during motion and recover when it stops? Record the segment and viewing conditions without diagnosing a codec, rate or network fault from appearance alone. Use the same local file first. Test an alternative playback route separately with size held fixed. A clear still does not establish equally clear motion, and blurred motion does not erase usable information in the static segment.

## Trace the source and copy chain

If the original route is clear but iCouldPlay is not, check compressed-copy identity, displayed frame size and overlays first. If both are unclear, revisit source text and export history rather than applying sharpening and guessing. A single failing line calls for its original size, contrast and punctuation, not a verdict on every line. Share only a permitted short sample, unclear words and conditions with the recorder. Change one factor and preserve versions to distinguish larger source text from better viewing framing.

## Keep a legibility result table

For each line, record reference text, original-route transcription, iCouldPlay whole-frame reading and larger-view reading, retaining uncertainty. Screenshots locate issues but do not replace playback observations. Restore orientation, speed and captions and keep the original and useful copies. Sample small text in the next course before choosing phone or larger display, without deriving a universal minimum font size from three lines. Success identifies readable and insufficient information rather than filling uncertain characters into a deceptively complete sentence.
