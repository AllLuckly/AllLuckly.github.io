Use a self-made transparent PNG to compare image resources, background contrast and observed display.

## Define the observation

A transparent PNG reveals the background behind transparent areas; lines close to that background’s color can be hard to see without the image being missing. EPUB supports PNG resources. This exercise observes a self-made image in Book Isle without assuming a particular theme control or that the reader applies a book’s background style.

## Prepare authorized images

Draw a simple arrow with dark lines and a transparent background and save the PNG original; also save a comparison image with an opaque light background. Use distinct captions to identify the two images and no private photographs or restricted materials. Keep the unchanged original and test-book backup to verify provenance.

## Inspect image pixels externally

Use a trusted image editor to verify that the transparent version has transparent areas, the comparison has an opaque background, and both have the same arrow shape and pixel dimensions. The editor’s checkerboard indicates transparency; it is not an actual image background. Record filenames, dimensions and line color rather than relying only on thumbnails.

## Add both images to an EPUB

Add both images and captions to an editable EPUB you own or may modify. Ensure the editor packages them and lists them in the manifest, and supply accurate alternative text rather than merely “image”. Check that chapter image paths resolve to the respective files. Save a separate test book; without an authorized editable sample, mark later steps unperformed.

## Validate resources and text

Run EPUBCheck or the editor’s checks for images, paths and chapter completeness, retaining the report. Manually compare captions, alternative text and arrow direction to avoid swapped image files. A passing report does not prove adequate visual contrast on every background or establish that accessibility was tested.

## Open the sample in Book Isle

Use Book Isle’s actual file import entry to add the sample, confirming title and both captions so an old copy is not mistaken for it. Record device, app version, current background and reading settings. If import fails, retain the message and check file access rather than clearing the shelf or overwriting an original. Open the chapter and record what is visible.

## Compare transparent and control images

Under the same page and reading conditions inspect both arrows, captions and backgrounds, noting which parts are hard to distinguish. If only the transparent image’s dark lines blend into the background, treat that as a contrast clue rather than immediately claiming an app defect. If both are blank, inspect resource paths, sample identity and files.

## Conditionally compare backgrounds

Only if the current interface actually offers a reading background or theme setting, record the original, change one condition, observe the same image again and restore the prior value. If unavailable or inconvenient, mark it unperformed. Keep device and sample constant; an EPUB background rule and the app’s actual background are not necessarily identical.

## Diagnose and improve safely

If the transparent image in an authorized sample is hard to see on a background, increase line contrast or use an opaque background appropriate to the content in a working copy, then recheck caption and alternative text. Change one item, save separately, repackage and validate. Do not alter another person’s original without permission or claim all themes were tested.

## Keep reviewable results

Record image filenames, transparency, captions, reading background, visible outlines, app version and unperformed steps; use a new row for another device or background. Share only self-made images and records without private paths. Identify the test book before deciding whether to remove it and retain originals and backups. No device or accessibility test is claimed.

## Check the actual transparent region

Temporarily change the viewing background or inspect the alpha channel in an image editor to confirm the arrow and transparent regions are where expected. Do not mistake white pixels for transparency or infer that a page background will be light because the checkerboard is light. Preserve the pre-inspection original in case an export accidentally changes transparency.

## Avoid confounding the sample

Use the same arrow strokes and dimensions in both control images, changing only background transparency; line width, scaling and compression differences can also affect legibility. Label captions “transparent sample” and “opaque control” and check that content references are not swapped. If book layout scales them differently, record the comparison as imperfect.

## Observation is not accessibility certification

A visually clear graphic does not ensure every reader can understand it or prove a particular contrast standard is met. Check meaningful alternative text and captions and separately observe assistive technology where available; without the necessary device or tool, mark that unperformed. Do not claim the sample is accessibility certified on the basis of this guide. Record the image creation date and tool version to help identify each copy.

## Recheck both file references

Open the transparent image and opaque control separately in the editor and compare the two chapter references and captions, ensuring they do not accidentally point to the same resource. If you replace one image, save a separate copy and rerun resource checks, then compare under the same reading background. Keep unobserved image content unknown.
