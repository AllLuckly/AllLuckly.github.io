## Prepare a familiar configuration and exit method

This exercise is for someone already familiar with iPhone Voice Control who can return to everyday operation. Read [Apple’s Voice Control guide](<https://support.apple.com/en-ca/guide/iphone/-iph2c21a3c88/ios>), confirm the system’s available language, how to pause or stop listening, and how to obtain help. If not configured, the language is unsupported or the exit is unclear, learn with Apple’s guide or a person familiar with the device first. Do not change the configuration just for this exercise without that preparation.

Voice Control interprets spoken commands and can also recognize dictation in a text area. Use your familiar pause method when you do not want speech processed. Choose a quiet place without exposing private conversation; do not enter or speak passwords, verification codes or real contacts. Do not alter another person’s accessibility setup without consent, and follow device management rules.

## Distinguish item labels from entered text

With the existing Voice Control configuration, use the system’s actually supported command to show item names or numbers and inspect the visible keyboard. Apple says the system can label recognizable screen items, but items, language and commands vary with interface and OS. Note which keys or areas have recognizable labels and which are not individually identified. Never invent an assigned number or assume one device’s number is fixed on another.

A label establishes only that the system offered a visible identifier, not that the key can be activated or that text was committed. If a grid rather than item numbers appears, record the actual mode; do not call grid coordinates proprietary keyboard numbers. If no usable label appears, preserve that observation without disabling accessibility.

## Select one item and observe feedback

If the user is familiar with Voice Control and the target has a clear usable name or number, issue one selection command supported by the current language and command list. Try only the first letter of the sample; do not guess device numbers. Pause, then record system selection feedback, any key or candidate change, and whether one `o` actually appears in the body. A command entered as text, no response and a different character are distinct outcomes.

Do not repeat commands rapidly to conceal the first result. If a command is dictated as text, use the user’s familiar method to inspect mode and focus. Apple distinguishes command and dictation modes; follow the commands available in the device language. If the mode cannot be safely identified, stop with the practice line and do not edit important text.

## Check the second character and host body

If the first item can be reliably selected, use the actual displayed identifier to try `k`, then check for lowercase `ok` in the body. If only the entire keyboard area is selectable, no individual character appears or the target cannot be activated, record the reachability boundary and stop. Do not assume all third-party keyboards expose the same accessibility elements. The user may finish with their normal method, but label it as such, not as a Voice Control success.

A candidate is not necessarily committed text. If the input method creates candidates, inspect actual confirmation. If the host changes case or substitutes text, retain the initial feedback and compare on another line rather than attributing host behavior to speech recognition. Do not mark unperformed actions as passed.
