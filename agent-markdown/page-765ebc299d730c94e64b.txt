Change one visible space-bar style condition, then check its actual function in document text.

## 1. Preserve the theme and original space bar

Record the active theme, language, layout and visible space-bar colour/style while preserving the original configuration. Prepare an ordinary note with short words and two practice markers around a space so its insertion point is clear. Avoid passwords and real verification codes. Establish the original action before changing appearance. This task compares the individual space bar, not a simultaneous full-theme replacement. An existing input failure needs diagnosis first; a colour change does not repair it.

## 2. Identify individual styling rather than the whole theme

The public description supports individual space-bar style, colour and personalisation. Find a control clearly scoped to that key, inspect its current parameters and how to restore them, and distinguish it from the whole background colour. Follow the installed names and available elements. Personalisation does not promise arbitrary images, text or animations. If an option is absent, choose a real available style condition instead of using an unpublished plug-in and attributing the result to a built-in feature.

## 3. Change one visible appearance condition

Choose one identifiable colour or style and change only that space-bar condition. Retain old and new values, then preview boundaries with adjacent keys, label contrast and background relationship. Avoid obscuring text with decoration. For a colour comparison, leave pattern and font fixed. If the theme limits an individual control, record that scope instead of replacing the whole theme and calling it one-key change. New decoration proves appearance only; space insertion still requires an ordinary-note check.

## 4. Check identity and labels after application

Apply through the actual flow, redisplay Jianlai in the note and compare the key with the selected condition. Record whether adjacent areas remained unchanged. Confirm extension identity when names or colours look similar. The space bar’s label, artwork and activation behaviour are separate layers. A decorative change does not turn it into a macro or add a quick-send function. Do not invent an action configuration or assume a decorative word will be sent automatically.

## 5. Check insertion without an active candidate

First finish composition so no candidate awaits confirmation. Press the space bar once between two recognisable markers and inspect the document gap. Use the host’s existing cursor or editing tools if needed; no external text upload is necessary. Record the action and actual insertion. Visible blank width alone does not prove one space because proportional spacing also affects appearance. If the language behaves differently, retain state and output rather than assume another layout’s convention. Unverified character counts remain unknown.

## 6. Record candidate-state behaviour separately

Compose a short phrase that needs candidate selection and separately observe the space bar before committing it. Inspect the final text. A language or layout may use this action to confirm composition, which is different from the no-candidate insertion test. Do not prescribe one rule across every input scheme or press repeatedly to force a gap. Record composition state, one action and output separately. This distinguishes recognisability from activation and avoids mislabelling candidate confirmation as failure. Finish composition before handling any desired spacing according to observed behaviour.

## 7. Separate appearance failure from functional differences

For unchanged colour, inspect application, theme scope and active extension. For changed appearance without a space, inspect composition state and insertion point. For one affected host, compare an ordinary note. These small checks do not require toggling every permission, deleting vocabulary or resetting the device. Restore one condition per round while preserving feedback. Size, touch area and typing speed were not precisely measured here; a styled screenshot cannot establish improvements in those properties.

## 8. Restore and deliver the one-key comparison

Restore the original space bar or deliberately retain the new style. Confirm the overall theme remains identifiable and save both no-candidate and candidate-state text rounds. Deliver old/new settings, actual display, composition state and output, leaving unavailable elements unclaimed. Explain why individual styling does not add an action and why input states need separate checks. Repeat necessary comparisons after language, layout or theme changes. One spacing exercise does not physically certify every shortcut, host and device.
