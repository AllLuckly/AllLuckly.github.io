A forward-moving playback position does not prove events appear in their original recording order. A reverse-ordered export still plays forward as a file. Use your own documented paper-card example to map visible actions to original events. No iCouldPlay reverse button is required, and an odd movement in an unfamiliar film is not proof of deception or reverse processing.

## Establish an original event sequence you can verify

Film your own empty tabletop: place card A, then card B, then remove both, pausing briefly between actions. Record the event order and filename during production. Use readable cards without private information and preserve the original. An existing trusted editor may optionally create a separately named reversed export with its processing recorded. Without one, document the original and reason on paper, leaving reversed playback untested. External editing is optional preparation, not an iCouldPlay capability.

## Identify the production history of each file

List original and processed copy as separate objects, noting names, durations and documented processing. The [Adobe reverse-video explanation](<https://helpx.adobe.com/ee/premiere/mobile/playback-and-timing/reverse-and-forward-video.html>) illustrates that processing can reverse presentation order. It supplies the concept here, not a requirement to buy, install or use that software. Similar images and duration do not establish byte identity. For unfamiliar media, observe clues without treating “reverse” in a filename as proof of the entire production history.

## Play the original and record visible actions

Play the original normally and record four visible states: empty table, A placed, A and B present, and both removed. Use content landmarks rather than timestamps alone. File position is not the filming day’s wall-clock time. If a hand obscures an action, note the before and after states and the obstruction instead of importing unseen finger movements from production notes. Complete the viewing record independently, then compare it with filming notes and confirm card identity.

## Play the processed copy normally as a file

If you prepared a reversed copy, play it at normal speed from its beginning in iCouldPlay. File position still increases while card states appear in reversed order. Dragging the timeline backward is not evidence of continuous reverse presentation. Keep separate observation rows for both files and check source and caption identity separately. Without a processed copy, mark this step unperformed rather than describing an imagined reverse sequence as successful playback.

## Reverse the state sequence without inventing causation

In a complete reversed export of this sample, the final removal appears near the beginning in reverse, followed by reversed actions involving B and then A. Use the actual continuous images without requiring exact pauses on every frame. A card appearing to move into a hand does not establish attraction or autonomous movement in the original event. Keep file presentation order and original event order in separate columns so “before” does not silently refer to both timelines.

## Do not use sound as the sole reverse indicator

An editor may reverse pictures while preserving audio or add narration, so natural sound does not prove unreversed pictures. Record whether audio is documented original sound, known replacement or uncertain. Without evidence, leave it unresolved. A silent example remains adequate for state comparison; reversed speech is unnecessary. Captions may retain old timings and need independent source checks. A caption saying “A first” cannot override the sequence visibly shown in the current file.

## Distinguish complete reversal, local reversal and looping

Unfamiliar clips can alternate forward and reverse sections or process only one passage. Divide observations at visible changes rather than generalizing one action to the whole file. A back-and-forth loop can repeat a pose at a boundary without representing a second real action. If action boundaries are not visible, conclude that order is uncertain instead of proven reversed. Record any cropping of your sample, because original timestamps cannot directly align a trimmed copy.

## Check file identity and stale resume positions

If the processed item appears original, check its actual file and start position, then replay from the beginning. Do not rename production media or repeatedly delete libraries. Same-named entries may reference one path, and captions may belong to the original. Use existing identity and checksum methods read-only. If evidence still conflicts, preserve production, import and playback records and leave the cause open. Do not claim automatic restoration by the player or treat one resumed section as a whole-file test.

## Finish with two explicitly named orders

Retain original event order, visible order in each file, documented processing, landmarks and uncertain sections. Your own production records can establish which copy was reversed; unfamiliar media supports only evidence-based local observations. Restore normal position and speed without overwriting originals, copies or notes. Backward seeking is not treated as reverse playback. No in-app editing or frame-by-frame physical-device validation is claimed. Success means clear temporal relationships and evidence scope, not a definite explanation for every unusual motion.
