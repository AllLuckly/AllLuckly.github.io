## Identify table relationships

A data value needs its row heading, column heading, unit and table title for context. W3C describes marking header and data cells and expressing their relationships; scope can identify simple row or column directions. Whether EPUB readers and assistive technology communicate these relationships depends on file, device and implementation. This exercise does not assume dedicated table navigation in Book Isle.

## Prepare a small self-made table

Use a self-made or authorized EPUB sample with a two-row, two-column table titled “Daily reading minutes.” Columns are Monday and Tuesday, rows A and B; values are A 10 and 20, B 15 and 25, all in minutes. Preserve the sample; the numbers are fictional. Without a sample, draw it on paper and mark app testing unperformed.

## Establish a visual baseline

Write four complete facts: A Monday 10 minutes, A Tuesday 20, B Monday 15 and B Tuesday 25. Check intersections, title and units against the original table so rows and columns are not swapped. If a narrow screen hides columns, use available scrolling or zooming to inspect the whole table rather than guessing hidden values.

## Optionally inspect the source

An owner authorized and familiar with EPUB can inspect the isolated copy’s XHTML read-only: whether the title uses caption, row and column headings use th, data use td, and direction has appropriate scope. Simple and merged multi-level tables require different associations; this sample has one row and one column heading per value. Mark uninspected structure unknown instead of inferring semantics from appearance.

## Open the same table in Book Isle

Open the same EPUB copy in Book Isle and locate the table using actual contents, search or sequential-reading controls. Record title, visibility of both rows and columns, app and system versions and time. Confirm the edition. If text shrinks, requires horizontal scrolling or is clipped, record the observation without altering the source to force a complete screen.

## Check cells individually

Find A Tuesday 20, then B Monday 15, confirming the row, column and minutes each time. Record the path from headers to data and check for merged cells or horizontal displacement. A correct single number does not establish all table relationships. Leave illegible cells pending.

## Optionally observe assistive output

If device accessibility and personal workflow permit, follow current system instructions to enter the table and observe what is spoken with focus on A Tuesday’s value. Record whether value, row heading, column heading and unit are heard. Without focus or familiarity mark not observed or not performed. Do not disable a user’s usual accessibility tools, and do not infer that heard content necessarily came from scope markup.

## Compare file, screen and speech

Keep source-structure inspection, visual Book Isle display and actual assistive output in separate columns. Header markup establishes that markup exists, not identical speech in every system combination. Visible headers do not prove programmatic relationships either. Record focus, versions and steps for any difference and leave uninspected layers unknown.

## Handle complex tables and alternatives

For a real table with merged cells or multi-level headings, record the title and each header level. W3C also describes id and headers associations for complex relationships; do not apply this simple scope example to every table. If Book Isle cannot show the full table, compare an authorized accessible edition and record version and location. Do not overwrite or delete the EPUB.

## Record how each cell was located

Give each of the four values a row in your ledger with row heading, column heading, value, unit and whether it was fully visible. Find A Monday starting from the table title, then B Tuesday starting from the Tuesday column. Different paths can reveal swapped headings or horizontal-scroll errors. Do not copy the four numbers as a bare string: without headings their people and days are ambiguous.

On a narrow screen, record the visible region and use available scrolling or zooming to inspect the rest. When returning to an earlier column, recheck the current row heading, especially if it is no longer fixed on screen. Mark a persistently obscured cell unobserved and use another authorized viewing method rather than filling a guess.

Use the same cell for assistive output. Verify focus is actually on A Tuesday’s 20 and record the words heard. If a heading is absent from speech, check focus and system settings before declaring missing source markup. Conversely, th in the file does not guarantee the reader and assistive technology associate it correctly. Each requires independent evidence.

For a larger real table record chapter, table number, edition and units. Draw levels for merged or multi-level headings and verify all headings associated with each value. Compare an authorized text description or accessible data file if supplied. The four-cell sample does not establish behavior for every complex table or device.

## Restore and record

Restore original screen orientation and reading settings and confirm the original book, bookmarks and notes are unchanged. Record the four facts, visible range, source inspection, assistive output and unperformed steps. A publisher report can include edition, table number and sanitized steps without uploading private books or account information. This W3C-based guide claims no Book Isle device or assistive-technology test.
