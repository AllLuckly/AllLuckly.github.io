Check fictional digits while separating system autofill from real account verification.

English translation of the [Chinese original](<https://allluckly.cn/guides/jianlai-practice-code-leading-zero-autofill-boundary/>), translated on 2026-11-25. Original publication dates, attribution, code and version notes are retained.

A one-time verification code usually expires, and a system may offer an autofill suggestion in a suitable sign-in interface. Jianlai can enter ordinary text, but system suggestions, code sources and website verification are separate stages; typing digits on a keyboard does not mean verification succeeded. The service determines validity and acceptance; a correct-looking keyboard entry does not establish that the service received, compared or approved it. This exercise uses fictional digits only in local notes to check leading zeroes and operational boundaries, without triggering a real sign-in.

## Set up a non-sensitive exercise

Create a test page in an editable ordinary notes app. Confirm Jianlai is enabled in system keyboards and choose an actually visible number-entry method. Write the fictional practice string “004271”; it is for practice only; do not use it for any account. Do not open a real sign-in page, request an SMS, scan an authenticator QR code or enter an account password. Record Jianlai version, host and layout. If the current input source is uncertain, type a meaningless character in the note to check, then remove it.

## Understand where system suggestions come from

Apple says iPhone may offer one-time verification-code autofill in supported websites and apps; the exact availability depends on system, account and service. Such a system suggestion is not guaranteed by Jianlai. Real codes are sensitive and should not be copied into shared notes, chats or screenshots. Different services can use different methods, including a system-generated code or a service-sent message; whether a suggestion appears depends on the actual system and service. Do not treat a code requested by an unknown caller or message as practice material. This ordinary-note exercise does not simulate a real system suggestion, configure autofill or change account security.

## Enter the practice string manually

On a blank line, use Jianlai to enter zero, zero, four, two, seven and one, yielding “004271”. Observe each character entering the body and compare the completed line with the reference. Leading zeroes are part of the string and must not be omitted because a number might have the same value. Follow the actual key labels if the numeric layout differs. If you mistype, establish cursor location before a local correction. Do not repeatedly guess on an actual sign-in page to test entry.

## Check characters rather than numeric value

Confirm that the line contains exactly six characters: two leading zeroes followed by 4, 2, 7 and 1, with no spaces, newlines or punctuation. If the host supports selection, select the whole string and inspect both selection boundaries. Cancel and reselect if the selection expands unexpectedly. Treat it as identifier text rather than an integer; “4271” is not the target in this exercise. This is a character-check method, not a claim that real services always use six digits.

## Compare a second ordinary text field

Create another ordinary text field or test note that does not connect to a network or submit data. Switch to Jianlai and manually enter the same practice string. Record the visible keyboard, layout, resulting text and any automatic replacement in each host; do not use a real verification suggestion to fill an observation. Some fields may let the system or host restrict third-party keyboards, so behaviour in an ordinary note cannot establish behaviour in every secure field. If Jianlai is unavailable, mark that round not tested.

## Compare manual input and system autofill

Make two columns on paper: manual input actually performed in this exercise, and system autofill described by Apple but not triggered here. The first can record whether the six fictional characters match. Write “not tested” in the second; do not invent a suggestion or successful verification. In real use, first confirm you intentionally visited the service and understand the prompt, then follow the service's and system's security flow. If the source is unfamiliar, do not proceed under this tutorial.

## Correct one entry error

In a practice copy, select the final digit and replace it with another, then restore 1 from the reference. Confirm that the selection contains only one character each time and recheck all six from left to right. If cursor or selection is unclear, cancel and reposition. Keep the first correct line as a baseline so the only record is not edited repeatedly. This exercise does not require disabling device verification, security prompts or autocorrection.

## Record observations and limitations

For each round record entry method, actual text, character count and reasons for unexecuted steps. The record uses only fictional “004271”; do not store real SMS codes, authenticator secrets, accounts, autofill contents or screenshots. If a numeric layout is missing or input differs from expectation, inspect the current keyboard, language and host, then change only one condition at a time. Even an exactly correct practice string does not prove a real service accepts it or that device autofill is enabled.

## Clean up and restore

Keep or delete the test note as you prefer and restore your original keyboard selection. Do not delete or alter actual account verification settings, and there is no need to send the test result to anyone. If a real login issue arises later, consult the service's official help and independently verify prompt provenance; do not disclose a one-time code to another person. This guide uses Apple's public documentation and does not claim a test on a personal device or real account.
