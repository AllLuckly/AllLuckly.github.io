从 Kodi 已有媒体库出发，分开填写服务地址、端口与认证信息，验证目录和一段实际播放。

Kodi 的电视界面能播放，不代表手机已经能够访问它的媒体库。云映 1.1.1 的公开更新加入 Kodi 媒体库，本篇把首次连接拆成服务准备、地址确认、认证和样本播放四个环节。你需要一台自己管理或已获准使用的 Kodi 主机，以及其中已有的一段许可视频；教程不要求安装插件、开放公网端口或建立新服务器。先在受信任的同一局域网练习，完成后留下可回查的连接记录。

## 在 Kodi 端确认服务和样本

先在 Kodi 本机找到目标视频并播放一小段，记下标题、时长和一个内容锚点，确认不是仅有海报但原文件已搬走。再按当前 Kodi 版本进入服务的控制设置，查看是否允许通过 HTTP 远程控制，并记录它实际采用的端口。这个开关和允许其他设备通过其他控制协议访问不是同一件事，不需要为本教程把所有远程控制开关全部打开。参考 [Kodi 官方控制设置](<https://kodi.wiki/view/Settings/Services/Control>)，保留认证，不把服务端口直接暴露到互联网。

## 确认手机访问的是那台主机

让手机与 Kodi 主机处于允许彼此通信的网络，记录主机当前局域网地址或已经配置好的可信主机名。手机上的 localhost 指向手机自己，不能代替电视盒或电脑的地址；访客网络即使名称相近，也可能隔离设备。不要通过反复更换密码解决连错主机的问题。主机从休眠恢复或网络重新分配地址后，先重新确认地址再测试；若已有受信任的浏览器访问方式，可用它核对同一主机的服务是否响应，不把浏览器能打开首页当作媒体全部可播。

## 把地址与端口分开填写

在云映添加媒体服务器的入口选择 Kodi，名称写成能辨认设备的称呼。地址填写实际 HTTP 或 HTTPS 服务基础地址；如果表单另列端口，按 Kodi 的真实端口填写，避免把端口既留在地址里又错误叠加。不要把某一部电影的完整文件路径、浏览器页面的长查询串或下载链接粘进服务器地址。HTTPS 应来自你已经配置并能验证的服务，不能为了让表单看起来安全而把原来只有 HTTP 的地址文字直接改成 HTTPS。保存前逐项对照主机、协议和端口。

## 使用 Kodi 的网页服务认证

用户名和密码对应 Kodi 服务设置，不是 Apple 账号，也不是某个影视网站的登录。若管理员已经启用认证，按其提供的方式填写，不为了省一步而关闭。密码复制时注意首尾空格与输入法替换，显示密码的操作只在无人窥视的环境里短暂进行。不要把完整凭据放进本文建议的连接笔记或问题截图。云映提供测试保存时先执行测试，失败只说明当前组合没有通过，不能据一条笼统提示断言密码必然错误；还要保留地址、网络和服务开关这些可能条件。

## 先核对小范围目录内容

连接成功后先找刚才在 Kodi 本机确认的视频，比较标题、类型与可见时长，不急着浏览整库。如果进入的是剧集层级，继续选到实际一集，而不是把节目总目录当成可播放文件。找不到样本时，回 Kodi 确认它确实已经进入相应媒体库，而不是只存在于文件管理列表里；不要立刻删除云映来源重建。记录看到的是空列表、部分列表还是正确项目，这三种结果对后续排查的意义不同。暂不修改正式影片的已看状态，避免首次练习影响已有观看记录。

## 实际播放才能确认内容路径

打开样本，从开头看听十几秒，再定位到预先记下的内容锚点，确认声音、画面和文件身份。海报加载与媒体播放可能走不同请求，不能把列表成功当作传输成功。若 Kodi 本机能播而手机失败，保留该差异，转入媒体路径核对，不继续用更大的影片反复试。若同一许可样本还有已知可用的本地副本，可以把它作为播放器对照，但不要据此宣称远端文件已完整下载。首次成功的结论只覆盖这台主机、这个来源与这个样本。

## 按失败发生的位置逐项排查

尚未保存就连接失败时，先看主机是否开机、地址端口是否一致和网络是否隔离，再检查认证。已经列出影片却播放失败时，保留列表成功的事实，重点核对 Kodi 能否提供客户端可访问的媒体路径。只缺某一部时先检查其文件和来源类型，不重置整个媒体库。一次只改一个条件，并记录修改前后的结果；若需要管理员协助，提供应用与 Kodi 版本、失败阶段和样本代号即可，不发送密码、完整私有路径或含认证的链接。

## 结束后保留可重做的连接记录

记下服务器显示名称、使用网络、实际端口、样本名称与结果，认证信息仍放在原来可信的凭据管理方式里。若本次只是演练，恢复原先观看位置；只在确定不再需要时移除练习来源，不删除 Kodi 的原媒体。以后换网络或主机地址改变，先重跑地址与样本检查，不把一次成功解释为公网或所有插件内容都兼容。最后分别写清能够连接、能够看到项目、能够播放三项，任何一项未完成都保持待核对，这样下一次继续时不会从含糊的连接成功重新猜测。
