When an audio file contains words, readable text and text that follows playback are separate questions. Compare an untimed text frame and a timed text frame on copies of the same recording; record the file information, import result, and what 调调 actually displays. ID3 defines USLT and SYLT, but the specification does not establish whether 调调 reads or displays either frame. Do not fill in a successful result before observing it.

## Prepare inspectable samples

Use a short MP3 that you recorded yourself and have permission to edit, and keep the untouched original. Choose about thirty seconds of speech, write three original sentences with no private information, and note roughly when each begins. Duration and sentences are examples. Copyright-restricted lyrics, credentials, and private recordings are unsuitable for a shared sample. Listen to the entire original first to establish a clear sound and consistent start, then create two working copies with distinct, recognizable names so they cannot be confused.

## Distinguish the text types

Read the ID3v2.4 definitions of USLT and SYLT. The former stores unsynchronised lyrics or transcription; the latter associates text fragments with timestamps, expressed in MPEG frames or milliseconds. Tag editors use different labels and offer different fields; an ordinary text box is not automatically an SYLT frame. If no tool available to you can identify frame types, record only what is visible and stop preparing that sample. Renaming a file extension does not create a tag.

## Write each copy separately

Open the first copy in a trusted tag editor. Follow its actual instructions to add your three sentences, confirm the frame type is USLT, and save. Proceed with the second copy only if the tool explicitly supports writing SYLT and exposes the time unit and preview. Use the beginning of the file as zero and enter the start of each sentence in order. For example, starts at 2, 12 and 23 seconds become 2000, 12000 and 23000 in milliseconds. If the tool requires another unit, convert according to its instructions. Avoid adding other lyric sources, which would make a displayed source harder to identify.

## Read the files back

Close and reopen each copy in the tag editor. Check the frame type and all three sentences, and check the second copy's times. A save confirmation alone does not establish the file contents. Verify increasing timestamps and make sure seconds have not been entered as milliseconds. Listen to the beginning, middle and end of each file to check for truncation. Record paths, durations and frame types locally without uploading recordings or placing sensitive paths in shared notes. Mark a frame unconfirmed if it cannot be read back reliably, and exclude it from conclusions. A tag editor may rewrite other fields, so compare the title and artist before and after saving and record observed changes. File size alone cannot establish whether sound changed because tags affect size too. Distinct names do not guarantee that the app will identify two separate tracks.

## Import and identify the tracks

Use the file import entry actually visible in 调调 to select the first confirmed copy. Record its displayed title, duration and source. Import the second separately and see whether it appears as an identifiable entry. If the interface reports a duplicate, merger or rejection, record the actual response rather than assuming an overwrite. Consult the related import and duplicate guides if identity is unclear. Do not delete earlier music with the same name, and do not describe the external tag editor's display as the app's display.

## Observe text and timing in separate rounds

Open the first copy and record whether the lyrics area actually visible in your version shows words, which sentences appear, and whether a current line changes as playback advances. Reset playback and observe the same three points on the second copy, recording lyric-area state, playback position and the sentence heard. Allow for manual timing error. If the app has no visible lyrics entry or shows no text, record that observation; it does not by itself prove the tag is damaged. Mark an inaccessible copy as not tested rather than using the other round to fill its result.

## Interpret differences and troubleshoot

Both may show no text, only one may display it, both may display without scrolling, or the interface may behave differently. First read the actual frames back in the external tool and verify which copy 调调 opened. Resolve merged or unidentified entries before interpreting the result. If timing differs by a factor near one thousand, inspect the conversion between seconds and milliseconds. Visible text alone is not proof of synchronized-frame support. The specification defines a format, not the app's compatibility; offline conditions, version and source can affect an observation.

## Keep the result and restore your setup

Prepare four columns: sample identity, frame read back, text status in 调调, and observed timing behaviour. Any column may say unknown or not tested; include the installed version and observation date. Leave the unchanged original in place. If cleaning up test entries, first identify the exact copy and follow the controls actually present. This guide is based on public format and store information; no test on a personal device or private server is claimed.
