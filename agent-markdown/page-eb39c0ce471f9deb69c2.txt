Preserve a master and move only a working copy between folders, then reopen its 调调 item and record source-path and local-playback states separately.

## 1. Create a master and a recoverable working copy

Choose a small authorised audio file, preserve an untouched master separately and make a working copy with filename, size and opening/end cues. Verify that these are real copies rather than two shortcuts to one file. Prepare Before/After ordinary folders within one provider you manage. Move only the exercise file, not app containers, system libraries or a sole original. If the provider disallows moving, stop that step instead of substitute deletion/redownload and call it equivalent.

## 2. Record the original path and empty destination

Place the working copy in Before and ensure After has no conflicting name, preventing ambiguous overwrite choices. Record provider, both paths, master location and date privately. Re-find the master before proceeding; artwork in a file list does not establish complete content. Keep provider, format and tags unchanged so location is the intended variable. Ensure the provider can actually deliver the working file instead of using a cloud placeholder as the exercise asset.

## 3. Establish local playback before moving anything

Import the working copy explicitly from Before, then verify local title, duration and opening/later cues after feedback. If content already exists, verify that item and state that an existing import is used rather than delete music to force an addition. Obtain the baseline while the source is still at its old path; do not fill it retrospectively. A server namesake cannot substitute for the local item. Published local-storage behavior guides the task without revealing an internal path or filename.

## 4. Move once through the file provider

Use the actual Files/provider Move operation to transfer the working copy from Before to After, without copying, renaming or editing audio. Apple documents available file actions; identify the current system/provider menu rather than assume every option exists. Inspect both locations afterward. If both still contain the file, investigate whether it was copied and retain that fact instead of immediately delete a side to force a move result. Preserve the master and keep network/app configuration unchanged. The table can record Before-present/After-absent, then Before-absent/After-present, with restoration verified anew. Inspect explicit paths: absence from a Recent list does not prove absence from the old folder. Check filtering and location first.

## 5. Reopen the same local item

Leave the current player and reopen the same item from local music, verifying identity/cues. Continued pre-move audio alone is insufficient, and importing again from After changes the object under examination. If it works, record that this imported item reopened after the working copy ceased to appear at the old path. This is current-path evidence, not a guarantee across providers or storage-cleanup conditions. A visible title with silence has separate visibility/failure results rather than a blanket storage pass.

## 6. Separate the new external path from app results

Inspect After for filename, readability and size. A normal move is intended to preserve content, but do not claim equal hashes without checking bytes. External opening and app-item opening need separate results: one does not prove the app depends on that path, and the other does not prove another master backup was created. Provider synchronization across devices is outside this same-provider path test. If the operation actually copied across providers, record the additional process rather than retain a single-location-change claim. If the app plays but the working file cannot be found in After, investigate the move instead of passing the external-path column from sound alone. Each evidence chain can fail independently. A separate master makes recovery possible but does not fill missing move evidence.

## 7. For failure restore the original path first

If reopening fails, preserve error/path and move the exercise copy back with its name unchanged, then check the same item. This tests restoration without guaranteeing a fix. Continued failure needs file/identity/output checks. Do not reinstall, clear the library or overwrite the master, which destroys the baseline. Stop on a name conflict and inspect possible prior copying or another file rather than overwrite blindly. Keep restoration times/results separate instead of rewriting an intermediate failure after later success.

## 8. Deliver three states with the master preserved

Optionally return the exercise file to Before, inspect After and verify the master still exists. Deliver original/moved/restored states with working-file location, item visibility and actual listening; mark an unperformed restoration pending. Explain move versus copy, why reopening adds evidence and why this does not disclose internal storage. Preserve master, working copy and records. Changed providers/devices need appropriate new checking without deleting important files to enlarge the test.
