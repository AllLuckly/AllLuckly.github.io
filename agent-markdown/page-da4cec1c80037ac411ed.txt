Preserve originals and a three-track manifest, then check source availability and one imported track on your own target device without assuming automatic library migration.

## 1. Define the target and preservation conditions

Choose another owned/authorised target device and check OS, installable version and actual space. Today’s published minimum is 17.6; a later handoff requires then-current store conditions. Preserve the old device/library rather than begin by uninstalling. Without a target, prepare the package but mark target checking unperformed; moving folders on one device is not completed cross-device migration. Preserve existing target collections rather than clear or overwrite them for a clean-looking result.

## 2. Gather three independently managed originals

Choose three different authorised source files you independently hold, labelled A30/B30/C30, and verify provider readability. Published material does not guarantee bulk original-audio export from the app, so start with preserved sources rather than a guessed hidden folder. Server listening access without a source file does not create a local-original package. Record any compatible server as a separate future setup, managing credentials yourself. Keep filenames, verified artist and audible cues; unknown fields remain unknown.

## 3. Separate audio from the manifest

Create a private handoff folder with three verified originals in an audio subfolder and a separate plain-text manifest. Record relative path, actual size, duration, verified title and opening/later cues in a fixed field order. The example lists three audio files plus one manifest, not four songs for import. Keep paths private and exclude passwords/tokens. This external file is not a promised app playlist parser, queue-restoration format or batch-verification report.

## 4. Check the package at the target provider before importing

Copy the package through an existing method to a location accessible to the target, then locate all audio/manifest entries. Apple Files documentation distinguishes available file actions; follow provider support and keep the old package. A cloud placeholder is not target-readable content. Compare full names/sizes and record byte checks only if actually performed. This verifies source-package availability, not a completed 调调 library merely because another device sees the files. If a transfer tool produces ZIP, it is an external transport container. Extract real audio through a capable file tool before selecting it in 调调. This does not add ZIP to published import formats; renaming it M4A or counting the manifest as a song does not supply three audio files.

## 5. Import one target sample before expanding

On the target import only A30 through the actual file flow, verifying path/identity and waiting for feedback. Find the local item, compare title/duration and both cues, then leave/reopen it. If identical content already exists, record duplicate handling and verify it without deleting collection items. A passing establishes this file’s path on this target; B/C remain unchecked. One sample is not restoration of all three or automatic synchronization of old history, themes and queue.

## 6. Assess sources separately from app-specific records

For each track keep target-readable, imported/existing and actually-heard columns, with app-specific arrangements separately assessed. A source package preserves files/your manifest, not guaranteed lock-screen state, sleep timing, themes or lyrics. Lyrics still depend on target file/service data; old-device display does not prove package inclusion. Any server needs its actual compatible connection/identity check separately. Do not distribute credentials inside an ordinary manifest.

## 7. Diagnose missing source and failed importing separately

For missing files inspect transfer location/provider; for readable sources that fail import inspect format, size, protection and track readability; for silent present items inspect identity/output. These are not one reinstall diagnosis. If one size differs, preserve the old package and recopy that item before handling its target record. Old-device playback does not repair a missing target source. Record target/version/item outcomes after each correction; total app storage cannot prove all originals were safely transferred. For a target filename conflict, inspect identity and use a separate dated handoff folder instead of overwrite another edition. Update the manifest after a genuine relative-path change. Three surviving files with stale nonexistent manifest paths do not yet form a returnable handoff record.

## 8. Finish with the manifest and unfinished checks

Re-find the old package/originals, confirm A’s actual target state and explicitly list unfinished B/C checks. Add real outcomes if later importing them. Return from any manifest row to its source and distinguish visible, importable and playable. Package existence does not establish an unpublished cloud-sync guarantee. Handle the old device only under your own later plan after verified backups/results; this lesson deletes nothing. The deliverable is recoverable preparation and performed spot checks, not automatic restoration certification for every device/setting.
