A series with only one collected book is not necessarily a one-shot. Check the server rule first, then observe the actual Manyue+ display.

## Distinguish a one-book series from a one-shot

Komga defines a One-Shot as a series containing one book, but a continuing series with only one collected book is not necessarily a One-Shot. A library option can recognize a configured directory and create a single-book series for each file. Directory matching has version-specific details. Check only in an isolated library and do not assume the server interface is built into Manyue+.

## Prepare safe samples

Have the administrator prepare two self-made or authorized one-shot copies A and B and a test book C representing an unfinished series in an authorized test library. Give each a distinct self-made first-page marker and record filename and page count. Back up original files and server data; do not change production libraries. Without administrative access or a reliable backup, read the workflow and mark it not performed.

## Confirm directory and configuration

Have the administrator configure a separate test-library directory, for example \_oneshots, and confirm the current Komga version’s One-Shots option and matching scope. Place test copies A and B in that directory and C in a different regular series folder. The documentation says the configured string is checked against the full directory path; a leading slash can limit matching to directory starts. The administrator checks platform and actual library paths before acting, without blindly enabling the rule in production.

## Write the ledger and prediction

Record three rows: A and B in the one-shot directory and C in a regular series folder. Per the documentation, if the option is enabled and the path matches, A and B are expected to form separate single-book series; C follows its regular parent-folder rule. This prediction does not follow solely from file count and does not guarantee the client shows a One-Shot label. Record starting settings and time for restoration.

## Wait for the scan and inspect the web

The administrator scans the test library normally and waits for completion. Identify A, B and C by first-page markers on the web, recording series and book counts, titles and status. If A and B merge or C is misclassified, first inspect the configured directory string, actual relative path, scan completion and identity. Do not start by changing production files or bulk-editing metadata. Compare the client only after the server result is understood.

## Understand metadata differences

Komga documents that One-Shot series title and summary come from the book, status is set to Ended and total count to 1. Series local artwork and series.json are ignored, but book artwork is processed normally. This describes server representation, not an assertion about a real creator’s publication plans. If fields differ from the prediction, first verify actual One-Shot recognition and current configuration rather than declaring a damaged archive.

## Open the same source in Manyue+

Use the same server and account in Manyue+ to find A, B and C in the test library. Record the series or books actually shown, titles and whether first pages open. If the app has no dedicated One-Shot control or label, mark unavailable or not observed. Correct web categorization does not guarantee that the client reproduces every management view. Although C has one test book, assess it using actual series information and test identity.

## Check the path-matching boundary

The documentation says the configured string can match part of a path, so another directory containing it could also be affected. Write two actual test relative paths and have the administrator compare them with the current rules. Do not create similarly named production directories for testing. If the setting uses a leading slash to constrain directory starts, record it exactly; do not treat the example as a general regular expression.

## Separate book and series artwork

If an administrator has an authorized test cover for A, record the picture shown for the book and any series page separately. Ignoring series local artwork for a One-Shot does not mean book artwork is ignored. If no distinguishable test image is available, mark this step not performed. Do not replace production covers or repackage the only original, and do not infer merging from a shared cover alone.

## Check search and recent views separately

Komga also documents different web views: One-Shots do not appear under recently added series but can appear under recently added books, and search treats them as books. After the isolated scan, the administrator can check each location and record time and actual result without expecting the same Manyue+ home layout. Recent views can depend on other content and display scope. If an item is absent, verify its test title and first-page marker before declaring a scan failure.

C in a regular series folder is a single test book, but its count on a screen alone does not make it a one-shot. Record list count, One-Shot flag and actual publication plans separately. Real completion status requires reliable publishing information; it cannot be inferred from a test directory. If the server flag is inaccessible, leave it unknown and continue checking client readability.

## Restore and hand off

The administrator restores test-library options from the initial record and retains or cleans up A, B and C under normal policy, confirming production libraries and backups are unchanged. Record configuration, identities, web recognition, actual Manyue+ display and unperformed steps. Exclude private paths, accounts and tokens before sharing. This guide uses public documentation and claims no private-server connection or physical-device test.
