Check system local-network access, server identity, folder browsing and video playback as separate stages for one existing home media source.

## Prepare an existing source and a local control

Choose a home media server you are authorized to use and one short video you own. Record service type, server name, folder and a recognizable opening scene. Use an existing account and connection; this exercise does not create accounts, expose a server to the internet or change router configuration. Keep a separate local clip that already plays on the device as a player control, while recognizing that it cannot prove a network server is healthy. Preserve the existing network and privacy settings rather than manufacturing a real failure.

## Check the device and server’s actual network first

Check the Wi-Fi name shown on the device and confirm with the server administrator that the server is on the expected network and its service is running. A shared network name alone does not guarantee reachability: guest isolation, VPN routing or a sleeping server can affect the path. An accessible website does not establish that a media protocol is available. If only the administrator can confirm service status, record it as pending rather than guessing addresses or scanning unfamiliar devices.

## Inspect the system’s local-network access state

Apple documents system control of local-network access under Settings, Privacy & Security, Local Network. If iCouldPlay actually appears there, record its current switch and the user’s choice. Only if the user wants to access their own server should they decide whether to allow the actual system prompt. If iCouldPlay is absent from the list, record that absence rather than assuming access was granted or denied. Record the system version, time and actual path, then retry the existing source and observe whether the system shows a prompt. Without a new prompt the result remains unobserved. System access, server credentials and network reachability are three separate pieces of evidence. If sharing a screenshot, obscure personal addresses and account identifiers and omit passwords; a written switch state may suffice. Do not repeatedly reset the whole privacy system. Wording and screens may differ by system version.

## Separate system permission from protocol credentials

Allowing local-network access concerns the app’s local network scope; it does not create an SMB, WebDAV or SFTP account or prove credentials and folder permissions. In iCouldPlay choose the actual source type matching the existing service and use the administrator-provided address and account. Keep plaintext passwords out of notes and screenshots. If system access is allowed but login still fails, retain the actual error and ask the server administrator to check the account; do not broaden shared access as a routine troubleshooting step.

## Record connection, folder and playback separately

Use the installed version’s actual interface to open the configured source. Record connection or login feedback, then open the agreed folder and finally choose the owned clip. Mark source opens, target is visible and video actually starts as verified or pending separately. A directory listing does not prove the file is readable, and playback starting does not establish smooth playback throughout. If the interface provides no particular status, record it as unavailable rather than inferring success. Do not mistake a same-named item from another saved source for this result.

## Use a single documented permission comparison

Only when iCouldPlay is actually listed in the system’s Local Network settings and the user is willing to adjust it, record the original value, change that app’s switch once and retry the same source with the same network, address, account and file. Record the actual feedback before and after, including no change if that is what occurred, then restore the original value. If the switch is absent or the user does not want to change it, skip the comparison and keep the item pending. Do not suggest disabling a firewall or encryption or resetting all network configuration.

## Look for the next evidence at the failing stage

If a list is empty, check the source, folder and account’s visible scope. For a connection failure, inspect system access, network path, server state and protocol address separately. If a visible file does not open, record file identity, format, service authorization and the error text. If the local control also fails, retain that local result instead of attributing everything to the home network. Change one condition at a time and preserve before-and-after records. Leave server configuration that cannot be confirmed to its administrator; the tutorial does not claim to have tested the user’s network.

## Restore original settings and deliver the diagnostic record

Afterward restore any iCouldPlay local-network setting changed for the comparison and verify the existing source remains as the user intends. Deliver a credential-free layered record of device network, system access, service login, folder visibility and video playback, including actual times and who can check pending items. Preserve the source video and backups. One successful action does not establish compatibility across all protocols, servers or future network conditions. This exercise does not require buying a service, changing sharing rules or enabling remote access.
