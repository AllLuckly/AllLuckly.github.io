## Select a color and observe twice

Find the keyboard background color setting and choose a color you can distinguish, recording the original color and transparency first. If a control is labeled opacity, a higher value generally means more opaque color; if labeled transparency the direction may be reversed. Follow its actual label and preview rather than guessing a percentage from slider direction or inventing a default absent from the screenshot.

For the first round, make the color visibly more opaque while keeping font, key style, image, and layout unchanged. Inspect the boundary between keyboard background and key text in the editor preview. After saving, apply the theme if the interface permits it, invoke 键来 in the note, and enter the test phrase. For the second round, reduce only the background color’s opacity, or increase transparency according to the interface label, and repeat the same phrase. Observe whether the area beneath changes, especially whether candidates, function keys, and numbers remain legible. ## Make an observation table

Give each round a row: background color, the visible transparency or opacity label, light or dark editing state, save result, whether letters and candidates are legible on the keyboard, and whether the test phrase matches. If the control has no number, write “more transparent” and “less transparent” as relative descriptions. Do not convert the distance your finger moved into an exact percentage.

Inspect the same letter-key position first, then function keys and the candidate area, since these regions may use different colors. ## Separate transparency from contrast

Transparency affects how a color layer combines with what is beneath it. W3C describes general color and alpha compositing, but this does not establish 键来’s particular rendering method, and a setting percentage alone cannot calculate the real screen color. A picture can be light in one area and dark in another, making the same text clear in one place and hard to read elsewhere. Inspect several actual key positions.

To estimate text-background contrast further, first use two known solid colors as an example and calculate them with the existing contrast guide. ## Troubleshoot and restore

If the slider changes but the keyboard looks the same, first verify that the edit was saved, the intended theme is active, and the current light or dark appearance matches the edited state. The underlying content may also be similar. Do not change several settings at once just to force a visible effect. If the background or labels become hard to read, restore the more opaque state or the original theme, then type the test phrase again. If committed text differs from the baseline, check actual typing and host substitutions before blaming transparency.

Record the settings actually visible in both rounds, the preview, keyboard, and text, then return to the original theme or keep the copy you prefer. Before deleting a test copy, confirm the original remains available. Mark inaccessible controls or unobserved backgrounds as unverified; there is no need to capture private content to demonstrate appearance.
