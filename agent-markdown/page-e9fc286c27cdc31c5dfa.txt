## Preserve one original and two processing branches

Choose an owned short recording with a decodable original FLAC and retain source/project. Create separate tag-copy and half-copy branches: metadata-only versus changed sample amplitudes, without combining operations. Use an identifiable opening and moderate peaks, requiring no high-volume/full-scale test. Keep original title and external branch label separate. Names are preparation plans, not supplied downloads. Without suitable tools preserve the original and mark each unavailable processing branch pending.

## Identify ReplayGain as gain metadata

Xiph’s metaflac documentation describes calculating track/album gains and peaks and storing them as FLAC tags. Do not invent scan results. If an existing tool is used, follow its actual instructions on tag-copy only and save real output, noting replacement of related existing tags. Keep originals outside the operation. Without that tool, inspect an authorized documented working copy or leave fields unknown. Scan result, tag text and player application are separate states. Listed FLAC import does not promise every ReplayGain interpretation in 调调.

## Check whether the tag branch preserves decoded samples

Compare original/tag-copy decoded audio externally: rate, channels, frame count and full PCM when suitable tools exist. Keep the decoded output format fixed for the sample comparison. Whole-file hashes may differ after metadata changes without implying changed decoded samples. Unchanged size alone proves no audio identity. Claim sample equality only from an executed reliable comparison; otherwise retain metadata-operation scope and leave samples unverified. A FLAC internal checksum is no universal edited-file security certificate. This branch separates metadata from audio changes rather than predetermine player volume.

## Halve samples in the separate branch under an explicit model

Actually reduce amplitudes externally in half-copy. The paper model stipulates y=0.5x, e.g. 0.6 → 0.3, −0.4 → −0.2 and 0 → 0. If a tool accepts decibels, follow its conversion and retain the actual value; integer −6 dB is not an exact mathematical synonym for halving. Fix rate/channels/interval and avoid unverified gain tags confounding this branch. Integer formats introduce rounding; sample examples promise no byte-wise halving. Save processing/export evidence rather than call a lowered player slider changed source samples.

## Fix output and volume while recording limited observations

Only for distinguishable sources, play the same interval at normal speed through fixed output and the same comfortable volume setting. Verify title/anchor before recording perceived differences; do not adjust each file to equal loudness. Similar sound in tag-copy does not prove that the tag was ignored, and quieter sound alone does not prove that ReplayGain was applied; other processing may intervene. Reduced external amplitudes do not guarantee perceptually half loudness. Without a loudness meter claim no LUFS, peak or sound-pressure measurement. Inconclusive perception is a valid scoped observation.

## Diagnose branch and identity confusion

Inspect one branch/factor while retaining originals and initial responses. Unknown tag fields remain source text/unknowns rather than a fabricated professional-looking set. External sample equality certifies those files only, not bit-perfect phone output or automatic loudness normalization across every service.
