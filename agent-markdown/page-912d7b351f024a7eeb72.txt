Use self-made clips to distinguish Plex date-based episode filenames, server matching and actual iCouldPlay playback.

## Understand date-based naming

Plex’s TV organization documentation explains that some shows use dates rather than season-and-episode numbers and gives formats including YYYY-MM-DD and DD-MM-YYYY. Consult the chosen metadata provider to determine whether a show is date-based. A date in a filename does not by itself establish actual broadcast time. Server recognition and iCouldPlay display are separate observations.

## Prepare isolated self-made samples

In an isolated TV library you administer, prepare two self-made authorized clips with visual markers A and B, record durations and preserve originals. Use a fictional show name and dates rather than another person’s real program or private viewing history. A normal test account needs library access. Without a restorable environment, observe read-only and do not alter a production library.

## Create specific directories and dates

For example, in fictional River Journal (2020) under Season 01, place River Journal (2020) - 2020-05-06.mp4 with marker A and River Journal (2020) - 2020-05-13.mp4 with marker B. The dates are test identifiers, not real broadcasts. Files must actually be playable videos rather than renamed extensions. Keep original self-made files backed up outside the test directory.

## Record pre-scan server state

As the normal test user inspect existing series, directories and entries in the Plex test library. If a same-name show exists, confirm identity before overwriting anything. Connect iCouldPlay to the same server and account and record current access to the series entry. Check full filenames and hidden extensions and record copy completion; involve an authorized administrator for server checks when needed.

## Scan and inspect server results

Wait for or run an isolated-library scan using current Plex controls and record task, completion and server version. Check separately whether A and B become distinguishable entries and whether displayed dates correspond to images. A fictional show may not match a remote provider, so absent artwork or description does not itself mean playback fails. If entries are missing, check library path and scan state first.

## Separate filename and metadata dates

Record both test filename dates, dates displayed on the server, remote metadata source and actual file content separately. The server may match based on the selected provider and show order; equal dates alone do not prove item identity. Mark unclear source, time zone or date meaning unknown. Do not present a fictional filename as a real broadcast fact.

## Verify both clips in iCouldPlay

In iCouldPlay open the test show on the same server and normal account and record listed items and dates actually visible. Play authorized A and B clips separately and check visual marker, duration and return position. Mark unavailable dates or entries as not displayed or untested. Server support for date-based naming does not guarantee an iCouldPlay date label or identical sorting.

## Troubleshoot and preserve originals

If only one server entry appears, check file completeness, library directory, date format and scan completion. If web shows two but iCouldPlay shows fewer, check account, show identity and page state first. Change one restorable condition at a time and record it. Do not overwrite real programs, delete others’ progress or map fictional dates to unrelated works.

## Restore and document

Restore test directories and settings from backup, confirming originals and other users’ data remain; defer uncertain effects to the administrator. Record both paths, filename dates, server entries, iCouldPlay display, actual A and B playback and skipped steps separately. Remove private paths and credentials before sharing. This guide relies on public documentation and claims no device or private-server testing.

## Record date format without guessing

This sample records 2020-05-06 and 2020-05-13 as year-month-day; Plex also documents day-month-year forms. Avoid mixing ambiguous numbers and never treat 05-06 alone as a complete date. If the server displays only month and day, mark the year source unconfirmed rather than filling it from list order. All sample dates are fictional.

## Separate program matching and file playback

A provider’s title, date and artwork can help an administrator identify a real show, but actual local video content remains a separate check. Fictional River Journal should not impersonate a real program ID. Record basic entries if remote metadata is absent. Playing A and B does not establish a correct external match, and complete remote metadata does not prove both local files play.

## Preserve the same-day and duplicate boundary

Two files with one date need a separate controlled experiment; this example uses different dates and does not establish how same-day segments are grouped. For duplicate entries, inspect relative paths, duration and self-made markers before deleting anything. Real shows may have revisions or different time zones; use reliable sources instead of guessing a unique broadcast time from a filename.

## Record list-order conditions

For both server and iCouldPlay record sorting controls, visible order and each item’s marker. Chronological order and display order can differ because of settings. If the sort criterion is unavailable, mark it unknown; an order difference alone does not establish incorrect date parsing. Do not change global server sorting or other users’ preferences merely to align interfaces. Keep observation times.
