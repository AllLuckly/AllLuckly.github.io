Record the device and identity and time of two backups, check their recoverable scope, then decide whether to restore.

## Preserve the current device state

Use a device already running ManYue normally; do not overwrite its library for practice. Record device name, app version, one recognizable comic, chapter and a nonsensitive reading record. Confirm the original comic file has a recoverable source. Reading data, a backup and original comic files need not cover the same scope. If the current state cannot be preserved, stop at read-only inspection.

## Identify the cloud account and storage conditions

Check the current Apple account and iCloud availability in system settings, using actual system prompts to inspect storage and network. Do not include account screenshots, email addresses or codes in shared notes. Apple’s iCloud guidance describes system prerequisites, not proof that a particular ManYue backup exists. Stop if the account is not yours or cloud access is unavailable; do not switch to someone else’s account.

## Export all cloud copies before choosing a restore

The public 2.0.6 notes describe exporting all cloud copies first, then selecting an identifiable backup for recovery. If the current interface actually offers export of all cloud copies, read its stated source, destination, available space and effect on existing files. Export only when authorized and the effects are clear. Observe progress, an actual completion message and the export result; stop and mark the step unconfirmed if the entry is absent, scope is unclear or export is incomplete. Export obtains copies; it is not a restore and does not prove every copy usable. Do not select a restore target or confirm an overwrite in this step.

## Locate the actual backup list and identify entries

Find the iCloud backup or restore entry actually visible in the installed version; if absent, record that and do not invent a button path. List two candidate copies only where visible, including device origin, displayed time, filename or interface identifier. Do not infer undisplayed contents. If only one appears, mark the second absent or not observed rather than inventing it.

## Check times and possible time zones separately

Compare the displayed date and time and device origin of both copies, noting the system time zone. If the interface does not label its zone or source device, mark them unknown; a larger number alone does not establish recency. If times match, use another actual identifier and refrain from restoring if ambiguity remains. Export time is not necessarily the last reading time.

## Check the prompt and visible restore scope

When viewing details or a pre-restore prompt, read what the current interface explicitly says about contents, target device and any replacement or merge behavior. A backup’s presence does not establish that all original comics are included. Public notes mention preservation of original copies and integrity protection, but the actual interface and conditions must be verified. Do not perform the final restore if scope or preservation of current state is unclear.

## Check authorization and action scope first

If the copies came from different people or shared devices, first confirm you may inspect and restore the selected data; avoid importing another person’s records into this device. For sync, storage or network warnings, record the nonsensitive part of the actual message and resolve the corresponding condition first. An old entry still visible in a list does not establish that its backup is complete. If overwrite protection or a separate copy is unclear, keep the current state and consult the app provider before deciding.

## Restore the identified copy only when conditions are clear

Only after confirming a recoverable current state, the correct target and an understood prompt should you select the clearly identified copy and follow the actual interface. Observe progress and completion or failure. If interrupted, preserve the error and original copy, follow any current resume guidance and avoid repeated taps or file deletion. For a read-only exercise, mark the restore unperformed.

## Verify the original comic and records in layers

If recovery was actually performed, reopen the same comic and chapter and compare the body, position and selected record with expectations for that copy; also check whether the original backup remains visible. A completion message or shelf count alone does not establish complete recovery. If the original file is not local, retrieve it from an authorized source and record file acquisition separately from reading-data restoration.

## Use a comparison table to avoid confusing copies

In a private note, make rows A and B with only the date, device nickname, displayed name and ability to open details that the interface actually confirms. Exclude real account names, tokens and private paths. Add a known-content basis only where an actual preview or your own earlier export record exists; otherwise write unknown. Record the current device state separately as C rather than assuming it is automatically A or B. Label inferences as uncertain so the restore decision remains assessable.

## Deliver a credential-free recovery record

Record redacted identifiers of candidate copies, displayed times and uncertainties, target device, scope confirmed in the prompt, whether restoration was performed and item-level checks. If only the list was inspected, say no restoration was performed. Confirm the original sample and important records remain available. Do not publish account details, tokens or backup contents. No real iCloud restore is claimed.
