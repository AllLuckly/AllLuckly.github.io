Scan count in a progressive JPEG is neither comic-page count nor animation-frame count. Read two encodings of one original image in ManYue, checking format and final content before noting whether any intermediate display is actually visible. Encode externally and observe the current supported reader path. An online progressive-loading demonstration is not a result measured on this device.

## Fix one original pixel image

Create an original twelve-hundred by eight-hundred-pixel page with fixed wording, numbered corners, fine lines and a gradient. Retain the lossless source and use no one else’s comic collection. Record dimensions and colour conditions, keeping byte size separate. Export both JPEGs independently from that source, not through repeated lossy recompression; otherwise artifacts involve more than progressive versus ordinary encoding.

## Save both copies and their export reports

If the external tool offers ordinary sequential and progressive encoding, save A and B while matching quality, chroma sampling and dimensions as far as possible. Preserve real settings or credit the creator’s report if controls are unavailable. Both may use jpg; a filename containing progressive is not proof. Record uncontrolled encoding differences, since equal quality numbers across different software need not represent identical settings.

## Separate scan organisation from image count

The libjpeg-turbo documentation describes progressive encoding as multiple scans progressively conveying one image’s information, not new comic pages per scan. This exercise has one final image throughout; do not multiply scan count into page count. Progressive JPEG is not GIF animation or a multipage PDF. If a report says only JPEG, leave scan type unknown rather than infer a parsed marker from a fleeting blurry display.

A paper ledger lists one source image, two exported files and one final image per file. Importing both in one folder can produce two pages because there are two files, not because B has multiple scans. This isolates file organisation from JPEG internals. Removing bytes for one scan creates a damaged stream, not a valid half-page control.

## Check final content before judging sharpness

Open A and B externally and check dimensions, wording, corners and bounds so that neither is merely a thumbnail. Lossy export can alter fine lines or gradients; do not assert pixel-identical decoding without comparison. Record content completeness before artifacts, edges and colour observations. Smaller size does not imply missing pages. Resolve an already cropped source before attributing that difference to import or progressive organisation.

## Import separately and check actual page count

Place each copy in its own clearly named one-page folder and import through an available path. Do not combine two files and then misinterpret two pages. Check identity, centre and corners before recording visible page position or count; invent no absent counter. If B fails on a particular path, record that scoped failure rather than describe its scans as many comic pages still waiting to arrive.

## Report intermediate previews only when observed

Open B normally and note a coarse-to-refined preview only if actually visible. The reader may wait for complete decoding, and a fast local file may reveal no stages; neither disproves progressive encoding. Do not damage files or interrupt connectivity to force an effect, or arrange static screenshots as fake real-time evidence. If A also appears briefly soft, consider thumbnail replacement, zoom and caching conditions before assigning the cause.

## Check incomplete files and recompression

If B fails, check completeness with an existing external reader, then truncation, mismatched reports or selection. Keep ordinary A as a readable fallback instead of recompressing the library. Trace detail differences to quality, subsampling and recompression history before blaming the word progressive. Two original images and reports suffice for support, with performed actions separated from plans. Static website validation is not testing these files on every physical device.

## Leave and return to separate three counts

Leave and return to both samples and check final text and markers. Keep dimensions, file count, actual comic-page count, scan report, visible loading behaviour and unknowns, explaining why scans differ from pages and animation frames. Success is an auditable same-source comparison with readable A retained and B observations scoped honestly. A different exporter or recompression requires a new record rather than attaching the old report to changed bytes.
