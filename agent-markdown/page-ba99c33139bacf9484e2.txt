Discover actions actually offered by the installed app, inspect inputs, run manually, and check system feedback and playback separately.

## Prepare an identifiable owned recording

Choose a short recording you are entitled to use that already plays in 调调. Note its title, duration and an audible opening cue. Keep the original, set a comfortable volume and identify the output device. Record the OS and installed app versions if visible; otherwise mark the installed version unknown. The public release notes mention Shortcuts support, but do not enumerate actions, parameters or results. Follow only what the installed version actually displays.

## Establish a player baseline

Play and pause the same recording with the app’s existing controls. Record the position and visible queue. If this fails, check readability, volume, output and recording identity before attributing the problem to Shortcuts. Record the original player state and network condition for restoration. Do not clear the library, delete the track or reinstall simply to test whether an action exists.

## Find actions actually offered

Open Apple Shortcuts, create a private test shortcut and search the action library for 调调. Record the exact name of one suitable action if one appears. If none appears, check that the app is installed, its version is identifiable and the search uses its actual name; record the absence. A release note does not establish that every device offers a specific preset. Do not invent a missing action.

## Inspect inputs and side effects

Choose only an action actually shown whose purpose you understand and can test safely. Read its fields, defaults and description. If it asks for a source or target, inspect the real choices instead of assuming support for file paths, server addresses or playlists. If it changes content, shares information or triggers an unclear network operation, stop in the editor and choose a clearly understood test. When parameter help is visible, record fields and selected values, distinguishing system defaults from your own choices. For account or personal-path fields, record their presence and provenance without exposing private values in a public screenshot. If the effect remains unclear, leave it unrun and consult its actual description; discovering that no understood action is available is itself a valid outcome. Give the shortcut a recognizable name; do not add an automation trigger.

## Run manually and check three layers

Run the inspected action once in the editor. Record whether Shortcuts reports completion, an error or a wait. Return to the player to inspect the visible track and queue, then check the playhead and sound. System feedback, player display and audible output are separate observations. If the real action only retrieves information or opens the app, check it against its description rather than demanding playback. Mark unclear results pending.

## Change one condition to troubleshoot

Keep the action name and any error. Check whether the selected input still exists, then alter only one condition. For an action that actually permits track selection, reselect the same known playable recording instead of also changing the network and output device. If success is reported but no sound is heard, check the player state, output routing and mute level. Repeated runs can change state; record the state before each attempt.

## Distinguish manual execution from automation

This exercise tests manual execution only. A completed editor run does not prove automatic execution at a time or location, in a device state or in the background. For a later automation, independently test an explicit trigger, system prompts, actual execution and effects of repetition. Do not assume 调调 supplies a scheduled-play action or describe personal automation as a built-in app scheduler.

## Deliver a reproducible record and restore

Keep the action-search result, actual action name and fields, manual run time, system response, player identity and sound observations. Mark unfinished checks pending. Stop test playback and restore the output and queue. The user can decide whether to remove the private shortcut when it is no longer needed. Recheck the action list and fields after app or OS updates. This guide uses public release notes and Apple documentation; it does not claim completed device, server or background-automation tests.
