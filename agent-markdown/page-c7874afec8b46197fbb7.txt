Observe page progression and chapter sequence in authorized samples without assuming gestures or support.

## Separate the two observations

The EPUB spine records default reading order; page-progression-direction expresses global content progression as ltr, rtl or default. Default expresses no creator preference and the reading system chooses. Sequence and direction are distinct: chapter A before B does not imply a universal forward gesture in every reading interface.

## Prepare an authorized two-chapter sample

Create an editable short EPUB you are authorized to use, with distinct titles and opening sentences in chapters A and B and enough text to observe page changes. Record spine file order and keep an original backup. Do not unpack or modify a protected purchase; without an authorized sample, prepare a paper record and mark device steps unperformed.

## Read the package direction

In an EPUB editor inspect the package spine and record the actual page-progression-direction value. If omitted, the EPUB reading-systems specification treats it as default, not automatically ltr or rtl. Note explicit chapter-level formatting such as writing-mode, because a content document can override the global direction.

## Create controlled comparison copies

In a working copy you may modify, save a second sample changing only the global direction from ltr to rtl while keeping text, chapter order and other settings consistent. Use distinguishable filenames but keep the internal title the same, recording the single change inside the package. Identify copies from the filenames and observed import results; if they cannot be distinguished or the app merges them, stop and mark the comparison incomplete. Do not present test copies as formal editions. If the editor cannot do this, stop and record the limitation.

## Validate the files

Use EPUBCheck or the editor to check package structure, resources and links in each sample, and retain both reports. Fix problems in working copies and check again. Validation does not guarantee identical rendering or prove that an app has a direction setting. Record creation times and intended directions to identify the imported copies later.

## Open the first in Book Isle

Use Book Isle’s available import method to open the first copy and confirm its title and chapter A opening. Record device, app version and reading layout. Advance using controls actually available and observe content and the action used; do not assume tap zones, swipe direction or continuous-scroll behavior. If import or pagination is unavailable, record it and stop that branch.

## Check logical chapter sequence

Continue from the known beginning of A until B and use B’s distinctive opening to verify sequence. Record chapter order separately from the direction pages appear to progress. An action that changes the display does not necessarily enter the next chapter. If you did not reach a chapter boundary, record unknown rather than guessing from screen position.

## Compare the second under matching conditions

Import and identify the second sample, keep device, layout and other observable settings consistent, and repeat the first-to-second page and A-to-B observations. If comparable layout is unavailable, entries merge or another result appears, report the fact. Do not claim rtl always takes effect or invent a particular app button. First exclude an old copy when results differ.

## Check local overrides and settings

If direction differs from the package value, inspect the actual file, package attribute, local CSS and currently visible reader settings. The specification permits local overrides and a reading system may provide an override, but this does not establish a particular Book Isle option. Change one controllable condition at a time and retain before-and-after observations.

## Separate text direction from gestures

Bidirectional text layout, page progression and the user’s action are separate observations. Do not infer a whole book’s direction simply from Arabic, Chinese or English. Record actual text and page order, using short phrases and clear page markers you can verify. If the reader scrolls, describe scrolling rather than forcing it into left or right page turns.

## Record results and preserve backups

The table should contain filename, spine order, global direction, local overrides, reading layout, actual action, content reached and reasons for unperformed steps. Record each device or version separately and omit private paths and accounts. Identify a working copy before deciding whether to remove it; retain the original and backup. No device test is claimed.

## Mark content boundaries first

Add distinct short markers to adjacent sample paragraphs, such as “sample A one” and “sample A two”, and record their source order. Screen size and font size affect pagination, so do not assume each marker fills a page; observe where the content actually appears. Keep device orientation and font size consistent when comparing copies and note any intervening change.

## Reopen the same copy

After one pass, close the test book and reopen the same copy from the current shelf. Confirm title and chapter text first, then observe whether the restored position affects the starting point. If comparing from the beginning, return to confirmed chapter A using the interface actually provided; if no return method is found, preserve the result and mark the retest incomplete. Record restored position separately from progression direction; one resume result cannot establish their relationship.
