Project note: For readers unfamiliar with Cocos2D-X or Swift, this project uses Objective-C and UIKit. In other words, if you can use UIView, you can try building a game!

The original game was developed with Cocos2D-X, so some image animations in this version are less fluid, such as image slicing, deformation, and rapid image replacement. ## Overall architecture

### Sound effects and background music

Sound effects and background music use a WNXSoundToolManager singleton wrapped around AVFoundation. Background music uses AVAudioPlayer; sound effects use AudioServicesPlaySystemSound.

The following methods and properties are available for global calls or changes. Adjust bgMusicType and soundType to control music and sound-effect volume. Use playSoundWithSoundName: to play a sound by name.

```
// 音效或背景音乐播放声音打大小枚举
typedef NS_ENUM(NSInteger, SoundPlayType) {
    SoundPlayTypeHight = 0,
    SoundPlayTypeMiddle,
    SoundPlayTypeLow,
    SoundPlayTypeMute
};

@interface WNXSoundToolManager : NSObject

// 背景音乐声音大小Type
@property (nonatomic, assign) SoundPlayType bgMusicType;
// 音效声音大小Type
@property (nonatomic, assign) SoundPlayType soundType;

// 暂停背景音乐
- (void)pauseBgMusic;
// 停止播放背景音乐
- (void)stopBgMusic;
// 重新播放背景音乐
- (void)playBgMusicWihtPlayAgain:(BOOL)playAgain;
// 播放音效:音效名称
- (void)playSoundWithSoundName:(NSString *)soundName;
// 设置背景音乐音量:音量大小0~1
- (void)setBackgroundMusicVolume:(float)volume;

// 获取SoundManager单利对象

@end
```

## Launch-screen animation

Launch animations are common in apps such as SF Best, Shunshou Pay, and SF Haitao. The effect is an illusion: in AppDelegate's didFinishLaunchingWithOptions(), add an AnimVC that looks exactly like the launch image and make it keyWindow's rootViewController. Run the animation in AnimVC's viewDidApper(), then use a Block to replace keyWindow's rootViewController with the home VC when it finishes.

```
- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {

    [[UIApplication sharedApplication] setStatusBarHidden:YES];

    [NSThread sleepForTimeInterval:1.0];

    [self setKeyWindow];

    return YES;
}

- (void)setKeyWindow {
    __weak typeof(self) weakSelf = self;

    WNXLaunchAnimationViewController *launchAnimationVC = [[WNXLaunchAnimationViewController alloc] init];
    launchAnimationVC.animationFinish = ^{
        UIStoryboard *sb = [UIStoryboard storyboardWithName:@"Main" bundle:nil];
        WNXBaseNavigationController *rootNav = (WNXBaseNavigationController *)[sb instantiateViewControllerWithIdentifier:@"RootNavigationController"];
        weakSelf.window.rootViewController = rootNav;
    };

    self.window = [[UIWindow alloc] initWithFrame:[UIScreen mainScreen].bounds];
    self.window.rootViewController = launchAnimationVC;
    [self.window makeKeyAndVisible];
}
```

I will not explain the animations here. Interested readers can study the project code.

## Home screen: WNXRootViewController

The home screen is actually an image. Based on the device's screen size, it reads the corresponding button Plist and obtains the Frames of the 6 home-screen buttons. In touchesBegan(), CGRectContainsPoint checks whether the tap lies inside a specified Frame and triggers the corresponding action. Here is the code:

```
// 加载当前设备对应首页按钮Frame
- (void)loadHomeButtonFrame {
    NSString *framePath = [[NSBundle mainBundle] pathForResource:@"home.plist" ofType:nil];
    NSDictionary *frameDic = [NSDictionary dictionaryWithContentsOfFile:framePath];

    NSDictionary *dict;

    if (iPhone5) {
        dict = frameDic[@"iphone5"];
    } else {
        dict = frameDic[@"iphone4"];
    }

    _settingFrame = CGRectFromString(dict[@"btn_setting_frame"]);
    _languageFrame = CGRectFromString(dict[@"btn_language_frame"]);
    _moreFrame = CGRectFromString(dict[@"btn_more_frame"]);
    _rankFrame = CGRectFromString(dict[@"btn_rank_frame"]);
    _playFrame = CGRectFromString(dict[@"btn_play_frame"]);
    _getFrame = CGRectFromString(dict[@"btn_get_frame"]);
}

// 判断点击点是否在对应的Frame内
- (void)touchesBegan:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event {
    UITouch *touch = [touches anyObject];

    CGPoint touchPoint = [touch locationInView:touch.view];

    [[WNXSoundToolManager sharedSoundToolManager] playSoundWithSoundName: kSoundCliclName];

    if (CGRectContainsPoint(_settingFrame, touchPoint)) {

        [self performSegueWithIdentifier:@"Setting" sender:nil];

    } else if (CGRectContainsPoint(_languageFrame, touchPoint)) {

        [[UIApplication sharedApplication] openURL:[NSURL URLWithString:kBlogURL]];

    } else if (CGRectContainsPoint(_moreFrame, touchPoint)) {

        [self performSegueWithIdentifier:@"Rare" sender:nil];

    } else if (CGRectContainsPoint(_rankFrame, touchPoint)) {

        [[UIApplication sharedApplication] openURL:[NSURL URLWithString:kWeiBoURL]];

    } else if (CGRectContainsPoint(_playFrame, touchPoint)) {

        [self performSegueWithIdentifier:@"PlayGame" sender:nil];

    } else if (CGRectContainsPoint(_getFrame, touchPoint)) {

        [[UIApplication sharedApplication] openURL:[NSURL URLWithString:kGithubUrl]];

    }
}
```

## Level-selection controller: WNXSelectStageViewController

The level-selection controller uses UIScrollView containing 24 WNXStageListViews. You could implement a reuse pool, but I did not think it necessary. Each view has a stageModel, loaded from project -\> Resources -\> Plist -\> stages.plist. Its fields supply the level image, unlock state, previous score, Rank marker, and other information.

Each WNXStageListView receives a Tag based on its ID and a tap gesture. Its tap handler uses the navigation controller to push WNXPrepareViewController, passing the selected stageModel so the preparation screen can display the appropriate information. The level-selection result is shown below.

## Score-results controller: WNXResultViewController

Every completed level enters the score-results controller. A method in WNXBaseGameViewController lets every level controller calculate its score directly. When a level ends, call the function below. I took a shortcut and only implemented addition, but subtraction should be easy to implement using it as a reference!

```
- (void)showResultControllerWithNewScroe:(double)scroe
                                    unit:(NSString *)unil
                                   stage:(WNXStage *)stage
                              isAddScore:(BOOL)isAddScroe;
```

The purpose of isAddScore

In some levels, a higher score is better. Their results animate upward from 0, so pass YES for isAddScore.

In some levels, a lower score is better. Their results animate downward from a larger value, so pass NO for isAddScore.

After score calculation, several outcomes are possible. Execute the appropriate logic for each score condition, as shown below.

### State one: Game failure. A grade of F or below is not saved, and the following screen appears.

![1](<https://allluckly.cn/images/blog/tuogao/tougao54/9.gif>)

State two: Game success If the level has no score record and the grade is above F, save the score, display the result normally, and unlock the next level.

![1](<https://allluckly.cn/images/blog/tuogao/tougao54/10.gif>)

If the level already has a record but the new score does not exceed it, display the result normally without saving this score.

![1](<https://allluckly.cn/images/blog/tuogao/tougao54/11.gif>)

If the current level already has a record and this score exceeds it, display the record-breaking animation and replace the previous score with the new one.

## Failure: WNXFailViewController

Some levels can fail during play, as shown below.

This also uses a method wrapped in WNXBaseGameViewController. When a level fails, call showGameFail() to push the failure controller.

If failure needs additional actions, such as stopping a timer or animation, override showGameFail() in that level and execute the required code before calling the superclass method, as follows:

```
- (void)showGameFail {
    // 需要在游戏失败时执行的相应代码
    // do something

    [super showGameFail];
}
```
