Draw a number line for \[-2, 3), checking endpoint inclusion, ticks, interval notation and test values.

## Define the intended set

This diagram represents all real numbers satisfying -2 ≤ x \< 3, written \[-2, 3). The left endpoint -2 is included, the right endpoint 3 is excluded, and every real number between them is included; this is not merely a list of integers. OpenStax uses a bracket for an included endpoint and a parenthesis for an excluded endpoint. Write the inequality, interval and endpoints before drawing so their meaning stays fixed.

## Create a canvas and separate objects

Create a landscape VectorPaint document and save an editable original, for example around 1600 by 900 units. Use the available object or layer controls to keep the axis, ticks, interval line, endpoints and labels separate or grouped as appropriate; the names are your choice. Leave space above and below for notation and explanation. If the interface differs, locate the controls actually present rather than assuming identical labels.

## Build the horizontal axis

Draw a horizontal axis using a line or open path with margins on both sides. If you use arrows, make them indicate that the axis continues, not that the interval extends in both directions. Keep the axis separate from endpoint shapes so its stroke can be adjusted independently. Zoom out to check continuity and alignment; if a drag introduces a tilt, compare endpoint heights using the controls available in the current interface.

## Place evenly spaced ticks

Mark eight ticks for -3, -2, -1, 0, 1, 2, 3 and 4, with equal distances between neighboring integers. Duplicate a short line and move copies with the available controls, or place them individually and check the spacing; do not assume an automatic distribution command exists. Put labels below their ticks and keep the minus signs clear. Check each label against its tick and compare adjacent spacing; ticks remain equally spaced even when labels have different widths. The distance from -2 to 0 should equal the distance from 0 to 2.

## Draw the interval segment

Draw a separate prominent segment from the tick at -2 to the tick at 3, with a different color or weight from the underlying axis. It represents every real number between the endpoints, not five discrete tick marks. Stop at the two endpoints rather than extending to 4 or starting left of -2. Temporarily reduce its visual weight to inspect the base axis, then restore the style with endpoint markers still visible.

## Distinguish closed and open endpoints

Overlay a filled circle at -2 to show inclusion and an open circle at 3 to show exclusion. With transparent fill, the segment behind an open circle may pass through its center and confuse the result. A background-colored fill with a visible outline can help, while keeping the circle independently editable. Zoom in to align each circle center with its tick, then zoom out and confirm the two states are distinct.

## Add interval and inequality labels

Place \[-2, 3) above the diagram and -2 ≤ x \< 3 below it. Match the left bracket to the filled point and the right parenthesis to the open point; do not change the right inequality to ≤. Leave space between labels, ticks and endpoints so the minus sign, comma and brackets are not covered. If the chosen font lacks ≤, inspect the actual rendering and use a font that supports it if needed.

## Test specific values

Test -2, 0, 2.5 and 3: the first two satisfy the inequalities, 2.5 also satisfies them, and 3 fails because it is not less than 3. Try -2.1 as well; it is below the left endpoint and fails. Check that the drawing agrees with all five judgments. In particular, 2.5 lies inside the segment despite having no integer tick. If the graphic conflicts with the text, return to the original definition rather than hiding the mistake in a label.

## Check monochrome and small sizes

Make a working copy in monochrome or use same-color lines while retaining the distinction between open and filled markers; do not rely only on red and green for inclusion. Reduce the image to the intended reading size and check numbers, brackets and both endpoints. If the open circle becomes a black dot, increase its diameter and interior space, then verify its center still aligns with the tick at 3.

## Compare neighboring intervals

Save a working copy and change the right open circle to a filled circle, with labels \[-2, 3\] and -2 ≤ x ≤ 3. Keep ticks, segment length and the left endpoint identical; compare only inclusion of 3. Test 3 against both: the first excludes it and the second includes it. Change the circle, bracket and inequality together. Retain the original as the exercise result; use the copy only for comparison.

## Check objects and legibility

Select the right open circle and move it slightly to see whether the segment and axis stay in place. Undo the movement and confirm that its center remains at 3. This checks independent editability without requiring objects to be merged. Zoom in on the label and endpoint to check that strokes do not cover symbols. If text is hard to read when reduced, enlarge text and surrounding space before moving ticks or changing the interval length.

## Troubleshoot and save the output

If an endpoint is displaced, check its center against the tick before moving a label to match it. If the segment crosses the open point, inspect object order and fill. Save the editable original, then use an available export control to save a separate SVG or PNG. Reopen it to check endpoints, labels and cropping. Return to the original to confirm objects remain editable, and record the filename and test values. Mark unperformed device steps as pending.

## Recheck the minus sign and interval interior

Zoom into the left label to ensure the minus sign in -2 is not clipped. Point to -1.5 on the line: although not an integer tick, it lies inside the interval. Check that the inequality agrees so the segment is not mistaken for a finite list of points.
