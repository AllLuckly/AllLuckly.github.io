Use a self-made clip and two subtitle files to compare Plex filename flags, server recognition and track selection in iCouldPlay.

## Understand the flags

Plex documents forced subtitles as tracks often used for particular foreign-language segments and SDH or CC subtitles as potentially including sound descriptions and speaker identification. These flags describe different purposes; they do not create missing subtitle content. Plex specifies server-version and newer Plex Movie agent requirements for SDH or CC recognition. iCouldPlay’s labels and automatic selection must be observed separately.

## Prepare your own short clip

Use a self-made, authorized clip in an isolated movie library and back up the original video and subtitles. Choose short identifiable moments, such as an on-screen marker and a knock, and record duration and times. Do not upload copyrighted films or download unknown subtitles, and do not modify a production media folder used by household members.

## Create two distinguishable files

Using a UTF-8 plain-text editor, create two SRT copies timed to the clip: the forced file contains a self-written cue for the test-language moment, while the SDH file includes a self-written sound description at the appropriate time. Each cue needs a valid time interval and short text. Distinct content aids observation; filename flags do not mean automatic translation or a completed accessibility quality audit.

## Place files using movie naming rules

Follow Plex documentation to place sidecar files in the appropriate movie directory, matching the video’s base name and adding a documented language code and forced or sdh flag. Check the full extension, which the operating system may hide, and record all three filenames. Use a controlled test library and do not mix television episode directory rules with movie rules.

## Check server version and source

In server administration record Plex Media Server version, the test library’s movie agent and file paths, and check the documented SDH or CC support conditions. If version or agent is unclear, do not claim the flag must be recognized. Scan or refresh metadata only for the test item as the current interface requires, recording the action and completion time; do not simultaneously alter production-wide settings.

## Inspect tracks on the server first

Find the same clip in the Plex web interface using duration and self-made markers. Record available subtitle tracks and labels, whether forced and SDH appear separately and whether language matches the filename. If a track is missing, check path, extension, encoding, server scan and agent requirements. A file’s presence does not prove server recognition, and similar labels do not make two files the same track.

## Select tracks in iCouldPlay

With an account authorized for the test library, open the same clip in iCouldPlay and inspect the subtitle controls actually available. If both tracks can be selected, choose each in turn and play the relevant interval, recording whether the self-made cue or sound description appears; return to a known time between trials. If no selection control exists or labels are indistinguishable, mark the result unobserved rather than assuming a fixed menu or automatic choice.

## Separate automatic choice from file content

Keep audio track, account language preferences and test files unchanged while recording any automatically selected subtitle at initial playback, then manually choose the other track and observe its contents. Plex’s forced flag may participate in server preference selection, but audio, language preferences and client implementation also matter. An SDH file contains sound descriptions only if its actual text does; a filename does not prove accuracy or completeness.

## Troubleshoot and restore

For mistimed cues, first check the test video edition, SRT time range, encoding and playback position. For an absent track, inspect server recognition, account and client controls in layers. Change one condition at a time and retain unexplained differences. Restore the test library afterward, preserving original video, subtitles and other user data. Record version, agent, filenames, web and client observations and skipped steps. No device or private-server test is claimed.

## Check self-made cue timing separately

Use the self-made visual marker as a time reference and note expected cue start and end before comparing playback. If the forced cue appears but the SDH description does not, confirm selected track and its own time range before changing server preferences. If both are mistimed, inspect video edition and timestamp validity separately. Edit only test copies and keep before-and-after records. Mark playback untested if a valid sample cannot be prepared.

## Record uncertainty in track selection

Keep separate columns for server labels, visible iCouldPlay labels, content after manual selection and the initial playback choice. If the client shows no forced or SDH label but a selected track displays the self-made text, that proves only the observed playback, not recognition of the flag. An absence of automatically selected subtitles also does not alone prove that the server failed to read the file; account preferences, audio and client behavior may matter. Preserve unknown conclusions where evidence is insufficient.

## A reproducible test sample

Name the self-made movie River Demo (2020).mkv; in the same isolated movie directory place River Demo (2020).en.forced.srt and River Demo (2020).en.sdh.srt. The next two blocks are each one complete SRT cue, saved in that order as UTF-8 with cue number, time line, text and trailing line break. The forced cue is a self-made phrase and the SDH cue describes a self-made knock. Check version and Plex Movie agent as above before observation; client track selection is not guaranteed.

```
1
00:00:01,000 --> 00:00:03,000
[foreign phrase]
```

```

00:00:01,000 --> 00:00:03,000
[knock]
```
