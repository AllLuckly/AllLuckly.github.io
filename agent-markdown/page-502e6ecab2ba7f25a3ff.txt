Change an already compatible owned test collection from A/B to B/C, then compare server data, the visible catalog and playback rather than infer agreement from equal totals.

## 1. Use an authorised test music collection

This requires an already working compatible personal music server and permission to manage one isolated test collection. Read-only access is insufficient; leave the exercise pending rather than change someone else’s library. Prepare three owned clips A/B/C with distinct opening identifiers and preserve originals outside the collection. Change membership without deleting sole audio copies. Use the server’s own documented management/update method rather than invent protocols, APIs or administrative menus for 调调.

## 2. Give A/B/C traceable identities

Record source file, verified title, duration and audible identifier per item. Retain a stable server id only if actually available. Initial collection T0 contains A/B; keep C externally. Confirm that scope through the server’s existing view, then enter the same collection explicitly in 调调 and verify both identities/sounds. Whole-library totals are insufficient because other collections may contain A/C. Keep separate locations and observation times; a previously playing track is not evidence of a newly opened catalog.

## 3. Define the revised membership before applying it

Define T1 as B/C: retain B, remove A from this collection and add C. Both totals are two, so unchanged count can conceal a real change. Apply it through actual administration and confirm current data from the server before proceeding. If its documented workflow requires scanning/indexing, follow and record that workflow; instant updates are not universal. Preserve T0 and originals. Deleting local A in 调调 does not change the server collection and cannot substitute for this input change.

## 4. Re-enter the same source scope in 调调

Keep account, server and collection fixed and re-enter through the original browsing path. Use an explicit visible reload control only if present, recording its actual name. Do not invent forced refresh, cache clearing or push support, or sign out/reinstall to create another environment. Record the items actually shown; if A/B remain, do not substitute a B/C server screenshot. Investigate source scope and observation order before claiming a fixed refresh interval unsupported by documentation.

## 5. Check retained, added and removed identities

Make separate rows for retained B, added C and removed A, checking identities rather than two covers. When B/C appear, confirm title/sound to exclude another C. A absent from this collection does not prove source-file deletion or absence from a whole-library search. If only B appears, retain C unconfirmed and A currently unseen instead of declare complete agreement. Each row needs its own returnable evidence; unclear source scope remains unknown. A can still appear in another collection while this test collection contains only B/C. Both findings can hold. Record query scope rather than treat a whole-library hit as failure of this membership change. Catalog count and stored-audio location are different levels.

## 6. Open added C and retained B separately

Open B/C from the current source catalog and confirm actual sound rather than count background B as successful C playback. A visible C that will not play has separate catalog/access outcomes requiring investigation. A removed from the collection can behave differently through an old player reference; neither immediate failure nor continued playback is prescribed. Published material gives no universal cache/reference rule. Any optional A observation needs its entry path, without treating continued sound as proof membership never changed or clearing caches to force an outcome.

## 7. Describe identity differences rather than only counts

For stipulated T0 A/B and T1 B/C, common=B, new-only=C and old-only=A, with count two in both. Compare this expectation to observed results without equating membership differences with playback failure. If A/B remain, verify server update, collection/account scope and timing before assigning a unique cause. Changed title/artwork on retained B is a field change, not necessarily an addition. This is an external reconciliation table, not an assumed automatic difference report. If unexpected D appears, do not delete it to force count two. Check broader scope or another administrative change. B/C present does not justify ignoring extras. Record D as unexpected/unresolved while preserving the account and ordinary collection.

## 8. Restore the test scope and retain both rounds

If restoration is desired, the authorised administrator restores A/B from the original manifest and records a separate restoration round. Do not insert restored A into T1 evidence. Preserve all owned originals without clearing normal collections/accounts. Deliver both server manifests, actual app lists, identity rows and B/C listening outcomes, retaining unknown update timing. A changed service/account/collection needs a new scope. This does not promise identical administration, real-time synchronization, reference expiry or downloading across servers.
