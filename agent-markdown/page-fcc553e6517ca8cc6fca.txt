Use an isolated short video to distinguish external audio filename flags, internal stream information and actual player selection.

## Understand the rule’s scope

Jellyfin’s movie documentation describes filename suffixes for language and flags on external subtitles and audio, and notes that flags are ignored for containers with more than one stream. This concerns external track-file recognition and does not establish that every flag inside the main video is invalid. Server stream information and iCouldPlay display and selection can differ and must be checked separately.

## Prepare isolated authorized samples

In an isolated library you administer, prepare a self-made clip, a sidecar audio file containing one audio stream and an identifiable multi-stream sidecar container copy. Use self-made short sound or voice markers and preserve originals and backups. If you cannot safely create and inspect multi-stream files, perform read-only checks and mark the comparison untested. Do not download unknown tracks or modify others’ media.

## Confirm stream counts and identities

Using a trusted media inspector or information actually exposed by the server, record each sidecar container format, stream count, visible language and embedded title. An extension alone does not establish a single stream, and markers in a multi-stream file should be distinguishable. If stream count cannot be confirmed, do not treat that file as a multi-stream control. Exclude private paths and credentials from records.

## Check sidecar filenames against documentation

Use Jellyfin’s movie documentation to verify the shared base name, language code and chosen dot-separated flag for the test video and sidecar audio. Record both complete sidecar filenames and directories, distinguishing an external file from tracks embedded in the video container. Never rename production material for this exercise; edit only restorable test copies and check whether extensions are hidden.

## Establish the server baseline

Open the server web interface as a normal user authorized for the test library and verify the same video by duration and visual marker. Record the number of external tracks, names, languages, default or forced flags and playback preferences actually shown; mark absent fields not displayed. A file in a folder is not proof of server recognition, and a file title is not the same field as language.

## Observe single and multiple streams separately

Only after an administrator confirms isolation and restoration, observe single-stream and multi-stream sidecars separately with the same test movie. Change one condition at a time, complete any necessary library scan using the actual interface and record timing. Keep account preferences and other metadata unchanged. The documentation says filename flags are ignored for multi-stream containers; each stream’s embedded metadata still requires observation in the actual file and server version.

## Inspect and play in iCouldPlay

Open the corresponding short clip in iCouldPlay as the same user. Record the audio list, language, name and selectable items actually shown. If selection is available, play each self-made sound marker to identify the stream. Mark an absent flag as not displayed instead of assuming server labels are shown by the client. If no selector or playback is available, record the skipped step and actual message without bypass tools.

## Compare flags with actual sound

Record filename flag, server interpretation, iCouldPlay label and audible marker for the single-stream file, and a separate row for the multi-stream file. Identical sound does not prove a filename flag was read; a label does not guarantee content or language. If results differ from the documentation, check stream count, filename, scan state, account and server version before drawing conclusions. Do not change real users’ preferences to force an expected result.

## Restore and save the record

Restore isolated files and library settings, confirming original video, sidecars and other accounts’ data remain; defer uncertain effects to the administrator. Record app and server versions, stream counts and names, scan results, server and client observations and skipped steps. Remove private paths and credentials before sharing. This public-documentation guide claims no device or private-server testing and does not guarantee that iCouldPlay exposes all stream flags.

## Keep each experiment controlled

If both sidecars are present in one folder, the server may list multiple tracks; record which file and audible marker each entry corresponds to. With an isolated copy and administrator permission, run two observations: only the single-stream sample first, then restore the baseline and use only the multi-stream sample, recording each scan. If old server entries may persist, mark their source unknown rather than claiming every later entry came from the new file.

## Preserve playback-path differences

Servers may use different playback paths for different clients and devices. Even when the web interface and iCouldPlay select the same language, record audible content and displayed track names separately. Use short recognizable self-made audio rather than private recordings. If a track cannot play, record the error and environment without immediately blaming filename flags or assuming re-encoding will solve it.

## A reproducible test sample

Reproducible filenames: the self-made main video is River Demo.mkv. Prepare two backups and verify that one has exactly one audio stream and the other has multiple streams; extensions do not prove counts. In the first round copy only the single-stream backup into the isolated directory as River Demo.en.default.mka and record file identity, stream count, scan and sound. Restore the baseline and confirm the old test file was removed; in the second round copy the multi-stream backup under the identical name River Demo.en.default.mka and repeat the record. Do not overwrite both together; filename and default flag remain fixed. Documentation says filename flags are ignored for multi-stream containers and does not guarantee client labels.

```
River Demo.mkv | River Demo.en.default.mka
```
