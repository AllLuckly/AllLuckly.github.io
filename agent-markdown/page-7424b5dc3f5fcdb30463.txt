Using raw counts as heights with unequal bins gives wide bins extra visual weight. Draw a three-bin frequency-density histogram in VectorPaint, dividing counts by widths and recovering counts through areas. Its height rule differs from equal-width frequency charts. Values are an original exercise, not survey results or automatic app statistics.

## Declare bin boundaries and endpoint ownership

Use bins \[0,2),\[2,5),\[5,10\], widths 2,3,5 and declared counts 4,9,5, total 18. Mark boundaries 0,2,5,10 without equal-width boxes. Values 2,5,10 belong respectively to middle,last,last under this convention, never two bins. This is an exercise table, not collected survey evidence; recount any real data separately. The horizontal variable uses invented units, not unstated age or speed.

## Compute count density as count divided by width

Densities are 4/2=2,9/3=3,5/5=1, in counts per horizontal unit. Use heights 2,3,1, not raw counts. Last-bin count 5 exceeds first-bin 4 despite lower height 1 versus 2; area carries the difference. Count density is not bin probability and may exceed one. Check units before multiplying by a separate pixel scale.

## Draw adjacent rectangles with the actual widths

On an approximately 1800×1400 canvas use 100 px per horizontal unit, origin (300,1000), giving x-ranges 300..500,500..800,800..1300. At 160 px per density unit, heights are 320,480,160 and tops y=680,520,840. Rectangles touch; draw shared boundaries once. Fix equal-width mistakes before changing heights. Different axis scales are allowed if declared; screen squares do not define mathematical area.

## Recover four, nine and five from areas

Areas are 2×2=4,3×3=9,5×1=5, total 18. First/last counts compare 4:5, not height ratio 2:1. Renaming the axis “frequency” without changing geometry changes meaning. Mathematical areas remove display scales; pixel areas share factor 100×160, preserving ratios but not values 4,9,5. Retain a short area ledger so neither tallest nor widest alone misleads.

## Divide by eighteen for relative frequency density

For total area one, divide densities 2,3,1 by 18 to get 1/9,1/6,1/18. Bin areas become 2/9,1/2,5/18, equivalently 4/18,9/18,5/18, summing to one. Relabel the axis relative frequency density. Keep widths, declare any different display scale and avoid implying unchanged values from similar heights. Even relative-density height is not bin probability; multiply by width.

## Avoid inventing within-bin detail

Constant rectangle height does not establish uniform observed values within a bin, and count nine cannot recover nine raw observations. New boundaries require raw-data rebinning, not proportional slicing presented as measured counts. Closing the last endpoint at ten does not make its width six: 10−5=5, not six listed integers. Keep interval width separate from discrete-category counting and state the exercise’s unknown within-bin detail.

## Troubleshoot widths and axis labels

Areas 8,27,25 reveal raw-count heights; divide by widths. Total area one with a count-density label suggests missing normalisation relabelling. Recheck width subtraction and half-open membership for 6-wide last bins or repeated boundary values. Correct one condition, preserving counts and total 18. Labels move without boundaries; decorative shadows carry no area. Inspect export objects and do not assume axis text automatically recalculates heights.
