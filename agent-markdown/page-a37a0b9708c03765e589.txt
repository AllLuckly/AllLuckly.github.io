用同一条 SVG 路径比较圆形与平直端帽，观察零长度短划和间隔。

## 明确对照条件

W3C 的 SVG 描边规范给出零长度短划配合圆形端帽形成点状描边的示例。这个练习比较同样的 0 20 虚线数组在 round 与 butt 端帽下的外观；0 是绘制段长度，20 是后续空隙长度，并不是 20 个点。先在浏览器建立基准，再观察 VectorPaint 导入和输出；规范示例不保证任何应用版本保留属性。

## 设置直线和画布

在纯文本编辑器新建 UTF-8 SVG，根元素设置 SVG 命名空间和 viewBox 0 0 240 120。添加两条 line，均从 x1=20 到 x2=220，y 分别为 35 和 85，stroke 设同一深蓝色、stroke-width 为 8、stroke-dasharray 为 0 20。第一条设 stroke-linecap 为 round，第二条设为 butt。给根元素设置适合观察的宽高，保存为 zero-dash-caps.svg，复制一份备份并确认扩展名。

## 预测点的大小与间距

沿 200 用户单位的中心线，周期为 0 加 20，即 20 用户单位。round 端帽在零长度短划位置形成圆形标记，其直径由描边宽度 8 决定；相邻标记中心间隔约 20，间隔不是圆边之间的距离。butt 端帽的零长度段没有相应的圆形面积。路径端点处的截断及渲染细节需实际查看，不以理论端点数量推断每个浏览器显示完全相同。

## 在浏览器建立参考

用支持 SVG 的浏览器打开原稿，先观察上行是否呈一列圆点，下行是否缺少同样的圆点。确认路径颜色与背景对比足够，避免将不可见的零长度 butt 短划误认为文件无法加载。放大整个页面比较点的中心间隔；缩放会影响像素呈现，但不会把 20 用户单位自动变为 20 物理毫米。若上行是实线，检查数组、端帽属性拼写及 CSS 覆盖。

## 区分中心间距与空白

假设两圆点直径均为 8、中心相隔 20，位于直线内部且未被端点截断时，相邻圆边之间的空白约为 20 减 8，即 12 用户单位。这个计算只针对相同直径、同一条直线上相邻圆点；点被剪裁或变换时需重新判断。用纸在 x=20 和 x=40 标中心，再各向左右量半径 4，检查边缘位置。不要将空隙数组 20 直接称为圆边间的可见空白。

## 改宽度做一项对照

另存副本，把两条线的 stroke-width 同时由 8 改为 12，数组和坐标保持不变。预期圆点直径增大，相邻中心仍按 20 的周期排列，内部圆边间空白约变为 8；观察端点与边缘时仍需考虑裁切。不要只改上行的宽度后把两行不同归因于端帽。记录原稿和副本各改动的属性，再对照浏览器结果。

## 改变间隔再比较

再从原稿另存另一副本，将两行数组同时改为 0 30，线宽保持 8。现在中心周期是 30，内部圆点之间的可见空白约为 22 用户单位；点的大小不应只因间隔变化而增大。将该文件与改线宽的副本分开命名，避免同时改变两个因素。若圆点数量变化，以线长和周期共同解释，不把点数直接当作数组第二项。

## 在应用中打开副本

在 VectorPaint 的作品集，点右上角方框向下箭头导入图标（无障碍标签为“导入作品”）；若作品集为空，可点“从文件导入”，在系统文件选择器中选择本练习的 SVG 工作副本。若界面不同、入口不可见或文件无法读取，记录未完成。不要把 stroke-linecap 直接当作必须存在的应用按钮。导入后先不编辑，比较上行点的大小、间距和下行的外观，再尝试分别选择两条线。记录相对浏览器的变化，不因外观相同就断言零长度数组仍被原样保存。

## 排查样式和显示差异

如果应用中两行都变成圆点，先检查导入是否对端帽做了转换、是否有统一样式覆盖，以及是否打开了正确副本；不要立即断言应用有缺陷。若只有部分点消失，检查视图框裁切、缩放、透明度和导出范围。浏览器与应用可能采用不同渲染器，记录版本、文件名及可见结果，未实际测试的条件保持未知。

## 输出后进行两种检查

保存可编辑原稿，通过当前版本实际可见的分享或导出入口另存文件，不覆盖 SVG 备份。重开输出检查点形、间隔和是否裁掉首尾；若输出为 SVG，用文本编辑器查看线段、数组与端帽是否保留或转换成别的表示。即使外观相同，也不能仅凭截图证明属性仍可编辑；位图只支持外观比较。记录预期、浏览器、应用和重开结果，未执行的设备步骤标记待核。

## 对照全零数组

从原稿另存一份，将两行数组都改成 0 0。SVG 规范规定，数组所有值均为零时按 none 处理，因此预期变为无虚线图案的连续描边；这与 0 20 里存在非零空隙不同。比较时保持线段、颜色和宽度不变，并在副本名注明全零。若看到连续线，不要误以为零长度短划叠加了无穷多个圆点；这个结果是规范对全零数组的特殊处理。

## 记录实验边界

把每份文件的数组、线宽、端帽、浏览器版本和观察结果列成表。首次比较只需记录上行与下行，不把一次浏览器显示推断为所有设备结果。没有在应用中实际打开的文件应标为待核。
