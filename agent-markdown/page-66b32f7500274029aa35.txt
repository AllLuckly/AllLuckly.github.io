Prepare a manifest for three different tracks, import them together and retain item-level results rather than only a total.

## 1. Choose three small files with different content

Prepare three authorised, system-readable small audio files, labelled A, B and C externally, retaining originals, full filenames, sizes and opening sounds. Their content must differ: three renamed copies do not justify expecting three additions. Mark an earlier imported item and choose a new sample for this first all-new batch. Files well below the published 512 MB per-file limit are sufficient; there is no need to manufacture a maximum-size test. Preserve the existing library rather than clear older music merely to simplify counting.

## 2. Build three identity rows rather than rely on sorting

Create rows for source location, filename, verified title and audible anchor, followed by selection, feedback, library lookup and playback. Unknown titles remain blank rather than invented from folders. Keep this manifest externally; no batch-report exporter is assumed. Re-find each original, exclude same-name editions and establish provider readability. Three rows describe expected inputs, not three successful outputs. Fill each result from the action actually performed instead of checking every box in advance and supplying reasons afterward.

## 3. Verify all three selections in one flow

Use the installed file-import flow to select A/B/C together within a provider or location supporting multiselect. If the picker cannot retain selection across separate providers, record separate batches instead of claiming one three-file selection. Before confirmation, compare identities and visible count. A selection mark means pending submission, not library storage. Do not add an unfamiliar file merely to reach three. Correct accidental choices first, reconcile the manifest and selection, then perform the confirmation actually offered by the flow.

## 4. Retain actual feedback and uncertainty

Submit once and observe visible progress, completion or error without repeated confirmation or switching to another batch before its state is clear. Multiselect does not promise simultaneous success for every file; treatment of other files after one failure needs actual feedback. A general notice is not a per-item success list. Leave those checks for the library instead of inventing concurrency order or percentages. Record start time, selected identities and exact feedback, retaining uncertainty before resubmitting the same batch repeatedly.

## 5. Locate each row instead of checking only the total

Return to local music and locate A/B/C individually through title, artist and sound; filenames need not be displayed unchanged. A total increase of three alone cannot establish that these particular tracks arrived, especially if other library changes occurred. If only two are found, mark the third unresolved and inspect its metadata/source identity instead of substituting similar artwork. For a skipped duplicate, revisit prior-content history. Preserve the actual outcome rather than delete an older item to force additions to equal selections.

## 6. Listen at an identifiable point in each track

Open each located track, compare its opening sound with the manifest and try pause/resume. Record playback only when heard. Retain a duration or content mismatch in its own row instead of passing the whole batch because two others work. Use comfortable volume; complete albums need not be played. Preview artwork, progress and audible output are different evidence. Unheard positions and full later-track integrity remain unchecked; one small batch does not certify permanent compatibility of the collection.

## 7. Use the failing column to choose the next step

An unselected item needs selection checking; a submitted item without feedback needs import checking; an absent library item needs identity/duplicate checking; a silent present item needs track/output checking. These columns do not all mean multiselect failed. Change only an affected sample and label a new round. Preserve successful rows and failure evidence before retrying unresolved items. No automatic rollback, resumable transfer or retry-failed-only button is promised; use the actual flow instead of inventing batch controls.

## 8. Deliver selection-to-result differences

Re-find the three originals and confirmed library items, preserving manifest, submission feedback and listening results. State selections, additions/existing items and tracks actually heard separately instead of merging them into one count of three. Retain unresolved work rather than delete records to make every row green. Larger batches or another provider can reuse the method but need their own identities and outcomes. This delivers traceable reconciliation for three files, not physical-device certification of every batch size and device.
