Use two accounts you control to compare reading-list visibility before and after promotion and observe actual client access.

## Understand the sharing scope

Kavita describes reading lists as ordered chapters or issues that users can create and administrators can promote for server users. Promotion changes visibility within the server; it does not itself publish a library on the public internet or guarantee every user access to every item. Whether Manyue+ shows the list and under what name depends on the connection and actual interface.

## Prepare an authorized isolated sample

Use a test server you administer and two test accounts, A and B, each explicitly permitted to access the test library. Choose two authorized, distinguishable comics and create a test reading list in an isolated library without private information. Do not use another household member’s private list or include OPDS authentication keys in notes or screenshots. Preserve existing lists and reading progress.

## Record the starting state

Sign in to Kavita’s web interface as creator A and record the test list name, both item identities and their order, plus any current promotion indicator. Check whether B can find the same list in B’s own web interface. If it is already promoted, do not treat it as a private baseline. Confirm B can access the library containing both items without assuming library access makes A’s personal list visible.

## Observe accounts and client entry points

In Manyue+, open A’s own Kavita connection and check account identity, any reading-list entry and the test list. Repeat separately with B’s connection. Labels and navigation may vary with client version or connection type. If there is no corresponding entry, record it as unavailable or not observed; do not rename an ordinary series directory as a reading list. Record account identity before switching so cached A content is not attributed to B.

## Confirm authority to promote

Kavita controls promotion through server roles; its user-settings documentation describes Promote permission for sharing collections and reading lists. Continue only as the test server administrator or a user explicitly authorized to do this, after understanding that other server users may see the test name. If authority, audience or restoration is uncertain, stop at read-only observation. Do not elevate B or use someone else’s credentials to work around a missing control.

## Promote the isolated test list once

Using the control actually shown in the current Kavita web interface, promote only the verified test list once and record the actor, list name and time. If no control appears, mark the step incomplete and check version and permissions rather than assuming a fixed label. Since promotion can make the name visible to other server users, avoid sensitive names. Do not change library permissions or item order at the same time.

## Check visibility in the web interface first

Return to A’s web view to confirm the test list still references the same two items. Switch to B’s web view and record whether the list name, items and order are visible. If B cannot see it, confirm the correct list was promoted, the operation completed and the account is correct. If a visible list contains an inaccessible item, separately check its library and content restrictions; sharing a list and access to its resources are different conclusions.

## Then check actual Manyue+ behavior

Return to A and B connections in Manyue+, navigate back and reopen the relevant directory when the interface allows, and record whether the list appears and its count and order match the server. If the client exposes no list entry, retain the web result and mark client verification incomplete; server support does not establish app support. Open only authorized chapters, record opening and return, and distinguish list visibility from full-file download or page streaming.

## Troubleshoot and record safely

When results differ, check one condition at a time: account, server, list identity, promotion state, library authorization or whether the page needs reopening. Record the error category and observation time without exposing full authentication URLs, cookies or tokens. If items are missing, compare each item’s access rights and the server list. Do not broaden anyone’s access merely to pass the test or delete existing lists.

## Restore the isolated test and document the outcome

After confirming the selected list is the test list, use the current server interface to restore its original visibility. If the effect on others is uncertain, stop and let the administrator handle it. Preserve existing account data and sample comics. Record server results before and after promotion, client results for A and B, unavailable entry points and skipped steps. This guide relies on public documentation and does not claim access to a private server or device testing.

## Check order and permission separately

If both accounts see the list but one item is inaccessible due to permissions, preserve the original order and record the position of the missing item; do not infer that the server reordered it. Compare the administrator’s original list with visible items in B’s web interface and Manyue+. Permissions and ordering need separate evidence. If no authorized second item is available, mark that comparison untested.
