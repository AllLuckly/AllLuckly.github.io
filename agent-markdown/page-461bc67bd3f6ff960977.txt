While safely parked, compare one imported track across the phone, CarPlay list, output and queue.

## Prepare the track and environment

Choose an authorized track already imported locally in 调调. Record full title, artist and duration and retain the source file. Version 1.0.4 publicly describes CarPlay browsing of offline music, favorites and recent playback, plus queue viewing; it does not establish compatibility with every car. You need a CarPlay-compatible vehicle or receiver and an already paired iPhone. Without them, leave the in-car observations pending.

## Record a phone baseline

Before any playback, inspect visible favorites and recent playback on the phone, recording whether the target appears and the observation time; mark absent controls unknown. Then play a short recognizable part and note its cue. Record the current track and queue, distinguishing locally imported items from possible server items. Stop playback and note the previous output and volume. Preserve the existing queue and audio files.

## Connect only while parked

Park the vehicle safely and lawfully before connecting CarPlay using the actual Apple and vehicle instructions. Follow the existing wired or wireless pairing method; do not operate the phone, settings or list while driving. If CarPlay is unavailable, inspect vehicle support, connection or pairing and system requirements. Stop if you cannot operate safely. After connecting for the first time but before car playback, record visible car favorites and recent playback with time. Phone playback may already have changed history, so this is a pre-car-playback state, not the state before the entire exercise.

## Check list and track identity separately

When the 调调 entry actually appears on the vehicle screen, open it and find the visible offline list. Compare title, artist and duration; matching names alone do not prove identical audio. Use the recorded cue as another check. If an entry or detail is not visible, record it as unconfirmed rather than inventing a menu or assuming that the phone file must appear. Resolve same-name recordings on the phone first.

## Play and inspect the queue

Still parked, select the identified track and use low volume to check the output, track label and player state. Open the visible queue and record order. A queue is an arrangement, not a file backup; unseen entries are unknown. Record manual selection rather than describing it as automatic continuation. Do not add or delete server music.

## Treat connectivity as a separate condition

If safe and it will not disrupt other tasks, record the original network state and test the imported local track without network. Verify the actual source remains local. Restore connectivity before observing server items separately. Local success does not prove server caching or offline availability for all car items. If disabling network also disconnects wireless CarPlay, stop and record that conditions cannot be isolated.

## Compare favorites and recent playback

Compare the phone state recorded before the first playback with the car state recorded before the first car playback. Play once more and check each again if the interface allows it. Do not call the car state the baseline before the entire exercise: the earlier phone audition may have changed history. Favorites are explicitly saved items, recent playback is history, and the queue is future order; none proves the others. If no update appears, record any refresh and waiting conditions rather than assuming immediate synchronization. Do not alter personal favorites just for demonstration. If you create a test favorite, remove only that item afterward.

## Write an auditable observation table

List the phone’s local track, visible car list, actual choice, sound output and queue separately as observed, unobserved or not applicable. Include time, parked status, connection method and manual actions. A visible list before playback means list observed and sound pending, not an offline playback pass. If the network control breaks wireless CarPlay, mark conflicting conditions; sound buffered before disconnection does not prove sustained offline playback. Repeat from the same owned recording and volume when a comparable retry is possible.

## Troubleshoot and restore

First record a checkable observation, such as “the vehicle list shows the title but no sound was heard after selection,” rather than simply “the car is unsupported.” Note the displayed title, position, connection method and any error message so a later one-condition retry has useful evidence.

If the phone plays but the car is silent, check output, volume, source, player state and connection separately. For a missing item, check import identity and visible list scope. Change one condition per retry. Restore network, output and volume, stop the test and restore any queue you changed. Deliver device and system versions, track identity, parked condition, list, playback, queue and pending observations. No physical car test is claimed.
