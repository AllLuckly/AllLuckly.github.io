A mark beneath an English word does not necessarily mean the body text has changed; automatic replacement can actually change it. Apple documents system spelling checks and auto-correction, but host and third-party keyboard behavior can differ. Use Jianlai and a fictional sentence in an ordinary practice note to record each stage. Do not assume Jianlai offers a particular marker or that a system option applies to it.

## Create a non-private practice copy

Prepare your iPhone, an available Jianlai English layout and an ordinary note titled “Spelling observations”. Do not test in sent messages, account fields or formal documents. Enter or copy `target: the blue cup` as a reference and save it. Do not include real names or passwords. Verify a system keyboard remains available as a safe alternative. If keyboard identity or the English layout is uncertain, mark the exercise pending.

Prepare columns for input action, actual body text, visible feedback and manual correction. Record device, system, Jianlai and host versions or names. Some feedback is brief: write “not observed” if you missed it instead of inferring it from the final spelling. Preserve the practice copy and reference line. Do not clear personal dictionaries or change keyboard permissions.

## Inspect current settings before changing anything

Apple lists auto-correction and spelling or grammar checking among system keyboard options. Use the path visible on your device and record original values; wording and scope vary by version. System documentation does not guarantee identical behavior from a third-party keyboard, every host or every language. Record the system option separately from Jianlai’s actual feedback.

If the user does not want to change options, observe only the current state. An optional comparison requires a known original value, a restoration path and the user’s willingness. Do not disable necessary accessibility or input settings for an experiment. Restore any change afterward; deleting other keyboards or reinstalling Jianlai is unnecessary.

## Enter a deliberately misspelled example

Start a new line with `A:`, select the identifiable Jianlai English layout and use the available input method to enter `teh blue cup`. Here `teh` is an intentional practice spelling; the target is `the`. After the first word, observe candidates, body text and any underline or replacement feedback. If a component changes the word before you see it, record the actual outcome rather than manually reproducing the original and pretending it was retained.

Finish the line and record whether the body contains `teh`, `the` or something else, as well as confirmation and space actions. Do not assume a space accepts a candidate or that a marker is red. Font, host and accessibility settings can change appearance. Not seeing a marker differs from proving none appeared. One replacement does not validate the whole dictionary or spelling system.

## Separate feedback from text changes

If the body retains `teh` and an identifiable mark appears, record both before tapping. That is feedback, not a completed correction. If the body already reads `the`, record when it changed and whether you selected a candidate. The body result alone does not identify which component performed replacement. If neither feedback nor change is seen, record that without declaring the feature absent.

At the user’s choice, use a visible host suggestion or Jianlai manual input to change the practice word to `the`. Before replacing, verify the selection covers only the target. Afterwards check neighboring `blue cup` is unchanged. If the whole sentence was replaced accidentally, use known host undo or the reference copy and record the recovery separately; do not repeatedly delete blindly when undo is unavailable.

## Optionally compare the system keyboard

On another line `B:`, switch to the system English keyboard and observe the same spelling in the same host, recording that system settings stayed unchanged. Apple describes system auto-correction; actual words, suggestions and language support depend on the device. Matching or differing results describe this session only. A system suggestion does not establish an equivalent Jianlai feature.

To compare a system checking option, change only one at a time and only with user willingness and a known original value. Use a fresh line, record results and restore the option afterwards. A host can also supply its own checking; not every marker can be attributed to Jianlai. If the source is uncertain, record “source unconfirmed” and retain the actual text and actions rather than guessing.

## Troubleshoot and restore

If Jianlai is absent, check the field and active keyboard. If suggestions are missing, inspect language, host and current settings. If text changed unexpectedly, inspect selection actions and restore from the copy. Change one condition at a time; do not reset the phone or clear dictionaries to force agreement. Reopen the note, confirm the reference and observations remain, and restore the original keyboard and any changed system options.

The final table should distinguish intended input, actual body, feedback, automatic or manual actions and unobserved items. This exercise uses public system documentation and does not claim a device test. One example does not guarantee corrections for real names, other languages or all hosts. Observe afresh after a device or version change rather than pre-marking the table as passing.
