Public information describes Jianlai as multilingual, but does not guarantee identical Japanese layouts or voiced-kana controls on every device. Use two original nonprivate practice lines to check the available scheme, kana appearance and actual committed text separately.

## Prepare two explicit targets

Keep a reference card in a safe copy of an ordinary note: “かみ” on the first line and “がみ” on the second. Neither line has punctuation or trailing spaces; each commonly displays two kana positions. The first position is unvoiced か in the first line and voiced が in the second; both end in み. This is a character-copying exercise, not an inference about the fragment’s meaning or a required conversion to kanji. Preserve the reference separately.

## Confirm the actual keyboard and scheme

Confirm Jianlai has been added as a system keyboard and select it in an ordinary field. Find an actually available Japanese scheme and record visible layout, language and controls. Do not assume a kana layout, romaji conversion, separate voicing key or fixed candidate order. If no usable Japanese path is available in the installed app and host, mark entry pending. You may copy trusted references for later text checks, but identify those characters as pasted rather than directly entered with Jianlai.

## Enter the first line and retain the first result

In a fresh practice copy enter “かみ” using the real scheme. If candidates appear, confirm the target kana through the visible interface; if the scheme commits directly, record that. Before moving the cursor observe whether composition remains unconfirmed, then complete confirmation when possible. Inspect committed text for か followed by み, without kanji, extra spaces or punctuation. If a candidate converted to kanji, preserve that first result and correct a separate line rather than claiming first-attempt accuracy.

## Enter the second line position by position

Insert a real new line and enter “がみ.” Use only an actually visible and confirmable voicing method. If unavailable, leave the entry incomplete rather than trying imaginary shortcuts. Inspect the first kana’s voiced mark and the second kana, then verify the document retains the expected text. Candidate display, user confirmation and retained text are separate events. Seeing が among candidates does not establish it was committed. If the mark is too small to distinguish, record display conditions rather than declaring an input error.

## Compare text rather than pronunciation alone

Both lines retain み in the second position; the visible difference is the first. Do not infer identical or different text from listening or pronunciation alone, and do not turn speech recognition, pronunciation quality or language skill into an input result. Move the cursor or select text without altering the original and check each position. A visual wrap is not a new logical line; record two lines only after inserting a real break.

## Check possible code-point representations

Unicode provides a precomposed voiced kana and also allows a base kana followed by a combining voiced mark. A visible が may be U+304C or U+304B followed by U+3099; similar appearance does not establish raw code points. If a local tool can retain original text, inspect the first visible position in the second line, first checking known references to ensure the tool does not silently normalize. Without evidence write “appearance checked, code points pending.” Do not demand one representation from every keyboard or infer search or sort behavior from one example.

## Record target, action and first result

A local Unicode tool can inspect both raw lines: in precomposed form the first is U+304B U+307F and the second U+304C U+307F. A canonically equivalent second line can be U+304B U+3099 U+307F. These counts are code points, not necessarily user-perceived kana positions or cursor movements. Copying into the tool can also transform text, so record the handoff and validate the tool with known references. Do not submit private text to an external site.

For each line record target, available scheme, confirmation action, first committed result and any correction. If only the first was entered, mark the second incomplete; copied text is not direct keyboard entry. If both look correct without raw sequence inspection, do not claim code-point verification. You may repeat under the same display conditions and record both outcomes, but a single repetition does not establish behavior for all Japanese schemes or hosts.

## Troubleshoot and restore

If the Japanese scheme is absent, inspect the actually selected system keyboard and visible language options. If a candidate is missing, record the entry route and consider a reference paste for the text-only exercise. If unexpected kanji appears, inspect candidate confirmation and host conversion without automatically assigning blame. Change one condition per trial and keep a nonprivate starting copy. Restore the usual keyboard and display. The exercise draws on public multilingual information and Unicode normalization; no physical Japanese input, rendering or search test is claimed.

Keep the date, device and host version and use the same reference card for later checks. Record results after version changes separately.
