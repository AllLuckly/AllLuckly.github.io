Start with an authorized CBL list already imported in Kavita, and check server matches and books actually visible in ManYue.

## Prepare an authorized test list

Choose a small CBL reading list and two authorized comics in a Kavita instance you manage or may access. Record each intended series, volume, issue and a visual marker from the original book. Preserve the source list and original comics. Do not use another person’s private library, files or account key as test material; ask the administrator if management access is unavailable.

## Understand server-side matching

Kavita documents that CBL import matches entries to library series, volume and issue through ordered matching tiers, with user-created remap rules taking priority. Names, years and external identifiers depend on the actual file. A server match alone does not establish that the comic file is the intended edition; further checking is needed.

## Inspect existing results in Kavita

Find the imported test list in the current server interface and record each actual series, volume and issue match and any unmatched or error indication. Open the corresponding comic’s first page and compare the recorded anchor. If an item is unmatched, do not infer success from a similar title. Check list information, actual library item and account access. Record results before changing the library or overwriting the original list.

## Read the same source in ManYue

Open the same connected Kavita source in ManYue and confirm server and account. Use the actual interface to locate the corresponding series and chapter. Inspect a reading-list entry only if it actually appears; otherwise mark it not observed rather than claiming support for all Kavita list features. Open an accessible test chapter and separately compare title, number, page count and image.

## Separate matching from display differences

If Kavita matched the wrong issue, inspect the CBL entry’s series, volume and issue and any existing server remap rules. Let an administrator use official guidance; do not batch rename based on guesses. If Kavita is correct but ManYue differs, first confirm the same account, source and item, then record app and server versions, actual image and redacted errors.

## Preserve records and original configuration

Retain the source list, match outcomes, whether rules changed and reading-verification results. Mark unperformed imports or remapping unperformed. Do not change a shared list without authorization or share full server addresses, accounts or comic content. Confirm original files and reading records remain afterwards. This follows public documentation and claims no server, import or device testing.

## Separate the fields of each list entry

Give each test entry a row for the series, volume, issue and year in the list and the expected library item. Suppose the entry says “series A, volume 1, issue 2” but the library contains same-named editions from different years. Compare covers, years and self-made visual markers first. Kavita documents multiple matching strategies; similar names are not the sole criterion. Without actual evidence do not guess which tier was used.

If series is correct but issue is wrong, record series match and issue match separately instead of calling the whole list wrong. If the expected comic does not exist in the library, mark it not found rather than expecting the program to create a file. A reading list and the original comic are different objects; importing a list does not replace a backup or rights to the source file.

## Understand the scope before remapping

Kavita documents user-created remap rules at series, volume or issue level, taking priority over other strategies. Only an administrator or authorized user who understands their scope should change them; record existing rules and the test list first and validate in an isolated sample. Do not add a rule affecting an entire series to fix one result, or change someone else’s shared list. Without configuration rights, report the finding to the administrator.

For example, a test entry should point to issue two of volume A but matches issue two of a same-named volume B. Confirm provenance, year and content for both files, then inspect whether an existing rule affects the entry. If an authorized change is made, record destinations before and after and recheck both test entries; correcting one does not guarantee all others. If rules cannot be inspected, mark unknown rather than describing a guessed configuration.

## Move from server result to client verification

First record whether Kavita opens the target comic and its actual image. Then find the same series and issue in ManYue. If the list is absent but the chapter opens through the series, record those results separately; do not claim that the list feature succeeded. If ManYue differs from the server, confirm direct Kavita versus OPDS source, same user and whether data is still loading; do not reveal the server address to prove the connection.

After testing preserve the original CBL, comics, existing rules and reading progress. If a rule’s effect on other items is unclear, ask the administrator to compare current and original states instead of deleting it yourself. A support report needs only redacted series identifiers, volume and issue, server match, client result, versions and time—not copyrighted comics or access keys. Mark import, rule changes or playback unperformed if not actually done, and record the end time and test-account identifier.
