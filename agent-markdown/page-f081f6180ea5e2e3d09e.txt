在三条等长 SVG 路径上比较路径文字起点，区分路径长度和视图框百分比。

## 先确定百分比的分母

MDN 的 SVG startOffset 资料说明，textPath 的百分比偏移沿引用路径长度计算：0% 是路径起点，100% 是终点。这与描边虚线数组百分比所用的视口归一化对角线不同。本文使用从左向右的直线和一个英文字母，方便比较；规范描述不保证 VectorPaint 当前版本保留 textPath 或其属性，应用步骤需要实际观察。

## 设置三条同长路径

在纯文本编辑器新建 UTF-8 SVG，根元素设置 SVG 命名空间及 viewBox 0 0 280 140。建立三条独立水平 path，分别从 x=20 到 x=260，y 为 35、70、105，分别命名为 p1、p2、p3；三条长度均为 240 用户单位。用淡灰色描边使路径本身可见。路径方向均由左向右，避免在首轮实验混入方向变化。

## 为路径放置文字

建立三个 text 元素，方向设 ltr、text-anchor 设 start、字号相同。每个元素内放一个 textPath，分别用 href 引用 p1、p2、p3，并写入同一个字母 A；三个 startOffset 依次设为 25%、50%、75%。保存为 textpath-offset.svg，复制备份并检查扩展名。检查每个 href 指向存在且唯一的路径 ID；引号、标签及命名空间错误会使文字或路径不显示。

## 先计算三个起点

每条路径长 260 减 20，即 240 用户单位。25%、50%、75% 对应沿路径前进 60、120、180 单位，因此从画面左边计算，理论起始位置分别位于 x=80、140、200。这里说的是文字排版起始位置，不保证字母最左边的可见墨迹像素恰好接触该坐标。先把计算写在纸上，不要把百分比乘以 viewBox 宽 280。

## 在浏览器对照参考线

在支持 SVG 的浏览器打开原稿。三条灰线应平行且等长，字母位置从上至下逐步向右。可以额外添加经过 x=80、140、200 的淡色竖直参考线辅助观察，但不要改变文字或路径。若某行文字消失，检查路径 ID、href、标签及字体大小；若位置都一样，检查每个 textPath 的偏移和可能覆盖样式。记录浏览器与字体，不宣称所有渲染器的字形墨迹完全相同。

## 用数值偏移建立对照

另存一个副本，把三行百分比分别替换为数值 60、120、180，其他条件不变。在没有额外路径长度校准或变换的本例中，它们与原百分比指向相同的沿路径距离，浏览器中的相应字母位置应接近。用副本比较时保持同一字体与显示比例。如果两份差异明显，先检查引用路径是否相同、是否引入 pathLength、变换或不同字体。

## 单独改变路径长度

再从原稿另存一份，把第二行路径终点 x=260 改为 x=220，起点仍是 x=20；其他两行不改。第二行路径长变为 200，50% 对应从起点前进 100，即 x=120，而不是原来的 x=140。使用同一图内的灰线和文字比较，不把屏幕截图的缩放误当成路径长度变化。先只改变这一项，确保 href 仍指向第二行路径。

## 导入副本并核实可编辑性

在 VectorPaint 的作品集，点右上角方框向下箭头导入图标（无障碍标签为“导入作品”）；若作品集为空，可点“从文件导入”，在系统文件选择器中选择本练习的 SVG 工作副本。若界面不同、入口不可见或文件无法读取，记录未完成。导入后先比较三行文字与灰线的位置，再尝试选择文字与路径。文字显示正确不等于 textPath 及偏移仍作为可编辑属性存在；若应用只显示轮廓或合并对象，记录所见而不推断内部结构。

## 区分起点和居中

本文将 text-anchor 固定为 start，使文字从计算出的起始位置排列。若另存副本改为 middle，文字会围绕该位置居中，字母可见墨迹的位置也会变化；不要把这个变化归因于 startOffset。字体不同也会影响字母宽度，但路径起点的数值计算与字体宽度是两个问题。每次只改变一个属性，并在比较表中写明锚点、偏移和字体。

## 排查路径方向与样式

若 25% 的文字出现在右侧而不是左侧，核查路径命令是否从 x=260 指向 x=20；百分比从路径实际起点计算，不永远从画布左边开始。再检查方向、锚点、引用 ID、路径变换及 CSS 覆盖。曲线路径的长度不能用水平端点差替代；它需要沿曲线测量。本练习只对水平直线给出手算数值。

## 保存输出并重开

保存应用可编辑原稿，再通过当前版本实际可见的分享或导出入口另存文件，不覆盖 SVG 备份。重开输出检查三行相对灰线的位置；若为 SVG，用文本编辑器核 textPath、href 和 startOffset 是否保留，或是否转换为路径。位图只支持外观检查，不能证明文字可编辑。记录预期、浏览器、应用与重开结果，未实际执行的设备和导出步骤标记待核。

## 核对每条路径的身份

三条路径的纵坐标不同，即便长度相同也不能共用错误的引用。将 p1、p2、p3 分别与上、中、下三行配对，再核每个 textPath 的 href。若三行文字都挤在第一条线上，优先检查是否复制时保留了同一个 ID 或引用，而不是马上调整偏移。保存前确认 ID 唯一，参考线仅作视觉辅助。

## 考虑端点附近空间

本例使用一个字母并让最大偏移为 75%，以便路径末端仍留出空间。换成长单词或将偏移提高到 100% 时，文字可能超出路径可用范围；要另存副本并观察，不将结果外推为本例的计算错误。
