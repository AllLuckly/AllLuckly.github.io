Design a fictional reading-event ticket with a clear hierarchy, trim margins and checked serial numbers, while retaining editable text.

English translation of the [Chinese original](<https://allluckly.cn/guides/vectorpaint-event-ticket/>), translated on 2026-10-26. Original publication dates, attribution, code and version notes are retained.

A ticket must help its holder find the time and place and help staff locate its number. This fictional reading-event exercise focuses on the relationship between the main ticket and its stub. Example numbers and barcode-like decoration are layout elements without validation or security functions.

## Define the job of each part

Prepare a name, date, admission time, location, seat and number, deciding which must appear on both parts. Put full instructions on the main ticket and a short name and number on the stub. Remove decorative wording without a purpose. Use a 1200 by 500 pixel practice canvas, reserving roughly one quarter for the stub. For printing, obtain the actual dimensions, trimming and perforation requirements before choosing units and margins.

## Establish the two regions

Draw a light background and a thin divider, organising background, divider and text separately. A drawn divider is not a production perforation or cutting die. Inset content on both sides. Temporary safety-area shapes can help check boundaries, but ordinary shapes export and must be removed or hidden. Before moving a text group, ensure the background has not also been selected.

## Set the reading order

Place the event name first, date and times second, and address and instructions last, using no more than three size levels. Include the full date and label admission and start times separately when they differ. Break long addresses at meaningful location boundaries. Test the longest address before decorating so essential directions remain readable.

## Check number and seat correspondence

Keep the number editable on both parts. Make separate examples numbered 001, 002 and 003, updating each manually because duplication does not imply automatic numbering. Treat seat and serial number as separate fields. Read the main number, stub number and seat for each ticket before making the next copy, then compare all three for unchanged old numbers. Gallery thumbnails are insufficient for this check.

## Test the content margins

After saving the original, temporarily cover small edge areas in a preview copy to reveal content too close to the trim. This is a margin test, not a confirmed production tolerance; remove the covers from final output. If the stub is narrow, shorten its name or instructions before compressing the number. Inspect at the intended viewing size for ambiguous digits, hyphens and seat letters.

## Separate production and display files

Keep an editable original and export a display image with its full background. Ask the printer for accepted formats and dimensions; a pixel preview is not automatically print-ready. Reopen document exports to inspect fonts, numbers, backgrounds and edges. Name files with the number range and revision. Replace personal details before public display; actual check-in needs a ticketing system or explicit manual rules.

## Rehearse one check-in

Shuffle the three tickets and hide their main parts. Check whether each stub identifies its event and number, then reveal and compare both numbers. Inspect a full phone preview for easily found time and location. Adjust only the field first misread and repeat. Distinguish similar seat and serial values with explicit labels, not colour alone. This checks information retrieval rather than security; require matching halves, an explicit date and complete address before delivery.

## Troubleshoot mismatched numbers

For mismatched numbers, inspect both text objects in the correct original and rule out an old export. Correct that ticket, export again, then check the others without overwriting every copy. For clipped addresses, check text bounds, lines and font substitution before enlarging the canvas. For a mispositioned printed stub, measure the discrepancy and revisit production specifications instead of guessing another divider.
