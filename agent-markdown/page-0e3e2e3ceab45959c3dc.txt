Use self-made ordinary and special chapter copies to check Kavita recognition and content actually visible in ManYue separately.

## Prepare two self-made comics

Create two small authorized CBZ files: mark an ordinary chapter’s first page “ordinary 1” and a special’s first page “special A.” Record page count and size. Keep the originals and place copies in a test series folder on your own Kavita server. If an isolated test library or administrative rights are unavailable, stop writing and ask the administrator; do not modify another person’s comics.

## Understand Kavita special naming

Kavita’s file-management documentation describes SP01, SP02 and similar filename markers for forcing special status; words such as Annual or One Shot alone do not force it via filename. This is a server-side rule, not proof that ManYue displays the same name. ComicInfo metadata and library type may also affect results, so check current documentation and configuration before acting.

## Observe server classification

In the test series use a clear ordinary-chapter filename and a special test copy marked SP01, then scan the test library under the administrator’s process. After actual completion, check whether Kavita classifies the ordinary chapter and special and open each first page to compare markers. Filename, server classification and actual page are separate results. On mismatch record version, library type, filename and scan status first; do not modify the only original.

## Observe actual entries in ManYue

Connect ManYue to the same Kavita server and account and locate the test series. Record whether the interface displays ordinary chapters, specials or other groupings without assuming a dedicated specials tab. Open visible items and compare first-page markers and counts. If no special entry appears, record not observed; that alone does not establish deletion on the server.

## Handle mismatches in layers

If Kavita itself does not recognize the test copy as a special, the administrator checks file location, marker, library type and actual metadata first, changing one test condition before rescanning. If Kavita is correct but ManYue does not show it, confirm account, source, loading state and versions, then record the observation for support. Do not batch rename or delete a shared library for one test.

## Record and retain original material

Use redacted identifiers to record server version, naming of both files, server classification, ManYue display and opening results. Mark unperformed scans or playback unperformed. Do not share server addresses, keys or other people’s comics. Remove temporary copies under the administrator’s process and confirm original files and reading data remain. No device or server test is claimed.

## Sample files and expected records

In a practice-only series folder, prepare an ordinary copy `Sample c01.cbz` and a special copy `Sample SP01.cbz`. Open both archives on the computer first and confirm that their first pages say “ordinary 1” and “special A” respectively; filenames do not verify content. After Kavita scans, record server classification, displayed name and opened content for each. The example illustrates naming checks, not identical behavior across all Kavita versions or library types.

If `Sample Annual.cbz` is not classified as a special, do not call the server wrong merely because it contains Annual: official documentation says the word alone does not force special status through filename. Preserve the original test archive and inspect actual library settings and ComicInfo metadata. If an administrator decides to compare an SP marker, record the old state, change only the test copy, rescan and observe. Do not batch rename real comics.

## Verify content, classification and progress separately

Suppose the server shows an ordinary entry and a special, but opening the special displays the ordinary chapter. Check whether the wrong test archive was selected and which file the server item points to, then inspect actual metadata such as ComicInfo. Changing a display name does not fix content. If both contents are right but ManYue shows only one, confirm the same server, account, series and loading state before calling an absent interface entry file corruption.

If the special opens at a previous reading position, first confirm it is really the special using its page marker, then record content identity and reading position separately. Do not reset all comic progress for comparison. Mark unavailable classifications or operations not observed or unperformed; this sample’s presentation does not guarantee identical behavior for other sources or versions.

## Confirm the scope before cleanup

Keep a table of redacted test file identifiers, before-and-after names, scan completion and observations on each side. If the administrator lacks scan permission or the task has not finished, record unknown or incomplete. Afterwards handle only temporary test copies through existing procedures and confirm originals and the shared library remain unchanged. If uncertain, preserve the state and ask the administrator rather than expanding the scope.

## Check scan tasks and permissions

Before starting, have the administrator confirm that the account may view the test library and record the actual scan scope. A reader without access to administration should not try to change permissions. Queued and completed scan tasks are different states; compare classification after an actual result. Preserve a redacted failure prompt and do not repeatedly submit or expand to the entire library just because a task takes time. Keep other files and the account constant on retest and record its time.
