给自有短片建立响应身份记录，避免把服务器校验标记直接当成文件摘要。

同一个视频地址重新打开后，服务器可能给出相同 ETag，也可能给出新修改时间；这些信息与“我手里的两个完整文件是否逐字节相同”不是同一个问题。本课在电脑上保留响应与副本，在云映中核对实际观看到的版本，产出一份连接地址、响应记录、完整文件摘要与可见内容的身份表。它适用于整理自己有权访问的素材，不要求云映展示 HTTP 调试面板。

## 一、确定本轮比较的是哪两个副本

选一段自己制作或获准整理的短片，最好让开头有清楚的样本编号，避免只凭相似封面辨认。把电脑现有完整文件记为 A，把从自己可管理的远端来源取得的完整副本记为 B，并记录取得日期、来源路径和文件大小。不要把播放时临时缓存的一部分冒充 B，也不要拿经过转码的小副本与原片做同一份字节身份判断。先在云映中分别打开可用的本地或远端来源，核对开头编号与末尾画面能否对应。若有一份打不开，先记录打不开的阶段，本课的“内容是否相同”不能以看不到画面为证据草率决定。

## 二、保留一次实际响应，缺字段就记缺少

若你能在电脑上查看自己素材的一次下载响应，把状态码、最终响应地址、ETag、Last-Modified、Content-Encoding 与取得时间抄到记录中。只记录实际存在的字段；没有 ETag 就写“未提供”，不能根据文件名自行补一个值。发生跳转时要区分中间响应与最终媒体响应，不把登录页面的头字段套给视频。已有下载工具能保存响应头时可直接使用，不必为了完成本课另装代理或给云映增加系统证书。这里的响应记录属于外部排查证据，与应用播放器中的片名、海报和继续观看位置是不同层级的信息，应分栏保存，不能互相替代。

## 三、先读服务器标记，再决定可以回答什么

参考[RFC 9110 校验标记说明](<https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8>)，ETag 是服务器给表示分配的不透明标记；带 W/ 的形式标为弱校验。它不必使用某个哈希算法生成，修改时间也不能代替你计算完整文件摘要。下面三个值只是教学卡片，不是本次下载的真实结果。把卡片抄到纸上时保留大小写、引号与 W/，然后在旁边写“服务器标记”“服务器声明的修改时间”，而不是写“MD5”或“设备拍摄时间”。这一步的完成标准是正确分类字段；并不要求你从看似十六进制的标记猜出服务端实现。

```
ETag: "sample-a"
ETag: W/"sample-a"
Last-Modified: Tue, 10 Nov 2026 00:00:00 GMT
```

## 四、对完整文件计算同一种摘要

在电脑确认 A、B 都下载完成、没有占位图标且没有正在写入后，再为两份文件计算 SHA-256。下方是 macOS 上的示例命令，先把文件复制或改名到你自己的练习目录，确认命令中的两个名称对应实际副本；路径含空格时保留引号。分别记录完整输出与计算时间，不只抄最前面几位。摘要相同支持本轮两个完整字节副本相同的判断；摘要不同只说明它们不是同一字节串，不能立刻断言画面内容一定不同。封装元数据、转码或其他文件改写都可能让摘要改变，后面还要回到内容核对，而不是用摘要充当影片质量评分。

```
shasum -a 256 "sample-A.mp4"
shasum -a 256 "sample-B.mp4"
```

## 五、回到云映检查可见身份

把 A 与 B 作为独立练习文件打开，先看开头编号，再看中间一个明确动作和结尾标识。每次切换后先核来源名称，随后从对应位置之前顺播，不只依赖缩略图或上次继续观看位置。记录“编号相同、动作相同、结尾不同”这样的分项结果，比只填“同片”更有用。若摘要不同但三个内容点一致，只能报告本轮观察点没有发现内容差异，不能保证整部影片逐帧一致。若远端来源会在同一地址更新，给此次观察加上时间；电脑取得的 B 与云映稍后重新请求到的文件也可能属于不同时刻，必须保留这个时间边界。

## 六、把几种结果放进不同结论栏

给记录增加三栏：响应标记比较、字节副本比较、观看内容比较。两个 ETag 字面相同但来源或表示条件不同，先保留条件，不能跨不同服务器直接认定同一文件；两个摘要不同而片头相同，仍分别填“字节不同”和“片头观察一致”。如果服务器没有修改时间，但文件能够完整取得并播放，这不等于文件损坏。相反，有漂亮片名与更新日期也不能保证下载的是完整视频。练习时可以拿前面的虚构字段卡片组合几种情况，再用实际 A、B 填一次；任何未做的比较都写“未检查”，避免在空白栏中默认填通过。

## 七、问题排查：下载未完成与表示不同

若摘要每次计算都变，先检查文件是否还在下载、同步或被其他软件修改，稳定后再计算，不要责怪播放器修改了远端内容。若服务器返回了压缩传输或不同清晰度副本，确认比较的到底是哪一份表示及实际保存的字节，不把响应中的编码名称直接当视频编码。若本地文件只有几千字节或内容是登录提示，回到下载身份问题，保留响应状态后重新通过正常授权入口取得素材，不去改后缀伪装成 MP4。若某来源反复取到旧内容，记录来源、时间与标记供自己管理的服务端排查；本课不要求清空应用数据，也不保证某个缓存一定在设备端。

## 八、完成检查与后续更新

完成记录至少包含两个完整文件的身份与大小、实际存在或缺少的响应字段、同算法的完整摘要、三个播放观察点，以及每项操作的时间。让另一位读者只看记录，就能知道你证明了哪个层级的相同，哪个层级仍未检查。以后远端素材更新时新增一行，不覆盖这次结果；没有旧响应就坦诚写缺少，不补造历史值。最后确认原始素材保留，练习副本没有被误当成唯一备份。你最终得到的是可追溯的版本核对方法，而不是通过 ETag 的外形猜哈希，或把一次正常播放当成所有文件都完整相同的保证。
