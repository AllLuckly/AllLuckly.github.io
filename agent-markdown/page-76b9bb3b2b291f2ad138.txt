Record entry and return through sidebar and popover views using an authorized comic.

## Define the exercise

Apple’s public 2.0.7 notes mention improved iPad sidebar and popover return behavior and a fix for a tag long-press menu remaining after leaving a page. They do not guarantee every menu or layout. Observe navigation with an existing library and an authorized comic. Do not install an old version to reproduce a bug or mark an unperformed observation as passed.

## Record the starting position

Check the installed version and select an authorized comic with easily distinguished chapters. Note its title, chapter and visible page number; without a number, use a non-sensitive visual marker. Keep existing reading data; signing out or clearing cache is unnecessary. Put this initial state in a table and compare each return with it.

## Distinguish three levels

Identify the shelf, comic details and reading view as list, detail and reader. A sidebar may switch locations while a popover may temporarily present options; neither must represent a new detail page. Do not assume the destination of a back control. Record the entry level and visible controls; if the current layout lacks an entry, mark it not observed.

## Switch through the sidebar

Find the sidebar or navigation control visible on the iPad, enter an existing area different from the shelf, then use the available back or navigation control to return. Record the start, chosen area, return method and final location. Follow the actual layout. A hidden sidebar is not automatically an error: first identify window width and current level.

## Check return from details

Open the selected comic’s details from the same shelf and verify its title and cover. Use the available return method to reach the list. Compare whether the prior scroll position and filter remain identifiable. If they change, record what happened without assuming every filter must persist. Reopen the same item so a neighboring same-name edition is not mistaken for the original.

## Open an actually available popover

On the detail page or shelf, open an option or menu that is genuinely visible in the installed version. Record its name and entry point; do not invent controls. Avoid changing account or service settings. Close it and observe whether the underlying view is details or shelf. If no popover appears or the action is unavailable, mark that row unperformed.

## Conditionally inspect a tag menu

If an existing user-created tag is visible, long-press it and observe the menu. Otherwise skip this step; deleting, renaming or bulk editing is unnecessary. Note its position, leave using the navigation actually provided, and check whether the menu still obscures the new view. Observe only and do not choose destructive menu actions.

## Return to reading position

Reopen the same comic and chapter and compare the page number or visual marker. Distinguish returning to details from entering the reader. If the reader opens elsewhere, record both positions and the action sequence without immediately overwriting progress on another device. If the chapter was not opened or authorization is absent, mark this step unperformed; a cover does not prove reading position was restored.

## Compare window widths

If the user normally uses iPad multiwindow or resizes windows, note the current width and orientation, change it once with the system controls and repeat the same sidebar path. Record the two conditions separately; skip if irrelevant. Restore the original window size afterward and do not require the menu to occupy the same position at every width.

## Handle a lingering menu or unexpected return

If a menu remains, record the source page, menu name, navigation method and orientation. Try the currently offered close action before changing several settings. If the expected place is not restored, record destination and reading position separately and check for a similarly named comic. Keep reproducible steps; do not generalize one observation to all devices.

## Summarize without disturbing data

Summarize version, window conditions, list-to-detail return, popover closing, tag menu and reading position. Mark each row successful, different, unavailable or unperformed. Exclude private library addresses and account information. Reinstallation, history clearing and tag deletion are unnecessary. The exercise is based on public release notes; the author has not tested an iPad or private server.

## Keep a short control path

Try a shortest path separately: open the comic from the shelf and use the visible return control without opening a popover or resizing the window. Compare its destination and shelf position with the sidebar and popover paths. If they differ, first verify that the starting item and return action were the same. Similar-looking views do not prove identical navigation. Recording actual conditions makes a later report more useful.
