Create one optimization job for an isolated short and inspect its output, original and actual iCouldPlay playback.

## Define three objects

Plex Media Optimizer can create an optimized version for a playback profile; the conversion job, generated copy and original video are distinct objects. Plex notes that even Original Quality can transcode when source video is incompatible with the target container; the label does not guarantee identical bytes. iCouldPlay supports Plex, but listing, selecting or actually playing a particular copy depends on the current interface and server.

## Prepare a recoverable test

Have an administrator prepare an isolated movie library, a self-made or authorized short copy and a separate test account, keeping the source and backup outside the library. Record relative path, size, duration, encoding and opening picture. Plex documents that Media Optimizer requires Plex Media Server 0.9.14.3 or newer. Have the administrator confirm the installed server meets this requirement, then check sufficient free space and permission for one short job without disrupting other users. Stop before creating the job if the version is insufficient or cannot be confirmed. Without administrator rights, space or a suitable maintenance window, do not create the job; mark it unperformed.

## Establish original playback baseline

Place the short copy in the test library using Plex movie naming conventions and scan until its web item appears. In Plex Web play the opening, recording picture, sound, duration and server-visible file information. Connect iCouldPlay with the same test account, open the same movie and record actual playback. Use a fictional test title in both places; do not combine observations from different sources into one baseline. Record network and time as well. Keep these conditions consistent in the comparison when possible, or list a network change separately rather than attributing it to the copy.

## Create a single-item optimization

Have the administrator find the Optimize action visible for the test movie in the current Plex Web interface and create a job for that one item, recording quality profile and destination. The profile is a processing target; inspect actual output afterward. A mobile profile does not prove every phone can decode it or establish bitrate from its name. Do not create a whole-library rule or enable “unwatched only,” which removes watched items from the job’s scope. Plex notes that such an optimized version can be removed after watching; this exercise uses a stable single-item sample.

## Confirm destination and capacity

Plex explains that choosing storage with original items creates a Plex Versions folder within the source file’s directory; other provided paths may also be selected. The administrator verifies the actual destination and free disk space, recording a relative path without sharing a private root. Do not manually overwrite the original short or mistake the output folder for the original input directory.

## Wait for the conversion job

After submitting, use the conversion queue or status control visible in Plex to record start, completion or failure. A created job alone does not prove the output is usable. If it fails or space is insufficient, ask the administrator to stop and preserve the error while checking settings and server resources. Do not submit repeated duplicate jobs or delete another user’s conversion.

## Inspect the copy on the server

After completion, have the administrator inspect the output’s actual location, size, format and duration, recording it separately from the baseline original. Do not assume equal sizes or infer encoding from a filename. Play the optimized copy’s opening and chosen segment to verify picture, sound and identity. Also seek to a self-made middle marker: matching two moments supports a content observation but is not a byte-for-byte verification of the entire file. The original should remain at its baseline location; if it is missing, pause cleanup and inspect backups and the action record.

## Observe available choices in iCouldPlay

Reopen the same test movie in iCouldPlay and check whether the current interface offers a version selector. Record visible labels and actual picture, sound and duration; if there is no control or file identity cannot be determined, write “unknown.” Plex notes that not all clients permit manual version selection, so an optimized server copy does not prove iCouldPlay selected it. Ask the administrator to inspect the server’s current session if source identity is needed.

## Separate optimization from live playback

The optimized copy is output from a prior conversion job. Whether the server also processes a particular playback session must be checked separately for that session. Do not claim that a completed queue means iCouldPlay is playing the optimized copy, or infer quality or encoding from network speed. If server session information is insufficient, preserve uncertainty; two visually similar files can use different encodings. If server session details show the processing method, record fields and time; do not guess Direct Play when fields are missing, and ask the administrator to consult the current documentation if needed.

## Clean up and hand over

The administrator handles this single test job and copy through the current Plex management interface by agreement, checking identity first and never directly deleting an unverified original or another task. Confirm the original video, backup, real library and other users’ data remain intact. Record profile, job result, output path, server information, actual iCouldPlay observation and unperformed steps. Remove private addresses before sharing. This guide claims no private-server or device test.
