A darker patch is not automatically a changed player brightness setting. Prepare a colour-explanation video externally, distinguishing straight, premultiplied and opaque results; iCouldPlay only replays the flattened video.

## Fix the working space and an opaque backdrop

Use straight foreground green (0,1,0), alpha one-quarter, over opaque magenta (1,0,1). Define every component in one linear working space, not as screenshot byte values; display encoding requires a separate conversion. Record foreground, backdrop, alpha and calculation domain before creating the illustration. Without a suitable existing tool, keep the paper task and uncertainties rather than insert arbitrary screen-picker values. Retain sources and distinguish opaque from transparent backdrops.

## Multiply straight colour by alpha once

With an opaque backdrop, foreground contribution is green times one-quarter and backdrop contribution is magenta times three-quarters. Their sum is (3/4,1/4,3/4). Output alpha is 1 because the backdrop is opaque, not the foreground’s one-quarter. The ledger gives equivalent straight/premultiplied forms for ordinary source-over. Other blend modes or calculation spaces are different conditions; do not compare them and diagnose an error in this model.

```text
all colour components use one declared linear working space
straight Cs=(0,1,0); alpha_s=1/4; opaque Cb=(1,0,1)
premultiplied cs=alpha_s*Cs=(0,1/4,0)
correct output=cs+(1-alpha_s)*Cb=(3/4,1/4,3/4); alpha_o=1
wrong double multiplication=(3/4,1/16,3/4)
control alpha_b=1/2: co=(3/8,1/4,3/8); alpha_o=5/8
control straight Co=co/alpha_o=(3/5,2/5,3/5)
```

## Keep premultiplied colour and alpha in separate fields

Premultiplied foreground is (0,1/4,0) while alpha remains one-quarter. Premultiplication does not set alpha to 1 or create another opaque object: the colour already carries its contribution. Add it directly to the remaining backdrop contribution. Multiplying again incorrectly reduces green to 1/16. Label representations explicitly instead of transmitting a component triple without its semantics. The same numbers under different conventions need not represent the same foreground; inspect record meaning separately from appearance.

## Check output conversion with a translucent backdrop

In a separate paper control, change only backdrop alpha to one-half. Foreground contribution stays quarter green and backdrop contribution becomes three-eighths magenta. Output premultiplied colour is (3/8,1/4,3/8), with output alpha 5/8. Divide by 5/8 to recover straight colour (3/5,2/5,3/5). Keep numerator/denominator order explicit. This control tests representation conversion without silently replacing the main backdrop. An output alpha of zero cannot be used as a divisor.

## Prepare a flattened explanation video externally

Create labelled correct, double-multiplied-error and original-component explanatory frames externally. Assemble them into an owned video whose frames are already flattened onto an opaque backdrop, using a known-playable export. This does not require iCouldPlay to composite layers or support every alpha-video track. Burned-in numbers are labels, not a player colour meter. Retain the working source and conversion notes. Display conversion can change numerical coordinates; a screenshot is not required to equal the paper’s linear triples.

## Read labels before comparing patches on one output

Open the explanation clip through an available path and verify frame order/labels. Keep presentation, brightness and output fixed. Identify each calculation before interpreting darkness as an automatic display change. Record whether differences are visible under the actual conditions without inventing numerical colour error or calibration results. A new source/display mode is an added condition. App theme changes are also separate from pixel compositing and do not recalculate the source video.

## Diagnose representation, compositing and presentation

For incorrect green contribution, inspect premultiplication before compensating with brightness. For incorrect alpha, inspect the backdrop. For screenshot differences, inspect working space/export/display. These are separate layers. Correct one external condition while retaining the previous result as a control. Leave decoder, colour-management and panel behaviour unknown unless tested. One patch does not certify all HDR/alpha formats. Without external rendering, deliver paper calculations rather than claim device-rendering validation.

## Reopen with representation and movie identities

Retain straight/premultiplied records, correct/error controls and the translucent-backdrop page, then reopen the identified explanation video. Explain the opaque main output, why premultiplied colour is not multiplied twice, and how 5/8 recovers the alternate straight result. Preserve observations separately from calculations and restore everyday display conditions. New components/spaces require a new ledger. These values are not universal screen standards or proof of added layer editing, alpha codecs or device-wide colour certification.
