在自拟AES-128声明里按媒体序号列隐含IV，核大端、补零与窗口删首段后的身份保持。

同一密钥标签作用下，不同媒体分片仍可能使用不同IV。本课只在自己的假定清单上做十六字节换算，再区分清单审核、真实媒体与播放器结果；没有提供任何实际密钥，也不从别人的加密服务取材料。纸面计算成功不代表已经解密或云映已兼容全部加密方式。

## 先写清所用加密声明的条件

限定练习为METHOD=AES-128、默认identity密钥格式，并且EXT-X-KEY没有显式IV属性。RFC在这个条件下用每一媒体分片自己的媒体序号生成IV，而不是用今天日期或文件大小。若真实资料用的是另一方法、另一KEYFORMAT或写了显式IV，应停止套这个样本，先读对应条件。只准备自己有权使用的媒体报告与文字副本，不需要为了完成本课去找别人服务的密钥，也不将公开标签当成绕开访问授权的办法；输入条件必须在结果表之前留存。

## 从清单位置分配三个媒体序号

样本MEDIA-SEQUENCE为二百五十七，随后red.ts、green.ts、blue.ts依次取得二百五十七、二百五十八、二百五十九。名称中的颜色不参与计算，也不把前三行标签当成前三个分片。先建三行表，列媒体URI、在当前清单中的次序和真实媒体序号；三个四秒区间的总时长十二秒另算，不能拿四、八、十二当序号。这个例子没有EXT-X-MAP或间断标记，避免把初始化段或间断序号混进当前加一规则，后面每一项换算都对应已经固定的一行。

## 把十进制值转成完整十六字节

二百五十七等于二百五十六加一，十六进制为0101；按大端放在十六字节缓冲区右端，左边补十四个零字节。最终有三十二个十六进制数字，前缀0x只是写法，不多占一个字节。二百五十八与二百五十九只把最后字节分别改为02和03，倒数第二字节仍01。把字节以两位一组手写一次，别把字符串”257”的字符编码当数值缓冲区，也不要把十进制二五七直接写成十六进制0x257；后者表示另一个数。

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-TARGETDURATION:4
#EXT-X-MEDIA-SEQUENCE:257
#EXT-X-KEY:METHOD=AES-128,URI="keys/owned.key"
#EXTINF:4,
red.ts
#EXTINF:4,
green.ts
#EXTINF:4,
blue.ts
#EXT-X-ENDLIST

# implicit IVs (default identity; no explicit IV):
# 257 -> 0x00000000000000000000000000000101
# 258 -> 0x00000000000000000000000000000102
# 259 -> 0x00000000000000000000000000000103
# after removing red.ts: MEDIA-SEQUENCE=258; green still uses 258
```

## 用独立逆换算找出端序错误

从末尾01、01逆读为一乘二百五十六加一，应回到二百五十七。故意另写一份把01放到缓冲区最左端的故障卡，再按大端权位回算，结果会变成巨大整数而不是二百五十七；只说明这个副本端序错，不拿它尝试真实解密。若少一个零，先数三十二个十六进制位并按两位分组，奇数位不能当作完整字节串。逆换算是外部数值检查，不等于播放器给出了密钥或IV诊断工具，也不能代替真实打包资料的核实。

## 删首段后保持重叠分片的IV

另存窗口副本只移除red.ts，同时把MEDIA-SEQUENCE加到二百五十八。green.ts虽然变成当前第一段，自己的媒体序号和隐含IV仍是二百五十八及末尾0102；blue同理保持二百五十九。若删首段却仍写二百五十七，会给green错误地重配旧IV。这个比较的对象是同一原始分片，不是所有后来新编码文件都应沿用旧值。只改窗口中的条目位置不改变媒体身份，而真正重新打包、改方法或显式IV都要重新核来源，不能靠一张旧卡永久套用。

## 把显式IV和初始化段列为停止分支

若后续看到IV=0x开头的完整值，就按显式声明核对，不再因为序号二百五十八而覆盖它。另有EXT-X-MAP时，要查看它的实际加密与IV要求；RFC对AES-128加密初始化段要求相应KEY写明IV，不能直接把它当清单第零段套隐含数值。这里不增添地图样本，只把分支条件写成提醒，防止将一个简单例子推广到另一资源。保持密钥URI、方法、IV来源与分片身份四列；URI相同也不证明真实密钥字节从未变更，仍需受控来源证据。

## 真实来源失败先保留条件再排查

只有自己的真实服务与媒体齐备时，才通过云映已有来源入口做播放观察，并另记是否真正执行。失败先核返回内容、方法和打包报告是否符合本课条件，再核窗口序号，不能仅因屏幕黑就认定IV补零错。一次只改自有故障副本的一项，保留能够正常播放的原件；也不在问题报告公开任何真实密钥或账号。格式审核通过与本机播放成功分别填栏，没有真实加密样本时数值审核仍可完成，但播放栏只能写待验证，不能报已通过兼容测试。

## 重开交付可逆的三行数值账

保存三行URI、媒体序号、十六字节IV和逆换算结果，再附删首段前后green与blue的身份对照。重开笔记数一次三十二位，检查大小写变化没有被误记成字节变化，也确认0x前缀没有混入字节数量。最终能解释为何二百五十七不是0x257、为什么窗口移动后重叠分片仍用原序号，以及哪些条件一变就必须停止套公式。未进行的打包、解密或真机播放明确留待做，本课交付是可复核的声明与数值关系，不是密钥提取或任何服务的访问保证。
