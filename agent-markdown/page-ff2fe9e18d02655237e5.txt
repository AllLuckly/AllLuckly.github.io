## Understand three distinct phenomena

W3C CSS Text distinguishes manual and automatic hyphenation opportunities; the hyphens property has values including none, manual and auto. A soft hyphen can indicate an optional break, while an ordinary visible hyphen can remain visible without a line break. A dash at a line end alone does not reveal its source; app version and typography can affect the result.

## Prepare an authorized sample

Choose an English EPUB you made or may inspect, preferably one whose publisher identifies a short passage with a soft hyphen. Record title, edition, source and two target words, preserving the original backup. Use self-written sample text to avoid publishing copyrighted passages. If protection or license terms prevent inspection, observe only Book Isle and do not bypass protection.

## Record initial wrapping

Open the same section in Book Isle and locate target words using available contents, search or page navigation. Record font size, orientation, screen width and whether the word wraps. Separately note any visible in-word hyphen, line-end mark and text on the next line. Whether search includes a soft hyphen is an observed behavior, not a guarantee. Preserve bookmarks and notes.

## Inspect characters and CSS

With permission and suitable tools, inspect only the target chapter and referenced stylesheet in the EPUB copy. Check whether the word contains U+00AD soft hyphen and whether a hyphens declaration and language markup apply to the paragraph. Do not call an ordinary hyphen, source-file line break or another invisible character a soft hyphen. Mark the step skipped without permission or tools and do not edit the original.

## Change one reading condition

Where Book Isle allows it, change only font size or device orientation, keeping the same file and chapter, then revisit the same word and record wrapping. Mark unavailable controls as such; do not simultaneously change font, theme and file edition. A width change may move a hyphenation opportunity away from the line end, so a different appearance does not automatically mean the file changed.

## Compare the complete word

Compare the publisher-provided spelling and check that the two lines remain readable together, without treating a visible line-end mark from a soft hyphen as an extra character in the underlying word. If part is obscured or cut off, record its location and neighboring text without immediately declaring content lost. If original spelling cannot be confirmed, leave it unknown instead of editing the publisher’s text by intuition.

## Consider automatic hyphenation separately

Even with a CSS auto declaration, automatic hyphenation depends on the reading system, language information and available implementation; the specification does not prescribe exact points for all languages. A line-end mark where no soft hyphen was found can be recorded, but without further evidence do not assert that an automatic dictionary produced it. Likewise, absence of a break alone does not prove the app ignored the style.

## Use an independent control

When permitted, a trusted reader can open the same file and passage as an independent control; record its version, font size and available width. Different fonts, wrapping algorithms and reading areas can change the result, so differing displays alone do not establish an app defect. Skip without a trusted control and do not install unknown software or change system security settings.

## Record and restore

Record separately whether the file contains a soft hyphen, whether CSS was inspected, both reading conditions, complete word and observed wrapping, skipped steps and uncertainties. Remove private paths and unauthorized text before sharing. Restore original font size and orientation and confirm the file, bookmarks and notes remain. This guide relies on public standards and app information; it claims no device test and does not guarantee a specific Book Isle hyphenation feature.

## Create a self-made word control

Use a publisher-provided or self-made sample with two recognizable English words, one with a known soft hyphen and one without, and record complete spellings and source. Do not treat different words with similar meanings as the same sample. Different word lengths may reach the line boundary differently, so the control aids observation but does not alone prove an algorithm. Mark the step untested without an authorized sample.

## Separate source and screen evidence

Record actual characters, language and CSS declarations in one column, and observation time, orientation, font size and visible word position in another. Similar-looking hyphens do not necessarily represent the same character. A fully displayed word may mean no break was triggered during this observation; that is not a final conclusion about app support.

## Keep copy and search conclusions bounded

If Book Isle allows selection, copying or searching, privately record the actual result and compare it with publisher-provided spelling. Do not paste unauthorized text publicly. Whether invisible characters survive copying can depend on the operating system, app and destination; visible pasted text alone does not prove a source file changed. If the function is unavailable, mark it untested rather than seeking a bypass tool.

## A reproducible self-made sample

A self-made control can use the word cooperation with one U+00AD soft hyphen inserted between co and operation, alongside cooperation without that character. Source inspection should record the character after co rather than treating a possible visible line-end hyphen as an ordinary source hyphen-minus. Observe whether wrapping occurs there after narrowing the available width. No break does not prove the character is absent or unsupported; this is not a device-test result.
