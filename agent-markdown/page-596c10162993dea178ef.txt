English translation of the [Chinese original](<https://allluckly.cn/guides/diaodiao-id3-performer-musician-involved-credits/>), translated on 2026-11-25. Original publication dates, attribution, code and version notes are retained.

A recording can have a performer, a work title and other people who helped make it. ID3v2.4 places the lead performer, instrument roles and production credits in different frames; putting every name in the artist field loses those roles. This exercise distinguishes them on a copy of an owned recording and observes what 调调 actually displays, without assuming the app reads every frame.

## Prepare an editable recording

Choose an MP3 you have permission to edit, listen to it and keep an untouched original. Create a clearly named working copy and record its duration. Prepare a fictional credit card with no private details: lead performer “Performer A”, guitarist “Performer B” and mixer “Producer C”. These are exercise values; do not put fictional credits into a work intended for release, or use real people's details without permission.

## Read the frame distinctions

Read TPE1, TIPL and TMCL in the ID3v2.4 frame specification. TPE1 identifies the lead performer or soloist; TIPL pairs involved people's roles and names; TMCL pairs instruments and musicians. The latter two use paired text entries, not a generic artist field. The standard defines the file format; it does not dictate an editor's display or a player's support. This exercise uses defined frames as its reference and does not infer that 调调 exposes an editor for them.

## Establish the starting state

Open the copy in a trusted tag editor. Record its existing title, lead performer and any people fields the tool explicitly identifies. If the tool shows only a generic artist box, its label alone does not reveal the underlying ID3 frame; consult the tool's instructions or stop writing frames. Record filename and duration and listen to the beginning and end. This baseline separates existing information, this exercise's changes and text the app might obtain elsewhere.

## Enter the three identities separately

Only if the editor documents the target frames, write “Performer A” to TPE1, the pair “mix” and “Producer C” to TIPL, and “guitar” and “Performer B” to TMCL. These role labels are inspectable practice values, not a mandatory complete occupational vocabulary. If a tool cannot write one frame, leave it unwritten and note why; do not put it in TPE1 merely to fill the record. Save and close the tool so an unsaved form is not mistaken for file content.

## Read the copy back and listen

Reopen the file and check that each value remains in its intended frame. Specifically check that role and name are not reversed and that the two other people have not moved into the lead performer. Record the tool, frame types shown and actual values; an editor's friendly display label is not itself a frame identifier. Compare duration with the original and listen to the beginning, middle and end. A size difference can come from tags and does not establish an audio change. If sound is truncated or frames cannot be read back, stop before importing and prepare a fresh copy from the original.

## Identify the imported item in 调调

Use the import control actually present in 调调 to select the confirmed working copy. Record the pre-import library baseline, interface response, displayed title and duration. If a same-name conflict, rejection or merge appears, stop and preserve the actual message rather than guessing the overwrite behaviour. Use the original and working filenames to identify the source; if the app cannot distinguish items, mark identity unknown and do not substitute an old item's page for the new copy.

## Record visible information separately

For the confirmed entry, inspect the list and playback views actually available, and record whether the lead performer, instrument role and production role appear, including the displayed text. Not seeing a field on this interface does not prove it is absent from the file. Conversely, a frame present in the file does not establish the app displays it. If only the lead performer appears, record that observation; do not alter other fields merely to make the screen appear complete.

## Troubleshoot within the evidence

If the display differs from your expectation, first read the frames back with the external editor and verify that 调调 opened this copy. Check role/name ordering and whether another file was selected during import. If the tool does not expose underlying frames, record unknown rather than guessing. Different versions, editors and sources may behave differently; one observation cannot establish behaviour for all formats or servers. This guide uses a public specification and does not claim tests on a personal device or private server.

## Keep the record and restore

Keep four columns for sample identity, confirmed file fields, app-visible text and reasons for incomplete steps. Do not record private paths or unapproved real names. Keep the original unchanged. If you choose to remove the test item, first confirm it is the working copy and use the controls actually shown; retain any older entry whose identity is uncertain. Finally make sure the notes distinguish “the file contains a field” from “the app displays it”. If you later change editor or app version, read and observe again in a new round and preserve the original record date; an old result does not automatically describe the new version.
