Question marks, boxes or garbled captions are not usually diagnosed by repeatedly shrinking text. Make a small reference to compare the text file, loaded result and available display conditions. It requires no unknown font installation and assumes no manual encoding selector in iCouldPlay. Save or convert copies in an existing trusted text tool. A font change cannot recover original characters already replaced with question marks in the source.

## Prepare characters whose originals you know

Pair a permitted short clip with a few self-written cues: ordinary Chinese and digits, an accented Latin letter and a rare character or symbol you can identify. Add plain numbers for navigation without private names or details. Keep a readable original reference, not merely the suspect caption file. Make the sample small enough to inspect character by character rather than testing an entire film as a font collection. Replace any character whose expected form you cannot confidently identify.

## Inspect the text before the player

Open a copy in an existing trusted text tool and check whether characters are wrong before iCouldPlay sees them. Question marks or replacement characters call for checking transcription, copying and prior saves. Record an explicitly chosen encoding rather than forgetting a default. Do not repeatedly resave the only file between encodings, potentially turning recoverable bytes into damaged text. Keep original bytes and separately named conversions so the changing step can be identified.

## Separate encoding from glyph rendering

Encoding interprets bytes as characters, while a font renders visible glyphs. Consult the [Unicode encoding FAQ](<https://www.unicode.org/faq/utf_bom.html>) for the encoding layer; changing an extension is not conversion. UTF-8 can represent many characters, but that label alone cannot repair misinterpretation, lost source text or an unavailable glyph. You need not memorize code points: distinguish how a file was saved, read and displayed instead of calling every symptom garbling.

## Fix caption syntax and video identity

Confirm valid timing syntax for the chosen caption format and load it against the same sample video, tracking timing and character issues separately. Activate only one test version. If no cue appears, establish file reading before blaming fonts. Filename, extension and syntax must correspond; renaming ordinary prose is not caption authoring. A plain-letter cue can establish a working entry before a structurally identical copy adds the characters under investigation.

## Describe the symptom before diagnosing it

Record whether a whole line looks misinterpreted, isolated characters become boxes or a character disappears, preserving the cue number in notes or screenshots. A box can suggest unavailable glyphs but still requires a source check rather than proving a particular font is defective. A question mark already present in the file is not original text deleted by the player. Specific symptoms guide the next comparison better than indiscriminate global replacements.

## Change one existing display condition

If the installed version offers a font or style choice, retain file and time while changing one available option. Otherwise compare the same file in another trusted existing viewer rather than hunting for hidden controls. Do not install unknown font packages or configuration profiles for this sample. A visible glyph must still be the correct character; absence of a box is insufficient. A style comparison narrows rendering conditions without guaranteeing every font, script combination or device.

## Revalidate any converted copy

When conversion is justified, explicitly choose the correct reading method, verify the text, save a new copy and reselect it in iCouldPlay. If interpretation remains uncertain, stop with an unresolved result rather than cycling encodings until one line resembles Chinese. Check every test cue, including previously correct digits and accents, before extending changes to real captions. Preserve originals and verify timing syntax too: character correctness is only part of complete caption validation.

## Keep a three-layer comparison

Keep the original reference, file-saving conditions, player result and unknowns, identifying where divergence begins. Test a few characters again for another language rather than turning one working font into a universal configuration. For support, offer nonprivate self-written captions and an error screenshot with version and selected style, not an entire private film. Restore usual caption choices afterward. The method creates reviewable stages and reasons for edits rather than relying on repeated imports.
