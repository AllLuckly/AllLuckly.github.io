Change one reversible setting at a time and observe its title, switch state and return path.

## Check the update and scope

Apple’s public 2.0.7 notes mention settings-switch improvements and a fix for a title flash when switching settings pages on iPhone. Treat title presentation and the actual setting value as separate observations. The notes do not guarantee identical behavior for every device, setting or animation. Check the installed version and record a version difference rather than marking an unperformed step as passed.

## Choose a reversible setting

Open the settings page actually visible in Manyue and select a display preference the user understands and can restore, such as a theme option if offered. Stop if no suitable switch exists. Do not change a server address, sync account, permission or data-deleting option to observe a title. Record the option, initial value and page for restoration.

## Establish a page baseline

Before opening the setting, record the settings home title, screen orientation and device category, then note the visible entry used to reach its subpage. If an option is on the home page without a subpage, record that level instead of assuming all switches open a page. Separate before entry, during transition and after return in a short table; one final screenshot can miss intermediate state.

## Change the switch once

After confirming the display preference can be restored, tap the actually visible switch once and observe its state and the page title. Avoid rapid repeated toggles and simultaneous changes. Record the old and new values, any prompt and whether the title remains identifiable. If the user does not wish to change it, skip and mark dependent observations unperformed.

## Separate title flash from loading

Wait for the interface to settle and record the final title and setting value. If a brief title change is observed, identify whether it occurred on entry, change or return; do not label slow loading as a flash automatically. Recording a private library is unnecessary. If the user voluntarily records, first exclude account details, server information and restricted content, and let them decide whether to keep it.

## Return and re-enter

Use the visible back or close control to return to settings home, checking its title and the option’s location, then re-enter the same item. Observe whether the selected value is still shown. If not, record the actual state and any save prompt without assuming immediate persistence. If the destination differs, record the path separately from the value.

## Check the actual effect

Only if the chosen preference has an observable effect and the user agrees, return to the relevant view once—for example, a visual change for a theme setting. Observe other kinds according to their own instructions. Record switch state, visible effect and title separately; a changed switch does not prove every view updated. Note any required reopen or system condition.

## Restore and verify

Return to the same setting, restore the recorded initial value and check it after returning once. If save or cancel choices appear, let the user decide after reading them. Stop if the original value is uncertain rather than guessing. Compare the relevant view with the baseline and mark differences pending instead of repeatedly clicking at random.

## Repeat with one variable

If the user wishes, repeat the same path once with the same device orientation and window conditions, comparing entry, switch and return. Do not change orientation, account, network and several settings simultaneously. If a condition does change, record a separate row. A single observation is valid as a record but must not be described as repeated verification.

## Troubleshoot without disturbing data

For an unexpected title or value, record app version, setting name, entry and return methods, and initial and restored states, excluding accounts, personal content and private addresses. Confirm that the same settings page is open; if needed close it and re-enter once. Do not clear history, reinstall or delete server configuration as a first step. Mark unperformed work pending; the author has not tested a device or private account.

## Compare visible labels

In a non-sensitive written record, note the settings home title, option name and title after return separately. Instead of writing only “normal,” say which page can be identified. If a title is obscured, record when and whether it clears after the interface settles. Do not rapidly toggle the setting to expose a fleeting effect: repeated actions introduce new state changes and make a single path harder to compare.

## Recheck the restored state

After restoring the preference, leave settings normally and reopen the same item. Compare time, value and visible effect with the baseline. Persistence after closing the app is a different question; mark it untested if the user did not close it. If the value is restored but the effect differs, keep two separate results and check whether system appearance or other preferences changed before considering a reset.
