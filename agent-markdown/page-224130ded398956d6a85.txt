Check sources imported into ManYue separately from an existing Suwayomi server library, keeping scripts, extensions and reading results distinct.

## Prepare two identified sources

Choose a self-made or authorized comic and record series, chapter, cover and recognizable page. If you have your own Suwayomi server, confirm that its original interface can access the same test content. ManYue’s public description separately lists Venera source import and Suwayomi server libraries. Record the identity and configuration of both; the same title alone does not establish identical data.

## Distinguish client sources from server extensions

ManYue publicly describes importing JS or .ManYue source files or source links. Suwayomi documents separate server extensions and extension repositories. A server extension is not a ManYue source file, nor should a ManYue source be installed as a server extension. Content and features depend on each source. Do not install code from untrusted addresses or give account passwords to a source provider.

## Check the server’s own interface first

In Suwayomi’s own interface, confirm the test comic is visible in the account’s library, inspect chapters and check first and last pages. An authorized administrator handles extension repositories or server settings under official guidance; this exercise does not require installing a new extension or changing shared configuration. If the server interface itself cannot open it, record the prompt and investigate the server or source first.

## Open both paths separately in ManYue

In ManYue’s current interface enter the lawfully configured comic source and record whether the test work appears. Then enter the connected Suwayomi library and record whether the same series and chapter appear. Open only authorized items and compare page count and images. If an operation is absent in one path, record not observed instead of inventing a server-extension management button in ManYue.

## Record progress and downloads separately

Even if both paths show the same work, that does not automatically establish shared reading history, favorites or downloaded files. Record each actual source, chapter, page and whether a local copy exists. Verify only through operations the current interface and permissions allow. A server download, online client reading and a usable local offline copy are three distinct outcomes.

## Troubleshoot while retaining existing configuration

If the server library lacks a work, inspect account, permissions and library in the server’s own interface. If only the ManYue source lacks it, inspect that source’s actual state. If the server works but its ManYue entry differs, record versions, redacted source identifiers and feedback without deleting the shelf or reinstalling extensions arbitrarily. Confirm originals and records remain. No extension installation or device test is claimed.

## Record source identity in a table

Use separate rows for “ManYue source A” and “Suwayomi server B,” recording test series, chapter, recognizable cover or self-made page marker, and observation time. If titles match but page counts differ, check edition and chapter scope first; do not assume the same file. If only one source exists, mark the other unconfigured and check only the available entry. New code is not required to complete a table.

For example, source A shows 20 pages for chapter three while a same-named server B item shows 18. Compare chapter names, covers and first and last pages to determine whether editions or split chapters differ or display information is incomplete. If the cause cannot be confirmed, leave it unknown. Do not batch rename, delete local works or overwrite server records merely to make the numbers match. These numbers do not describe a fixed app rule.

## Verify server and client reading separately

After Suwayomi’s own interface opens the book, separately check the same server, account and chapter through ManYue’s Suwayomi source. Server success does not guarantee every client request succeeds. If the ManYue entry fails, record time and actual feedback, check connection and permissions first, then compare with the server interface. Mark an unobserved status code unknown rather than calling every failure an extension problem.

Conversely, if ManYue source A reads while Suwayomi B does not show the book, this establishes only different observed outcomes. Check whether B actually added the work to its server library and whether the server can read it. Importing A does not automatically install an extension or add the comic on B. Without server-management permission report concrete observations to the administrator rather than changing another person’s sources.

## Keep shareable feedback without credentials

For each source record version, entry type, redacted series, chapter, actual reading or download outcome and untested items. Exclude server addresses, tokens in source URLs, accounts, passwords and comic content from public feedback; self-made samples are easier to share. Afterwards confirm existing shelf and reading records remain. If no extension or source was changed, state unchanged rather than describing observation as completed configuration.

## Confirm recoverability before testing

If testing downloaded comics, first confirm originals and important reading records are separately preserved. Do not delete server works or clear client downloads to prove the two paths are independent; read-only comparison can record each visible behavior. Mark offline verification untested when not actually performed and record the observation end time.
