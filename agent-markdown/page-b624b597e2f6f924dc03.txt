Compare semantic headings, visual size and actual reader presentation in a self-made chapter.

## Separate two aspects of headings

EPUB content uses XHTML, where h1, h2 and similar elements express heading hierarchy; CSS can change visual size. Large bold text is not necessarily a structural heading, and a small heading can retain its semantics. This exercise checks actual structure and display in an authorized sample without assuming Book Isle offers heading navigation.

## Prepare a short two-section text

Write your own chapter heading, two section headings and one sentence under each, saving a separate EPUB and retaining the original and backup. For recognition, use a chapter such as “Garden notes” and sections such as “Sowing” and “Watering”. Do not copy protected text or modify protected purchases. Record the sample name and intended structure.

## Inspect XHTML elements

In an EPUB editor inspect source or structure view and confirm that chapter and section headings use elements matching their hierarchy, rather than only bold styling on ordinary paragraphs. Record element levels and text. The presence of a tag alone does not prove Book Isle or a screen reader presents it correctly. First check text order and section ownership.

## Observe style versus markup

Inspect whether the stylesheet sets heading size or weight and record the rules; changing style is not the same as changing structure. In an authorized working copy, adjust one heading’s visual size below another and verify the markup levels remain unchanged. Readers may apply their own styling, so visual results require observation.

## Validate structure and links

Use EPUBCheck or the editor to validate the package, chapter resources and navigation links, and retain the report. Manually read heading order as well: check each paragraph follows the correct heading and contents links reach expected locations. Automated validation cannot replace a human check of heading meaning and hierarchy; repair the working copy and recheck.

## Identify the sample in Book Isle

Import the sample using the method currently available in Book Isle, and confirm the book title, chapter heading and both sections. Record device, app version and reading settings. If import fails, retain the message and check file and permissions before deleting books or clearing the shelf. Mark later interface steps unperformed if import cannot be completed.

## Observe the reading sequence

Read from the chapter beginning and record whether both headings and paragraphs are complete, plus actual visual size and weight. Note any reader theme or font-size setting; operate only controls actually present and preserve previous settings for restoration. A visual difference alone does not establish that XHTML markup was lost.

## Conditionally inspect assistive reading

If system accessibility is enabled and the current reading interface actually permits the action, follow system instructions to check whether focus reaches a heading and record spoken text and results. Do not assume Book Isle provides a particular heading-navigation menu or speech outcome. Without the device or entry point, mark this unperformed; source inspection is not an accessibility test.

## Diagnose visual and structural mismatches

If a heading looks unexpected, confirm the open copy, stylesheet, reader settings and text scaling first. If the hierarchy itself is wrong, correct XHTML in the working copy one item at a time. Preserve before-and-after records and avoid changing style and tags together. Passing validation still does not guarantee identical rendering everywhere.

## Save the findings

For each heading record source level, expected text, visible style, assistive observation or reason it was unperformed. Use a separate row for another device and do not publish private books, paths or accounts. Identify the test book before deciding whether to remove it and retain backups. This guide claims no device or accessibility test.

## Design an unambiguous comparison

To observe visual size without confusing the result, use unique short phrases for the chapter and sections and record their intended hierarchy. Save the original before a size change and a new copy afterward. Inspect heading elements in both with the same editor to confirm only visual styling changed. Note any reflow caused by font substitution.

## Separate contents from text

Navigation labels can match body headings, but the contents list is not itself the body heading hierarchy. After selecting an available contents entry, check the chapter and section actually shown and compare with the editor’s XHTML structure. Record a missing contents item as a navigation observation; it does not prove a body heading tag is absent.

## Bound an unsuccessful assistive observation

If a system accessibility feature cannot focus a body heading, record device settings, actual action, feedback heard or seen, and whether adjacent text is reachable. Do not generalize one focus result to all versions. For further diagnosis compare the same self-made sample in another reading environment, recording results separately rather than presenting them as a Book Isle test.

## Record body sequence

List the chapter heading, first section heading and paragraph, and second section heading and paragraph in order. Compare the source with what Book Isle currently shows; a matching contents entry does not prove that the body text appeared. If only part was viewed, mark the remaining paragraphs unchecked and retain the current reading position.
