A show special may appear in a dedicated season and also be positioned between two regular episodes by the server. Check the server first, then observe iCouldPlay.

## Choose the observation

Use a Jellyfin show test library you manage or are authorized to inspect. Prepare three lawfully obtained short videos representing season 2 episodes 6 and 7 and one special. Work with test copies rather than renaming production files. Note their distinct images and durations to identify them. This tests listing position, not a real storyline or automatic continuation in iCouldPlay.

## Understand both positions

Jellyfin documents specials in Season 00. When display within the aired season is enabled and airing position is specified, the server can show the same special both in the specials season and the specified season. Two appearances do not mean two files were copied. This setting and metadata belong to the server; observe third-party client presentation separately.

## Check names and numbering

Ask the administrator to confirm the test show, Season 00 and Season 02 organization. When using a metadata provider, use that provider’s corresponding special number; numbering may differ between providers. If the provider has no matching special, the documentation recommends a descriptive content name instead of an unsupported S00E number that could pull incorrect metadata. Keep a filename and number ledger; the example number is not a real show identification.

## Record the starting state

After the administrator scans the test library normally, inspect season 2 and the specials season on the web. Note names, season, relative order and observation time. Write E06, E07 and special A on paper or make a sanitized record. If the special already appears in both places, record the existing settings rather than attributing it to this exercise. Without administrative access, do not change settings yourself.

## Have the administrator change only the test item

Following Jellyfin’s documentation, enable display of specials within their aired series under the server administration Library → Display settings. Open the test special’s metadata editor and set airs-before season to 2 and airs-before episode to 7. Do not also set airs-after season, because precedence would confound the observation. Labels vary by server language and release. If an option cannot be found, consult the version’s documentation and mark the step incomplete; do not present the server setting as an iCouldPlay button.

## Predict and recheck

The documented expected order is season 2 episode 6, special A, then season 2 episode 7; A should remain in the specials season too. Save, refresh using the administrator’s normal procedure and check identities and position on the web. If the special appears at the season start, check whether the before-episode value was omitted. A single screen does not establish actual playlist behavior. Record the displayed result and time.

## Inspect the same library in iCouldPlay

Connect iCouldPlay to the same server and account, enter the same test show and inspect both the specials season and season 2. Note whether A appears and which entries surround it. If the app offers a different ordering or does not display the special, report the observation; do not claim that server documentation proves client support. If playable, open all three clips manually and check picture and title. Do not assume automatic continuation matches the web interface.

## Investigate differences

If the web order differs from the prediction, have the administrator check display option, season and episode fields, saved metadata and scan status, changing one condition at a time. If the web works and iCouldPlay differs, compare account, server, library, refresh time and app version. Cache or client implementation may matter, but one observation cannot identify the cause. Appearance in both seasons is documented behavior, not a reason to delete the source file.

## Compare a second condition

With permission, record the settings, temporarily clear airs-before episode for the test item and leave airs-before season at 2. The documentation describes this as placing the special at the beginning of that season. Compare both web results for the same entry and account, then restore the test value. If editing is unavailable, mark the second observation not performed; do not invent it. Keep the experiment in the isolated library.

## Restore and bound the conclusion

Restore the original display option and test metadata from the initial record. Verify that production library and originals are unchanged; the administrator decides whether to remove test copies. Record software version, time, network and separate web and iCouldPlay observations without private addresses or credentials. The guide relies on public documentation and claims neither a private-server connection nor a physical-device test. Report listing order, actual continuation and metadata identity separately.

## Check the observation ledger

Before handing off, verify that each row uses the same show identity and account, and that both observations followed the server save. Use the distinct pictures in the clips to establish identity rather than position alone. If multiple fields changed, the record cannot prove which caused the difference; restore the starting values and retest individually if permitted. Client sorting and cache behavior can differ, so record a missing entry and playback failure as distinct observations without asserting a common cause.
