Check BGR colour and alpha using three cues with fixed styling, without confusing hidden fill with an entirely absent caption.

English translation of the [Chinese original](<https://allluckly.cn/guides/icouldplay-ass-bgr-colour-alpha-component-visibility/>), translated on 2026-11-14. Original publication dates, attribution, code and version notes are retained.

ASS colour order differs from familiar web RGB, and alpha zero is not fully transparent. Prepare red-fill, invisible-fill and fully invisible controls externally, then observe available caption handling. Keep syntax, expectations and actual compatibility separate without claiming advance device success.

## 1. Save a minimal caption copy and original

Keep an owned clip of at least ten seconds and original captions. Save a separately named UTF-8 ASS file externally and verify extension, encoding and video identity. Fix font, size, position and outline across cues, changing colour/alpha only. Record font substitution separately. Without media, deliver syntax and predictions while leaving importing/display unperformed.

## 2. Decode blue-green-red order first

[Aegisub’s ASS tag documentation](<https://aegisub.org/docs/latest/ass_tags/>) specifies blue/green/red component order for colour overrides: 0000FF is red and FF0000 blue. Draw separate B/G/R byte boxes before decoding. Style colour fields also carry alpha; do not conflate an eight-digit style value with a six-digit colour override.

## 3. Save a complete fixed-position control

Use two-second cues separated by one second, a black outline, no shadow and fixed centered placement. Cue one sets red fill, cue two hides only fill and cue three hides all components. Preserve actual backslashes rather than web-style hash colours. Verify event fields/times and reopen the saved file to check that punctuation and escapes remain literal.

```
[Script Info]
ScriptType: v4.00+
PlayResX: 640
PlayResY: 360

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Default,Arial,32,&H00FFFFFF,&H00FFFFFF,&H00000000,&H00000000,0,0,0,0,100,100,0,0,1,2,0,5,10,10,10,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:01.00,0:00:03.00,Default,,0,0,0,,{\c&H0000FF&}RED
Dialogue: 0,0:00:04.00,0:00:06.00,Default,,0,0,0,,{\c&H0000FF&\1a&HFF&}FILL HIDDEN
Dialogue: 0,0:00:07.00,0:00:09.00,Default,,0,0,0,,{\alpha&HFF&}ALL HIDDEN
```

## 4. Record both alpha endpoints

Alpha 00 is opaque and FF transparent in this notation. Cue two targets primary fill, leaving the styled outline potentially visible; cue three targets all components. Describe component visibility instead of assuming a middle alpha gives exactly half perceived brightness. Background and rendering conditions matter, and “caption present/absent” is too coarse for diagnosis.

## 5. Make a colour-only blue control

Duplicate the file and change only cue one from 0000FF to FF0000. Expect red to blue without automatically modifying later events; each event starts from its style. Compare files to avoid unintended replacements. If no display was performed, report text/semantic inspection only, not player results.

## 6. Record visible components at defined times

Select the copy through actual controls, verify source/caption identity and observe at two/five/eight seconds. Record fill, outline and literal-tag display. Unsupported external ASS or overrides remain a path-specific limitation. A black outline on black background may be hard to see; record that condition before comparing an owned bright clip. Unperformed observations remain pending.

## 7. Troubleshoot colour, alpha and component separately

For reversed colours, inspect BGR bytes before changing screen settings. Invisible fill with a remaining edge may match the intended component control. If cue three remains visible, verify file identity, literal backslashes and override handling. Reopen after one correction. An invisible cue still has timing, and invisibility alone does not prove the file was never loaded.

## 8. Restore ordinary captions and retain evidence limits

Reopen readable original captions. Deliver both texts, timed observations, BGR breakdown and alpha endpoint table. Explain red notation and component/global transparency with unresolved path capabilities. Recheck backgrounds/devices and distinguish document inspection, file preparation and actual playback rather than guaranteeing identical appearance or claiming unperformed tests.
