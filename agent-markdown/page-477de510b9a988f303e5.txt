A page visible on the server web and in Manyue+ does not automatically reveal whether its format changed in transit. Record each layer separately.

## Separate server decoding and client display

Komga says it need not decode every requested comic page. Thumbnail generation, barcode detection, dimension analysis and on-demand conversion may need decoding; when a requesting client can decode the format, raw image data can be passed through. Advanced decoding support varies by server platform. Whether Manyue+ reads a format must be observed in the installed version, not inferred from a server table.

## Prepare self-made test images

Create an owned image with clear text and color blocks, save JPEG and PNG copies, and put one of each in an isolated test CBZ. Use a trusted image tool to verify that extensions match real formats. Give the pages distinct markers. Renaming an extension is not conversion; no unknown-source comics or images are needed. Preserve original images and an original CBZ backup.

## Record files and server conditions

An administrator places a CBZ copy in an authorized Komga test library. Record server version, deployment platform, page count, actual image formats and time. Komga lists JPEG, PNG, GIF and WebP as common supported formats across platforms, but client and network conditions may still affect display. Mark platform and decoder details unknown if unavailable; do not guess about native libraries.

## Check the local baseline

Open both original JPEG and PNG copies in a normal image viewer and confirm text, colors and orientation. Use a trusted archive tool to inspect the two filenames and page order in the test CBZ. Record whether each opens and its self-made marker. Minor color differences do not automatically mean format failure. This exercise checks readable text and identity, not calibrated color accuracy.

## Observe Komga analysis

The administrator scans the test library normally and waits for media analysis. Find the same book on the server web interface and record whether it appears, page count and generated cover, then actually read both pages. Record sanitized analysis errors and stage if unsupported or failed; do not repeatedly analyze the entire production library. A generated cover and readable pages are separate checks.

## Open the same comic in Manyue+

Connect Manyue+ to the same server and account and identify the book by title, page count and first-page marker. Open the JPEG and PNG pages in turn, recording display, legible text and colors, and any error. If a page is absent, do not immediately blame app format support: server analysis, transfer, network and file integrity can all matter and require separate observations.

## Separate transfer from decoding evidence

If web and app both display a page, the observation establishes visibility under those conditions only. The picture alone does not reveal whether original image data passed through or the server converted it. If an authorized administrator has verifiable server information, record its wording, time and scope; otherwise leave transfer mode unknown. Do not disable secure connections or expose private request contents to inspect traffic.

## Check advanced formats separately

Komga documents JPEG XL, AVIF and HEIF decoding as dependent on deployment platform and native libraries, unlike this JPEG/PNG comparison. Skip without a supported platform and self-made authorized samples. Even successful server thumbnail generation does not guarantee that Manyue+ renders advanced formats unchanged on every path. Make separate samples and record platform and client observations without changing production comics.

## Investigate page order or orientation

If both pages appear in the wrong order, first inspect archive filenames and the server-recognized page order rather than blaming JPEG or PNG. If text rotates or crops, compare the same page in the local original, server web and Manyue+, noting image orientation, screen orientation and position. Change only one reading setting before recording another observation; do not change archive contents and layout together.

## Build a source chain for each page

Use a table for the original JPEG, original PNG, corresponding CBZ member, server web page order and Manyue+ page order. Record self-made markers and times for each. If both images derive from the same original, distinct small corner marks can identify them; do not mistake the marker difference for a format conversion. If actual CBZ member format cannot be confirmed, inspect a copy separately rather than inferring it from an extension.

A server-generated thumbnail can come from the first page or be affected by local artwork settings. Open both pages in the reader instead of inspecting only a book or series cover. If one page looks old, confirm both interfaces refer to the same test book and record the state after normal re-entry. Leave unverified caching behavior unknown; do not clear all local data.

Files of one format can still vary in dimensions, color profile or integrity. One visible self-made JPEG does not establish compatibility for every JPEG, device or future version. Retain sample dimensions, format and conditions so another person can check without accessing a private library.

## Restore and hand off

The administrator retains or cleans up the test copy under normal policy and confirms production libraries and original images are untouched. Record local opening, server analysis, web display, Manyue+ display, actual transfer evidence and unperformed steps separately. Exclude private addresses and unauthorized images. This guide uses public documentation and claims no private-server connection or physical-device compatibility test.
