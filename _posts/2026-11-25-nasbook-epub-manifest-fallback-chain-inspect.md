检查 EPUB 清单中的替代资源声明，并在书屿中记录实际可读内容。

## 先理解标准与限制

EPUB 3.3 允许出版者在包文档的 manifest 项目上使用 fallback 属性，按目标项目的 ID 建立替代资源链。规范提醒阅读系统对清单替代链的实际支持有限；对于正文中的外来资源，规范强烈建议优先使用 HTML 或 SVG 内置替代机制，而被 spine 直接引用的外来内容文档则要求替代链中至少有一个 EPUB 内容文档。声明存在不代表书屿一定采用，也不能将这一机制与每个图片的 HTML 内置替代能力混为一谈。本练习只观察已有授权样本，不改变原书。

## 准备授权样本和观察记录

选择自己制作或出版者允许检查的 EPUB，最好附带清楚说明哪些章节或图片包含替代资源。复制原始文件到单独文件夹，保留文件名、来源和版本；如果书籍加密或使用许可不允许拆包，就停止文件检查，改用出版者提供的结构资料。选择一个目标章节，记录可识别的短文字与预计图像内容，不把缺少说明的任意文件当成合格测试样本。

## 先在书屿建立阅读基线

在书屿打开未修改的样本，用实际可见的目录、搜索或翻页入口找到目标章节，记录文字、图像、空白或错误提示及观察时间。若根本无法打开，先检查文件是否下载完整以及应用是否识别该格式；不要宣称已经进入替代分支。保存可用的本地书签或纸面位置，原有笔记与阅读记录应保留。

## 定位包文档和资源清单

仅在许可允许时检查复制件的 EPUB 容器结构。先查 META-INF/container.xml 所指的包文档路径，再在该文档中找到 manifest；不要假定所有书的包文件都在同一个目录。找到目标内容对应的 item，记录它的 id、href、media-type 和可见的 fallback 属性。路径可能相对包文档解析，只有文件名相同不足以判断引用对象。

## 沿 ID 查找替代项目

若目标 item 有 fallback 属性，在同一个 manifest 中查找 ID 与该属性值完全相同的 item，再记录其 href 和媒体类型。如果该项目还有 fallback，可继续按顺序追踪；每到一个节点就保存已见 ID，一旦再次出现已见 ID 就停下并记录疑似循环。标准不允许链条自引用或循环，但单凭属性拼写不能确认文件实际存在或内容等价。

## 核对文件与出版者说明

按包文档所在位置解析记录的相对路径，确认复制件中对应资源是否存在，并与出版者对章节或图像的说明比较。不要仅凭扩展名认定媒体类型、图像内容或授权；路径缺失、ID 找不到和无法解码应分别记录。若无法确定引用关系，保留原始路径字符串交由出版者核实，不使用网上不明来源的资源替换原件。

## 区分内容文档与嵌入资源

检查目标是 spine 直接引用的内容，还是 XHTML 页面内部嵌入的图片或其他资源；二者适用的后备要求并不相同。对于 spine 中的非 EPUB 内容文档，标准要求替代链包含至少一个 EPUB 内容文档。对页面内资源，还需考虑 HTML 或 SVG 自带的替代方式。这里只核对结构声明，不以一条规则断言整本书符合标准。

## 比较阅读结果和结构证据

回到书屿重新打开同一目标，比较此前记录的短句、图像和错误提示。如果能阅读，只能记录这个样本在当前环境下可读；无法根据外观断定阅读器选择了链上哪个资源。若看不到预期内容，记录书屿版本、设备环境、目标位置和样本来源，并与出版者提供的预期对照；不要以一次空白就归因于某个具体代码分支。

## 遇到问题时逐层排查

先确认打开的是同一份授权样本、目标章节和完整文件，再核对包文档、manifest ID、相对路径与实际资源。用已知可正常阅读的普通 EPUB 作独立对照，但对照成功不能证明问题样本结构正确。若需要修复，将记录交给文件制作方；不要直接修改唯一原件、重命名后缀冒充转换，或为排查关闭设备的安全保护。

## 保存记录并结束

记录样本版本、目标 ID、按顺序查到的替代 ID 与路径、实际可读内容、未执行项和任何无法确定的结论；不要公开含私人资料的电子书或截图。保持原件、备份和既有笔记不变。本文以 W3C 规范和 Apple 公开应用资料为依据，没有声称实际测试特定设备，也不保证书屿实现了 manifest fallback 机制。

## 检查资料是否足以支持结论

将观察分为三个栏位：出版文件声明了什么、书屿实际显示了什么、两者之间还缺少什么证据。例如，清单中存在替代项目并且画面出现图片，仍不能单凭这两条确认显示的就是该替代项目；原始资源本身也可能可以正常显示。需要进一步定位时，可请出版者提供授权测试样本及可区分的视觉标记，并使用另外一份独立副本观察。只改变测试副本中的一个条件，并保留每一步记录；无法确保可恢复时就不改文件。对不适用或未执行的项目明确留空，避免把推测写成实际观察。
