文件夹名里的空格和井号，与网络地址里的分隔符并不是同一种东西。调调 1.0.4 公开发行说明列出 WebDAV 连接与曲库浏览改进；本课先用不连接的示例核路径，再以授权服务器的实际界面检查来源，不假定调调使用某个固定编码方法。

## 写清非网络示例和目标

假设服务根是 `https://example.invalid/dav/`，其下有一个目录，名称恰好是 `A B#1`，其中 A 与 B 之间有一个空格，井号后为数字 1。`example.invalid` 是专供无效示例的域名，本课不要访问它，也不要把它作为真实服务地址。目标是明确这个目录名属于一个路径段，并分清展示名称、请求地址与服务端真正存在的资源；准备纸面记录即可，不需要创建服务或上传文件。

## 对照三个地址表示

从一个明确约定的 URI 路径段表示出发，空格写作 `%20`、井号写作 `%23`，因此示例可以写成 `https://example.invalid/dav/A%20B%231/`。两种百分号序列各代表原始目录名中的一个字符；末尾斜杠是这里约定的集合路径写法，不是目录名称的一部分。如果把井号原样放入 `https://example.invalid/dav/A%20B#1/`，`#` 后的 `1/` 是 URI 片段，不属于发往服务器的路径；它不是前一个地址的等价拼写。不同服务器对目录结尾与规范化可能有自己的规则，不能只靠纸面地址断言某台服务器接受请求。

## 做一次手工分段检查

在记录卡分别标出 scheme 为 `https`、主机为 `example.invalid`、父路径为 `/dav/`，目标目录段是 `A%20B%231`。对错误示例另标出路径中的 `A%20B` 与片段 `1/`。这里的片段是客户端 URI 的组成部分，不应当被解释成服务器目录中的井号文字。别把路径里的斜杠与目录名中的字符混在一起；若真实目录名本身还包含其他保留字符，需要依据那一字符在对应位置的用途另行核对。

## 区分一次编码与重复编码

如果有 Python 3，可在自己电脑上运行下面的纯本地示例。它只解析字符串，不发出任何网络请求；分别打印两个路径和片段。第一行的路径包含 `%23` 且片段为空，第二行的路径止于 `A%20B`，片段是 `1/`。输出用于检查示例语法，不等于证明真实 WebDAV 服务已经响应，也不能替代查看服务端日志。

```python
from urllib.parse import urlsplit

examples = ["https://example.invalid/dav/A%20B%231/",
            "https://example.invalid/dav/A%20B#1/"]
for value in examples:
    parsed = urlsplit(value)
    print("path:", parsed.path, "fragment:", repr(parsed.fragment))
```

`%23` 表示编码后的井号；如果把已经编码的百分号再次编码，`%2523` 解码一次得到的是文字 `%23`，不是直接得到井号。不能因此把应用的每个 `%25` 都判为错误：实际目录名可能真的包含百分号字符，而且客户端与服务器的解码层次需要证据。保留输入与实际观察，不要在不知道原始目录名和服务规则时反复增删编码字符。URL 的字符处理应以 RFC 3986 和实际服务接口为准。

## 在授权服务中确认真实身份

如果自己管理或获准访问 WebDAV 服务，在服务自身管理界面找到一条包含空格或井号的现有音乐目录，记录非敏感服务别名、父目录和显示名称。不要更改或删除共享文件，也不要把密码、令牌、完整内网地址和私人曲库分享到记录中。若没有这样的授权资源，保留纸面练习即可；不必为测试创建公开文件或在互联网上寻找陌生服务器。

## 在调调中按实际入口浏览

打开已授权的 WebDAV 来源，先确认服务别名与账户，再逐级浏览实际能看到的父目录和目标目录。若应用显示的是解码后的名称，就记录显示值；若不显示原始请求地址，不要声称已经观察到它编码成了什么。找到自己有权播放的一首音轨后，分别核列表、曲目身份和实际播放状态。显示正确名称而播放失败，可能涉及网络、权限或文件，不能单凭一个结果断言编码问题。

## 排查并写出证据边界

目标不出现时先核所选服务、用户权限和父目录，再检查服务器侧资源是否真实存在；如果有合法的服务器日志，去除敏感信息后再比较实际请求路径。不要为排查把认证信息发给第三方，也不要关闭安全保护或开放公网。系统或服务可能重定向路径；需要记录实际状态和位置，不猜测每个服务都采用同一重定向方式。每次只变一个条件并保留原始结果。

## 交付与恢复

交付示例的三种表示、编码和片段边界，另附真实服务中可见的去敏目录、曲目与待核项。不要把示例域名改写为可连接的真实地址，也不要把列表可见写成文件已下载。完成后恢复原先来源、音量和队列，不修改服务器内容。本文依据 RFC 的通用 URI 语法和公开发行说明设计；未声称抓包、私人服务器访问或真机播放测试。

若服务实际使用的目录名含有中文或其他非 ASCII 字符，应根据服务文档与真实观察另建一项，不将本例的两个转义结果直接复制到其他名称。记录日期及所用服务版本，方便后续复查。
