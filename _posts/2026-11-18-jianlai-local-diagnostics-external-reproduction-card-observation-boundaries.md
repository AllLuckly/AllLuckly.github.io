从普通笔记的三字符短卡开始，用实际本地诊断入口保存能确认的状态，再另写一张人工复现卡。区分用户观察、诊断页原文与推测原因，不承诺诊断能修复、自动导出、检测所有宿主或替你发送报告。

## 一、先选一个真正需要记录的现象

可以记录自己确实遇到的键盘状态、候选显示或某个设置返回后的差异，不要求先制造故障。若当前输入正常，也可做一份标清正常的基线，不把它改写成已复现错误。先记版本、设备类别、宿主、方向、当前语言和最后一次相关动作，主题与字体保持当时状态。所有试输在新的普通草稿，原稿不删除。官方设置图侧栏有本地诊断入口，能支持本课寻找该页，却没有展示它必定列哪些字段或错误码；因此观察卡先由自己建立，不等一个未承诺的自动报告替你补起点。

## 二、用三字符短卡确定操作起点

在可辨的普通输入框中录入“岸40”，这是一个汉字和两个ASCII数字，目标没有空格、句点或换行。先确认实际显示的是键来，再观察输入过程与提交后的正文，保存实际结果；候选看见岸而正文仍空不是同一状态。若无法完成短卡，记已经到哪一步以及看到什么，不由目标字串替自己填已输入。三字符只为缩小复查范围，不表示它覆盖了所有输入方案，也不把手动字数当准确率。原有长文暂不拿来回放，因为看不清最早变化发生在第几步，会让诊断页即使有信息也难与用户操作对应。

```text
岸40
```

## 三、找到真实本地诊断页再抄现有字段

保留短卡与当时状态后，回键来主App寻找能明确认出的本地诊断入口，按安装版真实流程进入。不要把键盘里的普通设置、系统分析页面或另一应用的日志叫同一页。记录当前页名、实际可见字段和原样反馈，没有的项目写未提供，不从截图侧栏推断它必有内存、网络、权限或宿主事件列表。若没有对应入口，就交付版本与停止点，外部复现卡仍可继续完成。打开页成功只能证明进入该页，不能因此写诊断运行成功、问题已修复或所有检查通过；需要操作的真实控件另行确认后才记录。

## 四、诊断原文与自己的判断分两栏

对实际可见信息尽量按原样保存，旁边另写自己如何理解，空白处不补造状态码。页面若显示某项正常，它只覆盖该项公开可辨的范围，不能由此证明原来候选问题不存在；页面无明显异常也不是所有宿主兼容证明。自己的“可能与字体有关”属于待验证假设，不把它改成诊断页已经确定字体损坏。没有可辨导出按钮时可人工抄下必要字段，不能指示用户寻找本文虚构的自动上传、复制全日志或一键修复。记录发生时序，尤其说明诊断是在原现象之后打开，而不是把后来的正常页当原现场同时证据。

## 五、另建人工复现卡串起前后状态

在自己掌握的外部笔记填写下方字段，分别写基线、触发动作、实际结果、预期依据与停止点。预期可来自原样目标岸40、自己先前确认的基线或有出处的公开说明，不能只是想象某按钮理应如此。每个动作写一次，例如进入一个设置、只改一个值、返回同一草稿，再核相同短卡；未做的动作留空，不补成已执行脚本。卡片是人工格式，不要求键来解析或导入。把本地诊断的具体原文作为附件一项关联，不将整个外部表假称为应用自动生成，后面审阅者才能知道每个结论来自哪里。

```text
manual reproduction card
version / device / host / language / original values
baseline / one trigger / actual result / expected-result source
local diagnostic text / observation timing / repeat / recovery / pending
```

## 六、只重做一个可恢复条件并保留两轮

如果原动作可安全恢复且你愿意复查，可先回已确认的原值，再只重做那一项，记录第二轮是否同样出现现象。不能重做时直接标未重现，不把第一轮删掉；两轮不同也保留各自宿主、方向和起点。正常基线可重复同一短卡，不必为了出现红色状态改坏更多设置。诊断页打开本身是否改变了键盘会话要作为可能的条件差异记录，不能凭结果好转就认定它执行了隐藏修复。没有连续守候的部分不填稳定多长时间，实际两轮也不等于统计意义上的全部场景通过。

## 七、沿证据缺口补记录而不猜内部原因

复现卡缺起点就补原值，缺实际结果就重看已保存稿，缺字段说明就保留原文和未理解的范围；这与已经知道内部原因不同。不要把打开诊断页后无错误扩展成所有网络、词库或字体都已检查，也不凭一张截图判定某个宿主有缺陷。需要另试宿主时建立单独条件，原轮不改名覆盖。没有真实支持的重置词库、清缓存或发送日志流程不作为修复步骤。可恢复的普通输入基线仍不可建立时，交付具体停止点与当前能用的输入方式，避免反复改动到无法回到最早现场，再把一串推测叫排障结论。

## 八、恢复原值并交付两份来源清楚的记录

按起点记录恢复本轮真正改过的设置，再回普通草稿核岸40或自己原来可用的短卡，实际做过才记恢复通过。交付本地诊断页的真实范围、人工复现卡、两轮结果与未执行项，注明它们各自时间顺序和来源。原稿、目标与修订稿保持可回查，不把诊断记录自动发送给任何人，也不声称教程已经提交工单。一次正常结果可以作为当前基线，但不能保证未来无故障；一次可重复问题也不代表全部设备都受影响。以后更新版本或换宿主，应附新条件再记录，而不是用旧诊断图覆盖新现象，最终成果是能复查的证据链而不是猜出的内部实现。
