在普通草稿中用键来输入一个只有两个成员的原创 JSON 对象，交付原文、成员类型账与一个修复反例。输入准确和外部解析成功分别验收；键来负责文字输入，不被写成 JSON 编辑器、解析器或数据上传工具。

## 一、先画出两成员的纸面结构

先在纸上写明这个练习对象只含姓名标签与数量两项，标签内容是示例品牌拼写，数量值是二，没有账号、令牌或服务器地址。把成员名、值、值类型各分一栏，明确成员名都为字符串，而第二个值才是数字。下面代码块提供唯一原始行，不含注释、外层说明或代码围栏本身。普通文本宿主可以保存这行字符，但这不等于理解其结构；如果需要解析，必须另用明确的工具。先确定交付边界，避免为了证明键盘可用而把无关的网络接口或真实应用配置带进来，本课全部输入都可以留在本地草稿。

## 二、先输入外壳再补每个成员

进入普通可编辑区域并确认当前键来，使用安装版实际英文字母与符号键面输入目标。可以先完成左花括号与第一个成员，再输入分隔逗号、第二成员和右花括号，不要求通过某种未公开快捷方式一次生成成对符号。成员名与示例品牌都要保留半角直双引号，数量二外面没有双引号；两个冒号分别连接各自成员名和值。当前样本无空格，虽标准允许某些位置的空白，本练习仍先按原样交付。先提交组合再检查正文，不用候选栏里尚未上屏的英文来充当已经输入完整的证明。

```text
{"name":"Jianlai","count":2}
```

## 三、对符号做角色而非总量检查

核对最外面一对花括号，里面一枚逗号隔开两成员，两枚冒号各在正确的成员名之后。整行共有六枚半角双引号，分为成员名两对与第一个值一对；最后的数字不占一对引号。仅仅数够六枚仍不够，要确认成员名的闭引号仍位于相应冒号之前，分隔逗号也没有混进字符串。参照原始样本逐段指读，遇到全角冒号、弯引号、单引号或长得相似的括号就记为字符差异，不靠主题颜色判断语法。将错误位置记在外部核对表，不把额外说明插入 JSON 行，否则会引入新的、不属于目标的字符。

## 四、读回值与类型，特别保留数字条件

纸面读回时，第一成员的值是大小写按样本保留的字符串，第二成员的值是数字二。若给二加上直双引号，结果在语法上仍可能是合法对象，但值类型变成字符串，已经不是这份任务的目标；这说明“能解析”与“数据符合约定”是两个条件。成员名也必须核对原拼写，不能因为人能猜到意思便接受大小写或字母变化。此对象只有两个不同名称，不涉及重复成员名的处理差异；不为了扩展练习随意添加第三项。保留一张两行类型账，使后续工具给出什么输出都有明确的比较依据。

```text
name: string = Jianlai
count: number = 2
```

## 五、用尾逗号副本验证定位能力

复制正确行到另一份练习区，在最终右花括号之前故意多加一枚逗号，原始正确行保持不动。按 JSON 对象语法，逗号用来分隔成员，后面应接下一成员，不能把这个尾逗号视为无害的装饰；某些宽松语言或工具允许的写法不等于标准 JSON。先人工圈出多余符号，再用宿主选择或插入点只删除那一枚，核对两成员及内部引号没有受影响。修复后应回到唯一目标，不顺便改成员顺序或加空格。若不小心删除数字或花括号，停止连按，依据原文重建副本再检查，避免在不确定状态下继续扩大修改。

## 六、外部解析报告必须另列

有可信的本地 JSON 工具时，可以给它正确的无隐私样本并记录实际报告，检查输出对象恰含两成员及前述类型。不要把文章围栏、成员账或“解析通过”字样一起送进输入；工具若支持宽松模式，要明确是否按标准 JSON 检查。没有工具则保存人工结构检查，标记尚未解析，不需要在线搜索校验站或上传自己的其他配置。工具通过仅说明它接受了本次输入，不能证明所有未来对象都可用，更不能说键来提供 JSON 校验功能。实际报告与纸面预期分开保存；若工具把对象美化换行，另存输出，不覆盖原样输入依据。

## 七、按字符、语法、类型分层排错

出现报错先比较直双引号与半角标点，再检查括号配对、分隔逗号与冒号位置，最后核值类型和成员拼写。字符全对但输出不是预期时，回到类型账，不先换皮肤或重装键盘；例如字符串形式的二并非显示字体导致的数值二。若宿主自动把引号变弯，应记录发生在提交、粘贴还是保存重开之后，并用可保留原文的副本重试。某工具报错的行列位置只在其当次输入里解释，不能当作键来统一错误码。每轮仅修一个可说明的差异，保留原行与运行报告对应关系，避免把后一次报告错配给前一次文本。

## 八、保存一份最小可复查包

最终保留干净目标行、两成员类型账、尾逗号修复记录与实际验证状态。先检查源字符，再检查标准语法预期，最后记录外部工具是否真正运行，这个顺序可以让失败落在具体层次。关掉再打开宿主，确认原文与说明没有混成一行；若没有执行这一步就留待办，不填写已保存的结论。把当前使用的键面与宿主名称写在旁注，下次复现仍用相同样本。以后若引入反斜杠、换行转义或更深对象，应另设新约定和新例子，不能拿本次两个简单成员的通过状态替代更复杂内容的检验。
