LANraragi 以漫画归档及标签管理为核心。漫阅+ 可以通过它的原生服务入口读取自己的归档库，每个归档通常对应一部作品和一个章节。本篇先连接一份小归档，重点检查服务根地址、API 密钥与页面索引。

## 准备一个已完成索引的归档

在自己的 LANraragi 服务中确认练习归档能打开，页面顺序和数量正确。可以用一份自制或有权阅读的短篇 CBZ，先给它清楚的标题和两三个真实标签，例如作品主题和作者名，之后分别用标题与标签寻找，便于确认资料确实来自这份归档。归档尚在导入或索引时，页面信息可能还没准备好，应等服务端处理稳定后再连接客户端。

记录服务器根地址与访问模式。公开读取与要求认证的配置不同；开启相关限制时，可能需要 API Key。漫阅的原生服务器书库属于 Ultra 范围，服务器访问控制仍由你自己的部署决定。不要把后台管理员网页密码直接当作 API 密钥使用。

## 添加 LANraragi 类型书库

在「书库」→「管理书库」中选择添加书库，服务类型选 LANraragi。填写名称和服务器根地址，例如结构上类似 `http://192.168.1.20:3000/`。实际地址以自己的部署为准，不要追加某个具体归档页面，也不要手动拼上 API 路径。

反向代理使用子路径时应保留正确前缀。需要密钥的服务，把原始 API Key 填入专用字段，不要手动进行额外编码，也不要把它放到地址里。公开读取的服务是否允许空密钥，应以服务器设置为准；不能从能看见首页就推断所有 API 都允许匿名访问。

## 连接后按标题和标签寻找样本

提交「连接并保存」，等待访问验证和书库加载。先搜练习归档的标题，再尝试它已有的标签或作者信息。这里的搜索范围与当前已加载书库有关，不能直接当成全互联网搜索。若目录尚在加载，等待完成或检查进度，再判断是否缺少作品。

LANraragi 的归档与普通连载网站的多话漫画结构不同。一个压缩归档可能就是一册或一个短篇，客户端显示一个章节不一定是漏掉其他章节。你需要比较的是归档内页数和图片内容，而不是要求它自动按故事场景切成很多话。

## 打开归档核对页面顺序

进入归档详情并打开阅读，检查第一页、中间和末页。页面顺序由服务器归档内容与索引提供；如果顺序错误，先在 LANraragi 自己的阅读界面查看同一归档。两边都错时，应处理源归档命名或服务端索引，而不是在漫阅里来回切换阅读方向掩盖问题。

若封面正常、正文却失败，先确认归档索引已完成、文件仍存在且当前账号有读取权限。封面和具体页面是不同请求，封面能显示不足以证明整个归档链路完整。暂时未完成索引的条目可以稍后刷新，不要立即删除服务器中的唯一原文件。

## 下载与阅读记录的范围

需要离线时，在漫阅中明确下载目标归档或相应章节，等待完成后断网打开。服务器上保存归档、手机显示目录、手机保存页面，是三个不同状态。尤其在 NAS 空间充足而手机空间有限时，应按最近阅读需要下载，不必整库复制。

当前原生 LANraragi 接入的阅读进度与收藏主要在漫阅本机管理，不应套用 Suwayomi 的服务端进度能力。你在漫阅读到第十页，不代表 LANraragi 网页端一定显示相同位置；多设备阅读资料同步也需要使用漫阅实际提供的相应功能。

## 密钥变更与服务器迁移

服务器修改 API Key 后，在连接中按当前界面更新凭据，再验证原先的练习归档。不要同时修改地址、账号和密钥后只凭一次成功判断全部关联正常。若地址变成完全不同的服务，应建立独立连接并保留原有下载、历史来源，不让同名归档混为一条记录。

备份和迁移配置时，凭据可能不会随普通数据备份移动到新设备。新设备看到连接名称却访问失败，应先补齐有效认证，再检查目录。不要把密钥写进公开截图或教程例子，求助时只描述认证模式、错误类型和必要的脱敏地址结构。

## 常见问题

**API Key 和管理员密码可以互换吗？** 不能。它们对应不同认证用途，按服务器设置取得 API Key，再填入专用字段。随意尝试后台密码不会让原生接口自动接受它。

**为什么一本归档只有一个章节？** 这个适配按归档映射作品和章节，归档内图片才是具体页面。判断是否完整应比较页数与内容，不是只看章节按钮数量。

**标签更新后搜索为什么暂时没变化？** 客户端需要刷新相应书库数据，搜索也可能作用于已加载的快照。先确认服务端已保存标签，再刷新当前连接，避免不断新建同名连接来尝试获取变化。
