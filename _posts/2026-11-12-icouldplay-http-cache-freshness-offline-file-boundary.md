响应中的 max-age=600 不是六百兆缓存，也不是影片恰好十分钟。本课把 HTTP 新鲜期、当前响应年龄和自己是否持有完整离线文件分开记录。云映正常观看与外部响应资料各有证据来源，不假定应用提供缓存头查看器，也不通过改系统时间或清空数据来凑出一次结果。

## 一、固定自己有权核对的资源

选择自有小视频或自己管理来源中的一个明确资源，记录文件、版本、来源和取得时间。若只能看应用而拿不到响应资料，就先做观看记录，字段栏写未取得，不从播放顺畅反推响应头。若有电脑已有可信工具或管理员记录，标明证据来源，并区分清单、封面、字幕与真正媒体响应；这些资源可能各有缓存规则。不要把封面图片的新鲜期直接套给影片，也不使用另一份同名内容代替当前对象。初始原件保留，所有操作限定在可辨认小样本。

## 二、把响应例子与演算条件分开

下方第一行是教学响应字段，不是本次真实服务器结果；后两组是已经给定当前年龄的纸面计算。把600的单位写秒，再换算为十分钟，只说明新鲜期数值，不给影片时长栏填十分钟。当前年龄在真实缓存中需要按协议考虑相应时间信息，不能只看文件创建日期，或机械拿一个 Age 字段当全部条件。本例为了练习边界，明确直接给出100与600两个当前年龄，避免让尚未取得的服务器时钟或传输信息变成假定已知。

```text
Example header: Cache-Control: max-age=600
Case A: freshness_lifetime=600 seconds; current_age=100 seconds
Case B: freshness_lifetime=600 seconds; current_age=600 seconds
```

## 三、按新鲜期规则复核严格边界

依据[RFC 9111 HTTP 缓存说明](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2)，新鲜判断比较新鲜期是否大于当前年龄。本例只在没有其他更严格条件的纸面前提下，A 的600大于100，B 的600不大于600；不能把等号也当新鲜。A 距这个边界还有五百秒，是本例计算差，不是设备保证至少缓存五百秒或影片保证还能播放五百秒。将定义、算式与应用实际状态分栏，真实响应缺少必要资料时保留待核，不用这张纸面卡片替自己的网络来源通过验收。

## 四、新鲜不等于完整保存或永久不变

新鲜期涉及缓存何时可不再验证就复用相应响应，不证明完整视频已存到手机，也不证明来源在此期间绝不更新。文件是否完整、哪些依赖资源仍需访问、能否离线观看，要另按实际字节与播放结果核对。若只保存了 HLS 清单，一个新鲜的清单响应也不自动包含所有分片。反过来，自己已保留的完整合法副本不会因为纸面新鲜边界到了就被这个数字自动变成缺页文件。不要把缓存语义解释成应用定时删片承诺，也不从播放器继续观看位置推出已经有全部媒体。

## 五、回到云映分开核在线与本地副本

有真实来源与独立完整副本时，分别打开它们，先核开头、一个中间动作和末尾标识，记录所选来源身份。不要在缓存刚播过一小段后断网就宣告整片离线可用；完整离线准备应在已有流程下检查目标范围与重开结果。若本轮只检查在线顺播，就写在线观察，没有做的本地或离线环节仍未核。结果差异只能先定位到具体路径，不能从两条表现直接确定是哪一层缓存出问题。保留日期与版本，避免稍后远端已更新而两份内容不再可比。

## 六、其他指令另读定义，不靠字面猜

实际字段若出现 no-cache，要注意它要求复用前验证，不等于名字字面所暗示的绝不存储；no-store 又是另一项存储约束。分别保留原字段与适用对象，不把两个词互换，或声称其中一个会把你已有的全部影片删除。多个指令、共享缓存与私有缓存等条件可能改变实际判断，本课的两张年龄卡片不涵盖所有组合。遇到不熟悉指令先回规范，不自行修改服务器响应来让应用通过。应用未展示缓存内部状态时，就保留外部声明与观看结果两条证据，不补造实现细节。

## 七、排查单位、响应身份与历史页面

若把600写成兆字节，回到秒的单位；若结果与实际刷新不同，先查字段来自哪次请求、哪个资源和哪个最终响应，不把浏览历史页面状态直接当 HTTP 缓存新鲜度。若只见一次旧画面，记录内容锚点与时间，不直接要求清空所有应用资料。源地址换对象、清单更新或实际下载未完成，都需要各自证据，不能只用“缓存”两个字结束排查。每次只改变一个已发现条件，保留原响应和副本，不改系统时钟；无法解释的差异明确待核，避免从有限观察断言服务端或客户端一定违规。

## 八、完成三层记录与可恢复结果

最终保存响应来源与原值、纸面年龄条件与结果、实际在线或副本播放观察，以及未确认项。退出再返回同一素材，复核自己确实选对来源；未执行离线验收就不写离线通过。检查结论没有把十分钟新鲜期写成十分钟影片，没有把缓存声明写成下载完成，也没有把边界到时写成自动删除。原文件与记录不覆盖，下一次换资源重新核声明。成果是能说明缓存定义与实际可读范围的分层清单，不是对所有网络、服务器或设备的永久可播放保证。
