同样以 UTF-8 保存的两份 TXT，一份开头可能多出 `EF BB BF` 三个字节。Unicode 把位于 UTF-8 数据开头的 U+FEFF 用作可选签名；它不改变 UTF-8 的字节顺序。本课制作一对无隐私的小样本，在电脑先核字节、再尝试书屿导入，观察正文开头和目录。它补充普通 UTF-8 乱码排查，不假定书屿一定忽略或显示该签名。

## 保存原书并确定测试范围

不要在唯一原稿或正在阅读的书上修改编码。建立单独练习文件，内容为两行“第一章”和“春天。”，记下正文、换行及文件身份。准备一台有 Python 3 的电脑和可将文件传到 iPhone 或 iPad 的方式；没有电脑或不熟悉命令时，只阅读字节说明并把生成与导入标为未完成，不从网上下载未知脚本。两份样本是自己创建的示例，不包含私人书籍或版权内容。

公开资料列书屿支持 TXT、本地导入及目录浏览，但具体识别、去重和显示行为需在安装版观察。这个任务比较文件开头的可选签名，不测试所有编码、章节标题规则或应用内部解析方式。先记录系统及书屿版本，保留现有书架与笔记。

## 在新目录创建两种文件

在电脑上先进入用户自行选择的安全工作目录，确认其中不存在 `bom-demo` 文件夹。将下面完整代码保存为 `make_bom_demo.py` 并运行 `python3 make_bom_demo.py`。代码使用新建目录和独占写入，若目录或文件已存在会报错停止；不要删除已有目录来强行重跑，应改用新位置。它只创建演示文件，不读取或转换私人书稿。

```python
from pathlib import Path

folder = Path('bom-demo')
folder.mkdir()  # 若已存在则停止
content = '第一章\n春天。\n'.encode('utf-8')
for name, data in [('plain.txt', content),
                   ('signed.txt', b'\xef\xbb\xbf' + content)]:
    with (folder / name).open('xb') as out:
        out.write(data)
    print(name, len(data), data[:6].hex(' '))
```

预期 `plain.txt` 开头是 `e7 ac ac`，表示“第”的 UTF-8 字节；`signed.txt` 开头多出 `ef bb bf`，随后同样是 `e7 ac ac`。签名版比普通版恰好多三字节，其余字节一致。程序实际输出有差异时先核代码、编码和选择的文件，不把纸面预期填成电脑实测。

## 核对字节与正文不是同一层

`EF BB BF` 是 U+FEFF 在 UTF-8 中的编码；位于数据流最前面可作为 UTF-8 签名，并不意味着文本是 UTF-16，也不表示 UTF-8 分大小端。签名可选，因此没有它不代表文件有问题。某些解码方式会在开头识别并略去签名，另一些可能将 U+FEFF 保留在文本中；具体显示由工具和协议决定，不能从文件名推断。

如果要在 Python 中另行核对，可在不改文件的情况下用 `read_bytes()` 读取两份，然后比较 `signed[3:] == plain`。不能运行时保留“未实际比较”。位于文本中间的 U+FEFF 与开头签名不能一律当成同一用途；Unicode 对中间位置有不同说明，不要用全局替换删除真实书稿中的所有不可见字符。

## 传到设备并分开导入

用自己信任的系统文件传送方式把两份练习文件送到设备，确认接收位置和两个文件名；传送成功提示不等于书屿已导入。按书屿当前可见的本地文件入口先选 `plain.txt`，记录反馈并打开；再尝试选择 `signed.txt`。如果应用按内容去重、只保留一个条目或不允许分别导入，如实记录，不删除其他书或修改内容来强行制造两条。

在实际能打开的条目中核第一行“第一章”、第二行“春天。”及有无异常可见符号，再检查应用显示的目录和可用的重开路径。纸面样本中的换行是内容，不保证每种标题都会被识别为章节。若只导入一份或界面没有目录，记录实际范围，不推断另一份必然相同。

## 用只读检查区分签名与正文

如果电脑文本编辑器支持查看编码或显示不可见字符，可分别打开两份副本，观察开头显示；也可只在外部 Python 中比较字节，不需修改文件。系统预览中看不到某个符号不等于文件中不存在签名；同样，应用显示了一个方框时也不能单凭外观断言那一定是 BOM。先核当前选中的确切文件与原始字节，再记录视觉结果。

为避免混淆，不要在两个样本中增减正文、改换行或修改章节名。若书屿显示不同，保留两份原始字节、导入反馈和版本供排查；若它们显示相同，也只说明这两份小样本在该次观察中相同，不能证明对所有 TXT 和所有位置的 U+FEFF 都一致。

## 排查并保留原文件

生成失败时先看目录是否已存在、Python 是否可用及报错位置；不要用覆盖命令重跑。设备找不到文件时检查实际接收位置与可读权限；书屿提示重复时记录实际行为，必要时只比较已导入项与外部样本。若原书出现乱码，应回到保留的源文件判断原编码，不把删除三个字节当成所有乱码的修复方法。

记录样本文件名、前六字节、每份大小、传送与导入反馈、首行和目录结果、未完成项；不分享私人书稿或账户信息。用户决定是否清理 `bom-demo` 练习目录，删除前确认目标仅包含本课生成的无隐私文件。原书、旧条目和阅读进度保持不动。本文没有声称执行书屿真机或编码兼容测试。
