把 CSS 写进字幕文件，不表示所有播放器都按网页方式执行；把 STYLE 当作正文，又会丢掉样式块的边界。本课制作一个原创小文件，先审核结构，再在云映分开核文字与外观。编辑使用电脑现有文本工具，应用里只使用已有加载和播放入口，最终保留可读备用版与明确的兼容性观察。

## 一、准备不被样式覆盖的文字基线

选择至少十秒的自有短片，背景尽量稳定，没有烧录本课句子。在云映先确认基本播放，再记录文件、来源与当前字幕显示条件。电脑用纯文本编辑器新建 UTF-8 文件，另保存只含普通句子的副本，用于样式出现问题时继续阅读。开始前说明测试对象是一个简单样式块，不是整个网页 CSS 系统，也不是云映提供了样式编程界面。若当前版本没有外部字幕加载入口，就先完成源码检查并把播放状态记未执行，不用一张文件列表截图代替显示结果。

## 二、完整保存一个样式块和两条条目

复制下方原创文件，STYLE 位于第一条字幕之前，块内部不插空行，结束后用空行与时间条目分开。review 是本课自定义类名，第一条引用它，第二条用普通正文；可读句子相同。不要把样式声明移入时间区间后的正文，也不要为注释加入时间箭头。保存为真正的 .vtt 后逐行核括号、句点与大小写，确认编辑器没有改成富文本。若只想改变颜色作对照，保留字号、方向和视频文件，不同时修改很多条件让结果无法解释。

```text
WEBVTT

STYLE
::cue(.review) {
  color: yellow;
  background-color: black;
}

00:00:01.000 --> 00:00:04.000
<c.review>Read the complete sentence.</c>

00:00:05.000 --> 00:00:08.000
Read the complete sentence.
```

## 三、给结构、预期与实见各留位置

参考[W3C WebVTT 样式块说明](https://www.w3.org/TR/webvtt1/)公开草案，样式块与有时间区间的字幕条目有不同角色；本例样式指向 review 分组。先在笔记标出样式开始、结束及两条时间范围，再写规范层面的样式意图，实际显示栏保持空白直到播放。不要因为样例写 yellow 就先填已显示黄色，也不因为未见差异就宣布样式块不存在。播放器不同路径对样式的处理仍需单独确认，标准文件结构与当前应用兼容性是两层结论，不能用其中一层替另一层盖章。

## 四、先读全句再描述颜色与底色

配对文件后从零秒顺播，两条各先核完整单词和标点，再记录文字颜色、背景及可辨认程度。出现同样外观时如实记当前未观察到样式差异，不为了达到预期先换另一个影片。出现差异时说明哪一条的哪些外观不同，仍不将一次结果推广到所有 CSS 属性或全部设备。暂停可帮助读清文字，之后恢复顺播检查起止范围，避免把暂停留屏误记成样式阻止字幕消失。文字完整但颜色不变，与文字丢失是两种结果，应分别进入记录。

## 五、用普通版定位文字与样式问题

切换到没有样式块与类标记的普通字幕副本，保留相同句子、时间与短片，先核选中的文件名再从头顺播。普通版可读而样式版少字或露标签时，记录差异到具体条目，保留两个文件供重查，不直接删掉所有符号覆盖唯一原稿。两版都不出现时，优先核加载状态、字幕选择与时间范围，不把所有故障都归给 CSS。若应用中已有字幕外观设置，原样记录当前值，不凭猜测新增“启用网页样式”开关；任何设置变化都作为另一轮条件。

## 六、制作错误位置对照只做文件审核

另存一份教学错例，把 STYLE 放到第一条字幕之后，并在文件名标为错例；先只在文本中比较边界与顺序，不要求将错误文件加载到日常观看流程。这个对照帮助你看见样式块位置也是文件条件，不是把相同字母放在哪里都等价。不要为修错例改写原文件的时间或句子，也不把错误样式行当新增字幕台词。若实际素材结构复杂、不能确认块范围，就先保留原件并按规范回查，不能把清理后的副本反说成作者原稿本来没有这些内容。

## 七、排查空行、转义与双重字幕

若 STYLE 文字直接出现在屏幕，先核它是否落在正文区、是否被错误转义或因空行分隔而改变结构。若两句重叠，先查烧录字幕及另一条内嵌轨道，而不是只找颜色属性。更换文件不生效时，重新核选中身份，必要时退出播放页再选副本，从条目前顺播。不要把 app 当前没有展示的调试日志补进笔记，也不为排查清空媒体库。每次保留修改理由与前后版本，不能通过同时换文件、方向和设置后恰好可读就断定唯一原因。

## 八、完成与保留可读回退

最终保存块位置、类引用、条目时间、完整文字、实际外观和未知六项。重新打开普通版顺播到八秒以后，确认仍有一份可读备用文件，并保留原片与样式原稿。源码审核通过不等于设备样式全部兼容，播放通过也不证明任意外部网页规则都能搬进字幕。对本轮只报告真正执行的动作与观察，换引擎路径、来源或显示设置后另记条件。这样可以清楚说明问题发生在文件组织、文字读取还是外观呈现，而不是用一个模糊的“样式正常”掩盖尚未检查的部分。
