Use an ordinary non-verification slider on a trusted source and record drag, value and return separately.

Define applicability

Apple’s public Manyue 2.0.7 notes mention a fix for dragging sliders in an embedded web page. This exercise applies only to an ordinary volume, preview or display-value slider actually visible on a trusted source the user is authorized to use. Not every source offers one. Without a suitable control, mark it unperformed. CAPTCHA and security verification sliders are outside this exercise and are not automated.

Choose a reversible control

Confirm the installed version and open an existing trusted comic source through the web entry actually provided. Choose an ordinary slider with a visible effect, understood by the user and restorable to its starting value. Avoid controls for payment, deletion, account permissions or form submission. Record the public source name, purpose and current position without private URLs, accounts or sensitive pages.

Record the starting state

If the page displays a value, record it and its unit. Otherwise describe the thumb near the left, center or right rather than estimating an exact percentage. Note orientation and window size, ensure the page is loaded and identify the slider rather than a nearby scroll area. Stop when the original value or effect is unknown; do not change a preference you do not understand.

Drag once slowly

Touch the slider thumb and move it slowly a short distance in the other direction, then release. Record whether it follows, whether the page scrolls unexpectedly and the value after release. Avoid rapid repeats or other controls. Follow the page’s actual range, units and instructions; if it cannot be moved, retain the original state and record an unsuccessful attempt.

Observe the visible effect

Only when the control’s purpose is clear and the user agrees, observe its direct effect, such as a displayed value or permitted preview. Record thumb position, text value and effect separately; a change in one does not prove all succeeded. If an effect depends on network or media loading, wait for the current operation and record it. Do not immediately attribute service delay to app dragging.

Restore the initial value

Return the slider to the recorded value or position. Prefer a displayed value when available; otherwise describe restoration as approximate. If the page asks to confirm a change, read it and let the user decide; stop if unsure rather than submitting repeatedly. Recheck the displayed value so the test preference is not accidentally left in the user account.

Check the return path

Use the page’s or Manyue’s currently available close or back action to return to the original source and record action and destination. If the same web page and control remain available on reopening, compare its displayed value with the restoration record. Websites need not preserve temporary values. If not reopened or a new login is required, mark the step unperformed rather than relying on an old screenshot.

Separate dragging from tapping

If the ordinary slider also permits a track tap and its value can be restored, record one tap separately and restore the original value. A successful tap is not proof that dragging succeeded. No response to a track tap may reflect page design or device behavior; record the actual result. Skip if a safe tap is not clear.

Diagnose touch and page conditions

If the thumb does not move, first check page loading, touch location and whether another popover obscures it. Keep network and orientation stable, change one condition and retry once. If the page is unavailable or the control disabled, stop and record the error; do not clear reading history or reinstall first. Do not send screen recordings containing sign-in information.

Summarize the result and gaps

Record app version, public source name, ordinary control purpose, before and after values, visible effect, restoration and return destination. Mark anything not performed. Page behavior depends on both source and device; one failure does not establish behavior for every source. This exercise uses public release notes; the author has not tested a private source, device or account.

Check a safe range

If the page explicitly labels minimum and maximum, record both and compare two safe interior positions. Avoid extremes that could mute, overbrighten or trigger another action; the effect depends on the control. Movement in one direction does not prove the other direction works. With the user’s consent, observe one movement each way inside the safe range, then restore the original. Do not guess an unclear range.

Keep samples and records separate

Use one source page and one control at a time. Record a non-sensitive page name and control label without copying the page or private session data. If the page reloads and the slider changes, record the reload separately on the timeline rather than merging it with the immediate post-drag value. A different page or control needs a separate row to distinguish drag behavior from source state.
