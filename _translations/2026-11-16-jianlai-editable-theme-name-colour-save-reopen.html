Preserve provenance and original values in an actually editable theme, then complete one traceable appearance change.

1. Start with a theme you can actually edit

Begin with a theme you can edit and restore, recording name, source, background and colours. A built-in preview is not an automatically created copy. Published customisation/screenshots show editing and theme information, not universal duplication/new-theme actions. For read-only choices, preserve the state and record availability instead of inventing a copy button. Do not clear themes for a clean start. This task delivers one controlled revision, not a reorganisation of a theme marketplace.

2. Give the working record an identifiable name

Label the external record Working A. If an editable name field exists, follow its actual requirements and use a distinguishable name. Theme information may include identifiers/descriptions; do not force read-only fields or invent ID-generation rules. Without renaming controls, keep only the external label rather than claim an in-app rename. Preserve authorised provenance without impersonating a brand/author. The name assists traceability, not an assumed copyright or version-history system.

3. Choose one actual colour control

Fix background, font, language and layout, then choose one real colour control with an identifiable scope. Retain old/new values without assuming hexadecimal entry, an eyedropper or sliders. If it affects the full palette, record that scope instead of claiming a one-key change. Choose readable foreground/background relationships. A recoverable original value is more useful than many arbitrary selections for the later check.

4. Inspect the preview’s actual scope

Inspect which preview regions respond and whether labels, neighbours and candidate areas remain clear. Unshown pages need active-input checks. An attractive cover does not establish every state applied. Light/dark choices do not automatically create a schedule; record the side actually edited rather than assume the other synchronises. Decorative symbols are not functions: a pictured play icon does not add keyboard media controls.

5. Save and identify the working draft again

Use the real save/finish action, leave editing and identify the same theme in its list by name or recorded clues and colour. If unchanged, distinguish preview, saving and applying to the active keyboard. No automatic draft, rollback or cloud backup is assumed. Unclear feedback remains pending instead of repeated overwrites. Preserve source assets and provenance so the saved identity traces to this round rather than only a guessed colour.

6. Verify the active keyboard with fixed text

In an ordinary note, confirm Jianlai and the chosen theme, then type nonsensitive text. Inspect colour, readable labels and candidate commitment, retaining changed and unchanged regions. Appearance does not establish styled document text or enlarged controls. Keep background, space bar and sound fixed. Preserve selection versus application separately when needed. An editor screenshot is preview evidence, not a substitute for active typing and re-finding the working draft.

7. Diagnose naming, storage and application separately

An external label absent from the list is not failed saving if no in-app name field existed. A lost preview change needs storage checking; a saved list value with old active appearance needs identity/application checking. These are different layers, not reasons to delete themes or reinstall. Restore one condition using original values and retain feedback. Do not claim export, sharing or cross-device sync without controls, or invent a theme-file format to prove customisation.

8. Reopen and deliver revision or restoration

Reopen the draft and verify recorded name/provenance, single change and actual display. Restore original values and identify it again, or deliberately retain the revision. Deliver real editable fields, save/application results and uncertainty without calling external notes an automatic version system. Another reader should trace the source, change and recovery path. Recheck scope after version/theme/device changes. No exhaustive preset, purchasing-entitlement, export-format or device testing is claimed.
