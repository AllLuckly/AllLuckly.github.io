Compare a Kavita Continue From alias, underlying item and chapter actually opened in ManYue without treating two entries as two comics.

Prepare an authorized comic with progress

Choose a short comic in a Kavita library you manage or are authorized to use. Record series, volume or chapter, page count and a nonprivate visual anchor at the current position. Confirm the original file is recoverable. Use your own account and do not share a key or complete OPDS URL; ask the administrator if you cannot inspect the library or settings.

Understand the server continuation entry

Kavita documents that, when progress exists on a series, volume or reading list, OPDS can place a “Continue From X” entry at the top of the first page as an alias of the underlying file. The enhancement is configurable in user settings. Appearance depends on server version, settings, user and progress. An alias and original entry can point to the same file, but similar titles alone do not prove identity.

Record both server-side entries first

Using an authorized Kavita interface or trusted OPDS browser, locate the series and record whether a continuation entry actually appears, its indicated chapter and the corresponding ordinary list item. Do not copy URLs containing an Auth Key into public reports. If the continuation entry is absent, record not observed and inspect account, progress and server settings without forcing a shared configuration change.

Confirm the connection type in ManYue

Open the Kavita OPDS source configured in ManYue and confirm it uses the same account and library as the server-side check. A direct Kavita API connection and an OPDS source may show different entries; do not assume one interface guarantees the other. Find the series and continuation entry using the current interface, recording what actually appears. Mark a missing entry not observed.

Compare chapter and content

If ManYue actually shows both entries, record each title, chapter and visible page count, then open them as permitted by the installed version and compare the recorded visual anchor. Opening an entry, seeing the same chapter and landing at the same reading position are three different outcomes. ManYue’s public description says ordinary OPDS items that only provide whole-archive downloads do not support direct reading; follow actual link types and interface rather than promising every entry opens directly.

Record and troubleshoot

If Kavita confirms an alias but ManYue does not display it, first check account, connection type, first page and actual loading state; do not immediately delete the source or reading history. If chapter matches but position differs, record times, chapter, images and whether synchronization occurred without assuming either side is wrong. Keep redacted versions, observations and untested items. No physical-device or server test is claimed.

Compare identity through both entries

Suppose your test series has three chapters and Kavita’s progress is at chapter two. The server’s first page actually displays “Continue From 2” and the ordinary list also contains chapter two. Record location and text of each entry, then open ordinary chapter two to inspect cover, page count and a self-made marker. Where the server permits, inspect the destination of the continuation entry too. Only after checking agreement can this test record that the two entries point to the same chapter; the name alone is insufficient.

If ManYue shows only the ordinary chapter, record “continuation entry not observed,” then check the same account, whether you are on the first page and whether the list is still loading. If both entries appear but cannot be read, first establish whether OPDS provides page resources or a whole-archive acquisition link. Do not repeatedly import the same comic merely to display two entries or delete server reading history without authorization.

Separate server progress from client position

Kavita’s alias derives from server-side progress information. ManYue’s last position and whether it synchronizes depend on the current source, account and actual result. If the server indicates chapter two but ManYue opens chapter three, record observation times and book identity on both sides, then check whether a different series or edition was selected. Server progress, chapter mapping and client page position are different layers; do not automatically attribute one to another without verification.

If you need to observe a change in your own sample, preserve the original state and visual anchor, perform one reading action through the actual interface, then observe when each side changes. Without a sync prompt or permission, do not take extra action; mark synchronization unconfirmed. Do not request another person’s account key or call a delay data loss. Current version and server results must establish the behavior.

Protect the source and keep test results

Use identifiers such as series A, chapter 2 and visual marker B in notes. Record app and server versions, connection type, redacted account, visibility of both entries, each opened chapter and position and untested items. Kavita OPDS URLs and authentication keys are credentials; remove complete URLs, tokens and private comic images before sharing a report. Afterwards confirm the original comic and reading records remain, without unverified cleanup or replacement.

Recheck access conditions

Before testing, confirm the device can reach the private library and the current account may read the test chapter. On connection failure record the network and prompt; do not guess links when access is unavailable. After observation, restore the original network and reader view and confirm the source remains accessible to the authorized account.
