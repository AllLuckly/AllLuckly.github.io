One film can have regular subtitles, subtitles covering only foreign-language passages, and subtitles with sound cues. Jellyfin supports describing external subtitles through filename suffixes; iCouldPlay's visible names and playback behavior must be observed in the actual environment. A filename alone does not guarantee automatic selection or correct display.

Prepare a verifiable sample

Choose an owned or authorized short video and existing external subtitles, with permission to inspect the folder and Jellyfin library. In a trusted player check the opening, subtitle text and timing, and record a nonprivate reference line and time. Without external subtitles or server access, mark the prerequisite unmet. Do not download subtitles from an untrusted site or change a shared library for the exercise. Preserve originals and backups first.

Observe filenames and flags

In an authorized file manager record the video filename and its corresponding subtitle filenames. Jellyfin's official film documentation uses examples including Film.mkv, Film.default.en.forced.ass and Film.en.sdh.srt; these explain rules and are not your files. The suffix en identifies language, while default, forced and sdh are different flags and are not interchangeable. Record each actual file; format alone does not establish subtitle content or client compatibility.

Note the documented ambiguity of hi: hi alone resolves as the Hindi language identifier, while alongside another language identifier it can mark a hearing-impaired track. Do not promise a language or accessibility content based on those letters alone; check the server record and actual text. Do not rename existing production subtitles here. Ask the administrator to confirm server version and library rules first.

Record server results separately

In the authorized Jellyfin interface find the same film. Record visible subtitle tracks and language, default, forced or hearing-impaired flags; mark fields not shown as invisible. Match each server record to the actual file and distinguish external subtitles from embedded tracks. If identically named films have multiple versions, identify the current film and version first rather than attributing another version's track list to this sample. If a file exists but is not recognized, retain that observation without renaming or triggering a full-library refresh.

Inspect visible tracks in iCouldPlay

Open the configured authorized Jellyfin source in iCouldPlay and confirm the server, account and film. In the playback screen use a subtitle selection entry only if the current version actually provides one; entrances, labels and choices can vary by version and source. If no entry is visible, record that limitation rather than claiming the required control exists. Compare visible language and labels with the server list row by row and retain unknowns.

Compare subtitle content and timing

If selection is available, select one track and play the previously confirmed reference time. Record whether the reference text appears, whether its language agrees and whether timing roughly matches. Then switch to another track using the visible entry and repeat. Fill two-track results only when both can actually be selected and compared. A track covering foreign dialogue may correctly show nothing during ordinary dialogue; a track with sound cues should not be judged on language alone. If selection is unavailable, record the limitation and do not treat a server flag as proof of automatic playback.

Investigate missing or inconsistent tracks

If files exist but the server lists no track, check expected video/subtitle folder, matching filenames and the Jellyfin account's read access. If the server lists a track but iCouldPlay does not, confirm the same server, film version and playback session. If the displayed language and text disagree, recheck reference time, selected track and actual subtitle content. Change only one reversible condition at a time and record it; do not modify shared files, lower permissions or publish private subtitles or server addresses.

A default flag and an actual default selection are separate evidence: player, preferences and source can affect behavior. Mark unverifiable points pending. If text remains on the picture after subtitles are turned off, do not immediately attribute it to an external track; investigate whether it is part of the image. Format, fonts and client capabilities can affect rendering, but this observation cannot guarantee behavior on every device.

Make the comparison auditable

Keep the observation time for each row and identify whether it came from the file folder, Jellyfin interface or iCouldPlay playback. Do not combine results from different times or film versions into a single successful run. If an administrator later changes subtitle files or rescans, add a separate row for the new state and preserve the original pending items. When actual content conflicts with a flag, investigate using verifiable file content and the administrator-confirmed source; the filename is not proof of subtitle quality.

Save the comparison

Deliver a sanitized table of filename flags, Jellyfin-visible tracks, iCouldPlay-visible tracks, reference time and observed text. Confirm original files and configuration remain and restore the prior subtitle selection. The official documentation describes Jellyfin naming; this guide claims no physical test of any private server, app device or subtitle format.
