Prepare three samples with distinct spoken identities and record filenames, external track numbers, player display and the actual queue separately. Deliver an order ledger that can be heard back as one, two, ten. A file browser’s lexical order is not album order, and no native track-number sorting control is promised in 调调.

1. Establish three audible identities

Outside the app, make three owned short recordings whose openings say 曲一 (track one), 曲二 (track two) and 曲十 (track ten). They may be twelve, fourteen and sixteen seconds long. Retain untouched masters. Each must really contain its own spoken identity, rather than one recording renamed three times. Give the working copies the filenames below and separately record spoken labels and actual exported durations. A filename does not prove correct content. Leave preparation blank if recording and export have not happened; this article supplies no downloadable finished audio. Preserve the existing library and daily playback arrangement. Use only three identifiable exercise assets so a real album is not renamed or re-encoded for the test.

2. Record titles, album and track numbers externally

With an existing tool that can read tags back, give all three copies one exercise album and artist, titles 叶片甲, 叶片乙 and 叶片丙 (Leaf A, Leaf B and Leaf C), and track numbers one, two and ten. Save and reopen the tag reader to confirm these are audio metadata rather than a renamed folder. For MP3 ID3 tags, a track-number field can map to TRCK. A source specification explains field meaning, not that 调调 displays every field. Do not set a total of three and then diagnose track ten as an app error. These are three selected positions, not a complete ten-track album. Mark an unread field unverified instead of substituting a tidy external table for actual metadata.

3. Distinguish lexical from numeric order

Make a paper control from the filenames below. Character-by-character ordering yields the assets corresponding to one, ten, two, while numeric track order is one, two, ten. Different comparison rules produce different orders; ten preceding two does not indicate damaged audio. This control explains only the given strings and numbers, not which rule the file provider or 调调 will choose. Nor should title labels A, B and C silently become track numbers. Draw one mapping row per asset joining filename, title, track number and opening sound. When a view exposes only some fields later, the identity ledger still provides a reference.

4. Record the library’s actual arrangement

Import the three working copies through 调调’s published file-import flow, recording each response, then identify library items by audible content and visible titles. Write the arrangement actually shown. If no track-number or album-sort control exists, invent none; a missing displayed track number does not establish tag deletion. If an item is skipped, check for a mistaken existing asset or duplicate notice rather than deleting old music to force three new entries. Distinct audio helps identification, but the public description does not disclose duplicate-comparison internals. Retain each response. Only genuinely identified items proceed to queue arrangement; unconfirmed ones remain pending.

5. Arrange one, two, ten using the real queue

Set track one as current and use the queue facilities actually present to place track two and track ten next. The target is audible order one, two, ten, not a requirement to reorder the library first. Confirm ordinary sequential playback so repeat or shuffle does not invalidate the comparison. If you cannot restore the previous setting, record the state and stop manipulating unknown menus. When queue titles show the Leaf labels, use the external identity ledger rather than equating row positions with track numbers. If a drag or insertion action is unavailable, use an actual supported addition method and rebuild the practice arrangement if necessary. Do not claim an unobserved automatic numeric queue sorter.

6. Hear both natural transitions

Play naturally from track one’s beginning and hear all three opening labels in sequence, checking the current title after each transition. Repeatedly pressing Next is manual navigation, not proof of natural ordered playback; record identity checks using skips separately. Track two should precede track ten, established by sound and current-item identity rather than an already sorted paper table. If exported durations differ from the preparation plan, update the ledger honestly instead of treating a few seconds as misread track numbers. For silence, check pause, output and the original before blaming ordering. Leave any transition not actually observed pending rather than passing both.

7. Locate the layer behind a one-ten-two mismatch

If playback yields one, ten, two, first compare whether the queue was added in filename order, then whether titles were matched to the wrong sounds, and finally reread external track tags. Do not change tags, filenames and playback mode together, which would obscure the cause. Library arrangement, queue order and stored track number are three evidence layers. A pass at one does not pass the others. A missing track ten first calls for import verification, not a claim that two-digit numbers are unsupported. Keep the initial result, repair only the demonstrated arrangement error and recheck the necessary boundary. Preserve originals instead of permanently renaming them to suit a current list.

8. Restore playback and deliver the four-column ledger

Before leaving the practice queue, save filenames, titles, track numbers and audible identities, together with actual library order and the observed one-two-ten queue result. Restore daily playback through visible controls and record any unresolved final state rather than deleting music to clear the test. Mark reopening passed only after recognizing the exercise item again. The deliverable explains why filename order can differ from numeric order and which sounds verify the actual queue. Three samples do not certify every album tag or sort rule. A new tag editor, format or app version requires fresh field and control checks rather than reusing display positions.
