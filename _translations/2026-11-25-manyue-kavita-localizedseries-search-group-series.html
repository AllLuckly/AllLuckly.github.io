Use self-made comics to distinguish ComicInfo series and localized names, server search and client display.

Understand the documented field

Kavita documents LocalizedSeries as a non-standard field for a displayed localized series name, searchable by either series or localized name, with files using those names grouped into one series. This describes server behavior; it does not guarantee that every Manyue+ connection displays the same name or exposes the same search. Record versions and observed results.

Prepare self-made isolated samples

Prepare two short self-made comics in an isolated library you administer, with clear visual markers for first and second issues. Choose two fictional, non-sensitive names for series and localized name and record originals and backups. Use a normal test account authorized for the library. Do not rename another person’s comics or a production library, and do not assume similar names mean the files belong to the same work.

Establish web and client baselines

In Kavita’s web interface record the samples’ current series grouping, names, issue counts and search results, distinguishing any same-name real work using visual markers. In Manyue+ connect with the same normal account and note displayed names and available search. If the sample has not been scanned or the client lacks library access, record that state rather than blaming the localized field.

Inspect metadata location and original values

In authorized copies, locate ComicInfo.xml at each archive root and record Series, LocalizedSeries, Number and Volume for each file. Kavita calls LocalizedSeries non-standard; record it as absent where missing. Do not merge filename, displayed title and XML field into one value, or combine fields from different archives into a single record.

Configure restorable test copies

Only an editor familiar with XML, after an administrator confirms an isolated and restorable environment, should set corresponding names and issue numbers in self-made copies according to the documentation and validate XML. Record old values, new values and each file identity. Stop without authorization or a clear structure; never edit the sole original. Fictional test names are identifiers, not official translations of real works.

Check server grouping after scanning

Wait for or perform a test-library scan using current server controls and record the action and completion. Check whether both self-made comics appear in the expected series and issue positions, then record the displayed name. If grouping differs, check each file’s metadata, scan completion, series locks and access conditions without changing several fields at once. Even with a correct display name, verify issue and content identity using visual markers.

Compare both server searches

As the normal test user, search separately for the fictional series name and localized name, recording each term, search location and result instead of submitting both together. The documentation describes searching by either name, but version, library search settings, permissions and scan state may affect results. A missing result does not immediately establish file corruption; do not share authenticated search URLs.

Inspect actual Manyue+ display

In Manyue+ return to the server directory with the same user, record displayed names, series count and issues, and search separately for both names only if the app offers it. If search is absent, only one result appears or an older name remains, record it and check account, connection and page state. Server search support does not establish identical client behavior. Open only authorized self-made chapters to check markers.

Restore and retain evidence boundaries

Restore isolated files and settings from backup, confirming original samples and other users’ data remain; defer uncertain effects to the administrator. Record versions, fields per archive, scan results, both web searches, client observations and skipped steps. Remove private paths and credentials before sharing. This public-documentation guide claims no private-server or device testing.

Check same-name different works

Different series can share a localized name, so display text alone does not establish that they should be grouped. Record source, issue number and visual markers for self-made controls; real works also need publisher or authorized-source checks. If unrelated samples are grouped, record each archive’s fields and scan result for an administrator. Do not delete existing works or other users’ data to make search counts look correct.

Separate successful search from grouping

A search hit means only that a keyword produced a result in that entry point; open it and check series identity, issues and content before calling it the target. Conversely, two issues can be grouped while a client offers no localized-name search. Record server search, server grouping and client search separately; none substitutes for the others.

Preserve uncertainty about display source

A displayed localized name may come from several metadata sources, prior cache or saved server data. Record the actual ComicInfo field and display, but without refresh and source evidence do not claim this field change necessarily caused it. If neither keyword works, first check normal-user access, whether the library participates in search and scan state; mark the test incomplete if verification is unavailable.

Reproducible test values

Reproducible sample: archive one root ComicInfo.xml has Series River Demo, LocalizedSeries 河流样本 and Number 1; archive two has Series 河流样本, LocalizedSeries River Demo and Number 2. Distinct self-made images identify both issues. After scanning the isolated library, search the server separately for River Demo and 河流样本 and inspect grouping and two issues. Record any effects from the installed version or other fields; do not presume Manyue+ search results.
