A commentary file beside a movie is not proof that a client will display or play it. Check server recognition, then verify the sound.

Distinguish external and embedded audio

Jellyfin documents external audio and subtitles named with file suffixes. Language, flags and recognizable title text describe the stream. An external audio track is a separate file alongside the movie; an embedded track resides in the video container. Whether iCouldPlay displays and plays a server track must be observed on the installed version and cannot be guaranteed by naming rules alone.

Prepare two distinguishable sounds

Using a self-made or authorized clip, prepare a video and a self-made commentary copy matching its duration and timeline in an isolated test movie library. For example, record “original” near the video opening and “commentary” at the same position in the alternate track. Use moderate volume and verify both source files play. Commentary must lawfully correspond to the picture; do not extract unauthorized audio from restricted sources.

Make a file identity ledger

The administrator records relative paths, duration, opening sounds and format for video and commentary. With Test Film.mkv as an example, name the commentary copy Test Film.English Commentary.en.mp3 and place it in the same test movie folder. The English title and language code are only an example; actual audio language must match the tag. A Chinese commentary needs an appropriate language tag, and a filename change does not change the spoken language.

Understand title and flag rules

The documentation says arbitrary text not parsed as a language or flag may become the track title if an embedded track title is absent. In its example English Commentary is the title and en is English. Existing embedded titles may affect what appears, so record them rather than promising a particular label. The documentation also says filename flags are ignored on containers with more than one stream; do not generalize this into a claim that all tracks cannot be recognized.

Check the server web interface first

The administrator scans the test library using the normal procedure for the current server and waits for completion, then opens audio choices for the same film. Record whether original and external commentary appear, displayed language or title, selected state and time. If only one appears, do not delete or rename production files. Check placement, common base name, actual format and scan completion using only the test copies.

Confirm the selection by listening

On the web choose each available track in turn, return to the same picture time and listen for the prepared marker words. Record the option and sound actually heard. If silent, check mute, output device and volume. If commentary leads or lags the picture, record the offset; listing a file does not prove synchronization. If the web does not offer the external track, record it absent and stop comparisons that depend on it.

Observe the same film in iCouldPlay

Connect iCouldPlay to the same server, account and test library, open the same film and inspect the audio control actually offered in the installed version. Record visible choices and comparison with the web, then select available tracks and listen at the same time point. If controls or choices are absent, mark unavailable or not observed. Do not assume a feature of another client exists in iCouldPlay; if external commentary cannot be chosen, mark its playback not performed.

Investigate differences without guessing

If the web offers two tracks and iCouldPlay one, check server address, account, film identity and refresh time. Network, server output and client implementation may affect the result; one observation cannot establish the cause. If different selections sound identical, verify that switching actually occurred, the two audio files contain different material and the output device is correct. Preserve files and records; do not change format, permissions and names simultaneously.

Check timeline and stream count

At a second clear visual event later in the clip, record picture time and matching commentary, then compare playback on each side. Different durations, leading silence or different edits can cause mismatch. Record observable offsets without inventing a universal fix. For a container with multiple streams, have the administrator confirm its structure and consult the documented filename-flag limitation. A visible label does not prove the actual sound content.

Separate default and forced flags

Jellyfin lists filename flags such as default and forced. They are track metadata, not proof that a client will automatically select or mix tracks as expected. This commentary example adds neither flag and uses manual selection first. To explore automatic selection later, make a separate copy, record language preferences and the initial selection, and change one flag at a time. Successful manual playback does not verify default selection.

Use the same test files on web and iCouldPlay. If the administrator replaces a file, note the time and both identities and establish a new baseline. Avoid confusing lingering sound from a previous playback with the current track; pause and restart at a known position to relate the selected option to the sound heard.

Finish and restore

Prepare a table of source files, track labels, visible web and app choices, actual sounds at both points, timing differences and unperformed steps. The administrator handles test copies under normal practice and confirms production files and library are untouched. Remove account details, tokens and private addresses before sharing. This public-documentation guide claims no private-server connection or physical-device testing.
