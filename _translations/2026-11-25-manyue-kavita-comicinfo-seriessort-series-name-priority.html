Use self-made comics to compare ComicInfo Series, SeriesSort and actual server grouping.

Understand the field

Kavita’s comic-metadata documentation describes SeriesSort as a series sort title and says Kavita prefers it over Series. It is a non-standard extension in Kavita’s documentation; not every archive has it, and clients need not display the same name. Record Series, SeriesSort, displayed name and filename separately.

Prepare isolated self-made samples

Prepare two short self-made comics in an isolated library you administer, using distinct visual markers for issue identity and backing up files and metadata. Choose fictional non-sensitive series and sort names and use a normal account authorized for the library. If isolation cannot be restored, observe existing samples without editing another person’s comics or a production library.

Record current server state

Find the target series in the server web interface and record displayed name, series count, each issue’s identity and current search results. Distinguish same-name works using self-made markers and issue numbers. Record visible names and issues in Manyue+ with the same normal account. Note pending scans, insufficient permissions and absent client search separately rather than attributing them directly to SeriesSort.

Inspect both fields per archive

In authorized copies inspect Series, SeriesSort, Number and Volume in each ComicInfo.xml and record which archive contains each; Kavita requires that XML at the archive root. Distinguish a missing SeriesSort from an empty one. File title, archive name and folder name may also participate in identification and are not the same ComicInfo field.

Prepare a restorable field comparison

Only with administrator-confirmed isolation, backup and restoration and an editor familiar with XML, set different fictional Series and SeriesSort values in self-made copies. Record original values and validate XML. Do not simultaneously change issue numbers, account permissions or production works. If editing is unsafe, preserve the original observation and mark the test unperformed without claiming priority was verified.

Scan and inspect the server

Wait for or perform an isolated-library scan using server controls and record the action and completion. Inspect the name and grouping actually recognized by the server and verify each issue with visual markers. If results differ, check per-archive fields, file location, series metadata locks, scan state and server version, changing one condition at a time. Matching names do not prove both items were grouped correctly.

Compare server and client

In Manyue+ use the same server and normal account, reopen the directory and record displayed series name, chapter count and any visible search results. If the client name differs, check item identity, connection type and page state first. Server preference for a field does not prove the client exposes that field. Mark absent entry points, unsynchronized results and unobserved states separately without substituting administrator results.

Avoid overclaiming sort behavior

Preference for a sort-title field does not guarantee a particular language collation order. Studying sorting requires at least two distinct series and the current list’s sort criterion. This exercise checks naming and grouping; one sample cannot establish the entire shelf order. Do not change system locale or other users’ series names to force the expected result.

Restore and document

Restore isolated samples and settings from backup and confirm originals, other users and reading progress remain; defer uncertain effects to the administrator. Record fields per archive, scan results, server name, Manyue+ display and skipped steps. Remove private paths and credentials before sharing. This guide relies on public documentation and claims no private-server or device testing.

Record original and sort names separately

For each archive keep separate columns for raw Series and raw SeriesSort without rewriting punctuation, prefixes or language differences. Add columns for the server’s displayed name and the Manyue+ name. A single visible value does not mean the other field was removed from the file; inspect an authorized copy where possible and mark source fields unknown otherwise.

Use one controlled variable

When a test copy can be restored, change only the fictional SeriesSort value after recording the baseline, keeping Series, issue number, file location and account unchanged; record the scan separately. If files move or series names also change, the result cannot be attributed solely to the sort field. Skip without editing permission or confirmed scan completion and do not infer execution from similar labels.

Preserve grouping and search evidence

Record whether both files remain grouped, each self-made marker matches its issue, the server name and whether client search exists. One search result does not establish that every issue was identified. Open authorized chapters to check issue numbers and visual markers. If client search is unavailable, retain the web observation and mark that step unperformed.

Note version and field locks

The documentation describes Kavita’s metadata interpretation; interface, scan timing and existing locks can affect actual results. Record version and lock state, without unlocking production series when the effect is unclear or generalizing one version to all devices. If observations differ, retain source fields and task state for the administrator; mark a display name’s source unknown when it cannot be identified.

Reproducible test values

Reproducible sample: both archive-root ComicInfo.xml files have Series River Demo and SeriesSort Demo River, with Numbers 1 and 2. After scanning the isolated library, record server grouping and series name and check whether it reflects documented SeriesSort priority; use visual markers to identify both issues in Manyue+. If changing only SeriesSort as a restorable control, keep both Series values, issue numbers, paths and account fixed. Do not presume the client title.
