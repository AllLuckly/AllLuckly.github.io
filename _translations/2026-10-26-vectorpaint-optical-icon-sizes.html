Vector artwork scales, but its details may not survive reduction. Compare a fictional storage-box icon exported at 16, 32 and 64 pixels and make manual size-specific corrections. Do not assume the app automatically produces optically adapted versions.

Choose a simple baseline icon

Construct a monochrome box icon from a rectangle, opening and handle on a square canvas. Save a baseline and independent 16, 32 and 64 pixel working versions. Name them by target size. Distinguish document geometry, canvas zoom and exported pixel dimensions; confirm the actual export values before judging small-size appearance.

Inspect untouched reductions first

Export all three without adaptation and compare at their native display sizes. Record a disappearing handle, closed gap or uneven apparent edges before editing. Magnification can explain pixels but does not replace actual-size judgement. Check viewer scaling, then change one issue at a time so its cause remains clear.

Prioritise important visible gaps

In the 16 pixel version, enlarge a critical gap or simplify the handle before thickening every stroke, which can close openings. Remove secondary decoration while retaining meaning. Re-export and compare under identical viewing conditions. A clearer canvas at high zoom is not sufficient evidence, and the 32 pixel version may need less adaptation.

Adjust optical weight and centring

Make essential lines slightly stronger where useful and remove subordinate marks. Assess optical centring, which can differ from bounding-box centring because of openings and filled weight. Compare small whole-icon moves against the original centred version. Preserve shape proportions; the goal is clearer recognition rather than additional canvas detail.

Keep the editable sources distinct

Record each version’s changes, such as a wider opening only at 16 pixels. Keep those differences during future colour revisions. Reimporting a small PNG does not restore editable paths. Export from its appropriate original. Label any vector delivery by visual version; one file does not automatically select three distinct optical adaptations.

Check the actual backgrounds and placement

Test each size on light, dark and intended page backgrounds. White artwork vanishing on white is a contrast issue, not necessarily corruption. Pages may rescale the image again, so inspect actual placement. Keep an output list with dimensions and intended uses, and verify file properties rather than trusting filenames.

Compare without visible size labels

Compare baseline and corrected images at equal display sizes without first reading filenames. Record clearer gaps and more stable weight before consulting the change log. If a correction only makes the icon heavier, restore some weight while retaining useful spacing. Repeat on light and dark backgrounds. Restore explicit size, revision and use labels for delivery.

Rule out extra scaling before changing geometry

If all sizes blur, check viewer/page enlargement, exported dimensions and stale files first. For one uneven line, compare small position or weight changes in actual output. Increasing print resolution metadata does not substitute for required pixels. Retain a correction only when equal-size comparisons show clearer openings or more stable weight.
