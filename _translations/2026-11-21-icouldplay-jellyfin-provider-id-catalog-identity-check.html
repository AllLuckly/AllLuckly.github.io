A movie poster in iCouldPlay does not establish its metadata source or the file that will play. Select a Jellyfin movie entry you are authorized to manage and record provider ID, server entry, client display and actual opening separately. Jellyfin documents provider identifiers as an aid to identification; whether iCouldPlay shows one depends on its actual interface.

Choose an entry safe to inspect

Prepare an existing Jellyfin movie library, an authorized account and an authorized test video. Record its file name, duration and a non-private identifying opening cue, and retain backups of the file and current metadata. For an original clip with no public listing, do not invent a TMDb or other provider ID: mark it “not applicable” and practice the later entry and playback checks. Without server administration rights, do not rename files or edit metadata; observe only within existing authorization.

Confirm the provider and identifier source

In Jellyfin's actual server interface, inspect the entry's visible title, year and provider identifiers. Record provider name and actual value; if none is shown, write “not displayed” rather than inferring one. Jellyfin also documents placing some identifiers in file or folder names as one input to identification, but that does not require renaming every file. For an entry with a public listing, compare the provider's actual page with the work and retain its link and check date. Stop without a match rather than copying an example identifier at random.

Preserve a server-side baseline

Without changing configuration, record library name, entry title, year, visible poster and associated file identity. Similar or cached posters do not prove an identifier or file is correct. An ID identifies a work in a provider's catalog, not a checksum of the video. For similarly named works, record the year and other verifiable information rather than judging by poster color. Exclude private server domains, accounts, tokens and file paths from shared notes.

Locate the same entry in iCouldPlay

Open the already configured Jellyfin source in iCouldPlay, confirm the server and library match the baseline, and find the film through the list or search actually offered. Record visible title, year and image. If no provider ID is shown, leave that field blank instead of presenting the server-side ID as client-visible. If absent, first check account visibility, source and connection; one unsuccessful search does not justify deleting a library or changing server recognition rules.

Play and verify the file identity

Open the entry and compare duration, opening cue and one middle scene with the prepared video. If the server offers multiple versions, record the visible versions and your selection; do not assume iCouldPlay offers a selector if none appears. If actual playback differs from the server record, preserve the first observation and inspect the server's entry-to-file association before concluding that matching title or poster proves file identity. For a failure, record whether it occurred at listing, opening or playback.

Separate server metadata from client updates

Make a table for provider page, Jellyfin entry, iCouldPlay display and actual playback, listing verifiable information and time for each. If server metadata changes while the client still shows an older title or image, first confirm the source and whether a visible re-entry or refresh method exists. If not, mark pending rather than asserting a fixed cache lifetime. A delayed display alone does not establish an incorrect ID; conversely, a new poster does not prove the video file was replaced.

Keep a recovery path for corrections

Only when you are authorized and have backups, inspect the appropriate provider and correct ID on an independent test entry using Jellyfin's official material. Record before and after values and use the actual server interface. This exercise does not require renaming production files, replacing someone else's ID or assuming iCouldPlay has permission to edit server metadata. If the provider is unreachable on the current network, record that limitation and use existing reliable information rather than inventing a lookup. Return to the same Jellyfin source and client entry, checking title and actual playback separately.

Check the search entry separately

If iCouldPlay offers search, search once using the complete title actually visible on the server, then enter the same item from the current library list and compare displayed title and playback opening. Skip when no search control is offered; absence of a control is not a zero-result search. A hit establishes that an entry was displayed, not that provider ID or underlying file is correct. If the two routes differ, preserve query, library name and time, removing potentially private terms before sharing.

Deliver and restore

Deliver a comparison table without private addresses, the test video's identifying cue and source links. Preserve original file and prior state. If you only observed, explicitly record that the server was not changed. If you changed an independent test entry, restore it from the backup and recheck. Mark unperformed playback, server operations and device tests pending; this guide does not claim tested compatibility with all Jellyfin versions.
