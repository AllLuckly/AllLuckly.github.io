When entering an invented name, visible suggestions, a deliberate selection and any host change after commitment are different events. Use nonprivate English text to observe them separately without assuming Jianlai or every host applies the same correction.

Prepare a comparable test word

In an ordinary note you control, create a practice copy with the invented target Lunora: uppercase L followed by lowercase unora, six ASCII letters. Save a separate reference. Do not use real contacts, accounts or passwords. Write lunora, Lunorae and Lunora followed by an extra space as controls for case, an extra letter and a boundary. These controls are not messages to send.

Record actual conditions before entry

Confirm Jianlai was added and is actually selected in an ordinary field. Record system, host, Jianlai version, keyboard language and layout. Inspect the system auto-correction and prediction options actually visible and record their original states. Whether those options affect the current third-party keyboard or host must be observed, not assumed. Avoid secure fields or anything that publishes automatically. Preserve existing keyboards and drafts; no permission changes or dictionary clearing are needed.

Enter characters and observe suggestions

Type Lunora in the practice copy. Observe actual key labels and suggestions, recording whether the target or other suggestions appear. Complete input using the real interface; do not assume Space, Return, Shift or any suggestion has the same effect in every scheme. If none appear, record that they were not observed. Do not change system settings during this entry or require a private account.

Check the first committed document

Confirm ordinary text contains L, u, n, o, r, a in order with correct case and boundary spaces. Record any unconfirmed composition and whether the user selected a suggestion. A visible suggestion does not prove selection; a key label does not prove committed text. If the first result differs, preserve it and correct another copy rather than retaining only a successful revision.

Observe the effect of one delimiter

In the same practice line use an actually available method to add either a space or a line break, then inspect the preceding word immediately. Record text before and after, action order and any replacement feedback. Space and Return are separate controls: do not perform both and then infer which caused a change. If the host gives no distinguishable feedback or the text remains the same, record that; do not assume every input scheme corrects at a delimiter.

Make one reversible setting comparison

If the system exposes an auto-correction switch and you can restore it, record the original and change only that setting. On a separate line repeat the same input and same delimiter, keeping host, keyboard, language and target fixed. Record candidates, selections and final text in each round. Identical results mean no difference was observed in this trial; they do not prove whether the setting controls Jianlai. If unavailable, managed or unsafe to restore, skip and mark pending. Restore immediately afterward without deleting dictionaries or personal entries.

Use a control without broadening the conclusion

To separate word boundaries, put the practice word between user-chosen markers, for example [Lunora]. Check the six letters and both markers separately. Preserve the whole line before and after the delimiter. If the host inserts different brackets, record that separately from a spelling change. These are manual markers, not an app feature for recognizing or locking proper names; no real contacts need alteration.

Make a three-row table: target before entry, committed text after first confirmation, and text after one delimiter. If the second row already differs, do not attribute the entire third-row error to the delimiter. If it changes only afterward, distinguish host, keyboard and system feedback; time order alone cannot establish the cause. No observed change is a valid result.

If useful, switch to an already enabled system keyboard in a separate copy in the same host, repeat the same conditions and verify the keyboard actually selected. Keep this as a control, not proof of Jianlai behavior. Device language, input history and host settings can influence results; when any changes, record a new trial instead of merging it with the baseline.

Troubleshoot and restore

For case errors inspect Shift and final text separately. For extra letters inspect user selection and host replacement feedback. Compare trailing space against the field boundary. When candidate and host rewrite cannot be distinguished, record the observation rather than assigning blame. Change one condition per trial, restore system settings and the usual keyboard, and keep sanitized reference and first result. Apple’s typing guidance and public Jianlai multilingual information inform this exercise; no physical auto-correction test is claimed.
