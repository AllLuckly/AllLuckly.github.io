Use a self-made bidirectional phrase to observe HTML inline direction isolation, screen display and source text.

Understand inline direction isolation

W3C internationalization guidance explains that an HTML bdi element or an element with dir=auto can isolate an inline phrase’s direction when left-to-right and right-to-left text mix. Markup describes text direction and does not change chapter order in a file. The guidance does not guarantee Book Isle supports every markup feature or uses a particular layout engine.

Prepare an authorized self-made sample

Choose an EPUB you made or the publisher permits you to inspect, using a self-made sentence containing Latin text, digits and a short Arabic example. Record source character order and intended meaning separately. Avoid private names, addresses or unauthorized passages. Back up the original; if internal inspection is not allowed, observe only the reader without bypassing protection.

Observe the initial reading view

Open the target section in Book Isle and record the visible word order, relative position of digits and punctuation, font size and orientation. Confirm the same self-made passage first. If the whole book cannot open, check completeness and format without blaming bidirectional text first. Preserve bookmarks and notes without resetting the app or overwriting the original.

Inspect inline markup

Only with authorization and suitable tools, inspect target XHTML in a copy. Record paragraph direction, whether the phrase has bdi or dir=auto and whether adjacent punctuation is inside the element. W3C explains that bdi without dir behaves as automatic directional isolation. Invisible control characters can also affect order; mark them unknown or record actual findings rather than guessing from display.

Compare source and screen

Record authorized source character order and Book Isle’s visual order separately; bidirectional storage and display order should not be treated as one column. Compare whether digits and punctuation remain associated with the intended self-made phrase, but do not infer text was modified simply because visual and source order differ. Report screen observation only if source is unavailable.

Change one reading condition

If available, change only font size or device orientation, return to the same sentence and record wrapping and punctuation positions. A different screen width can move text without changing HTML character order. Mark absent controls unavailable; do not change file, language settings and font size simultaneously.

Check optional copying

If Book Isle permits selection, copy the self-made sentence into a private plain-text editor and record pasted characters and visible order. The destination editor’s bidirectional layout can also affect appearance. Different pasted display alone does not prove the source EPUB changed. If selection is unavailable, mark the step skipped; do not install unknown tools or paste private text publicly.

Compare and troubleshoot independently

When permitted, use a trusted reader for the same file and passage, recording version, device, orientation and display. Fonts, width and implementation can differ. If results differ, check markup, paragraph direction and file edition; one reader’s behavior is not automatically proof of another’s conformance. Preserve uncertainty without a control.

Restore and document

Restore original font size and orientation and confirm the file, notes and bookmarks remain. Record authorized source, actual markup, Book Isle display, copy control and skipped steps separately; remove private paths and restricted content before sharing. This guide uses public standards and app information, claims no device test and does not guarantee Book Isle implements a particular bidi marker.

A reproducible short phrase

In a self-made conforming EPUB section, use the short phrase Hello <bdi>مرحبا</bdi> 12!: Hello is Latin text, مرحبا is an Arabic greeting, and 12 and the exclamation mark are outside the bdi element. Record actual source characters and element boundaries first, then observe the phrase, digits and punctuation in Book Isle. This example identifies structure only; fonts, direction and reader implementation may differ, and it does not establish support in Book Isle.

Record punctuation boundaries separately

List the text inside bdi separately from digits and punctuation outside it, with a third column for screen display. A visible bracket or exclamation mark alone may not reveal whether it is inside the source element. If the publisher permits two self-made copies with different markup, keep text fixed, compare each and record versions and actual edits. Never modify the only original without an authorized copy.

Avoid guessing invisible controls

Direction-control characters may be invisible and a destination editor may re-layout pasted text. If code points cannot be inspected with suitable tools, mark them unexamined rather than guessing from visual order. Use trusted tools and your own copies. One readable result establishes behavior only for that short phrase in that environment, not full support for every language, mixed layout or assistive-reading path.

Record glyph and font information

If a box appears or characters are illegible, record the device and visible font settings first; unavailable glyphs and directional isolation are different issues. Do not substitute similar characters or treat a box as source content. Restore original settings and retain the observation.
