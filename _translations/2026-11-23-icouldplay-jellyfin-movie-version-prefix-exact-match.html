Whether movie versions group as one item can depend on their filename prefixes. Compare them character by character with isolated samples.

Understand movie version recognition

Jellyfin documents that videos in one movie directory must match the parent directory base name character for character, including any year or provider ID, followed by a version label separated by a hyphen, dot, underscore or brackets. A mismatched prefix may be treated as a separate item. This server rule and the availability of a version selector in iCouldPlay are separate questions. Check the server first, then observe the client.

Prepare authorized test copies

Have an administrator prepare two self-made or authorized copies of the same short clip in an isolated test movie library, for example a 720p and a 1080p copy. Their opening images and content should match. Record duration, measured dimensions and identity first; labels are not measurements. Do not rename a production collection. Without permission or suitable clips, mark the experiment not performed. The example film and year do not identify a real library.

Establish the correct common prefix

Name the test folder Test Film (2030). Within it, have the administrator use Test Film (2030) - 720p.mkv and Test Film (2030) - 1080p.mkv as example names. Copy rather than move the originals, keeping parentheses, spaces and year identical to the parent name. Stop and preserve existing data if names collide. Record relative paths before and after while excluding the private server root.

Predict recognition and sorting

The documentation says that, when recognized as versions of one movie, pure resolution labels sort from highest to lowest and the first version is selected by default. The example predicts 1080p before 720p. This depends on recognition and both files being the same clip. Server versions, client behavior and additional parts can change observations; a filename is not evidence that the test succeeded.

Observe the web baseline

The administrator scans the test library using the current server’s normal procedure and waits for completion. On the web find the film and record entry count, version labels, order and selected item. Play the beginning of each to confirm identity. If two separate entries appear, first check character-for-character parent and file prefixes, scan scope and that both are in the same movie folder. Do not alter production films to force one entry.

Introduce a controlled prefix difference

With permission and only on the test copy, change the year in the 720p filename from 2030 to 2031, leaving other characters and file content unchanged. Record the previous name and backup location, then rescan. The documentation indicates a prefix mismatch may be treated as a separate item. This is a prediction for observation, not a guarantee of identical results across server settings. Record changes in entries and version lists.

Restore and confirm content

The administrator restores the 2030 prefix on the test copy and rescans normally. Compare with the original record, confirming both files still exist, content was not overwritten, and whether the web again presents versions under one movie. If it does not restore, record scan completion and exact names rather than deleting the database or other users’ data. Change one character group at a time to preserve interpretability.

Inspect version controls in iCouldPlay

Using the same server and account, open iCouldPlay, find the test film and inspect version controls actually shown by the installed version. Record visible labels, order, current choice and opening picture. If there is no control or only one version appears, record it as not shown; server web functionality does not guarantee equivalent third-party client support. First in a list and selected are different observations; if selection is not visible, mark it unknown.

Separate labels, quality and files

For each file record the 720p or 1080p filename label separately from measured image dimensions. Larger dimensions do not establish codec, bitrate or visual quality. Different cuts with the same name can also have different duration or content. If the copies are not the same edit, stop the ordering comparison and use authorized same-content samples; do not misdiagnose content differences as recognition or switching failures.

Check the separator and label boundary

Write the parent directory name on one line and the part before the version label from each filename on separate lines. Compare parentheses, year, spaces and any provider ID character by character. The version label needs a separator described by the documentation. Do not confuse its hyphen with part of the title or assume full-width and half-width characters are interchangeable. If the administrator changes both folder and file names in one round, the outcome cannot isolate which change mattered.

Before retrying, note the prior scan completion time, entry title and chosen file so a stale or similarly named item is not mistaken for the new result. If an old entry remains, ask the administrator to check the normal refresh behavior for that server version. Do not clear server data or attribute the old entry to iCouldPlay without evidence.

Clean up and hand off

The administrator retains or removes the test copies under normal policy, then confirms production films, original names and library are untouched. Record the matched prefix, controlled mismatch and restored web results, plus actual iCouldPlay observations. Clearly mark unperformed steps. Remove private addresses, usernames and tokens before sharing. This guide uses public documentation and claims neither private-server connection nor physical-device testing.
