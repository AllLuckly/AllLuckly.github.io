Use self-made comics to compare ComicInfo SeriesGroup and StoryArc metadata with server-generated results.

Understand the two outputs

Kavita’s comic metadata table maps ComicInfo SeriesGroup to Collections and StoryArc with StoryArcNumber to Reading Lists. Library settings manage collections and reading lists separately; automatic collection management from SeriesGroup is off by default. A collection and an ordered chapter-level reading list serve different purposes, and server support does not guarantee that a Manyue+ connection exposes both.

Prepare isolated comics and backups

Prepare two short self-made comic archives in an isolated library you administer, with clearly distinct visual markers. Back up files, metadata and test-library settings; do not use another household member’s real material. Use a normal test account with library access, with an administrator only for necessary settings. Stop at read-only observation if restoration or metadata effects are unclear.

Check metadata file location

Kavita documents a ComicInfo.xml file at the root of the comic archive. Inspect the name, location and XML only in authorized test copies, distinguishing the archive’s name from its internal filename. If the sample is protected or editing is not allowed or possible, mark the step incomplete rather than renaming an unrelated file. Preserve original comics and reading progress.

Record fields and expectations

Record SeriesGroup, StoryArc and StoryArcNumber values in authorized test copies. If adding test data, use self-created non-sensitive names and have someone familiar with XML edit according to the documentation. SeriesGroup can contain comma-separated collection names; story name and order fields need separate checks. Distinct visual markers prevent same-title samples being mistaken for correct relationships.

Inspect library settings separately

Record current Manage Collections and Manage ReadingLists settings and server version for the test library, using labels actually shown. Only an administrator who understands the effects and restoration should enable necessary options in an isolated environment. Do not toggle production-library settings or grant administrator rights to the normal account. Mark dependent steps incomplete if controls cannot be found.

Scan and inspect server results

After saving controlled test copies, run or wait for a test-library scan using the current server interface and record task timing and completion. In Kavita’s web interface inspect the series, resulting collection and reading list: whether the collection associates the expected series and the list contains expected chapters in order. A visible collection does not prove a list was generated. If the list is absent, check its setting, fields, scan and permissions separately.

Inspect actual Manyue+ entry points

Connect to the test server in Manyue+ with the same normal user and look for collection or reading-list entry points actually offered by that connection. Record names, items and visible order. If an entry is absent, mark it unobserved rather than calling an ordinary series directory a list. Verify self-made imagery in authorized chapters. A server-generated object does not guarantee client display or continuous cross-chapter reading.

Distinguish order from access

If a reading list shows only some chapters, compare the original list on the server and then check the account’s access to each chapter’s library. Missing entries can involve metadata, scanning or access conditions. A different client order does not prove the server rewrote ComicInfo. SeriesGroup commas separate collection names, not chapter order; observe actual StoryArcNumber handling separately.

Restore and document

Restore isolated files and settings from the pre-test backup and confirm other users’ data, original comics and progress are preserved; ask the administrator if restoration effects are unclear. Record metadata location and fields, settings, scan result, server objects, Manyue+ entry points and skipped steps separately. Remove private paths and credentials before sharing. This guide relies on public documentation and does not claim private-server or device testing.

Compare management settings separately

If both settings were originally off, an administrator can, when restoration is possible, observe one enabled setting at a time rather than changing both and claiming separate effects. Record scan or task completion before inspecting the self-made series. If variables cannot be isolated, report multiple configuration changes rather than assigning a cause. Restore both original settings and do not affect other libraries.

Check series and chapter identities

A collection associates series, while a story reading list contains chapters or issues. Record series name, chapter number, list order and sample imagery separately. Even when two ComicInfo files share a story name, check each file’s actual series and chapter; one duplicated item is not two successful matches. Before retrying in the client, check whether an absent item exists in the server’s original list.

Limit conclusions about generated results

A server object and a client entry are separate findings. If permission or an app entry is unavailable, report server visibility and an untested client. An empty list name is not successful chapter matching. An administrator may handle test-generated data after confirming its identity and restoration path; never delete production collections or other users’ reading lists to tidy the experiment.

Reproducible test values

Reproducible sample: archive one has Series River Demo and Number 1; archive two has Series Hill Demo and Number 2. Both have SeriesGroup Demo Group and StoryArc Demo Journey; StoryArcNumber is 1 in the first and 2 in the second. Each needs ComicInfo.xml at its root. With the corresponding management options enabled and a completed scan in an isolated library, check whether Demo Group associates both series and Demo Journey lists both issues in order 1, 2. Actual generation and client entry points remain observations.
