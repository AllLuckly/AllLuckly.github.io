Compare any and all genre conditions with three test series, then inspect the catalog in Manyue+.

Separate server filtering and client display

Kavita documents user-bound saved Smart Filters: for a multi-select field Contains matches at least one selected item and Must Contains matches all selected items. Its OPDS documentation lists Smart Filter feed entries. The filter is evaluated in Kavita; do not assume Manyue can create or edit the same filter. Compare two server results, then observe an authorized feed in Manyue.

Prepare permission and restoration

Ask the administrator or account owner for an isolated test library and three authorized series; record server version and existing filter settings. Use distinct test names that do not collide with production names, and do not alter another user’s filters or sharing permissions. Without access, use the table exercise only. Do not publish an OPDS URL, account name or key.

Set three test genres

In test series metadata, the administrator assigns Adventure to A, Mystery to B, and both Adventure and Mystery to C. These names are examples; use fields and options actually present in Kavita. Give each series a clear title and volume count, recording original values for restoration. Do not apply test labels to others’ production works or directly modify original file metadata.

Write both expectations

Make rows A, B and C and two condition columns. With both genres selected, Contains should match A, B and C because each has at least one; Must Contains should match only C because it has both. The chosen field must be series genre, not title text. Recalculate the table if the actual field or additional conditions differ.

Create the any-match filter

On a Kavita page that supports filtering, the account owner chooses series genre, both test genres and Contains, checks for extra conditions and inspects results. Record version-specific labels. If saving is available, use a unique test name and save as a Smart Filter. Stop and record missing fields or unavailable saving; not every page offers identical controls.

Create the all-match filter separately

Without overwriting the first test filter, create a second test name using the same field and genres with Must Contains. Confirm no extra condition and see whether only C appears. Record names, conditions and results separately: changing a bound filter can affect places using it. If two filters cannot be saved independently, retain a non-sensitive screenshot or written record before comparing.

Check the account and OPDS feed

Kavita says Smart Filters are user-bound and OPDS supplies entries for different collections. Access the relevant OPDS feed with the same test account and identify both filters and their series. If absent, record version, account identity in non-sensitive form and filter name; do not substitute another account’s filter. Never include a private authenticated link in a report.

Observe the same feed in Manyue

Use Manyue’s currently supported Kavita or OPDS connection for the same authorized account and look for the two test filters or corresponding feeds actually shown. If not presented, record unavailable or not observed; server capability does not guarantee client support. Record each feed name and visible A, B and C. Check for later pages before treating the first page as the entire set.

Open and return from a test series

Select C from visible authorized results, verify its title and test volume, then use the actual interface to open one book and return to the filter feed. Record result visibility, book opening and return position separately. If only an ordinary OPDS whole-file link is available and direct reading fails, mark incomplete instead of treating it as a filter-calculation error. Skip without an authorized sample.

Troubleshoot and restore

If results differ, first verify account, shared library, metadata, selected field, both conditions and refresh time, then examine one variable at a time. Do not rewrite the original expectation when samples are empty or labels differ. After testing, the account owner restores test metadata and filters from the record and decides whether to remove only confirmed test objects. Do not delete production data. No private-server or device test is claimed.

Check conditions, not names

The user may choose any nonconflicting test names, so a name containing “all” does not prove the operator is Must Contains. When reopening the filter, compare its field, operator and two selected genres before checking results. If C’s metadata changed afterward, record the time; do not compare the new result directly with an expectation made before that change.

Understand dynamic-filter scope

Kavita describes a Smart Filter as a saved dynamic filter: newly added matching entities may appear. Observing a change does not require copying or uploading additional works. If the test catalog did change, record the series and metadata change before refreshing. Without new content, do not alter a production library merely to produce a change; the core exercise compares the same A, B and C under two conditions.
