“Each term sums the previous two” does not uniquely specify a sequence: seeds, starting index and update order matter. Read an original recurrence card in Book Isle and match definition/state table, checking F8=21 externally. Pseudocode explains a paper algorithm rather than app execution; finding familiar numbers does not verify all premises.

Fix zero-based indexing and both seeds

Card R1 declares F0=0, F1=1 and Fn=F(n−1)+F(n−2) for n≥2. Zero is an index, not a physical page zero. Map a textbook’s F1/F2 naming before comparison. Keep recurrence and both seeds in one readable PDF/EPUB passage and verify R1 after import. Do not omit seeds from an excerpt or merge two equal ones: equal values do not mean equal indices.

Keep boundary queries separate:F0 returns seed zero, F1 returns one, without an extra update before output. This exercise accepts nonnegative integer indices; negative queries are outside its scope and are not arbitrarily extended backward. State inputs and whether stopping occurs before or after an update.

Expand through eight instead of recognizing a pattern

Compute F2=1+0=1, F3=1+1=2, then F4=3, F5=5, F6=8, F7=13, F8=21. F0..F8 contains nine terms, not eight, with seven newly computed terms F2..F8 beyond the seeds. Keep index, two inputs and sum per row rather than an unlabelled familiar list 0, 1, 1, 2, 3, 5, 8, 13, 21. Find the first incorrect row and its inputs instead of rewriting the rest from memory.

Interpret the state pair as consecutive terms

Define state(a, b)=(Fn, F(n+1)), initially(0, 1) at n=0. The next state uses old b and old a+old b:(0, 1)→(1, 1)→(1, 2)→(2, 3). Incrementing n shifts one term, not two. Record n/a/b every round so b is not mislabelled Fn. Page/scroll positions are unrelated indices; an eighth displayed row is not automatically F8 if a header/initial row is included.

Pause the paper exercise at n=4, state(3, 5). Four more shifts reach n=8, state(21, 34). Resetting the counter without the pair mislabels indices. A reading bookmark returns to the row; it does not preserve/execute algorithm variables, so retain the complete state externally.

Save old values before two assignments

Use temporaries so both right sides refer to the same old state:

next_a = b
next_b = a + b
a = next_a
b = next_b

One execution from(0, 1) gives(1, 1). This explains assignment semantics without claiming Book Isle runs the four lines. A note saying only a becomes b is incomplete. Highlight calculation and assignment pairs separately if available; color does not prove simultaneous-state correctness.

Compare the overwrite-old-a error

The wrong order is:

a = b
b = a + b

From(0, 1), a becomes 1 before the second line uses new 1+old 1=2, yielding(1, 2); another round gives(2, 4). Correct two-round state is(1, 2). Matching an isolated two does not establish algorithm equivalence. Separate versions without changing seeds to hide overwriting. Repair old-state access rather than manually replacing every result.

Change seeds to show the recurrence is not unique

On R2 set G0=1, G1=1 with the same recurrence:1, 1, 2, 3, 5, 8, 13, 21, 34, so G8=34 rather than R1’s 21. Changed seeds define another sequence, not a reader omitting zero. For R1, eight state shifts yield a=21, b=34, while filling F2..F8 computes seven new list entries. One counts generated entries beyond two seeds and the other shifts from the initial pair. Their different starting points explain the counts.

G’s first two values match F1/F2 and the same recurrence continues, so G_n=F_(n+1) under these seeds. G4=5 while F4=3 and F5=5. This is an index shift, not random output. Other seeds need not yield a one-term shift merely because recurrence forms match.
