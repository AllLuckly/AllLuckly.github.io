Use a self-made phrase to compare CSS case declarations, Book Isle display and available plain-text copying.

Understand visual transforms

W3C CSS Text describes text-transform as a visual styling transformation that does not change underlying content and must not affect plain-text copy and paste. Whether a publication uses it, Book Isle implements it and the system copy path behaves as specified require separate checks. Visible uppercase alone does not establish that the source was uppercase.

Prepare an authorized self-made sample

Use an EPUB you created or the publisher permits you to inspect. Choose a self-written English phrase without private information, record exact case and preserve an original backup. Retain publisher information if it identifies a text-transform declaration. Do not publish substantial copyrighted passages. If protection or license terms prohibit unpacking, observe only the interface without bypassing protection.

Establish the reading baseline

Open the target section in Book Isle and locate the phrase using contents, search or page controls. Record visible case, font size, orientation and a context marker. If it is absent, confirm the book, section and file edition first rather than immediately blaming CSS. Preserve bookmarks and notes without clearing app data or replacing the original.

Inspect source and style

Only with permission and suitable tools, find the target XHTML source text and referenced styles in a copy. Record any text-transform and applicable uppercase, lowercase, capitalize or other value. Multiple rules and inheritance can exist, so one search hit does not prove the rule applies to the target. Mark source text and declarations unknown or uninspected when unavailable.

Compare display and source

Compare the confirmed authorized source phrase character by character with Book Isle’s display, recording source and screen separately. Different case is an observed display difference; without rule-scope and implementation evidence, do not assert its exact cause. Case can matter in proper names, so do not rewrite the publisher’s source based on visual form.

Check plain-text copying

If Book Isle permits selecting and copying the self-made phrase, paste it into a private plain-text note and record actual characters and case against the source. The specification has a plain-text copy requirement, but OS, app and destination can affect an observation; do not generalize one result to all devices. Mark selection or copying unavailable rather than using unknown bypass tools.

Compare search separately

If the app offers search, try the self-made phrase in source case and visible case separately and record query, location and actual match. Search may be case-insensitive and affected by indexing or language handling; both matching does not prove source text changed. Mark the step unperformed without a search entry or authorized sample.

Troubleshoot and preserve originals

If display, copied text and source differ, check edition, target passage, style scope, current app and paste destination one at a time. A trusted reader can be an independent control, but a difference alone does not prove a Book Isle defect. Do not install unknown software or edit the sole original. Preserve unknown causes and contact an authorized sample maintainer when appropriate.

Restore and document

Restore original reading settings and confirm the file, bookmarks and notes remain. Record publisher-provided source, inspectable CSS, Book Isle’s visible characters, plain-text paste, search and skipped steps separately. Remove private paths and unauthorized content before sharing. This guide relies on public standards and app information, claims no device test and does not guarantee support for a specific CSS property.

Confirm the comparison phrase

A self-made sample can contain a short title with mixed-case letters, numbers and punctuation, with exact source spelling kept privately. Confirm the target section and nearby marker before comparing so a similarly named contents entry is not confused with another passage. For publisher samples, record edition and permission scope; names, email addresses and other private data are unnecessary.

Separate declaration from actual scope

Record a discovered value, selector, whether the target matches it and any overriding rules separately. Uppercase elsewhere in a file may apply to a different heading. If scope is uncertain, mark it unconfirmed. Visible capitals could come from source text, style, app handling or another cause; do not choose one without evidence.

Record the paste destination

Plain-text and rich-text destinations can retain different formatting. Where selectable, record the editor and whether plain-text mode was used, then inspect the characters without entering private text on a public site. Automatic rewriting or an unknown mode prevents attributing the result solely to the reader. A second trusted plain-text destination can be a control; do not install unknown software for it.

Preserve meaning and uncertainty

Case can matter in languages and proper names, and visual transforms can change interpretation. Use publisher-authorized source as the reference rather than rewriting a displayed all-caps name by intuition. If neither source inspection nor copying is possible, honestly record the display and skipped steps. Leave undocumented internal implementation and source unknown rather than filling a table with guesses.

A reproducible self-made sample

Reproducible self-made sample: write the source text Read Me 42 and declare text-transform: uppercase for the target paragraph. CSS describes a visual result that can appear as READ ME 42, while underlying text remains Read Me 42 and plain-text copying must not be changed by that property. Verify the selector targets the sample, then record Book Isle display and pasted text separately. This is a standards expectation, not a support guarantee or device-test claim.
