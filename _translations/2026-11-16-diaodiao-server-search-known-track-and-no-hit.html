Use two queries inside a verified library and identify each result’s source and recording edition.

1. Fix a working target library

Begin with a confirmed compatible authorised server. Browse to known track A and record library, account scope, title, artist and edition. Searching does not repair an unknown protocol or address; verify the connection first. Use owned or authorised content rather than a public catalogue. Finding A by browsing supplies a positive control, not proof that every field is indexed. Distinguish this service from another similarly named collection so familiar results do not obscure provenance.

2. State a small verifiable search question

State the goal as locating A in the current source, not every edition across the internet. Use A’s verified title for query one and a clearly different external marker for query two. The latter observes no hits or other results; it does not prove that text is absent from the whole server. Preserve exact characters, spaces and case for both. Verify unfamiliar title characters against the item instead of diagnosing an empty result caused by a transcription error.

3. Identify the search scope

Use the identifiable server-search flow and verify the selected source/scope before interpreting results. A local list or another service is not this query’s output. Published browsing/searching does not promise universal field filters, fuzzy matching, regular expressions or cross-library search. Record visible scope indications and leave undocumented indexing unknown. An external web search is not a result supplied by 调调; remain within the identified personal-service flow.

4. Submit the verified title and inspect candidates

Enter query one, verify its text and submit once. Wait for real results/errors and retain the query with visible candidates. For same-name tracks, compare available artist, album, duration or edition clues instead of automatically choosing the first. Highlighting, if present, marks a match but does not establish every field or audio identity. If A is missing, preserve the query and browse control before changing anything. Simultaneous keyword, source and account changes would obscure the cause.

5. Verify an opened result by sound

Open the result matching A’s reference, check player identity and listen for its opening anchor. Search matching and playback are distinct; shared artwork cannot replace sound. If title matches but audio differs, retain the edition discrepancy and revisit candidates before editing server metadata. Preserve query and target on return. Re-finding it checks traceability, not guaranteed retention of the query or exact scroll position. Re-enter the recorded text if needed.

6. Interpret the second query only within its returned scope

Save the first round and submit query two with the same source/account. Distinguish no hits, other candidates and an error. No hits means this query returned no item within its current scope, not proof of absent files, complete account visibility or an empty service. If A remains, check execution and stale results before inferring matching behaviour. Leave undocumented algorithms unknown. An empty list and loading failure require separate feedback rather than both becoming a normal result count of zero.

7. Diagnose query, scope and playback separately

For missing A, inspect title spelling, spaces and scope, then compare browsing. If browsing also fails, inspect service identity/access. For a present silent result, inspect track/output. These are not all search inaccuracy, and font changes or clearing local music do not diagnose them. Change one query condition per round and observe case sensitivity instead of promising it is ignored. Use invented names and redacted scope for help, without credentials, a private catalogue or unperformed search claims.

8. Deliver two queries and a provenance chain

Save each query’s scope, candidates/errors and A’s browse-to-search-to-audio identity chain. Explain matching, wrong same-name editions, no hits and access failure separately instead of supplying only a search-box screenshot. Leave unverified fields/indexing unknown and preserve server data. Re-establish controls after library, account or service changes. One title match does not physically certify every field or personal server; the deliverable is a repeatable minimal search record.
