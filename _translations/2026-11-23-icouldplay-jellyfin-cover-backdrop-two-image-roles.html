A movie cover and a detail-page backdrop have different roles. Use two distinct test images and record server and iCouldPlay display separately.

Separate image roles

Jellyfin primary covers and backdrops are different image types: the primary identifies media, while a backdrop serves as a media-page background. Its documentation supports external files alongside media, normally taking precedence over other sources; movie folders can use names such as cover.jpg and backdrop.webp. Server support does not guarantee that every iCouldPlay page shows both types or that an old image immediately refreshes.

Prepare authorized samples

Ask the administrator to place a self-made or authorized short video copy in an isolated test movie library. Create two distinct images yourself: a blue primary cover with a white A, and a yellow backdrop with a black B. Make the letters prominent and omit private information. Record filename, dimensions and role. This is not a poster-quality evaluation and does not require changes to production artwork. Without server-management permission, observe only; do not request write access from another person.

Record the baseline

Before adding images, wait for server recognition and record the test film title, existing cover and backdrop, and time on the web. Connect iCouldPlay to the same account and library, inspect the same film in the list and details, and record visible image locations. If no backdrop area is provided, mark it unavailable or not observed rather than presuming the image is missing. Confirm identity using the video opening and duration to avoid confusing similarly named entries.

Add two images with distinct roles

Have the administrator name a copy of the blue A image cover.jpg and a copy of the yellow B image backdrop.webp, placing them alongside the video inside the test movie folder. Confirm the file contents really are JPEG and WebP respectively; changing an extension is not conversion. If conversion is needed, save a separate copy using a trusted tool and verify it opens. Do not overwrite an existing file; stop and preserve it if the name is already present.

Record changes before and after

Make a checklist of the video, cover.jpg, backdrop.webp and any pre-existing images. Have the administrator refresh or scan the test item using the normal procedure for that server version and wait for completion. Inspect web cover and backdrop separately. If A is the primary and B the backdrop, record that observation. If only one appears, report each location separately. Do not change NFO, filenames and server settings together in the same comparison.

Compare list and details in iCouldPlay

Using the same server account, open iCouldPlay and record the list cover and any image actually shown on the detail page. If A is visible as the cover, note time and location. If B is not visible, first determine whether that page offers a backdrop region; absence alone does not prove the server failed to import it. If the app still shows old artwork, reopen the page normally and compare with the current web result. Record the steps without asserting a cache problem.

Check naming and placement

If neither web image changes, have the administrator verify the test movie folder, that extensions match actual formats, readability, and completion of the scan or refresh. If A appears in both roles, inspect whether the source images actually differ and whether names were swapped; do not use color alone as proof of file identity. If the web uses a different server or release, correct the observation conditions before drawing a conclusion.

Separate artwork and playback

Successful artwork import does not prove playback, and playback does not prove artwork updated. Open the authorized short clip manually, note its result and record it in a separate column from cover and backdrop. If playback fails, note whether it occurs in listing, opening or starting, without deleting or overwriting the images. If web and app differ, keep page, time and client version for the administrator to investigate within their permissions.

Check dimensions and legibility

The blue cover and yellow backdrop need not have equal dimensions. First confirm orientation and visible letters in a normal image viewer; then compare cropping, scaling or hidden portions on the web and in iCouldPlay. Different client layouts can crop differently; a crop does not establish source corruption. Record original dimensions and viewing location without claiming a fixed app crop ratio. Save a separate copy for adjustments rather than overwriting the first sample.

Make observations comparable

Use the same film and account for both observations. If the second uses a different device or network, record the change separately instead of attributing every difference to image files. If the server has other cover sources, ask the administrator to record the current choice; do not modify production provider settings to force the prediction. Where source precedence or client display remains uncertain, preserve the state and mark it pending rather than inferring unchecked files from a screenshot.

Restore and hand off

The administrator can remove the test images added for this exercise or retain the isolated library under normal policy, then confirm production movies and original images were untouched. Record both filenames and roles, web and app results and unperformed steps; remove server addresses and account information before sharing. This guide relies on public documentation and does not claim a private-server connection or physical-device test.
