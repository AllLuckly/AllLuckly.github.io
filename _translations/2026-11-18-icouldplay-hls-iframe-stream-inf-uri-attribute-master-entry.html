Master-playlist I-frame entries and ordinary variants both declare bandwidth but locate their targets differently. Build a per-tag ledger from an original six-line playlist and trace the child playlist. Without real I-frame resources, finish the audit only; placeholder text does not generate thumbnails or enable an assumed iCouldPlay preview.

Prepare ordinary-playback and I-frame evidence separately

Keep ordinary-playback playlist evidence from an owned clip and separately name the I-frame playlist produced externally. Record real paths, media bytes and packaging reports only when outputs exist; removing tags from an ordinary video does not create I-frame resources. The paper example names main/video.m3u8 and trick/iframes.m3u8. The directory trick is not an iCouldPlay menu command. Similar names do not establish a common timeline; preserve generation sources and the shared source identity.

Identify which tag owns each target

An ordinary EXT-X-STREAM-INF takes its following URI line as target. EXT-X-I-FRAME-STREAM-INF stands alone and supplies its own URI attribute. Give each tag a ledger row labelled following-line or attribute, rather than attaching whichever address looks nearest. The longer I-FRAME name does not inherit main/video.m3u8 or merge the declarations into one stream. Preserve case, hyphens and quotes. Compare syntax rather than visual wrapping: a long displayed line can still be one tag.

Audit the required fields in six sample lines

The I-frame entry includes BANDWIDTH and URI, while the ordinary entry is followed by main/video.m3u8. Its referenced media playlist must contain EXT-X-I-FRAMES-ONLY. That child file is not shown here, so mark it for inspection rather than certifying it from its name. Version 4 is stipulated, not a repair achieved by raising the number. Bandwidth is bits/s:80000 is not80000 bytes/s. Ordinary 1600000 and I-frame 80000 describe different resources; the smaller declaration does not mean the full movie lost quality.

#EXTM3U
#EXT-X-VERSION:4
#EXT-X-I-FRAME-STREAM-INF:BANDWIDTH=80000,URI="trick/iframes.m3u8",CODECS="avc1.4d401f"
#EXT-X-STREAM-INF:BANDWIDTH=1600000,CODECS="avc1.4d401f,mp4a.40.2"
main/video.m3u8
# child trick/iframes.m3u8 must contain EXT-X-I-FRAMES-ONLY

Resolve the two distinct child-playlist locations

For base https://media.example.invalid/lesson/master.m3u8, resolve targets under lesson/main and lesson/trick rather than appending to master.m3u8. Remove attribute quotes for URL interpretation while retaining them in source syntax. Do not contact the reserved invalid domain. Real sources require actual responses and redirect bases, not an old directory note substituted for a resource. Record each target once with its ordinary/I-frame role so later ordinary playback is not mistakenly attributed to the I-frame resource.

Do not copy excluded rendition attributes

The RFC does not define FRAME-RATE, AUDIO, SUBTITLES or CLOSED-CAPTIONS for this I-frame tag. In a failure copy add AUDIO="voice", identify that it is outside the tag definition, then remove it; do not invent a voice group to retain the mistake. This distinction does not prove every I-frame resource lacks any audio bytes or require a particular iCouldPlay error. Audit syntax separately from file content. Unknown player tolerance stays unknown, and tolerated mistakes do not rewrite the specification.

Record ordinary playback and preview observations for real media

Open the externally checked real master through an existing iCouldPlay source entry and verify ordinary source identity, action and audio first. If the installation offers preview or relevant selection, record its actual picture and time. Seeing a frame after seeking does not by itself prove this I-frame URI was fetched; retain resource evidence you control. Without preview controls, record ordinary playback only and the child-playlist syntax audit separately. Renaming bandwidth or sizes cannot manufacture a service that supplies no I-frame media.

Troubleshoot fields, ownership and child files separately

For a missing URI, identify the genuine required target; moving the next line closer is no repair. A child without I-FRAMES-ONLY requires checking packaging identity rather than tagging arbitrary media. Preserve separate ordinary-success and preview-unknown results. Change one copy factor and recount declarations and unique targets. Repair unmatched quotes before paths. A server returning an HTML login page does not supply I-frame media: resolve authorization or addressing rather than treating HTTP 200 as correct content.

Reopen with entry relationships and unchecked items

Retain the original six lines, failure difference, two resolved paths and the location of any actual child inspection. Reopen notes to ensure entry roles were not exchanged. In iCouldPlay repeat only source/control checks actually available, verifying identity first. Identify the owning URI attribute, excluded copied attributes and required child marker, explicitly recording whether preview was tested. Without real preview evidence claim neither generated thumbnails, unrestricted seeking nor compatibility with every I-frame encoding. Paper audit and viewing retain their distinct limits.
