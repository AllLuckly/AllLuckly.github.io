Read-list ordering and the existence of comic files are separate questions. Observe server and Manyue+ behavior using a test list.

Understand read-list scope

Komga read lists gather books and can cross series and libraries. Its documentation says lists default to manual order; disabling manual order sorts by release date. List entries and source files are distinct. Compare web ordering only in a test list, then observe the actual Manyue+ interface; do not promise that the client exposes lists or follows server ordering.

Prepare three identifiable test books

Use three small self-made or authorized comic copies A, B and C in a library you manage or are authorized to use. Distinguish their covers and first pages. Ask the administrator to confirm account access and whether release dates are visible. Mark unknown dates as unknown rather than inventing them. Preserve original files and existing lists; do not edit another person’s list.

Create a prediction ledger

Record series, volume, release date and first-page marker for each book. For example, if dates are 2020, 2022 and 2021 respectively, a chronological candidate is A, C, B, while a manual sequence can be B, A, C. Confirm the direction actually displayed in the server version rather than assuming ascending order. Do not predict the relative order of equal-date entries here. If dates are missing, mark the prediction pending rather than inferring them from filenames.

Create a test list in Komga

An authorized user creates an identifiable temporary read list for the three books in Komga’s web interface, adding them from book action menus as actually shown. If access or controls are unavailable, record the step unperformed and ask the administrator; do not expand production-library permissions. Check covers, series and first pages to avoid adding similarly named volumes.

Record manual order

Open the test list details and confirm manual ordering. Using the web edit controls, arrange B, A, C, save and reopen to verify; do not reorder production lists. Record the time and complete book identities, not just initial letters. If controls are unavailable or saving fails, preserve the starting state and stop before the next step; do not claim the order took effect.

Compare release-date ordering

After recording manual order, disable manual ordering in the test list settings and save, then wait for the page to update. The documentation describes ordering by release date. Compare the web sequence with the recorded dates. Do not assume unknown dates or tie behavior. If it differs, check book identity, date fields, saved setting and refresh time, one condition at a time.

Observe list availability in Manyue+

Connect Manyue+ to the same server and account and inspect whether the installed version offers a Komga read-list entry. If it does, open the same test list and record the three-book order. If absent or identity is uncertain, mark unavailable or not observed; do not assume all Komga web functions exist in the client. Even when the list is visible, separately verify opening a book and its first page.

Separate ordering from content

Choose one test book and check cover, first-page marker, page count and series on web and Manyue+. A changed order does not mean the book was deleted or that progress synchronized. If web and app differ, first compare account, list name, identity and observation time; keep the raw observation instead of asserting a cache or synchronization fault without evidence.

Restore the test state

If needed, return the temporary list to manual B, A, C order and reopen to verify. If the list was created solely for this exercise, an authorized person can decide whether to delete the list under administrator policy. Komga says deleting a read list does not delete its items or media files, but confirm the selected list is the test one first. Do not delete books, comic files, production lists or another account’s data.

Compare two states of the same list

Record the list name, series and volume identities after saving manual order. After saving date order, verify the same list and same books before comparing. For lists spanning libraries, note each source. A book hidden by existing account restrictions is not necessarily an ordering problem. Ask the administrator to verify existing permissions without expanding access for the test.

Mark equal or missing dates as order pending. Do not change production book metadata to manufacture unique dates. An authorized person can verify fields and sources on isolated samples, but change only the list order setting in one comparison to avoid conflating it with a date edit. Retain both observations for later version or interface checks.

Prepare a reproducible record

Record the three identities and dates, manual order, release-date order, web save result, Manyue+ entry and actual display, and unperformed steps. Exclude private server addresses, accounts and unauthorized images. For ongoing issues provide versions, time and sanitized observations. This guide relies on public documentation and claims no private-server or physical-device test.
