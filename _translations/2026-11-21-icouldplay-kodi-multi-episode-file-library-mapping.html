One owned video file may contain both the first and second episodes of a show, while the library lists two episode entries. File count and episode count can differ; episode cards in iCouldPlay do not prove separate files. First check the Kodi server mapping, then observe actual client presentation and playback.

Prepare an existing sample

Choose an authorized Kodi TV library and existing multi-episode video file, with permission to inspect its name, Kodi entries and playback. Preserve the original and backup; do not combine, split or rename shared media for this exercise. If there is no suitable file or access, mark the prerequisite unmet. Examples cannot replace device results. Record inspection time with a source alias; do not expose private paths or credentials.

Separate file and episode counts

In an authorized file manager record filename, size and known included season/episode numbers. For each episode note a recognizable opening picture or time point. The example S01E01E02.mkv lists season 1 episodes 1 and 2 in its name; it is only an illustration, not your file. Use content you are authorized to watch to identify actual boundaries. A name alone cannot establish complete content, runtime or presence of an opening sequence. One file containing two episodes does not imply two separate files.

Check Kodi version and naming rules

With the server administrator's permission identify the Kodi version and inspect the corresponding show in its library. Kodi documentation says multi-episode filenames for v21 and earlier must identify the episodes; it also describes episode ranges starting with v22. The example S01E01E04 identifies episodes 1 and 4, not automatically episodes 2 and 3. Check range syntax against documentation for the version in use. Observe existing names only; do not assume newer range support in every version.

Inspect server entries

Open the same show and season in Kodi's TV library. Check each sample episode number and whether its title, year and season/episode identity are sensible. If only one appears, unexpected episodes appear or identity differs, record server state separately from the file inventory. Kodi recommends single-episode files where possible, but this does not require immediately splitting existing media. For renaming or rescanning, have an administrator assess impact and back up first; do not clean the library, overwrite files or trigger a full-library update yourself.

Inspect corresponding episodes in iCouldPlay

Open the configured, authorized Kodi source in iCouldPlay and confirm server, account and show identity. Find each number in the episode list that is actually visible; record name and other visible information. If the interface does not expose file path, starting point or server mapping, mark it invisible. Two visible episode numbers do not prove the app made two files, and do not claim a start-point selector that you did not observe. Record discrepancies when server entries exist but the client does not show them.

Compare actual playback from each entry

Use a trusted player to compare the known openings and time points for both samples. In iCouldPlay open each visible episode entry and observe whether playback starts and which segment its picture and sound match. If the current interface offers a progress control, you may inspect the known boundary within your permission. Do not assume that selecting the second episode starts at its own boundary, or infer that a successful seek applies to all server configurations. Checking segments does not establish that the entire file is intact.

Preserve evidence for troubleshooting

Make a sanitized table of filename season/episodes, reference time points in actual content, Kodi library entries, iCouldPlay entries and observed opening picture. For missing episodes first check file, server version, naming rules and authorized source access. For a client/server discrepancy, confirm the same server and account. Mark unavailable paths or controls pending rather than concluding the file is missing. Change one reversible observation condition at a time and record time and result.

If multiple entries open at the same picture, first check server mapping and actual playback position. Do not immediately delete an entry or assume damage. A library entry, a physical file and playback start position are three different facts. A user without server-setting access can pass pending questions to the administrator without sharing passwords or signed media links.

State the observation boundary

Record the reference segment's source and time together, distinguishing pictures you personally observed from mapping information supplied by the administrator. If the library changes during inspection, record a new time and state instead of overwriting the original result. When start position or mapping remains uncertain, suspend judgment and ask an authorized person to check; do not change production files to force agreement.

If server version or naming rules are unknown, mark the version pending rather than choosing the rule that fits; preserve existing filenames until an administrator confirms them.

Finish without changing the library

Deliver the file-to-episode comparison, separate Kodi and iCouldPlay observations, sample openings and pending questions. Confirm source files, library and backups remain intact and restore playback position. Kodi versions and configurations can differ. This guide claims no private-server operation or iCouldPlay physical-device test.
