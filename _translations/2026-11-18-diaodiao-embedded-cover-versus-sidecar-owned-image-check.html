Use three owned samples with distinct audible identities: embedded artwork, a picture beside the audio only, and neither. Deliver a source ledger and display comparison without assuming folder-art scanning or treating a placeholder or similar composition as proof of online artwork retrieval.

1. Make owned, recognizable artwork and audio

Externally create an owned square image, for example one hundred sixty pixels on each side, with blue in the upper left, orange in the lower right and an exercise label in the center. Keep the source and use no real album art or another person’s photo as supposedly original work. Record three short audios opening with 甲封面, 乙旁图 and 丙空白 respectively, identifying embedded art, sidecar and blank, so the image is not the only identity cue. Distinct sounds intentionally separate the assets; this is not a listening experiment changing artwork alone. Accordingly, compare supplied metadata with display rather than infer artwork causation from different sounds. Work on copies, preserve the collection and claim no finished downloadable assets are supplied here.

2. Confirm the image is embedded in A

Use an existing tag tool to place the owned image inside working audio A, then save and read it back. In an MP3 tool supporting the relevant tags, ID3 APIC represents an attached picture, but verify actual image data: the specification also permits a linked form, so the APIC name alone does not prove embedded bytes. Choose a direct-picture method that the tool can confirm and record image format, actual dimensions and distinguishing pattern. 调调 publicly reads available embedded covers without promising every tag version or picture variant. Keep external-tag verification separate from app readability. Without confirmation, mark A pending; a preview window by itself does not prove the file was written.

3. Preserve distinct source conditions for B and C

For B, confirm no embedded image through the tag tool and put a copy of the owned picture named cover.jpg beside it in the external folder. C has neither embedded art nor a folder cover. This filename is an exercise convention, not a claim that 调调 recognizes it or scans sidecars. Give titles 封面甲, 旁图乙 and 无图丙 for A embedded, B sidecar and C no image while retaining spoken identities, since matching placeholders can otherwise confuse them. Save folder states and tag reports. Failing to read an image tag differs from confirming absence. If the tool cannot inspect it, keep the state unknown rather than filling in “none” to complete a three-way table.

A: embedded image data confirmed
B: no embedded image; folder contains cover.jpg
C: no embedded image; no folder cover

4. Import only the three audio files

In 调调’s file importer, select only the working audio, not cover.jpg as another playable item. Retain each response and identify library entries before continuing. If only two appear, inspect selection, failures or duplicate notices rather than infer song count from artwork count. Internal deduplication rules are unpublished. Do not casually alter audio to force three entries and keep using old tag reports; reread any changed asset and update evidence. No deletion of existing real same-titled songs is required. An import list’s image is not a substitute for checking the player. Import outcome, item identity and displayed artwork are separate acceptance points.

5. Check A’s pattern rather than screen dimensions

Open A and first hear its embedded-art spoken label, then compare the upper-left blue, lower-right orange and central exercise identifier. Matching patterns support consistency with the verified embedded source in this case, not proof that no other source was accessed or that original image resolution is displayed pixel for pixel. Scaling, cropping or controls can obscure regions. Keep unclear parts unknown rather than treating one visible color patch as a full match. If expected art is absent, reread the saved external copy, image type and tag and retain the actual placeholder state. Reading available artwork is not a promise that every file must display an image.

6. Observe B and C without prefilling outcomes

Open B and C separately, hearing each identity before recording the owned image, placeholder, blank area or whatever actually appears. Even if B shows artwork, a nearby cover.jpg alone does not prove its source; retain other tag and source conditions. No image for B would not contradict the public embedded-cover description. If C shows a pattern, first check item identity and remaining metadata rather than immediately call it online enrichment. Missing artwork does not establish unplayable audio; verify image and sound separately. The comparison distinguishes known source, unknown source and visible state instead of forcing a predicted pattern across all three assets.

7. Diagnose file contents, sidecars and views separately

If A shows art only in one view, record that view difference before embedding again. If A and B’s sounds are mismatched, repair item identity rather than hide it with another image. When the external image exists but the tag was not written, fix the working copy externally and account for reimport feedback; do not claim 调调 wrote the tag. Changing artwork, title and encoding together cannot isolate one cause. Do not delete the source folder to test an assumed cache. Keep sidecars in the controlled exercise directory and preserve existing work. Record whether evidence is inside audio or beside it, what is confirmed and what is unknown instead of a vague “broken cover.”

8. Reopen and deliver a source-display ledger

Leave and reopen each confirmed item, comparing sound and image state with the record. Mark reopening only if performed. Deliver the owned image, source ledger for three working audios, external tag evidence and actual player display. Source dimensions describe the original, not a screen measurement. If an asset type was not prepared or imported, retain that missing stage rather than filling blanks with “no cover.” Explain why embedded data, a sidecar and a placeholder are different evidence categories, while acknowledging that this exercise establishes no universal artwork-search policy. A new format, tag version or source needs fresh checks, not a whole-library compatibility claim from one matching picture.
