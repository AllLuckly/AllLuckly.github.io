Open a trusted JS source file from Files, then check its identity and a known search in Manyue+.

Check version and provenance

Apple’s public release notes say 2.0.7 can open and import a .js comic source from Files. Check the installed version first; record any older version or different interface. Sources are user supplied, not bundled content. Use only a source you wrote or received from a trusted maintainer with clear permission. An extension alone does not establish safety.

Prepare one identifiable file

Find the JS file in Files and note its full name, location and modification date. If it came in an archive, follow the trusted maintainer’s extraction instructions; do not rename the archive to JS. Keep an untouched backup and note the expected source name and version. If the file is cloud-only, confirm it is downloaded. Stop here if no trusted sample is available.

Record the starting state

Open the existing source list in Manyue and record whether the same name already exists, the number of entries, and their names. If a same-name version is ambiguous, retain a screenshot or written note without deleting it. This baseline helps distinguish a new entry, a conflict prompt or an existing entry; a count alone cannot prove functionality or file identity.

Open from Files

Return to Files, select the trusted JS file, and use the system’s available open or share action to choose Manyue. A direct Open in Manyue option may also be visible. Menu labels can vary. If Manyue is absent, check the extension, installed version and available system actions and mark the task incomplete. Do not install an unknown profile as a workaround.

Check any confirmation

If Manyue displays an import preview or confirmation, compare the displayed source name, address or maintainer details with the trusted documentation. Cancel if the identity is unfamiliar or different. Read any same-name conflict choices shown; do not assume replacement or automatic merging. The user decides whether to confirm; this tutorial does not inspect or approve the code.

Identify the list entry

After confirming, return to the source list and find the expected name. Compare with the baseline and mark it new, existing, or not observed. If details are available, compare the displayed address or version, without treating a shared name as proof of identity. If missing, check whether you cancelled, selected another file or saw a failure; retain the original and avoid repeated imports.

Run a known search

Choose a known keyword from content the maintainer permits, and search within the corresponding source in Manyue. Record the keyword, time, whether a list appears and any explicit error. If login is required, use your own account and the actual interface; never put credentials or tokens in notes. No matching result alone does not prove import failure; check the selected source and network first.

Check a chapter and return

Open a chapter you are authorized to read, wait for the first screen, then return to the list. Record open, read and return separately. Chapter loading depends on the source, network, login and rights; a visible source does not guarantee every chapter works. Do not download or distribute unauthorized content. If no suitable sample exists, mark the step unperformed and verify the source after returning.

Troubleshoot and record

If the file will not open, recheck location and extension. If import succeeds but search fails, record network, source identity and the error separately, then consult the trusted maintainer. Distinguish login from import and avoid clearing reading data as a first response. Change one condition at a time, repeat the same keyword and compare. Do not attribute a service outage to an unverified app defect.

Keep the backup and outcome

Record file provenance, installed version, source identity before and after, search and chapter outcomes, and reasons for unperformed steps. Exclude private addresses, credentials and sensitive screenshots. Confirm the backup remains in Files. Remove a test entry only after identifying it and understanding the effect; preserve same-name existing sources and reading history. No device or private server was tested by this tutorial’s author.

Compare a completed and an incomplete attempt

Separate the same file’s opening and search into two observations. First check whether the system hands it to Manyue; only then inspect the list and search. If opening was cancelled, do not mark it successful. For an existing same-name entry, record names and counts and leave replacement unknown. Before retrying, check the backup, provenance and user permission. Do not substitute results from another source. The record identifies where the attempt stopped; it does not promise every source will work.
