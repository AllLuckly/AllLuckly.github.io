Compare a catalog placeholder with a real video in an isolated library, recording server and iCouldPlay observations separately.

Separate two questions

Jellyfin media placeholders allow a movie entry to exist in the library without a playable video. Its documentation specifies an empty file with the normal title and a .disc extension; the contents are not used for playback. iCouldPlay publicly supports Jellyfin, but whether it displays a placeholder or a particular message depends on the client. Check the server first, then observe iCouldPlay; a poster alone does not prove a video file exists.

Prepare an isolated test

Ask a server administrator to prepare an isolated movie test library and a copy of a self-made or authorized short video with sufficient storage. Choose a fictional sample name unlike any real movie, for example “Practice Film (2030).” Record the test root and relative location of the short copy without disclosing server addresses, accounts or tokens. Without administrator access, read the procedure but mark server operations and results unperformed.

Create the placeholder

Inside the isolated movie folder, have the administrator create an empty file named Practice Film (2030).disc. In the file manager, verify that its extension is actually .disc, not a hidden .disc.txt. Do not rename a real video into a placeholder or overwrite a same-named file in the real collection. The title and year are fictional and do not guarantee external metadata.

Scan and record the web baseline

Have the administrator scan the test library using the current Jellyfin version’s normal process and wait for completion. In the web interface record whether the item appears, its title, folder contents and whether an actual media file exists. Treat posters or matched metadata as separate information, not proof of a video. If another folder shares the title, pause and check the server-relative path to avoid touching another user’s film. If no item appears, inspect library type, path and full extension before touching any database.

Observe the placeholder in iCouldPlay

Connect iCouldPlay to the same server with an account authorized for the test library and look for the same title. Record item visibility, visible controls and actual feedback. If the item or playback control is absent, record that rather than inferring a hidden feature. Do not immediately blame the network for failure; first confirm on the server that the sample contains only the empty placeholder.

Prepare a playable control

Have the administrator create a differently named control movie folder in the test library, copy a self-made or authorized short video into it with its normal video extension, and preserve the original. Do not alter the placeholder folder. Make titles and folders distinct to avoid confusing matches. Record duration, a recognizable visual event and the actual container; an extension alone does not prove codec or client compatibility.

Compare both items

After a server scan, inspect both items in the web interface, then open them in iCouldPlay under the same account. For the playable short, record actual picture and sound; for the placeholder, record its display or inability to play. If both fail, verify the control on the server or web first, then compare account permissions, network and client observations rather than attributing every failure to placeholders.

Recognize extensions and types

Jellyfin also permits an optional type immediately before .disc, such as .dvd.disc or .bluray.disc, to label a physical medium; it remains a placeholder without video content. Do not confuse .dvd.disc with a real DVD folder or assume a type is recognized after inserting other text between the type and .disc. For a basic visibility test, keep the simple .disc first instead of changing several conditions together.

Record observations and unknowns

Use separate columns for the server file list, web item and iCouldPlay behavior. Record only observed titles, whether a video file exists, whether playback begins and any error; do not fill in an imagined playback control. If iCouldPlay shows an old list, reopen or refresh using a normal control visible in the current interface and note the time. If the item remains absent, preserve uncertainty instead of deleting other library data to force the expected result.

Troubleshoot while preserving originals

If the placeholder is absent, check that its directory was scanned and its extension is real. If the control short fails, separately check authorization, file completeness and server playback. If only the iCouldPlay list differs, record server and client versions and the behavior under the same account without promising that server support implies client support. Avoid repeatedly renaming real movies or replacing original media; do not share screenshots containing private addresses.

Clean up and hand over

Afterward, the administrator may retain or remove the two test copies and empty placeholder according to the test-library agreement, checking that the original short, real library and other users’ data remain intact. The handover should include scan completion time, relative sample names, server files and web results, actual iCouldPlay visibility, and unperformed steps. This exercise is based on public documentation and claims no private-server login or device test.
