A space or hash in a folder name is not the same thing as a delimiter in a network address. 调调 1.0.4’s public release notes mention improved WebDAV connection and library browsing. First inspect an offline example, then observe an authorized server through its actual interface; do not assume a particular encoding method in 调调.

Specify an offline example and objective

Suppose a service root is https://example.invalid/dav/ and a child directory is named exactly A B#1, with one space between A and B and a digit after the hash. The host example.invalid belongs to the reserved invalid domain and is used as an example: do not visit it or use it as a real server. Establish that the name is one path segment and distinguish display name, request address and a resource that actually exists. Paper notes suffice; no server or upload is needed.

Compare three address representations

In one explicitly chosen URI path-segment representation, space is %20 and hash is %23, giving https://example.invalid/dav/A%20B%231/. Each escape represents a character from the directory name; the trailing slash is this example’s collection-path convention, not part of the name. In https://example.invalid/dav/A%20B#1/, the literal # introduces the URI fragment 1/, not part of the path sent to the server. It is not an equivalent spelling of the first URI. Servers may apply different collection and normalization rules, so this paper example does not establish that a particular server accepts a request.

Inspect the components manually

On a card mark scheme https, host example.invalid, parent path /dav/ and target segment A%20B%231. For the incorrect example separately mark the path ending in A%20B and fragment 1/. A URI fragment is a client-side URI component, not literal hash text in the server directory path. Do not confuse path separators with characters inside a name. Other reserved characters require separate interpretation according to their position and purpose.

Distinguish one encoding from repeated encoding

On a computer with Python 3, this local program parses the example strings without any network request and prints paths and fragments. The first path contains %23 and has an empty fragment; the second path ends at A%20B and its fragment is 1/. Output checks example syntax, not an actual WebDAV response or server log.

from urllib.parse import urlsplit

examples = ["https://example.invalid/dav/A%20B%231/",
            "https://example.invalid/dav/A%20B#1/"]
for value in examples:
    parsed = urlsplit(value)
    print("path:", parsed.path, "fragment:", repr(parsed.fragment))

%23 is an encoded hash. Encoding the percent sign again yields %2523, whose single decoding produces the literal text %23, not a hash. This does not make every %25 an error: the real name may contain a percent character, and client/server decoding layers require evidence. Preserve input and observations; do not repeatedly add or remove escapes without knowing the actual name and service rules. Use RFC 3986 and the real interface for the relevant context.

Confirm identity on an authorized service

If you manage or may access a WebDAV service, find an existing music directory containing a space or hash in that service’s own management interface. Record a non-sensitive service alias, parent and display name. Do not alter shared files or publish credentials, tokens, complete internal addresses or private library data. Without such an authorized resource, retain the paper exercise; there is no need to create public files or seek a stranger’s server.

Browse using the actual 调调 interface

Open the authorized WebDAV source, confirm service alias and account, and navigate through the visible parent and target folders. If the app shows a decoded name, record that display. If it does not show the raw request address, do not claim to have observed its encoding. Find an authorized track and separately check list visibility, identity and playback. A correctly displayed name with failed playback can involve network, permissions or file state; one result does not prove an encoding fault.

Troubleshoot and bound the evidence

For an absent target, first check selected service, user permission and parent folder, then whether the server resource exists. If authorized logs are available, remove sensitive information before comparing the actual requested path. Do not share authentication data, disable security or expose the service publicly. A service can redirect a path; record the observed status and destination rather than assuming all servers redirect identically. Change one condition per trial and keep the initial result.

Deliver and restore

Deliver the three example representations, encoding and fragment boundaries, plus sanitized real-service folder and track observations and pending items. Do not turn the example domain into a real address or call a visible listing a downloaded file. Restore the original source, volume and queue without modifying server content. RFC URI syntax and public release notes inform this exercise; no packet capture, private-server access or physical playback test is claimed.

If an actual name contains Chinese or other non-ASCII characters, make a separate check using service documentation and real observations; do not copy these two escapes to another name. Record date and service version for follow-up.
