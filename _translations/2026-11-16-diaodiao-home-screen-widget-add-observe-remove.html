Use the system widget flow with actual installed choices, record display scope and preserve music data.

1. Check the release scope and installed version

Version 1.0.1 release notes publish Home Screen widgets without a complete size, control, interaction or refresh specification. Check your installed version and working music state first. For an older version, retain preparation and resume after your normal store-update choice instead of deleting the app or local music to force a refresh. Home Screen widgets are not automatically Lock Screen widgets, Live Activities or Control Centre controls. This task checks only the Home Screen flow rather than claiming all similarly named surfaces.

2. Preserve layout and a track reference

Choose a Home Screen page with room, recording its existing icons and widgets before editing. In 调调 identify an authorised track and note title, artwork and play/pause state as a possible display reference. A self-recorded sample avoids exposing private titles in public screenshots. This reference helps identify content but does not guarantee the widget will show that track or follow it in real time. Observe what it actually provides instead of filling results from promotional expectations.

3. Open the system widget-adding flow

Following Apple’s current guidance, hold the Home Screen background to edit, then open the system’s Add Widget flow. Identify the actual controls because positions/icons vary by system release. Find the real 调调 entry and verify app identity, not merely colour. If absent, leave editing while preserving layout and inspect version, completed installation and device availability. 4. Choose only an available size and style

Inspect the actual preview, size and style choices and select one that fits the page. Release notes promise no fixed three-size set or editable parameters on every device; record the real names/count. Add it, place it while editing and finish through the visible system control. If space is insufficient, choose another suitable position/page rather than delete an app. Verify the ordinary Home Screen afterward: a gallery preview is not an already installed widget.

5. Compare the actual display with the reference

After editing, record the title, artwork, state or placeholder actually displayed. If no title field exists, title verification is unavailable. 6. Observe only interactions actually provided

If an identifiable button or tap area exists, save the state and observe one action: opening the app, changing state or an unresolved outcome. Without controls, do not invent play/pause, next-track or arbitrary selection. Opening the app does not establish full desktop control. Use only actual configuration options; Apple’s general examples of editable widgets are not a promise for every 调调 option. Keep unperformed actions pending and restore the reference after accidentally opening another audio session.

7. Diagnose missing entries, placeholders and actions separately

For a missing gallery entry, inspect version/availability. For an added placeholder, inspect app content/feedback. For an unexpected tap result, inspect actual interaction design and system state. These are not one generic widget failure, and reinstalling away local music is not a control. Change one known condition and retain system version, style and observation. Unconfirmed entries or unavailable choices remain incomplete instead of borrowing another device’s screenshot or inventing sizes/configuration.

Restore the layout, locate the original music and restore desired playback. Deliver version, real size/style, actual display, optional interaction and removal result.
