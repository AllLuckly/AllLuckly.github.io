Book Isle 1.1.4 clarifies note-centre export scope and batch selection, but you still need to define the intended set. Compare normal current-result export with selected-record export using a few self-written samples. This exports no complete book text, and opening a share sheet is not proof of saving a file. Preserve real notes throughout.

Prepare a few distinguishable export samples

Keep two or three self-written records in permitted sample books with unique annotation markers for external checking. Establish total, filters and positions in Notes without public demonstrations of private annotations. Samples across two books can test cross-section scope; headers are not individual records. Define a target such as A/B but not C before pressing buttons. Preserve books, real notes and old exports independently and use new filenames, rather than deleting records to force current results to equal the desired two.

Normal export includes current results, not one screen

Outside selection mode, the upper-right export icon exports current results: all notes/highlights without search/type/colour conditions, otherwise the filtered set. Record the count, open the format prompt and read its stated scope/count. This is not just visible rows or recently viewed records. If you want two but results contain five, cancel rather than claiming a two-item selected export. With zero results, a disabled entry reflects no objects, not necessarily permissions or a need to reinstall.

Select two records and inspect the batch summary

Enter Select mode and choose A/B individually, checking selected and current-result counts separately. C may remain in results without being selected; inspect actual row selection, not similar text colour. Export and Delete are distinct toolbar actions; use only Export here. With none selected, export is unavailable or requests selection; record actual behaviour. Reconfirm scope after cancelling rather than treating previous checks as a permanent set. Batch selection is an operation state, not a book tag.

Select all covers only the current filtered set

Clear the selection, then Select all: selected count should match current results, not the unfiltered library or visible rows only. Deselect all should return selection to zero without removing records. Filter to A/B for a clear test; C is not included merely because it shares a book. Cross-book sections still use the current record set, not selectable headers. Select all itself exports nothing. Counts need the later scope prompt and actual file before any backup claim.

Reselect after filter changes instead of trusting old checks

After recording a selection, change search, type or colour and inspect summary/rows. Reapplying filters here clears selection; old row positions cannot be assumed to identify the same notes. Reselect after restoring conditions, especially if updated records reorder book sections. Recheck after leaving/re-entering or reloading too, without assuming selection survives forever. Change one condition and record old results/selection and new state so cleared selection is not mistaken for deleted notes or lost exports.

Confirm scope in the export prompt before choosing a format

With A/B selected, use batch Export, read the selected-item count, then choose an offered format such as Markdown, HTML, CSV or Obsidian Markdown. Format does not change the target set. If batch Markdown formats show Collector Pro requirements, follow existing entitlement; a single-item scope test is possible without purchasing for this exercise or treating membership text as corruption. For Save to export destination, verify that destination: this path saves Markdown and is not identical to sharing any format. Configuring a destination alone writes no current export.

Open the saved file externally and check each record

After actual saving/sharing, open the file at the chosen location and verify A/B markers, book, chapter, selected text and annotations, excluding C. Formats differ structurally; inspect identities rather than file size alone. A share sheet or configured destination is insufficient, and cancelled sharing proves no save. This is a note-content copy, not complete book/cache backup. Verify destination/path results as applicable. Name scope, count and date and retain recoverable copies without overwriting prior exports.

Return to results and selection for too many or few exports

For extra C, check normal-result versus batch-selected export before deleting unwanted file content to hide the cause. For missing A, inspect re-selection after filtering and the prompt count. Correct selection without a saved file calls for share completion/destination checks, not resetting Notes. Repeated export taps cannot repair an empty selection; restore the intended set. Exit batch and restore daily filters afterward. Explain overall records, current results, selected set and actual file separately instead of treating a success message as universal evidence.
