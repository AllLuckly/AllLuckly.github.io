A gzip response label does not mean that the comic itself is a gz file, nor identify the ZIP method for every CBZ image. Keep an external transport ledger before and after ManYue import, separating three compression layers. Headers and file inspections come from existing tools or provider reports, with app results recorded independently. No server reconfiguration, private-token capture or invented low-level reader setting is required.

Fix one small original archive

Make a CBZ from three original numbered pages, verify local readability and record hash, byte size and entries. Without an available test source, perform only the paper audit below and claim no remote download. Name original and received copies distinctly to avoid an old file masquerading as fresh data. Remove accounts, cookies and signed private URLs: this exercise needs type, coding and identity, not secret headers.

Give two response fields separate columns

The original teaching record gives media type application/zip plus Content-Encoding: gzip. Type identifies the media after decoding; coding identifies an additional applied content coding. They are not competing suffixes. In a control, ZIP type with no Content-Encoding declares no additional coding in that field, not absence of ZIP’s internal compression. These records describe no live service and do not claim that a particular source necessarily uses gzip.

This paper audit merely separates the fields and decoding order; it sends no request or configures a server. Add your own timestamp, status and automatic-decoding behaviour only for a real available test. Otherwise mark those cells unperformed. No Content-Length or raw bytes are supplied, so do not invent a network size as captured-response evidence.

Identify the bytes actually handed to the user

RFC semantics require decoding content coding to obtain the data identified by Content-Type. A downloader may already do that, yielding a ZIP, or may deliver still-coded bytes. Inspect its documented behaviour and report instead of decoding blindly twice. Separate the received coded representation, tool decoding and final archive. A size measured after automatic processing is not a measurement of unrecorded raw gzip response bytes.

Inspect entry methods only inside the ZIP

After obtaining a parsable archive, inspect each entry’s storage or compression method. Outer gzip does not establish inner Deflate or identical methods across entries. A stored JPEG can still have compressed image encoding. Give content coding, ZIP method and image format their own evidence columns. Do not reuse one compression ratio across layers or equate removing outer gzip with decoding images into screen pixels.

Match byte layers before comparing hashes

Compare a provider’s final-CBZ hash with the final archive, not a still-gzip-coded body. Different byte layers naturally differ, so unequal hashes alone do not establish corruption. Matching same-layer hashes supports byte identity but not complete in-app readability. Record tool, layer and full result, retaining both representations when needed. No hash display or transport-coding analysis by the app is assumed.

Check numbered pages after import

Import the final readable archive through an existing ManYue path and inspect all three centres, markers, positions and return paths. A listed directory does not prove image decoding, so actually open every page or mark it unperformed. If only a remote source fails, retain source and final-file identity before investigating transport instead of first renaming the suffix. Success is limited to this copy and path, not every Content-Encoding combination.

Check double decoding and misleading names

If a tool says not gzip, first determine whether automatic decoding already occurred. Do not force library-wide processing. A ZIP signature with unreadable entries calls for entry-method and integrity checks, not automatic blame on the outer coding. A gz or zip filename alone is insufficient. Share only the original small sample and redacted fields; keep unseen server logs unknown and avoid account disclosure or security-setting changes.

Leave and return to reconstruct the compression chain

Leave and return to all three pages, then reconstruct content coding, archive-entry method and image coding in order. Preserve identities, tools, performed steps, page checks and unknowns. Explain why gzip is not a ZIP entry method and acknowledge missing raw-body evidence. Success keeps compression layers separate from app observations and retains recoverable originals, rather than calling every layer simply decompression successful.
