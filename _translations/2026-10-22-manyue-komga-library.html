Komga already manages your comic series, book information, and user permissions, while ManYue provides a reading interface on phones and iPads. You do not need to reimport the server directory as local files when connecting, but you do need an account that can actually access the relevant libraries. Verify one series and one small sample before expanding to the entire collection. This makes permission and path problems easier to identify.

Confirm a working sample on the server

Ask the service administrator for the base address and a personal account, and confirm that the account can see the target series. Use that same account on the website to find a comic with actual content, and check its title, page count, and access scope. An administrator's ability to see everything does not prove that an ordinary account has the right permissions. Do not temporarily use someone else's account as a substitute for your own long-term configuration.

Komga can restrict library sharing, page-by-page access, and file downloads separately. A successful login does not mean every operation is authorized. The server administrator manages these permissions; see Komga users and permissions documentation. You must also satisfy ManYue's server-library entitlement separately. App membership and a Komga account meet access requirements at different levels.

Add a Komga connection in ManYue

Open the server library's add-connection screen, select Komga as the service type, and enter a recognizable name, an HTTP or HTTPS address, a username, and a password. Use the server's base path. If the service is deployed under a subpath, retain the path supplied by the administrator.https://komga.example.com/library-service/ is only a placeholder example here, not a substitute for your actual address.

Do not paste a particular comic's browser details link, and do not append an API path to the base address yourself. Once the details are correct, choose Connect and Save and wait for validation. If it fails, retain the error text and check the address, account, and service type first instead of changing several fields at once. Put real credentials only in the appropriate fields, not in the connection name or public screenshots.

Understand how series and chapters correspond

After entering the library, find the series you just checked on the website and open its details. ManYue's Komga connection organizes entries by series, presenting individual books as selectable reading chapters. Several entries under one series cover therefore do not necessarily mean duplicate files; they may correspond to different volumes or books on the server.

Check the names and order of these entries, then open one. If the order differs from what you expect, inspect the book metadata and volume order on the server instead of repeatedly adding the same connection in the app. The client relies on information supplied by the server. After changing original files or metadata, let the server update first, then refresh the client and inspect the result.

Verify covers, pages, and downloads separately

A loaded cover shows that some metadata or image requests succeeded, but you still need to open the body pages. Turn a few pages, then jump to the middle and end to confirm that page-access permissions and file contents work. If the catalog is visible but the pages cannot be read, describe the failure as 'series can be listed, but pages cannot load.' This lets the administrator check the relevant permissions and specific book rather than reworking the entire account.

If you need offline access, try the download action offered for the current book and check the result in download management. Komga may permit page-by-page reading without permitting file downloads. If reading works but downloading is denied, check permissions first rather than repeatedly changing the address to bypass restrictions. After an authorized download finishes, still test the local copy without a network connection.

Example: start with a test series

Suppose you create a Short Practice Stories series in your own Komga instance containing two comics you made. First confirm visibility on the website with an ordinary reading account. Then add the connection in ManYue, find the series, and open the first book. After checking its last page, open the beginning of the second book to confirm that the series entries do not mistakenly point to the same file.

Next, download only the first book and verify that it is readable without a network connection. Keep the second book as an online comparison. You will then know exactly which book is stored on the device and which is merely an entry in the server catalog. After testing, you can connect more libraries without mistaking every cover for offline content.

When changing the address or account later

Retain the details of the working connection and read the current interface's guidance about changing the service, address, or account. A change may create a separate connection; the same display name alone does not guarantee that book identifiers and old records are identical. Recheck the same test series after the change. Do not remove your only working connection before confirming that the new one works.

Server data must be backed up through the server's own management process. ManYue reading-state synchronization does not replace a Komga library backup. Nor should you promise, without verification, that progress will always match in real time across every client and the website. Actual behavior also depends on the service's capabilities and the access method. To continue reading on another device, separately check the target title's state and file availability.

Where should I look first if login works but the list is empty?

First use the same account on the Komga website to check shared libraries and content access, then confirm that the server has finished identifying the sample. Content visible to an administrator may not be shared with this account. There is no need to begin by reinstalling the app or repeatedly recreating the same connection.

Downloads fail, but online page turning works. Is the file damaged?

Not necessarily. Page-by-page access and file downloads may have different permissions. First check whether the account is allowed to download, then examine the task's specific error. Only after permissions and connectivity are working should you investigate the file contents and device storage. Avoid attributing every failure to a damaged file.
