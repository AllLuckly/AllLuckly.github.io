Preserve reading-data copies while comparing device storage, actual WebDAV feedback and one controlled retry.

Protect existing notes and original book

Choose your own practice book and record chapter, one nonprivate note and current device state. Preserve important note copies and the original book using your existing process; synchronization is not the only backup. Record Book Isle version, device, WebDAV target and sync time, using redacted identifiers instead of public addresses and accounts. Stop before any potentially replacing operation if no reliable recovery copy exists.

Inspect device storage and actual feedback

Inspect available storage and actual system prompts in device settings, recording system warnings separately from the Book Isle sync message. Sufficient device space does not prove sufficient remote quota, or vice versa. If the system actually warns of low space, use your backups and system guidance to manage safely removable content; do not delete Book Isle, the only book original or all notes for testing.

Check the WebDAV target

Confirm Book Isle sync selects the intended WebDAV connection and directory, not a separate books-only path. Ask an authorized administrator to check the account’s read/write access, service state, free space or quota and actual error. Private sync concerns reading data; the public description does not say book files are automatically uploaded to the developer’s server. Do not infer an original was synced or lost from one failure.

Interpret 507 only when actually observed

WebDAV’s 507 Insufficient Storage means a method could not be performed because the server cannot store the representation needed to complete it; this is server response semantics. Record it only when the relevant request is reliably identified and 507 actually observed. If Book Isle shows only a generic error, mark status unknown. A 507 alone does not establish whether disk space, account quota or another restriction caused it; use server evidence.

Change one confirmed condition at a time

If the administrator confirms insufficient target quota, follow the service’s rules while preserving necessary content. Do not make the whole directory public, empty another person’s files or repeatedly tap sync. Record conditions before and after, confirm target and account remain the same, then perform one controlled retry through the actual interface and wait for its result. Changing device and remote capacity simultaneously makes the cause harder to identify.

Verify the note and retain results

If sync reports completion, reopen the same practice book and note. On a second authorized device, you may follow the existing sync process, but check book files and reading data separately. A finished task, remote write and the note actually appearing on the other device are different outcomes. Record versions, redacted prompts, whether capacity was confirmed, retry and untested items without sharing account details, tokens or private notes. No device or server test is claimed.

Keep separate records for two storage locations

Suppose the device reports free space but Book Isle sync fails. Put device free space and observation time on one row and administrator-confirmed remote account quota and directory state on another. The values come from different systems and can use different units and update times; do not fill the server quota field with device free space. If the administrator has not supplied quota data, mark it unconfirmed rather than inferring a full server from a generic error.

Suppose an administrator confirms that the same WebDAV write request returned 507 while that account’s quota was exhausted. Those two observations are concrete clues for this failure. A log for another account or time does not establish the cause of this sync. Conversely, if the device itself reports low storage but the server has no error, address the observed device issue first; one check does not exclude other simultaneous limitations.

Check target and data scope before retrying

Book Isle’s public description includes reading progress, metadata, notes and settings in private sync; it does not say all ebook files are moved to the sync directory. Confirm target, current notes and original-book backup, then read any conflict or replacement prompt actually presented. Cancel and seek help if unclear instead of selecting a whole-library overwrite to test capacity.

After an administrator frees space, record whether it was account quota or server storage and when; there is no need to publish capacity figures or a file inventory. Keep device, account and target constant, retry once through the actual interface and wait for completion. On another failure retain the latest redacted message and time rather than repeated taps or unrelated settings changes. Mark the retry unperformed if conditions are unavailable; freeing space is not itself successful sync.

Check both devices and restore

If a second device was configured for the same target through the user’s existing process, confirm original data is backed up, obtain updates using the actual interface and find the same book’s practice note. Check location, note content and original file separately; a visible title does not establish that the book file synced. Mark unobservable items untested rather than deleting books or another device’s data for verification.

Afterwards confirm the original device’s note, book and backup remain. Record app and system versions, whether device and remote space were checked, whether a retry was performed and outcomes on each side. If logs contain complete addresses, Authorization or tokens, have an authorized administrator redact them first. Do not send private notes or reusable links to support.
