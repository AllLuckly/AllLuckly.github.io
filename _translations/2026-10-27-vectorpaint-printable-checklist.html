A checklist should support item-by-item confirmation rather than maximise density. Build a fictional shoot-preparation sheet with boxes, wording and handwriting space. Images and ordinary document exports remain static artwork, not automatically clickable forms.

Write tasks with observable completion

List eight observable tasks and group them by equipment, files and location. Use one action per checkbox, replacing vague wording with verifiable descriptions. Reserve title/date and grouped tasks on a 900 by 1200 pixel canvas. Establish task order outside the app first; layout cannot fix ambiguous checklist content.

Draw a box large enough to mark

Create an unfilled box with enough room for a handwritten mark. Test it beside task text at the intended size. Duplicate a checked row with consistent alignment and spacing. A white-filled box remains a white object in transparent output. Verify box and text contrast separately for any dark-background version.

Give wrapped tasks enough row height

Allocate extra row height for a wrapped task and move following rows together. Keep continuation lines aligned with text, not beneath the checkbox. Choose one box-alignment rule throughout. Inspect without decorative dividers to confirm one box maps to one complete task, then stress-test with a deliberately long item.

Use spacing to show stages

Use larger gaps between equipment, files and location groups while keeping steady spacing within each. Keep headings restrained and any rules consistent. Order groups by the preparation process, not text length. Remove redundant tasks or split an overcrowded sheet rather than sacrificing handwriting space.

Reserve date and exception notes

Label date and name fields explicitly and reserve space for exceptions. A checked item can still reveal a problem, so distinguish inspection from resolution through notes. The static sheet does not calculate completion or issue reminders. For shared use, agree on the meanings of ticks, crosses and blanks and provide a short legend.

Test at the intended paper size

Save and inspect boxes, small text and writing areas at intended paper size. For printing, check margins and clipping, particularly footer notes. Pixel dimensions alone do not establish physical output size; paper, orientation and scaling matter. Reassess separately if adapting the sheet for phone reading.

Rehearse three different states

Test a completed item, an exception and a pending item. Add short identifiers if notes cannot be associated clearly. Keep task wording meaningful. Save the filled example separately from the blank template, and create future revisions from the blank editable source rather than a previously completed image.

Audit mismatched boxes and tasks

Inspect overlapping duplicates if a row has extra boxes. Adjust row height for text crossing a group boundary. For disappearing outlines, check contrast, weight and display size before thickening. Audit headings, tasks, boxes and notes without decoration, and confirm the blank template contains no completed states or old entries.
