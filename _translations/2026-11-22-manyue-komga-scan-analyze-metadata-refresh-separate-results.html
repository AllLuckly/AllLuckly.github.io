Use one authorized test comic to check Komga file scanning, analysis and metadata separately from ManYue display.

Prepare a recoverable test comic

Choose a Komga test library you manage and a small authorized CBZ. Inspect its first page and page count locally, recording filename, size and cover marker. Retain the original file and configuration; do not add or move files on another person’s server. Confirm the server, account and test library connected in ManYue. Ask an administrator if you lack management rights.

Understand three server operations

Komga documents that scanning checks folders for additions, removals and moves; analysis gathers media properties such as container and images; metadata refresh updates information such as title and artwork. New files are normally analyzed after scanning, and analysis also refreshes metadata, but these are not the same action or purpose. Names and scope depend on the current server interface.

Check the file and scan result first

On the server confirm the test copy is in the intended series folder under the library root, then scan the test library using the administrator’s process. Wait for actual completion and check whether the corresponding series and book appear in Komga. If folder, filename and cover are insufficient to identify it, use page count and first page too. For a large library, confirm scope with the administrator instead of blindly rescanning everything.

Inspect analysis and metadata separately

If the book appears but will not open, inspect Komga’s actual media-analysis status and error first. Official documentation describes an analysis view for failed or unsupported items. Record container, page count and redacted error. If content opens but title or cover differs, inspect the library’s metadata sources and actual refresh result instead; refreshing a title is not a repair for a damaged file.

Check the same book in ManYue

Open the same connected Komga source in ManYue, find the test book in the same series, compare name, cover and actual page count, and open the first and last pages. Successful Komga scanning, a ManYue listing and readable pages are distinct outcomes. If the server has the correct book but ManYue does not show it, confirm account, source and interface loading state before deleting anything.

Record results and restore the test setup

Record actual scan, analysis, metadata, ManYue listing and page-reading results and times separately, marking actions not run unperformed. For unresolved errors provide versions, redacted sample identity and prompts, not comic content, accounts or server addresses. Remove the test copy under the administrator’s process and confirm originals remain. This exercise follows public documentation and claims no device or private-server test.

Choose a next step using three examples

First, a test CBZ is in the intended series folder but Komga does not list it. Confirm that the folder is under the library root, the account can access it and scanning completed. Komga says ordinary scanning uses folder modification times and some filesystems behave differently; if the book remains missing, the administrator can evaluate a deep scan according to official guidance. Without evidence, do not attribute the issue to the ManYue client.

Second, Komga lists the book but media analysis reports failure or unsupported content. Record the actual error, container and server version and check whether the original archive reliably opens locally. An administrator should confirm the scope before reanalysis. Finding a file during scanning differs from analyzing its images. A metadata refresh does not replace file inspection, and the only original must not be deleted.

Third, Komga opens the complete comic but the title is old. Check the configured metadata sources and whether the relevant file is the expected version, then see whether an administrator needs to refresh that book’s metadata. Komga documents possible sources including ComicInfo.xml inside an archive, EPUB metadata and local media assets, depending on library configuration. Do not edit the only original archive just to change a title.

Confirm ManYue shows the same content

If ManYue still shows an old title after a server update, inspect the current source and refresh method actually present, recording the wait and result. Similar series names or multiple server accounts can exist, so identify the book by cover, page count and a self-made marker. Without evidence, do not assert that caching is the cause or repeatedly delete and change sources. If the title changes but first and last pages still differ, continue recording book content; a title update alone is not complete verification.

If Komga web works but ManYue cannot open the book, confirm the same account and book on both sides, then record versions, steps and redacted error for support. Mark an unobserved status code unknown; without administrator rights do not demand server logs or credentials. Before additional retries confirm the original can be recovered, and change one condition at a time.

Record operation scope

For each task record its target—one book, series or entire library—and whether it was actually run and completed. A queued task is not a completed analysis; wait for the server’s actual result before verification. If task status is inaccessible, mark it unknown and ask the administrator rather than submitting the task repeatedly, and record the check time.
