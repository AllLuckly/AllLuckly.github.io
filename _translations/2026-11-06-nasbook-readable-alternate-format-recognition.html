Book Isle 1.1.4 describes improved readable-version recognition for multi-format books, reducing cases where an existing readable file still leads to an unsupported message. Rather than repeating EPUB/PDF merging, inspect a record that already has multiple formats: its labels, whether alternatives remain present and which file the reading entry actually opens. Manageable does not mean directly readable in the original format, and recognising an alternative does not mean every file was automatically converted.

Confirm the record and content identity

Choose a local record known to contain multiple formats and verify title, author, translator or edition and actual text rather than cover alone. Prefer a small legitimately manageable sample with originals retained elsewhere, recording current primary format and important note anchors. Do not force different translations together or delete the record first. If only one file exists, label it single-format rather than imagining an alternative. Separate remote-not-downloaded from locally present, beginning locally so account, network and recognition do not all vary at once. A clear starting point identifies which file a message concerns.

Read primary and available formats separately

Long-press the book on the shelf and enter its available details page, inspecting primary and available formats. Transcribe labels first. Primary describes the record’s preferred identity, while available formats lists associated files rather than guaranteeing that each opens directly. Record any readable alternative such as EPUB or PDF and its relationship to the primary. If only MOBI, AZW, AZW3, CBR or DJVU appears, shelf visibility alone does not prove direct reading. Names follow the installed version; if the list is absent, confirm you are in details rather than the reading page. Keep identity stable instead of also changing author, cover and categories.

Distinguish a listed format from an existing file

Retain the format list, then open once through the normal reading entry and observe actual content or the error message. A listed item does not prove its local file remains accessible; moving, cleaning or external replacement may leave an association needing inspection. Do not trial-edit database paths or call a blank preview unsupported immediately. If you control the original, check its existence in your file manager and that it is not a directory, retaining name and size as clues without treating them as proof of integrity. Mark inaccessible alternative-file state unresolved rather than concluding the new version lacks recognition.

Identify what actually opened, not just an extension

If an originally non-directly-readable primary has an existing readable alternative, observe whether the reading entry reaches readable content. Verify title, chapter, figures and a distinctive phrase to exclude another volume. Reader appearance may suggest fixed PDF or reflowed text, but it does not establish conversion of the original: an existing alternative may have been used. An already owned AZW3-primary/EPUB-alternative record can illustrate this without requiring readers to generate one. If a message persists, retain its full text and associated formats before troubleshooting rather than repeatedly importing the same batch.

Explicitly select a verified readable format if needed

If details offers a matching switch-primary-format control for EPUB, PDF or another suitable alternative, save important anchors first, select the verified existing readable file and reopen from the shelf. Such a button depends on an associated alternative; not every book has the same choices. Switching selects a file rather than renaming or converting it, and does not align old page ten automatically with new page ten. Use chapter and phrase anchors across formats and preserve correct edition attribution for notes. If no target control exists, do not invent a hidden one. Recheck whether the alternative belongs to this record, retaining a separate file for inspection if necessary.

Separate file, association and parsing failures

If the alternative still fails, distinguish reported missing files, incomplete downloads and unsupported format from corruption, encryption or missing resources, recording only what is actually shown. A known-good EPUB or PDF can be an independent control; its success does not clear the failing book. Keep manageable sources such as MOBI distinct from readable targets such as EPUB. The 1.1.4 improvement does not imply one new parser for every format. If conversion is needed, use authorised originals and appropriate external tools, inspect quality and then decide association. Renaming an extension is not conversion, and the sole original must not be repeatedly overwritten for experiments.

Re-enter and verify recognition and identity

After successful opening, return normally to the shelf and reopen the same record, confirming expected text. Revisit details for unintended changes to primary and available labels. Record an explicit primary switch as your action instead of blaming automatic recognition. Conversely, opening an alternative does not necessarily mean the primary label must change. Compare notes, chapter anchors and edition, without treating different content as one source merely because both files read. Verify one record before expanding to others. For anomalies, retain version, format combination, file-presence state and message before further organisation rather than deleting the book and concealing association problems.

Keep four outcomes rather than one success label

Finish with four separate outcomes: correct record identity, accessible alternative file, readable-format scope and expected actual content. A list entry does not prove existence, existence does not prove successful parsing, and successful opening does not prove edition identity. Retain originals and important notes; make duplicate-file cleanup a later task rather than deleting comparison material during verification. A normal result applies to the current format combination and device, not automatic repair of every old book. Recheck the same small sample after updates and identify the improved or unresolved stage rather than simply saying multi-format now works.
