A heatmap makes distribution visible only when its colour rule is explicit. Build a static matrix from fictional data for three activities across five periods. It does not collect activity automatically; map every colour and value from one source list.

Define rows, columns and measurement scope

List three activities and five periods with one common measure, such as counts over equal durations. Reserve labels and a legend on a 1200 by 700 pixel canvas. Distinguish missing records from confirmed zero values. Complete the data table before choosing colours rather than filling cells by appearance.

Build consistently sized cells

Duplicate one cell into five columns and three rows with consistent size and spacing. Count all fifteen actual cells. Separate fills and numbers for independent editing. Spacing is structural, not a data variable. Check selection scopes before distribution so labels do not move with cells.

Define fixed bins before applying colour

Use four explicitly bounded bins—zero, low, medium and high—with no overlaps or uncovered boundaries. Map higher values to darker related colours. Keep one scale for all rows rather than normalising each independently. Test minimum, boundary and maximum values before colouring every cell, and preserve the legend with the graphic.

Audit every value-colour pair

Enter values row by row, then apply the defined bins and compare each row with the source. Do not invent numbers to match an attractive pattern. Maintain text contrast and keep values associated with their cells. Put a shared unit in the heading if repeated units crowd cells. Audit numbers and colours independently.

Give missing data a distinct treatment

Use an explicit missing-data style, such as grey plus a dash and legend, distinct from zero. Explain missing records without claiming no activity occurred. Verify every blank against the source to rule out omissions. Define any not-applicable state separately while limiting the total symbol vocabulary.

Keep the scale fixed for comparisons

Reuse bins for a comparable second dataset. Handle values above the top bin explicitly and update any affected comparison legends. Keep row order, cell size and units stable. Do not darken a pale-looking second chart merely for impact. Version the dataset and scale together so legends remain accurate.

Check the matrix at its intended size

Save and inspect labels, values and scale at actual size. If too dense, reduce or split the matrix while preserving a common rule. Check pale cells on the intended background and use a backing panel if needed. Keep dataset/scale revisions in filenames and share the full legend with the matrix.

Diagnose suspicious cells through bin boundaries

For an odd cell, check its value and bin boundary before selection/fill errors. Investigate inconsistent row scales without altering data. Repair missing-versus-zero definitions at the source. Audit column order, then sample cells by stating row, column, value, bin and colour meaning.
