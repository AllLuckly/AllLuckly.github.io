Use a video with identifiable chapters to check server chapters, chapter images and seeking or previews visible in iCouldPlay separately.

Prepare a video with identifiable scenes

Choose an authorized short video with visibly distinct scenes around 00:00, 01:00 and 02:00; record its exact duration and the image at each position. Confirm that the file itself has chapters or that chapters can be confirmed in the server interface; otherwise mark them unknown. Preserve the original and do not alter production-video metadata to manufacture an example.

Check server chapters and images first

Jellyfin distinguishes chapters from chapter images: chapters can exist without the image feature enabled, while chapter images are preview metadata corresponding to chapter times. In an authorized server interface, locate the same video and inspect chapter marks and images separately. Seeing marks alone does not establish generated images; images alone do not guarantee iCouldPlay displays them. Record server version, library and observation time.

Understand extraction settings and limits

Jellyfin configures chapter-image extraction per library, and warns it can be computationally intensive and slow scans substantially. If images are absent, first inspect existing configuration and task results; ask an administrator if you lack rights. Do not enable extraction across a large production library, delete caches or change intervals for this exercise. The server administrator decides whether to run tasks. Mark generation untested if not performed.

Observe the iCouldPlay player

Open the same server and video in iCouldPlay and record title and duration, then inspect the playback interface and timeline for chapter marks or thumbnails actually shown. Public information says iCouldPlay supports Jellyfin but does not promise every chapter-image or preview interaction. If no entry appears, record not observed rather than assuming a gesture or button exists. Record confirmed server state and client display separately.

Check the actual seek destination

If the current interface offers chapter seeking, select one recorded chapter and use it once. Compare destination time and image with the recorded scene. If only timeline dragging is available, drag near it but record manual seeking separately from chapter navigation. Preview image, destination time and actual playback frame are three observations; one correct result does not replace the others.

Troubleshoot in layers and restore

If the server lacks chapters, first confirm the selected video and source file. If chapters exist but images do not, inspect the library’s image settings and actual extraction results. If the server has images but iCouldPlay does not display them, record app and server versions and interface observations; do not claim image loss on that basis. Confirm the original video still plays, and record redacted times, settings and untested items without uploading private video or credentials. No device or server test is claimed.

Establish three time anchors

For example, a self-made video shows a red card at 00:00, a green card at 01:00 and a blue card at 02:00. Confirm the actual appearance times during ordinary playback, then check whether server chapter positions match them. Do not assume a scene change automatically creates a chapter. If the server actually has chapters only at 00:00 and 02:00, record those two; the green card at 01:00 is merely a visual anchor.

If Jellyfin displays a blue chapter image at 02:00, record the server’s chapter time and image first, then inspect whether iCouldPlay actually presents the corresponding image. If iCouldPlay shows a timeline mark but no image, record “mark visible, image not observed,” rather than calling the mark a preview image. If neither appears, still separate confirmed server metadata from the client’s current interface.

Why an image and playback frame may differ

A chapter image is a static preview generated or stored by the server for a chapter time; the player frame comes from the actual playback position. If they differ, first check the same video, version and chapter and compare displayed times; use manual seeking to check the known cards if necessary. Do not immediately erase server metadata or claim file corruption. If the source of the difference is unclear, record it as unresolved.

For example, if the server preview is blue but iCouldPlay shows green after seeking, check the actual preview time and the destination time displayed in iCouldPlay. If playback is still loading after one seek, wait for a stable result before recording; if it remains unclear, write unknown. Different video versions can have different chapters, so do not use another version with the same title as the baseline. Playback continuity, preview display and seek accuracy require separate checks.

Protect server resources and private information

Jellyfin warns that a short interval generating extra chapters may affect player and server performance; this exercise does not require changing the default interval for more images. If adjustment is necessary, the administrator should assess library size and maintenance timing and document the original setting and restoration method. Record app and server versions, test date and the three recognizable times, but not signed URLs, accounts or private video. Explicitly say if no extraction was run.
