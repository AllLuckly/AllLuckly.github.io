Check in-book credits, EPUB metadata and visible Book Isle information using a self-made sample.

Identify three information sources

An EPUB can show credits on an internal copyright page and list creators with refined roles in package metadata. Which fields Book Isle displays must be observed. In-book text, structured metadata and client display are distinct; a single name on a shelf does not prove another contributor is absent.

Create an authorized two-credit sample

Use your own short text and fictional example names to write “Author: Lin Example; Translator: Zhou Example” on an internal credit page, then save a self-made test EPUB. Retain original and backup and use a distinctive title; do not use private information or modify protected purchases. Record expected author, translator, filename and credit-page location.

Inspect package credits

In an EPUB editor inspect creator or contributor metadata; internal credits do not automatically create metadata entries for both people. If the editor permits it, add separate author and translator entries to the working copy using its actual controls and confirm their values; mark entries that cannot be added as not established. A role refinement can apply to either creator or contributor. Verify that each refinement points to the appropriate item identifier and uses a vocabulary and value consistent with the editor or specification. Display-name order alone does not establish roles.

Compare the internal credit page

Inspect in-book credits and confirm names, roles and order match the sample record. The page is reader-visible content and metadata is separate structure; correcting one does not necessarily update the other. If only one field changes, note that in the worksheet so a deliberate difference is not later mistaken for an import error.

Validate and save a copy

Run EPUBCheck or the editor’s checks for package structure, resources and metadata references, retaining the report. Save a working copy without overwriting the original. Validation does not establish that credits are true or that a reader displays every role. For a published book, check credits with a legitimate source rather than guessing or rewriting contributions.

Import and identify the book

Import the sample using Book Isle’s actual available method and confirm its distinctive title and chapter text; record app version, device and import messages. If the shelf does not display a filename, use the self-written text to identify it. For import failure, check permissions and file integrity before clearing the shelf or deleting books.

Record visible book information

Observe names and field labels wherever the current shelf or book details actually make them available and record them accurately. Mark an absent entry unavailable or not found. Do not assume Book Isle must separately display author and translator or say an undisplayed name was removed from metadata. Keep private library contents out of screenshots and notes.

Open the internal credits

Read the sample’s credit page and verify whether both names and roles are visible in the content. If a contents link is available, navigate using the actual interface; a label alone does not establish what the page contains. Put the internal credits and interface display in separate table columns, even if the shelf displays only one name.

Trace an inconsistency

If names differ, compare the imported file, metadata values, role-refinement targets and credit-page text, then confirm the device has not opened an older copy. If metadata is correct but the interface omits information, record actual display without immediately concluding the file was modified. Correct one item at a time in an authorized copy, validate and retain both results.

Finish records and preserve credits

The table includes package entries, roles, internal credits, visible interface, app version and reasons for unperformed steps. Do not publish private paths or alter the original credits of a published book. Identify the test book before deciding whether to remove it; retain original, backup and validation report. No device test is claimed.

Retain context for role vocabularies

If the editor supports contributor roles, record its vocabulary name, role value and referenced person, then compare with EPUB metadata documentation. Do not guess that an abbreviation means author or translator; mark the value unknown if the interface does not show it. Modify self-made samples using a specification-supported method and keep before-and-after copies and reports.

Check contributors sharing a name

If two sample contributors happen to have the same displayed name, distinguish each metadata entry by its identifier and role reference rather than comparing text alone. Start with distinct fictional names; create another copy and label it an edge case if testing same-name contributors. The internal credits should also explain each role to avoid confusing readers.

Track versions when retesting

After correcting an author or translator entry, save a distinguishable copy, validate it and decide whether the internal credit page also needs updating. After reimport, identify the version through its distinctive title or text before recording display. If the app retains an old entry, preserve the import message rather than guessing. Do not rewrite original credits or delete real shelf contents to troubleshoot. Record the date and editor version for each pass so the tested copy can be identified later.
