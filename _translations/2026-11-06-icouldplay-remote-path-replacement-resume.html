An unchanged remote path and filename can hold re-edited or different media. Existing directory metadata, duration or resume position in iCouldPlay may not establish current identity. Compare recoverable self-made samples without overwriting a shared server file. For an actual change, inspect source and content read-only rather than assuming how the app identifies same-path replacements.

Preserve the old record and scope

Record source type, authorised directory, displayed filename, old duration, resume time and a content anchor without exposing private full addresses. Inspect only permitted items and do not request extra write access. Without an actual replacement, use separate recoverable self-made A/B clips to compare identities instead of overwriting a server. Preserve originals, notes and the usable viewing entry. Focus on stale remote directory/progress, not local same-name imports or whole-library copying.

Check whether the source actually changed

Use an existing trusted source entry or explicit administrator notice to record modification date, size, duration and version clues. Copying can change dates, so date alone is insufficient. A path does not establish byte identity or unchanged internal server identity. Mark inaccessible originals unexamined rather than bypassing restrictions. If two local samples are readable, follow the existing checksum guide separately; differing bytes do not identify the edited scene. Separate confirmed, suspected and insufficiently evidenced change before attributing playback issues to replacement.

Compare list information with actual playback

Open the original directory entry in iCouldPlay, recording card duration, title and source before playing opening and a middle anchor. Equal posters do not identify old content; unchanged card duration can reflect unmatched metadata. Use an actual documented source/directory refresh only for the needed scope if offered, then recheck. Otherwise preserve observations instead of inventing a cache shortcut. Do not delete libraries, rebuild all indexes or duplicate remote files to create an entry. Keep metadata and media-content evidence separate.

Treat the old resume time as unverified

Do not accept Continue Watching as proof of restored content. Save old time and scene/teaching anchor before determining edition. In an invented sixty-second A and forty-five-second B, thirty seconds exists in both but may show unrelated material; a time beyond the new duration is invalid too. After identity checks, use ordinary seeking and playback from before the anchor. Preserve historical note times and separately map the new version, retaining any unmatched portions.

Recheck captions, tracks and chapters

After content changes, check audio language, external-caption edition and beginning/middle/end matches rather than trusting equal caption filenames. Insertions or cuts can create global or segment-specific timing differences; inspect content instead of subtracting one number from every cue and declaring repair. If chapters exist, check title and entered scene rather than assuming old mappings. Use visible controls without claiming server-caption editing or automatic chapter recalculation. Preserve original captions and media until accurate continuation is established.

Distinguish a local copy from current remote content

If playback still resembles the old edition, identify remote entry, acquired local copy or a namesake in another source from actual UI and records before deleting caches. A changed remote need not update an old local copy, and a new local file does not prove remote indexing updated. Limit conclusions when only one is accessible. Log duration and content anchors per entry, using distinct A/B sample names where helpful without overwriting production objects. This identity check requires no removal of unknown-purpose app files.

Leave and reopen to verify new mappings

Leave player and directory, re-enter the same authorised entry and verify title, actual duration, content anchor and selected captions. Retain old history and label the new resume mapping with edition and check date rather than erasing the change. If old imagery returns, log entry and observation and check for an old copy instead of repeatedly clearing the library. Investigate actual server behaviour through appropriate administrator/service information; no replacement or guaranteed refresh mechanism was executed here. Restore the intended edition and position afterwards.

Finish separate identity and progress conclusions

Keep old identity, current content evidence, usable resume mapping, captions and unexamined portions. Paths are not content identities, equal thirty-second positions can differ, and clearing records loses evidence without proving source refresh. If identity remains unclear, stop using old progress and retain originals/notes for investigation instead of deleting sole recoverable copies. Limit conclusions to inspected entries/editions; comparing self-made files is not a claimed same-path overwrite test on a private server.
