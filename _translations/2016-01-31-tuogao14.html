"CoreText is an advanced, relatively low-level technology for text layout and font handling. Its API was introduced in OS X v10.5 and iOS3.2 and is available in both OS X and iOS.:"


For requirements that are not especially complex, UILabel and UITextView usually suffice. Apple has wrapped text display for us in these controls. More complex cases include mixed images and text, recognizing links and replacing them with “Click link,” binding @someone mentions, recognizing phone numbers, and mixing text sizes. UIWebView can handle these too, but CoreText uses less memory and can render in the background, making it well suited to content layout. CoreText is highly flexible, although using it is more involved. When learning a technology, why not tackle the hardest part?

Before learning CoreText, you need to understand attributed strings: NSAttributedString or NSMutableAttributedString.

NSAttributedString and NSMutableAttributedString
NSAttributedString is a string with attributes. It lets you manipulate and display text in a variety of styles flexibly.

You can define the attributes in advance and then apply them to the text.

If we could only apply the same attributes to all the text, attributed strings would not be very interesting. We can assign different attributes to a portion of the text.

We can apply different styles to text at different positions, using NSRange to specify the range. NSRange is a structure with location and length fields; together, they uniquely identify a substring.

Which attributes can we set?

  • NSFontAttributeName sets the font. Default: Helvetica(Neue), size 12.

  • NSForegroundColorAttributeName sets the text color using a UIColor object. Its default is

  • NSBackgroundColorAttributeName sets the text area's background color using a UIColor object. The default is nil, meaning transparent.

  • NSLigatureAttributeName sets ligatures using an NSNumber integer: 0 disables ligatures; 1 uses the default ligatures.

  • NSKernAttributeName sets character spacing using an NSNumber integer. Positive values increase spacing; negative values decrease it.

  • NSStrikethroughStyleAttributeName sets the strikethrough style using an NSNumber integer.

  • NSStrikethroughColorAttributeName sets the strikethrough color using a UIColor object. The default is black.

  • NSUnderlineStyleAttributeName sets the underline using an NSNumber integer from the NSUnderlineStyle enumeration, similarly to strikethrough. NSUnderlineColorAttributeName sets the underline color using a UIColor object; the default is black.

  • NSStrokeWidthAttributeName sets the stroke width using an NSNumber integer. A negative value produces filled text; a positive value produces outlined text.

  • NSStrokeColorAttributeName specifies the fill-part color rather than the text color, using a UIColor object. NSShadowAttributeName sets shadow attributes using an NSShadow object.

  • NSTextEffectAttributeName sets a special text effect using an NSString. Currently, only the letterpress effect is available:

  • NSBaselineOffsetAttributeName sets the baseline offset using an NSNumber float. Positive values move it up; negative values move it down.

  • NSObliquenessAttributeName sets glyph slant using an NSNumber float. Positive values slant right; negative values slant left.

  • NSExpansionAttributeName sets horizontal text expansion using an NSNumber float. Positive values expand the text horizontally; negative values compress it.

  • NSWritingDirectionAttributeName sets the writing direction, either left to right or right to left.

  • NSVerticalGlyphFormAttributeName sets the text-layout orientation using an NSNumber integer: 0 means horizontal text and 1 means vertical text.

  • NSLinkAttributeName sets a link; tapping it opens the specified URL in a browser.

  • NSAttachmentAttributeName sets a text attachment using an NSTextAttachment object, commonly for mixing text and images.

  • NSParagraphStyleAttributeName sets paragraph layout using an NSParagraphStyle object.

There are too many attributes to remember. Google their usage when needed—they are powerful! 😄

That is enough about attributed strings. They are sufficient for simple rich text. Now let us turn to the main topic: CoreText.

CoreText

Attributed strings style text, whereas CoreText lays it out. You can customize each line's height, the space occupied by each character, and more.

CoreText is a low-level technology for working with text and fonts. It interacts directly with Core Graphics, also known as Quartz, a 2D rendering engine. Quartz can process fonts and glyphs directly to render text on screen; it is the only module in the foundational libraries that handles glyphs. For layout, CoreText therefore passes the text, positions, fonts, and glyphs directly to Quartz. This direct interaction gives CoreText fast layout performance compared with other UI components.

Let us look at a diagram of the CoreText object model.


First, a somewhat dry explanation; examples will follow. 🌰

In the diagram, Framesetter corresponds to CTFramesetter. It is initialized with a CFAttributedString; NSAttributeString can also be bridged seamlessly. It acts as a factory for CTFrame objects, producing a frame for the supplied path. CTFrame can be drawn directly into a context with CTFrameDraw. Before drawing, you can also manipulate its CTLine objects to fine-tune parameters. A CTLine represents one line of Core Text drawing. It provides the line ascent, line descent, and line leading, as well as all the line's Glyph Runs. CTRun, or Glyph Run, is a collection of glyphs sharing the same attributes. CTFrame represents the drawing area of the entire UIView subview; CTLine represents a line; and CTRun represents a string segment with identical attributes. For example, a string with a consistent font size and color forms a CTRun. A CTRun cannot cross a line boundary, regardless of whether attributes match. Typically, each CTFrame contains several CTLines, and each CTLine contains several CTRuns.

CoreText was originally designed as a desktop typesetting system, so it uses the traditional coordinate system with its origin at the bottom-left. Its text drawing is therefore relative to that bottom-left origin.


If you draw with CoreText directly in this context without any adjustment, the text will appear mirrored and upside down.

Mixing images and text

CoreText would be rather uninteresting if it could only define text-drawing areas. It also supports mixed text and images, including both local and remote images.

CoreText still uses NSAttributedString when moving from plain text to images. An image is represented by a blank-character placeholder in NSAttributedString. A delegate tells CoreText how much width and height to reserve for that character. Finally, draw the image in the reserved position.
