As a library grows, some works simply need to leave everyday view without deleting their files or reading records. The public release notes for ManYue 2.0.2 include hiding and restoring for organization. This guide hides one sample, then restores it from the hidden list to confirm that this changes presentation rather than clearing storage.

First decide why you want to hide the work

Good reasons to hide a work include finishing it but wanting to keep it, temporarily setting aside a long series, or keeping an alternative edition outside everyday browsing. Start with a sample you can find again, and note its title, source, current chapter, and favorite status. Do not begin with the entire library; a small test makes restoration easier to verify.

Hiding does not back up the original file or encrypt its content. For device access protection, use protection actually provided by the system and app. To free storage, manage caches or local copies. Keeping these three goals separate prevents assuming that a hidden item has been deleted or that all privacy concerns have been addressed.

Hide one work through the organization menu

Find the sample in the library, open its work menu or “Organize Comics,” and choose “Hide from Library” or the current equivalent. Before applying it, confirm the selected source edition, especially where multiple servers contain the same title. Return to the normal library and confirm that the item no longer appears.

If source, group, or reading-status filters are active, note them first so their effects are not later mistaken for hiding. Temporarily return to the full scope to verify, then restore your usual filters. Hiding primarily changes the normal display scope; it needs no new download and should not change the original file's page order.

Open a hidden comic and check what was retained

Find “Hidden Comics” in the library menu, then search or browse for the sample. The page explains restoration actions. First confirm that the title, source, and record still correspond to the original work. If a local copy exists, open it and check the original chapter and page to confirm that the reading content remains available.

For online sources, a server going offline or a source expiring may stop pages loading even though the hidden record remains. This is separate from hiding; restore access to the original source first. Temporarily inaccessible online content does not mean record retention failed. Verify records and content-file availability separately.

Restore to the normal library

Select the target work in the hidden list and use “Restore to Library.” Return to the normal library, find the sample, and confirm that it reappears, then open it to check the reading position. You can also return to the hidden list and confirm that it has left, completing the before-and-after comparison.

If it does not appear immediately, clear extra filters in the normal library and confirm that the current source scope includes it. Restoring does not make the work match every filter or guarantee that the list will scroll to its position. Searching the exact title is usually easier than repeatedly restoring it because it is absent from the first page.

Check the selected set before bulk organization

Once familiar with the single-work process, use multi-selection to organize two or three similar works. Check the selected count and actual titles rather than assuming that the visible cards define the selection. Some bulk capabilities require an entitlement; use the entry points currently available. Without bulk tools, hiding works individually achieves the same presentation goal.

Afterward, spot-check each work in the hidden list, then restore one to verify the way back. For a large list, work source by source to avoid hiding both an actively followed edition and a backup edition at once. Deciding which content belongs in daily reading and which only needs archiving is more useful than a broad “Select All.”

The difference between hiding, removing from Continue Reading, and deleting

Hiding affects library presentation; removing from Continue Reading mainly organizes the resume list; deleting reading history affects this device's reading position and read records; deleting a local copy concerns file storage. These actions may appear near one another in an organization menu, but their consequences differ. Read the specific explanation before acting.

If you only want fewer covers on the home screen, you usually do not need to clear all history. Conversely, hiding many works does not free content-file storage when the device is running out of space. Choose the action that matches your goal, then verify it in the library, history, or system storage as appropriate. One list changing does not prove that all data changed.

Frequently asked questions

Are favorites and progress retained after hiding? The public feature description says hiding and restoring organize the library while retaining files and reading records. Still test one sample in your current version, and remember that the source determines whether online content is accessible; hidden status does not guarantee it.

Why is the work still absent from the library after restoring it? First check source, group, and status filters, then search the full title. Restoration may have succeeded while the current view still excludes the work, or you may have opened a same-named work in another connection. Checking the source reduces repeated actions.

Is hiding a private mode? is not access authentication or file encryption. Someone who can enter the hidden list may still see those items, and exported files are not controlled by this display state. For device access protection, use the appropriate system or app features rather than relying on a temporarily invisible card.
