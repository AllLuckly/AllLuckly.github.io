The public release notes for 调调 1.0.4 mention improved WebDAV connection and library browsing. When two folders are both named “Demo,” the name alone cannot identify the target. Establish the authorized service root, then record each path and actual audio item.

Prepare authorized folders

In a WebDAV area you manage or may use, identify two accessible paths, for example “Work/Demo” and “Travel/Demo” under the service root. Each contains an authorized short recording with a distinguishable opening sound. If you cannot create folders, use existing authorized same-name folders; changing a shared service is not required. Preserve the originals and folder relationships, and record parent folders, track names and durations. These examples explain hierarchy; they do not imply the app supplies a sample server.

Draw a credential-free path card

Write “Service A → Work → Demo → Track A” and “Service A → Travel → Demo → Track B.” Service A is a private mnemonic, not the server address. Do not publish passwords, tokens, full internal addresses or another person’s library. Confirm your account can read each path. If only one is permitted, complete that baseline and mark the other as insufficient permission rather than assuming it was deleted.

Identify the connection and visible root

Open your existing authorized WebDAV source in 调调. Confirm service and account, then record the first visible directory level. The configured user root may already be a subdirectory, so the root shown in the interface need not be the server’s disk root. Start the path card from the actual visible point; do not assume every account sees the same folders or entry point. For connection failures check your own network and permissions without disabling security or exposing the service to the internet.

Walk the first path

From the visible root, select Work and then its Demo subfolder, recording the parent and current folder at each step. Find Track A, verify title, duration and playback source, and play briefly at a suitable volume to identify the cue. If the actual labels differ from the example, use the real labels and your recorded hierarchy. Stop when identity cannot be established instead of recording a guessed path. Directory visibility, file display and playback are separate observations.

Return and walk the other path

Use the interface’s actual back control to return to a confirmed common parent, then enter Travel and its Demo subfolder. Verify you left the first path rather than opening it again. Find Track B and check title, duration, audible cue and parent folder. Same-name directories may legitimately contain different material. Do not rename, move or delete shared folders to eliminate the ambiguity.

Compare path, metadata and sound

Make two columns with service alias, visible root, parent, child folder, title, duration, opening cue and actual playback. Matching title and duration still do not prove byte identity; if that matters, compare authorized copies using the same hashing method. If the interface does not show a real file path, record only the observed navigation rather than inventing an absolute server disk path.

Distinguish collections and individual resources

WebDAV collections can contain other resources, but a display name is not automatically a globally unique identifier. A client can map the server address to a different user-visible root and can present names, order or cached lists differently. Do not assume a percent-encoded address, server folder and displayed title must be textually identical. If needed, verify the path through your authorized server interface or documentation. A stale app list alone does not prove a server file disappeared.

Troubleshoot and preserve the original state

If a same-title track sounds unexpected, first compare the original clips to ensure the cues were not reversed, then return to a known parent and walk the path again. If both are copies of one recording, sound cannot distinguish their sources; use verified navigation and service alias. When identity remains unclear, mark the source pending rather than editing metadata or replacing originals to fit expectations. At the end check your authorized originals remain in place.

If only one Demo appears, check parent folder, account permission and whether you remain in the first path. If the folder is visible but a track is missing, inspect the account’s read scope and server index; if visible but silent, check output, audio format and network separately. Change one condition per trial. Restore output, volume and queue without modifying others’ directories. Deliver a sanitized path card and comparison table with unfinished checks. No private-server or physical-device test is claimed.

Record the actual observation date and app version for later checks.
