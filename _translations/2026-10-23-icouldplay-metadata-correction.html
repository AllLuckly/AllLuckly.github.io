Do not rush to delete a library card with the wrong poster. Its metadata may simply be mismatched, or it may be a same-name file from another source. When iCouldPlay connects to local storage, file servers, and media servers together, identify the card's source first to determine where the correction belongs.

First identify exactly which file is playing

Open details from the incorrect card and record the source, title, year, and duration, then play a short familiar passage. If the picture is actually another movie, check the file or selected source first. If the content is correct but the poster is wrong, address the metadata. These require different changes; the cover alone cannot determine the cause.

The same title may exist as a NAS original, local copy, and media-server entry. Their names may be similar while paths, editions, and viewing records differ. Search within one source first to reduce confusion from multiple parallel results.

Keep a brief record, such as 'Home SMB source; video content is correct, but year and synopsis belong to the remake.' This points directly to metadata matching and is easier to act on than 'the whole library is a mess.' You do not need to disclose private directories or server addresses; you only need to be able to locate the entry yourself.

Separate missing metadata, wrong matches, and version differences

Missing metadata This typically appears as a missing poster, blank synopsis, or absent year. Check network and metadata-loading status first rather than assuming a missing image means another title was matched. The app's ability to play a file does not guarantee access to the remote image service.

Wrong work selected means that the poster, year, and plot clearly belong to another work. Check same-title films, differences in translated Chinese titles, and confusion between movies and television first. Comparing these details together establishes identity more reliably than changing only the cover.

Version differences This commonly occurs with director's cuts, extended editions, and regional releases. They may belong to the same work while differing in duration or footage. Public databases may not provide a separate entry for every file version, so retain necessary edition information in your own filenames.

Check the title-and-year combination

Return to the file's directory and inspect its actual name, not just the title displayed in the library. Use a complete, stable movie title and verify its release year. A download date, restoration date, and original theatrical release year may differ. The number in the filename affects the identification clues.

For a film with several translated titles, choose a commonly used name that clearly identifies the work for your sample check instead of joining every alias into a long string. Change only one clue at a time—for example, correct the year first and then see whether the wrong work is still selected.

For specific filename conventions, see Organize movie titles and years. Test on a copy first, confirm that the organization improves the result, and only then consider bulk changes to files already in the library.

Check server entries on the server

If the entry comes from Emby, Jellyfin, or Plex, inspect its title, year, and match in that server's management interface first. If the server already shows incorrect information, correct it there first. After iCouldPlay retrieves the metadata again, check that it matches the server.

If the server is correct but iCouldPlay shows old metadata, confirm that you are connected to the same server, library, and record, then use the refresh method provided by the current interface. Do not mistake another local copy for a server update that failed, or delete the original movie simply to force metadata to change.

If a server account can access only some libraries, its search results may differ from an administrator's. Check the current account's visible scope before comparing records. A movie appearing in server management does not mean the account used by iCouldPlay is authorized to read it.

Watch for existing records when scanning file sources

For local, SMB, and WebDAV file sources, scanning primarily discovers files and organizes metadata. An entry that already has matching information may not be rematched on every scan. 'Scan again' is therefore not a universal action guaranteed to correct every error.

If your version explicitly provides a rematch or metadata-editing entry point, start with one sample and verify the candidate's year, type, and synopsis before confirming. If the entry point is absent, do not search for a similarly named button based on another app's tutorial. Organize the source filename first and keep a record of the error for feedback.

You can test naming with a copy in a separate test directory, but remember that it may become a new entry without automatically inheriting the original viewing position. Keep the original record until verification finishes. In particular, do not experiment by deleting a local entry, because deletion may also affect the actual video file.

How to verify that a correction is complete

Return to the original problematic source and entry, then inspect the title, year, poster, and synopsis. Play a known scene to confirm that it is still the original file. A corrected image with an incorrect synopsis means the metadata is not fully aligned. If the played content changed, recheck the path and source.

For shows, also check whether seasons and episodes belong to the correct series, not just whether the season poster looks right. For episode files, continue with Season and episode naming. If one directory mixes movies and shows, organize its scope before checking categories.

Finally, check that viewing progress remains and external subtitles can still be found. Open the video to verify associations after renaming or changing sources. Record the naming pattern that worked and reuse it for similar additions; this saves guessing from a wrong poster every time.

What to do when no matching metadata is found

Short films, family recordings, or obscure editions may have no matching public metadata. Keep a clear filename and play them normally rather than filling the gap with a movie that 'looks close enough.' Your library's first job is to help you find your content; metadata completeness can improve gradually.

For feedback, provide the title, year, source type, characteristics of the incorrect metadata, and what you tried. Account information is unnecessary. Information checked on October 23, 2026, against public iCouldPlay version 1.1.0. See Official App Store description and Apple release information.
