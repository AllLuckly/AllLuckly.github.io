WebVTT NOTE blocks can hold editing comments, but boundaries and actual parsing need checking. Edit a self-made sample externally and observe it in iCouldPlay. This does not claim in-app comment editing, collaboration or automatic hiding of arbitrary text.

Use comments without private information

Copy a working VTT or create a practice file for a self-made clip at least ten seconds long. Use neutral text such as practice checked rather than names, private server addresses or accounts. A comment is file text, not a confidential container: sharing the file shares the comment. Keep the original and a comment-free baseline; change comments alone, not media or timing.

Build a minimal file with blank boundaries

The NOTE block below ends at a blank line before the first cue. Save plain text without the Markdown fence markers, and do not join NOTE and the timing line into one block. Non-overlapping cues keep boundary errors separate from simultaneous display.

WEBVTT

NOTE practice checked
This comment is not a caption.

00:01.000 --> 00:03.000
Open the notebook

00:05.000 --> 00:07.000
Keep the original

Identify three roles in the source

Identify the header, NOTE comment and two timed cues in the external editor. NOTE introduces a comment block rather than naming an ordinary cue; timing lines swallowed into that block should not be expected to remain active cues. List two expected captions and the text that should not be dialogue. These format expectations still require playback; saving a file does not establish player success.

Check captions and the gap by playback

Load the practice captions and play from the start through eight seconds. Record the one-to-three and five-to-seven second intervals and any comment residue between them. One correct cue at six seconds is insufficient. If the installed version rejects the VTT, record that outcome and return to a known-working sample rather than claiming support. Use visible subtitle controls without unfamiliar parsing plugins.

Compare a comment-free copy

Make a differently named copy removing only NOTE, its comment text and surplus blank lines. Keep the header and timed cues, select it and replay the same intervals. If only the copy works, inspect boundaries and selection before attributing everything to missing comment support. Do not convert formats for this comparison: that changes too many variables and obscures the boundary being examined.

Find cues swallowed into a comment

If the first cue disappears, inspect a missing blank after NOTE that may absorb its timing and payload. If comment text appears, inspect whether it was pasted beneath a cue’s timing line. Keep a labelled erroneous copy and replay a corrected copy rather than repeatedly editing the only production captions. Confirm the second cue survived too. Record the exact moved line or inserted blank instead of merely saying resaving fixed it.

Inspect the file before sharing

Keep the corrected source, comment-free control, observed output and installed version. Before sharing, inspect every comment externally: invisible onscreen does not mean unreadable to recipients. Restore the normal viewing captions and separate practice filenames. W3C WebVTT supplies NOTE and blank-boundary rules; this is neither a privacy-erasure guarantee nor acceptance testing of every engine.

Distinguish the block introducer from an ordinary word

Use uppercase NOTE at the beginning of a new block followed by a space and comment. Do not assume lowercase note or NOTES has identical syntax, or that “take a note” in dialogue becomes a comment. Preserve case and line position without input-method symbol substitution. A second comment could be a separate NOTE block, but complete this one-block baseline before adding complexity.

Inspect the actual saved text

An editor may save rich text or append TXT to a visible VTT name. Close and reopen the saved file from its location to inspect the header, blanks and arrows as plain text before loading. A window title does not prove the right file reached disk. If a share sheet only previews content, inspect the final exported file rather than a draft screenshot. Check both copies so two names do not refer to one unsaved document.
