Compare episode numbers with actual scenes first, then inspect Kodi provider ordering and playback identity in iCouldPlay.

Prepare two episodes and content anchors

Choose two authorized episodes from the same show and record filenames, durations, openings and a nonprivate plot anchor for each. First play them on the server or in Kodi to confirm each file’s content; do not identify story order from S01E01 filenames alone. Preserve the originals and stop before changes if edition and source cannot be established.

Compare public information for each order

Kodi documents that some shows have different aired and DVD or Blu-ray orders and that providers offer alternate orders differently. Inspect the show’s actual episode numbers, titles and ordering in the current provider, recording which content corresponds to each aired and disc position. If one order is unavailable, mark it unknown rather than filling the gap by inference.

Inspect the actual Kodi configuration first

In an authorized Kodi installation, record the library type, information provider, displayed order and the two episode titles. Kodi documents that order configuration differs by scraper and can depend on version and show settings; do not assume all interfaces have the same switch. If you are not the library administrator, ask the administrator rather than changing a shared show library.

Check displayed titles against actual video

Open both episodes in Kodi and compare each displayed number, title and duration with the recorded scene. A correct title, number consistent with the selected order and correct video are separate results. If episode one plays content belonging to another order, record the file-to-provider mapping first. Do not immediately batch rename or refresh the whole library.

Observe the same source in iCouldPlay

In iCouldPlay open the same connected Kodi source and locate the show and two episodes. Record displayed titles, numbers and order, then play each opening and compare with the known content anchors. Public information supports Kodi libraries but does not promise a client order switch or exposure of every server setting. If no option actually appears, record not observed rather than inventing a button.

Act only after confirming the impact

If Kodi and iCouldPlay agree but content differs from expectations, ask the administrator to inspect the provider and file numbering. If Kodi is correct and iCouldPlay differs, record versions, entries and actual scenes on both sides. Only with an independent backup and an understood scraper and refresh impact should the administrator decide on changes. Do not alter the entire library or overwrite videos for one problem. Confirm originals remain and retain redacted notes. No device or server test is claimed.

Map the two orders in separate ledgers

Suppose a self-made series has episodes “Arrival” and “Departure,” with each test file displaying its name at the opening. Provider A’s aired order lists “Arrival” first, while provider B’s disc order lists “Departure” first. Write both mappings, then list the server’s actual filenames and openings; the same number can refer to different content under different orders. This example illustrates mapping and is not a claim about an actual show.

If Kodi currently displays aired-order data but the file named S01E01 opens with “Departure,” record the mismatch between displayed item and file content. Do not rewrite metadata solely because the filename says episode one or declare the file wrong from a title alone. Confirm file provenance and that the provider actually has the corresponding order before an authorized administrator decides on a remedy. The ledger can use redacted A and B identifiers without sharing video.

Check the provider’s scope

Kodi documents different methods of alternate ordering for different providers. Record the installed Kodi version, actual provider and current show configuration, then consult that provider’s documentation and data. If an order has no data, do not promise that switching will make it available. Plugin, version or individual-show settings may affect the result. Do not try different plugins on a shared source without authorization or repeatedly refresh merely to change a title.

If an administrator decides to compare configurations on an isolated sample, record original settings and mapping first, change one condition and follow that provider’s documentation for any required refresh. Afterwards check metadata titles and actual file content separately; if the result deteriorates, restore the test settings from the record. If an option is absent from the actual interface, mark it not observed rather than applying another scraper’s switch.

Hand off a client difference

Suppose Kodi shows “Arrival” as episode one and plays “Arrival,” while iCouldPlay shows the same title but plays “Departure.” Record the navigation path, selected number, opening, duration and both versions, then confirm both truly connect to the same server and show. Different servers cannot be treated directly as a client discrepancy. Do not publish server addresses, accounts, media files or private viewing history.

If Kodi itself mismatches title and video, investigate server-side first. If an entry is absent from iCouldPlay, record not observed rather than claiming that ordering was rewritten. In either case mark any refresh, rename or playback not actually performed as unperformed. Confirm both originals remain available, and preserve the pretest mapping and administrator-confirmed restoration method.
