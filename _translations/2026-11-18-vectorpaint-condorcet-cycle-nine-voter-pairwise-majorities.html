Make a three-option pairwise-comparison diagram. Every individual ranking is complete and transitive, yet aggregated strict majorities can cycle. All nine voters and rankings are fictional mathematical inputs, not polling data or evidence for a real voting strategy. Counts are primary; triangle arrows display the comparison relation.

Declare equally weighted complete strict rankings

Options are A,B,C. Each fictional voter has weight 1 and a complete strict ranking without ties or abstention. Groups are 2 voters A>B>C,3 voters B>C>A,4 voters C>A>B, totaling 9. Display group sizes 2/3/4 rather than count three groups as three equal ballots. Create ranking-table, pair-count, relation-arrow and control layers; save native work. Individual rankings are acyclic; the object tested later is the aggregated majority relation, not an individual preference.

Compare A versus B using every group size

For A versus B, group 1 contributes 2 to A, group 2 contributes 3 to B, and group 3 contributes 4 to A. Thus A wins 6:3, so the strict-majority arrow is A→B. C’s position gives no extra ballot in this pair, and C-first voters still rank A relative to B. Every pair must total 9. Keep group contributions and verify the total before drawing. First-choice counts 2,3,4 describe another rule, not this pairwise comparison.

Check B versus C and C versus A separately

For B versus C, groups 1+2 give B 2+3=5 and group 3 gives C 4: B wins 5:4. For C versus A, group 1 gives A 2 and groups 2+3 give C 3+4=7: C wins 7:2. List each winner-first pair with option names, preventing a5:4 label from migrating to C→A. A ballot contributes once per pair, without multiplying group size by rank. Recover every result from rankings instead of choosing a cycle first and fitting counts afterward.

Use the cycle to test for a Condorcet winner

A beats B, B beats C, C beats A: a directed three-cycle. Under this lesson’s strict definition, a Condorcet winner must beat every other option by a strict pairwise majority. A loses to C, B to A, C to B, so none qualifies. This does not mean no rule can select an outcome or that individual rankings contradict themselves. First-choice counts are A 2, B 3, C 4, so plurality would choose C, which still loses pairwise to B. Keep rule-specific outputs in separate columns. Do not multiply majority margins or treat arrows as transition probabilities: each edge summarizes a different pairwise question on the same rankings, with no random state-update rule.

Draw relation arrows from winner to loser

Use a suggested 2200×1600 canvas, ranking rows at Y=200–550 and nodes A=(650,850),B=(1550,850),C=(1100,1350). Direct all arrows winner→loser, labelled 6:3,5:4,7:2 with pair names. These are relations, not time, causality or geography; spacing does not encode margins. Draw thin arrows before labels and check one incoming/one outgoing edge per node. A loser→winner convention would require a new global declaration, not a local reversal under the old legend.

Change only group sizes to obtain a winner control

Keep the same three ranking types but save group sizes 5,3,1, still 9 equal voters. A beats B(5+1):3=6:3; A beats C5:(3+1)=5:4; B beats C(5+3):1=8:1. A is now a Condorcet winner, so three options do not inevitably produce a cycle. Change only group sizes, not rankings or arrow conventions, and retain total 9 per pair. This is a mathematical control, not advice for mobilizing, manipulating or improving real election outcomes.

Diagnose counts with totals and expanded ballots

If a pair total differs from 9, check omitted/duplicated groups. If totals agree but directions differ, expand 2/3/4 groups into nine ballots and inspect relative order. Arrows all favoring plurality leader C may indicate confusion between rules; calling the cycle individually intransitive confuses aggregation with ballots. Change one step and retain versions. Ties, abstention or unequal weights require new definitions/counts. One fictional profile proves possibility, not real-world cycle frequency or a group’s enduring preference.
