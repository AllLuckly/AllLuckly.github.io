When a movie description differs from its NFO, check which tags map to the same field, then observe the server web interface and iCouldPlay separately.

Define the boundary

Jellyfin can read local NFO metadata. Its documentation states that plot and review map to the same internal field and, when multiple tags map to one field, the last tag in the file takes priority. This is a server rule, not an iCouldPlay editing feature. Use an authorized isolated test library to inspect the web result, then observe whether iCouldPlay displays the same description. Do not assume immediate refresh in every client.

Prepare an isolated test movie

Use a short self-made or authorized video, with Test Movie (2030) as an example folder and filename. Ask the administrator to put a video copy in a separate movie library and prepare movie.nfo in the movie folder. Leave production films, original NFO files and images untouched. Without administrator access, ask the administrator rather than scanning an unfamiliar server. The title and year distinguish the test and do not identify a real film.

Record the initial state

Write an alias for the server and test library, the account, app version, time, and the title and description visible on web and iCouldPlay. Exclude real paths, passwords, tokens and private URLs from shared records. Confirm both interfaces open the same test film. If similar names make identity uncertain, compare the opening picture and duration.

Create two distinct candidate values

Have the administrator create a test movie.nfo in a plain-text editor with title, plot and review inside a movie root. Use “blue square” for plot and “red dot” for review, making the values distinguishable. Close the tags, use UTF-8 and place review after plot. Back up the test folder first. Do not paste a real NFO containing private information into the example.

Check the sample file

This self-made sample contains identifiable markers, not a review of a real movie:

<?xml version="1.0" encoding="UTF-8"?>
<movie>
  <title>Test Movie</title>
  <plot>蓝色方块</plot>
  <review>红色圆点</review>
</movie>

Confirm the name is movie.nfo, not movie.nfo.txt. Put the video and NFO in the same test movie folder. Leave other metadata settings alone initially and keep the prior version.

Predict and check the web result

Under the documented same-field rule, the expected description after reading this file is the last review value, “红色圆点” (red dot). Ask the administrator to scan or refresh the test film using the normal method for their server version, wait for completion and inspect the web interface. Record the displayed value and refresh method. If it differs, do not report the prediction as verified: check the actual file, entry identity, NFO parsing and refresh method.

Swap tag order for a control

With a backup available, exchange only the tag order so review comes first and plot last, leaving the values unchanged. Have the administrator refresh the same test item. The documented prediction becomes “蓝色方块” (blue square). Preserve both timestamps, file contents and web results so text, settings and tag order are not conflated. If refresh or editing cannot be confirmed, mark this comparison not performed.

Observe iCouldPlay

Using the same server account, open the same film in iCouldPlay and inspect the details page actually offered by the installed version. Record whether a description appears, its text, time and whether it matches the web. If no description entry exists or old content remains, confirm film identity and network, then reopen normally. Do not claim a guaranteed client refresh or infer caching from one difference. Record web and app separately and mark uncertain results pending.

Separate parsing from display

If the web never shows either marker, check the extension, XML closure, folder hierarchy and administrator-selected refresh scope. An old file, a different matched film or incomplete scan each require separate investigation. If both web results show the same marker, recheck saved tag order. A changed web description and unchanged app only establish differing observations, not their cause, and do not justify deleting production metadata.

Check other metadata sources

Jellyfin documents local NFO priority over remote providers. Record the existing provider configuration; do not disable providers in the production library to force an expected result, or equate network failure with an unread NFO. Ask the administrator to confirm the test file and refresh scope. If a remote description remains, keep it as an unresolved observation rather than claiming a test that was not completed.

Distinguish empty values from deletion

This exercise uses two explicit non-empty markers. It does not test empty tags or whether deleting a tag clears a stored description. Do not experiment by deleting production NFO files when old text remains. Keep the test backup and ask the administrator to confirm refresh and overwrite scope for their version. State the actual server and refresh conditions instead of generalizing one observation to all versions or clients.

Finish and restore

Have the administrator remove or retain the test copy according to normal practice, and confirm that the production film and NFO were not changed. Restore any modified test-library settings. The record should include both NFO tag orders, web results, app result and steps not performed. This guide is based on public documentation and claims neither a private-server connection nor physical-device testing.
