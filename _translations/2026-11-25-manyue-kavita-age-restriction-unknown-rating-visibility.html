Use an isolated test library to distinguish account age restrictions, unrated series and client catalog visibility.

Understand unknown ratings

Kavita’s user-management documentation says that when Include Unknowns is checked, a series without a defined age rating is treated as unknown and blocked for that user. This is a server-side user restriction and does not guarantee identical client messages. Server version, account and library permissions also matter. Do not equate an unrated item with a specific age rating or type of content.

Prepare non-sensitive samples

Use only an isolated server you administer and two short self-made, non-sensitive comic series. Record series names, content markers and library location, and back up originals and metadata. Adult material is unnecessary for testing. Create or use a normal test account with access to the test library. An administrator may bypass rating filters and cannot stand in for the normal user. Do not change real household users’ settings.

Record ratings and account baseline

In the server web interface inspect the two test series: one has a rating allowed for the test account and the other has no defined rating, using controls actually present in that version. Record the account age restriction, Include Unknowns state, library access and observation time. If it is unclear whether the second series is unrated, mark the condition unknown; a blank display does not alone prove metadata is absent.

Observe server and Manyue+ separately

Sign in to Kavita’s web interface as the normal test account and record whether each series is visible and an authorized chapter can open; distinguish search absence from an opening error. Then connect to the same server and account in Manyue+ and record names, counts and actual messages. Match content markers to avoid confusing same-name series. If the app does not display a rating, mark it unavailable without inferring which setting it read.

Confirm authority to change the setting

Continue with an Include Unknowns toggle only in the isolated environment when the administrator understands and can restore the original test-account setting. Record its current value and the user identity. This affects unrated content visible to that account and should not be tried casually on real users or shared libraries. If the control, authorization or scope is unclear, stop at the baseline; do not grant administrator access or borrow credentials.

Change one condition

Using the current server interface, toggle Include Unknowns once for the test account and record before and after values and time. Keep library access, age restriction, series metadata and files unchanged. Wait for the save to complete. If the control is unavailable or errors, record the incomplete step and actual message rather than repeatedly changing multiple permissions. This preserves comparable conditions and supports restoration.

Check the server result first

Revisit both series in the web interface as the normal test user. According to the documented rule, enabling Include Unknowns should block an unrated series; visibility of the rated control still depends on other permissions. Record what actually happens. If both disappear, check library access, age threshold and series identity. An administrator still seeing content does not establish that the normal user’s restriction failed.

Then check the Manyue+ catalog

In Manyue+ keep the same server and normal account, return to the directory and reopen it using available controls. Record visibility and chapter access for both series. If the web result changes while Manyue+ retains an older entry, check account, page state and identity first; cache or update timing requires evidence and should not be asserted as the cause. Do not bypass restrictions with old links, tokens or another account.

Troubleshoot in layers and restore

If results differ from expectation, check test user, library access, rating metadata, restriction threshold, saved option and server version one at a time, recording before and after states. Restore the original account setting after the test and confirm the self-made samples and other user data remain. Remove private addresses, account identifiers and credentials before sharing. This guide relies on public documentation and does not claim private-server or device testing.

Record distinct visibility outcomes

A series absent from a directory and a visible directory with an unopenable chapter are different observations. Record the series name, chapter entry and opening message separately for the server and Manyue+. A user lacking library permission may not see even an allowed rating; visible library access does not mean every item passes account restrictions. Ask the administrator to check settings they are authorized to view; do not share keys or administrative screenshots.

Preserve the control and uncertainty

The allowed-rating self-made series is a control, not complete proof of the permission mechanism. If it is also absent, check scan completion, series membership and server identity before changing anything. Do not simultaneously alter scans, accounts and ratings to force an expected result. Record unknown version differences, unavailable controls and pending updates, then verify the original setting was restored. Real-user access policies remain the server administrator’s responsibility.
