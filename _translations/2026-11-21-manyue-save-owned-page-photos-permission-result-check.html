Use an original comic page to check the visible save entry, system permission prompt and Photos result without equating an in-app favorite with export.

Prepare an original authorized page

Create a test comic page you own, visibly marked “Sample 01” with a nonprivate corner label. Confirm the original opens in an image viewer, record its dimensions and contents, and keep a separate original. A save or favorite control does not change copyright or redistribution rights for other works. Use only a sample you may handle; do not upload restricted comics.

Establish the page baseline in the reader

Import the sample through an entry actually available in the installed ManYue version. Open it and verify its number and corner label, rather than confusing it with another comic of the same cover. Record file identity, chapter and actual single- or double-page layout. If import feedback appears but the page does not open, troubleshoot import before comparing a save. If left and right pages cannot be distinguished, first use a state where the sample is clearly identifiable.

Identify the distinct favorite and save entries

Inspect the page-favorite, bookmark or save-image controls actually visible in the reading interface, recording their labels and locations separately. An in-app image favorite is for later review; a changed heart alone does not establish a file in system Photos. A bookmark records a position rather than an image copy. If the current source or version has no clear save entry, record that and stop rather than assuming a long press or menu always works.

Read the system prompt and current permission scope

If a Photos access prompt appears, read the requested scope and available options before deciding for this one original-page save. Options vary across systems; do not claim an unavailable option was set. If the user does not wish to grant the requested permission, cancel and mark saving incomplete. Do not turn off privacy protections for testing or publish personal information from permission screenshots.

Perform one save and record app feedback

Only when the entry is clear and the user accepts the relevant permission, select the current sample and perform one save. Record the actual success, failure or absence of feedback. Avoid repeated taps that could create multiple copies. App feedback reports the action; it does not by itself establish correct contents, dimensions or destination. Keep the task incomplete if canceled or unclear.

Confirm the actual image in Photos

Open the system Photos app and use its current interface to find the image marked “Sample 01” and its corner label. Open it and check completeness, orientation and content, then inspect date or dimensions only where the system displays them. Mark undisplayed information unknown. Similar or same-named images may already exist, so a thumbnail alone is insufficient to identify this save. If not found, record that before checking permission and app feedback.

Troubleshoot in layers and preserve the original

If the app reports success but the image is not found, confirm the same device’s Photos library and time range, then inspect the actual permission state and messages. If an image exists but differs, recheck the current page and layout in the reader. Change one condition per trial and retain the first result. Do not delete the original or clear Photos in bulk. If saving is unavailable for that source, record the limit and use the original you already possess.

Make a source, app and Photos checklist

In a private note use three columns for the same original page: original file location and marker, page currently shown in ManYue, and the image actually opened in system Photos. If the original has a blue triangle, the reader shows the same marker, but Photos only shows an older thumbnail with a red circle, record “this result not yet found”; the number 01 in both images is not enough to establish identity. If Photos displays capture date rather than save time, record the actual field rather than interpreting an older date as failure. Once a candidate is found, inspect the full image including all corners for cropping; mark dimensions unknown if the system does not show them. Only the completed comparison supports a checked save result. Granted permission and a save message remain separate observations.

Keep a reversible sample record

To investigate whether a second save creates duplicates, first finish and record the first original-page check, then decide whether to perform a separate second save. This is not required to recover from failure. If two images look alike, inspect their actual visible dates, dimensions and content; display order may not always establish source. Keep uncertain images. If the user chooses to remove a self-created test image, first confirm the independent original still opens, then use the Photos app’s normal flow to select only the intended image. Do not remove an entire date range or equate removing a Photos copy with canceling an in-app favorite.

Deliver redacted observations and restore settings

Record app and system versions, sample identity, actual entry, permission prompt scope, app feedback and Photos result, marking unperformed steps untested. Restore previous permission settings through available system controls if the user wishes. Before removing a test copy, confirm it is your own sample and preserve the original. The exercise draws on public feature and Apple Photos privacy guidance; no physical-device save or permission test is claimed.
