In a system environment that supports multiple windows, compare one self-made comic page and observed tap feedback before and after resizing.

Confirm public capability and environment

Public ManYue update notes mention iPad window resizing, popover positioning and touch response after rotation; that does not mean every iPad and system uses the same window manager. Record device, system and installed app version and determine which window states are actually available. Prepare an original comic page marked A, B, C and D at its corners and 01 in the center; open it in the ordinary full-screen state first.

Establish a full-screen observation baseline

Record the actual window edges, visibility of each page corner, center number and chapter. When the reading menu is actually displayed, record its position and an identifiable non-destructive action, such as opening and closing it. Do not use deletion or settings changes as a tap test. Verify the tap location and feedback before changing state. If the page cannot be read, resolve its import first.

Use a window state actually offered by the system

Using the system documentation and visible controls, change the ManYue window to an available narrower state, such as a supported split view or window size. Do not assume every device supports arbitrary dimensions or require an unavailable system feature. Record the new boundaries and ensure the tap belongs to the ManYue region. If resizing is unavailable, preserve the baseline and mark the comparison untested.

Check the picture before interactions

In the new state inspect A, B, C, D and 01 on the same page. If part is invisible, distinguish a narrower window, image fitting, pre-existing zoom and an actual page change before concluding content is missing. After confirming page and chapter identity, open the menu using an available control and observe whether it is visible or blocks important content. Record the result rather than assuming a fixed menu position.

Tap once and inspect actual feedback

Choose a visible non-destructive control, tap once inside it and record the location, interface change and whether the expected action occurs. If nothing happens, do not tap repeatedly or use an unknown button. Check window focus and obstruction before repeating the same action once. Record the visible target and action result separately; one menu appearing does not establish alignment of all controls.

Record a tap relative to visible boundaries

In a paper note or a note without private content, describe recognizable screen regions from left to right and top to bottom; a special coordinate measurement tool is unnecessary. For example, record “inside the menu button at the top right of the narrow window” and “blank space below the button,” followed by one actual tap, visible feedback and triggered action. Do not deliberately tap a control that could delete content. When the window boundary moves, identify the button’s visible area again rather than reusing its full-screen position. Record system window controls separately from comic-reader controls. A menu appearing supports only the “menu appeared” result, not page turning, zoom and all other buttons. For a repeat, close the menu, restore the same page and record whether the same result occurs; retain an isolated observation without calling it reproducible.

Return to the original size and verify the reading anchor

Restore the original window state using the visible system controls. Check the same book, chapter and page marked 01, then inspect corners and menu again. If a different page appears, first record the actual chapter and neighboring pages before deciding whether a page turn, reflow or unknown event occurred. A page number alone is insufficient. Keep the original image separately; restoring window size does not imply every setting was restored.

Change one condition when troubleshooting

If menu position or taps differ, record orientation, window state, control and observed problem. Return to full screen to recheck the same control, then change only the window state once. Do not simultaneously change comics, rotate the device and reinstall the app. Whether another window responds may help identify a system condition but does not establish ManYue’s internal state. Mark unsupported versions or system states incomplete.

Keep a reference in both window states

Start each observation with page number, device orientation and single- or dual-page layout. If the narrow window changes page fitting automatically, note that it followed the window change and then inspect content visibility; do not equate fitting with a tap-coordinate fault. If the same menu still cannot open after restoring full screen, the issue is not confined to the narrow-window condition, though the cause remains unknown. If screenshots are needed, use only the self-made comic and necessary controls, crop neighboring windows, notifications and account information, and safely retain any uncropped image.

Keep a redacted record and restore the setup

Keep before-and-after window states, visible corner marks, menu position, single tap and feedback, distinguishing actual observations from unfinished checks. Confirm the self-made comic and existing reading records remain, and restore the user’s window layout if needed. Exclude private information from other windows in a report. This exercise follows public information and claims no physical iPad, multiwindow or touch-accuracy test.
