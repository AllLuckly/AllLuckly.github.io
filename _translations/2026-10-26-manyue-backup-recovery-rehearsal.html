Possessing a backup does not establish what it restores, and recovered favourites do not supply missing images. Rehearse a small recovery while the old device remains available. Without a suitable spare environment, inspect the backups and prepare a recovery inventory while clearly marking the restoration steps that remain untested.

Separate three recovery inventories

Inventory comic originals and editions, application records, and server access information separately. Check whether each backup location remains available if the device is lost. Server originals also need their own preservation plan. Choose one short comic as a recovery sample instead of moving the entire collection before the basic process is understood.

Export the current application data

Export application data through the current backup flow and name the file with a date and source device. Verify that the resulting file exists in your managed destination. Treat it as private because settings and login-related information can be included. Preserve the sample comic separately and confirm the source is readable. Record both locations explicitly.

Review the current recovery scope

Read the current sync and backup scope before restoring. Comic files, download state and device access information are not interchangeable with application records. Restored connection names may still require credentials. Mark expected restored items, items requiring separate files or reconnection, and points that need observation so an intentional limit is not misreported as failure.

Choose a suitable recovery environment

Use a spare device you manage only after preserving any valuable existing records there. Read restoration prompts because importing can change current state. Without an appropriate environment, retain the exports and mark restoration as untested; do not uninstall the primary application to manufacture one. An explicit incomplete check is more useful than sacrificing the sole working state.

Inspect restored shelves and records first

Compare the sample’s shelf membership, history and important bookmarks with the old-device inventory before bulk downloading. A restored cover establishes only some record recovery. For missing items, check backup scope and whether you selected the intended file. Record the backup filename and source device so similarly dated exports cannot be confused.

Restore files and service access separately

Import or obtain the sample comic separately and verify bookmarked scenes. Re-establish NAS network access, paths and credentials as needed. Check offline availability independently. Compare identities before removing same-name entries. If a bookmark belongs to an old file identity, use its chapter and scene description to relocate manually and record that distinction.

Record a usable recovery sequence

Write a short recovery order naming the data backup, original-file location, reconnection requirements and sample-position check. Mark outstanding work, such as unchecked books or another device. Keep the old device until the important recovery targets are verified. A successful sample establishes a workable path and its remaining scope rather than proving every historical record was restored perfectly.

Questions and completion criteria

Can the old data be removed merely because a backup exists? Verify the necessary recovery targets first. Is preparation useless without a spare device? File checks and a recovery plan still matter; mark the untested restore. Finish with accessible originals and data exports, a clear sequence, and explicit verified or outstanding outcomes.
