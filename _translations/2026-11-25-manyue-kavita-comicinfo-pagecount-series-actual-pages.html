Use self-made comics to compare ComicInfo PageCount, server series statistics and pages actually readable.

Understand page-count layers

Kavita’s comic-metadata documentation maps ComicInfo PageCount to length and says it is aggregated at series level. A file declaration, server statistic and pages actually shown in a client are different layers. A metadata number alone does not establish that every image exists, is ordered correctly or has been read. Whether Manyue+ displays a statistic depends on its connection and interface.

Prepare identifiable self-made samples

Use two short self-made comics in an isolated library you administer, placing distinct numbers or color markers on each page and recording actual pages per archive. Back up files and metadata and use a normal account authorized for the library. There is no need to download or publish copyrighted comics. Stop if original and backup locations cannot be confirmed; do not edit household members’ production material.

Establish web and client baselines

Find the test series in the server web interface and verify both issues, visible page counts or length and series statistics, marking absent fields not displayed. Open the same series in Manyue+ as the same user and record visible chapters, counts and images. Match self-made markers instead of assuming that identical names or covers identify the same series.

Inspect PageCount per archive

In authorized copies, locate ComicInfo.xml at each archive root and record PageCount, series and issue number for each, separately from the image-page count you recorded. Distinguish missing, zero, uninspectable and nonnumeric values. Do not automatically count text, cover or documentation files as comic pages. Preserve originals when a declaration differs from file contents; do not immediately edit production works.

Set restorable test values

Only after an administrator confirms isolation and restoration and an editor understands XML, set clear PageCount values in self-made copies while recording originals and keeping series and issue numbers stable. Start with declarations matching each archive’s image count; deliberate corruption is unnecessary. Validate XML and archive structure. Mark the step unperformed if editing or file location cannot be verified, and never experiment on another person’s originals.

Scan and inspect server aggregation

Wait for or run an isolated-library scan using current controls and record completion. Recheck per-issue recognized counts and series length in the server web interface, observing whether an aggregate is exposed. The documentation describes aggregation, not identical labels in all versions. If counts differ, first check whether both archives are grouped, metadata was read and the scan completed, without changing multiple conditions together.

Check actual pages individually

Open authorized self-made chapters in a reading entry point actually supported by the server or Manyue+ and inspect numbered or colored markers from first to last. Matching declared and displayed counts does not automatically prove every image is complete; record blank, duplicate or missing pages separately. If reading or chapter access is unavailable, mark content inspection unperformed rather than substituting a statistic.

Compare differences and protect originals

If server statistics and individual-page observations differ, separately inspect metadata, image files, grouping, scan and client directory state. Change one reversible condition at a time and record it; do not delete production files, overwrite the only copy or rename a ZIP extension to simulate a repair. Ask an authorized administrator to inspect the test sample when necessary and preserve unknown conclusions.

Restore and document

Restore isolated samples and settings from backup, confirming originals, bookmarks and other users’ progress remain. Record actual page markers per archive, PageCount, server series statistics, Manyue+ observations and skipped steps. Remove private paths and credentials before sharing. This guide relies on public documentation, claims no private-server or device test and does not guarantee that Manyue+ displays this metadata field.

Separate issue and series statistics

For each issue record file identity, ComicInfo declaration, independently counted image pages and the server’s visible value, with a separate row for the series aggregate. If only a series total is displayed, do not copy it into each issue; if one file lacks PageCount, do not invent it. Confirm which issues the server recognized before comparing an aggregate, since an omitted issue can resemble a summation error.

Check page order, not just count

Two archives may each contain three images while filename sorting or a missing image changes the order of self-made markers. Record each recognizable marker in sequence, not only the final count. If the server and Manyue+ differ, verify the same issue and file edition before recording the difference. Preserve the unperformed status if access or a reader is unavailable.

Preserve metadata and display boundaries

The documented mapping suggests what to inspect, but the server may also read file contents or existing information. A displayed number equal to PageCount alone does not prove its source; controlled changes and scan evidence are needed for a stronger conclusion. Never delete or overwrite production metadata without administrator approval. Operate only on restorable isolated copies and mark uncertain sources unknown.

Reproducible test values

Reproducible sample: archive one contains three self-made images marked A1, A2, A3 and root ComicInfo.xml values Series River Demo, Number 1 and PageCount 3. Archive two contains B1 and B2 with the same Series, Number 2 and PageCount 2. After scanning the isolated library, first confirm both issues are recognized, then inspect whether series length corresponds to declared total 5. Verify A1 through A3 and B1 through B2 individually; actual labels and display depend on the server and client.
