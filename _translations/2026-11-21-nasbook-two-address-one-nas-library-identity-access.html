Use two already authorized access paths, verify they reach the same NAS library, and record network and reading outcomes separately.

Confirm the version and existing access paths

In this sampling, some China Apple lookup responses still showed 1.1.4, while cache-varied China, Finland and US lookups showed 1.1.5. The 1.1.5 release notes mention local and public addresses for one NAS library; availability depends on the actual store and installed version. Record app and system versions and the authorized local and remote paths you already use. Stop if the installed version lacks the relevant entry rather than inventing a button.

Preserve the current connection and one sample book

Record the existing connection name, service type, a redacted account label, library directory and the title, chapter and distinctive short sentence of an authorized EPUB. Confirm the server has a recoverable original and reading records can be recovered. Local and public addresses may reach the same host through different entries, but similar names do not prove identical libraries. Do not delete old connections or change server configuration for this check.

Make a two-path verification card first

In a private record, give local A and remote B separate entries for service type, redacted host label, actual visible root, sample title and chapter, and the account used. If titles match but chapter one contains sentence X in A and sentence Y in B, do not merge them as the same book: first check editions, directories and sample selection. A matching sentence establishes only that the sampled passage agrees, not that the entire files are identical. For an original-file comparison use files you may access and the same hash algorithm; mark it untested otherwise. Exclude real domains, passwords and tokens and do not expose an accessible private directory in public feedback.

Verify path identity on the server

Through existing authorized administration, check the protocol, host, port and actual root directory of each access path. Use redacted labels such as local A and remote B; do not publish real addresses, account names or tokens. Verify that the same authorized account can see the sample book, edition and directory structure through each. If identity cannot be established on the server, pause and ask the maintainer.

Establish the local-network baseline

With the device on the existing trusted local network, use the established local path through the actual Book Isle interface and open the same directory and sample book. Record actual text and connection outcome rather than just the cover or list. If it fails, check service availability, service type and that account’s permissions while holding other conditions fixed. Do not compare networks until the sample text is readable.

Check dual-address configuration carefully

If the installed version actually offers two addresses for one library, follow its prompt using the authorized local and remote entries you already have, checking protocol and path separately without disclosing credentials. Read whether the action affects a new or existing connection; pause if its scope is unclear. A remote address relies on an already authorized remote-access deployment; entering it in an app does not itself create a secure channel, and this exercise requires no new public exposure.

Reopen the same sample on the remote network

Under already authorized remote-network conditions, open the sample through the same library entry and check file identity, chapter and short sentence. Record the actual network, entry and outcome; a saved address does not establish successful remote reading. Preserve any cellular-data or unreachable-service message and mark the step incomplete. Do not assume a fixed automatic switching order; record only what the interface and observation show.

Separate progress from file state

After both paths show the same book, compare reading position with the earlier record. If the interface offers merging existing connection progress, first identify sources, target, prompts and recovery conditions; do not proceed if scope is unclear. Matching title or cover does not prove the files are the same edition. Record file readability, progress agreement and whether merging was actually performed as separate outcomes.

Locate failures and protect the original state

If local access works but remote access fails, first check the remote network, existing authorized channel and server-side permissions. If directories differ, compare roots before modifying books to make them look alike. Preserve redacted errors and times without publishing hosts or account details. If the source remains uncertain or a security change is needed, leave the check incomplete and contact your service maintainer.

Preserve incomplete status

If the remote path is unavailable on the current network, mark it untested and continue using the verified local path. Do not change server permissions or expose a new public entry merely to obtain a pass. On a later attempt use the same sample and redacted labels.

Deliver layered results

Record app version, sample identity, redacted A/B entries, network conditions, text outcomes and progress checks. Explicitly mark unperformed merges or recovery as untested. Return to your usual connection and confirm the sample and reading records remain available. This exercise follows public release notes and does not claim an actual NAS configuration, remote-access test or progress merge.
