For a large scanned volume, first identify the needed section and verify a supported reading route instead of downloading an entire collection blindly. Prepare a complete copy when offline use is required. On-demand selection does not imply arbitrary page-range downloads, automatic recognition or cropping.

Identify the required section first

Record the required chapter and file/printed-page relationship from available contents. Manually map image-only contents without assuming automatic chapter generation. State the lookup question and mark uncertain pages. Verify actual structure and text layers rather than relying on PDF/CBZ extensions.

Record file scale and device conditions

Note source size, page/image information, available device storage and network. Compressed size alone does not describe decoded demand. Preserve the original and compare one file without server upgrades, account changes or repackaging. These conditions guide the route, not a universal safe-size claim.

Try the supported remote route

Use the supported visible remote-opening flow, or a full download if that route requires it. Do not promise per-page streaming for every PDF/CBZ. Inspect the beginning and one known target page, recording acquisition, opening or individual-image failure separately. Names and cached covers are insufficient.

Inspect the target and surrounding context

Verify heading, figure number and surrounding text to exclude page offsets. Zoom does not restore missing detail, and scans/CBZ images are not automatically searchable text. Any external recognition copy needs proofreading. Retain edition, page, units and footnotes when citing the result.

Plan full acquisition for offline use

When offline use is needed, obtain the complete file through the offered flow with a storage buffer. Viewed target pages are not proof of a full copy, and arbitrary range download is not assumed. Verify beginning, target and end offline locally before adding more large files.

Use a simple reference to isolate failures

Compare the same original page externally and a small known-good file in Book Isle. Separate file failure, remote-route failure and local image-load failure. Keep conditions stable and use a self-made large numbered image for reports where possible. Describe file, page, action and result precisely.

Manage copies after the lookup

Keep citation pages and findings in notes and preserve the NAS original separately. Understand local-copy, shelf and source deletion scopes before cleanup. Retain a validated offline copy when needed and record version/local status rather than relying on a remaining cover.

Acceptance and capability boundaries

Finish with the correct readable target and context, understood remote/local state and any required full offline checks. Network transfer granularity depends on the route, and visible scan text does not imply searchability. State untested scope rather than guaranteeing every page from one successful lookup.
