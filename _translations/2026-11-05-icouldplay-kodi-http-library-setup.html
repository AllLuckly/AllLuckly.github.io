A working Kodi television interface does not establish that your phone can access its library. The public iCouldPlay 1.1.1 release adds Kodi libraries. This first connection exercise separates service preparation, addressing, authentication and sample playback. Use a Kodi host you manage or are authorized to use, with a permitted video already in its library. No add-on, public port or new server is required. Start on the same trusted local network and retain a connection record.

Confirm the Kodi service and sample

Play the target briefly on Kodi itself. Record its title, duration and a content anchor, confirming that it is not merely a poster whose file has moved. In the installed Kodi version, inspect the service control settings for HTTP remote control and note the actual port. HTTP access differs from the switches for other remote control protocols; enabling every switch is unnecessary. Consult Kodi control settings, retain authentication and keep this service off the public internet.

Identify the host from the phone

Put the phone and Kodi host on a network that permits communication, and record the host’s current local address or an already configured trusted hostname. On the phone, localhost means the phone, not the television box or computer. A similarly named guest network may isolate devices. Repeated password changes will not fix the wrong host. Reconfirm the address after sleep or reassignment. An existing trusted browser route can establish that the same host responds, but an accessible homepage does not prove that every video plays.

Enter address and port in their fields

Choose Kodi when adding a media server in iCouldPlay, and give it a recognizable device name. Enter the actual HTTP or HTTPS service base address. Where the form has a separate port field, match Kodi’s real port without incorrectly duplicating it in the address. Do not enter a film’s filesystem path, a browser page’s long query or a download link as the server address. HTTPS requires an already configured, verifiable service; changing the letters of an HTTP address does not provide it. Recheck host, scheme and port before saving.

Use the Kodi web-service credentials

Use the credentials for Kodi’s web service, not an Apple account or streaming-site login. Keep authentication enabled where the administrator requires it. Watch for copied spaces and keyboard substitutions, and reveal the password only briefly in a private setting. Neither the connection note nor support screenshots should contain credentials. If iCouldPlay offers test-and-save, test first. A failure means this combination did not pass; a generic message does not establish a wrong password. Addressing, network access and the HTTP service remain possible causes.

Verify a small library selection

After connecting, locate the video checked on Kodi and compare title, type and visible duration before exploring the whole library. For television, select an actual episode rather than expecting the series container to play. If the sample is missing, confirm on Kodi that it belongs to the relevant library rather than only the file browser. Do not immediately delete and recreate the source. Distinguish an empty list, a partial list and the expected item in your notes. Avoid changing watched status on real films during this first exercise.

Verify the media path through playback

Play ten or more seconds from the beginning, then seek to the recorded anchor and verify sound, picture and identity. Artwork and media can use different requests, so browsing success does not establish transfer success. If Kodi plays locally but the phone fails, retain that difference and investigate the media path instead of trying progressively larger films. A known working permitted local copy can be a player control, but does not prove the remote file was downloaded completely. The result applies to this host, source and sample.

Investigate the stage that failed

For failure before saving, check host availability, address, port and network isolation before authentication. If items appear but playback fails, preserve browsing success and check whether Kodi supplies a media path accessible to the client. A single missing item calls for checking that file and source type, not resetting the library. Change one condition at a time and record before and after. For administrator help, provide app and Kodi versions, failure stage and a sample identifier without passwords, complete private paths or authenticated links.

Keep a reproducible connection record

Record the displayed server name, network, actual port, sample and results. Keep credentials in the trusted method already used for them. Restore the earlier viewing position after a rehearsal; remove a test source only when unnecessary, without deleting Kodi media. After a network or address change, repeat addressing and sample checks. One success does not establish public-network or universal add-on compatibility. Record connection, item visibility and playback separately, leaving unfinished checks pending so the next session starts from evidence rather than an ambiguous “connected”.
