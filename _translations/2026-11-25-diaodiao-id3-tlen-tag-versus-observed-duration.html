The duration displayed by 调调 may differ from a duration tag within a file. ID3v2.4's TLEN frame records length as a numeric string in milliseconds, but the standard does not require a player to use it. Set different TLEN values on two copies of an owned MP3, then separately record external readback, app display and listening results without presupposing how the app reads tags.

Prepare an original and two copies

Choose a short MP3 you have permission to edit and preserve the unmodified original. Listen with a reliable player and record its visible total duration; a recording with a recognizable sound at the end is helpful. The example uses about thirty seconds, but your file determines the actual result. Make clearly distinguishable copies A and B. Check that both play the same beginning and ending with no obvious truncation. Do not intentionally put an incorrect tag on a file intended for formal release.

Understand TLEN units

ID3 defines TLEN as the audio file's length, represented by a numeric string in milliseconds. For example, thirty seconds is 30000 milliseconds and twenty-five seconds is 25000 milliseconds. The tag is metadata, not the audio itself; changing it does not automatically trim the sound. The example values provide a recognizable difference, not a true duration for arbitrary files. A player may calculate display from the audio stream, tag or other information; only observation establishes the interface result. If the external player shows whole seconds only, record A as approximate. Rounded thirty seconds is not a precise measurement of 30000 milliseconds; a precise comparison requires a trusted higher-resolution tool and documented measurement conditions.

Record a file baseline first

Open A and B in a trusted tag editor. See whether it explicitly identifies the TLEN frame, and record its initial value, title and duration. Do not assume a generic duration display with no identified source is TLEN; consult tool documentation or stop editing tags. Confirm original and working-copy paths to avoid changing the wrong file. Tools differ in empty tags, numeric entry and saving; follow the actual tool's instructions.

Write each copy's tag

Only if the tool explicitly supports TLEN, set A to the actual recording length converted to milliseconds, and set B to a clearly different positive integer for practice. For the thirty-second example, A can be 30000 and B 25000; for another duration choose and record values appropriate to that file. Do not write the wrong value to the original. Record the A/B mapping on paper before editing each so a later file reorder cannot reverse experiment labels and playback results. Save and close the editor. If TLEN cannot be edited or units are uncertain, mark not tested; do not change file extensions to bypass the problem.

Read back tags and listen

Reopen both copies and read TLEN separately, checking A and B against your record and making sure seconds were not mistakenly entered as milliseconds. Compare titles, file identities and visible durations, then listen to the beginning, middle and end of each. If sound is truncated, tags did not save, or a file will not play, stop the comparison and prepare fresh copies from the retained original. Tag changes may alter file size, so size differences alone do not establish an audio change; keep clear listening notes as well.

Import in separate rounds and identify

Record existing entries in 调调, then select A through the actual visible file-import control and B separately. For each round record app feedback, title and source. If the app reports a duplicate, same-name conflict or merge, stop and establish which item is which rather than assuming both must become entries. If B cannot be identified, mark its app observation unconfirmed; do not substitute A or an old file. Preserve old same-name entries rather than clearing the library for the test.

Observe display and playback separately

For identifiable A and B, record the duration shown in list or playback view and, where practical, play through to the recording's end. Record whether the final recognizable sound is heard and the playback state, allowing manual timing error. If display matches despite different tags, or differs while the sound is the same, record only the actual observation. If playback to the end is not possible, mark it not tested. A progress bar alone does not establish that the player uses TLEN.

Compare and investigate differences

Keep three columns for each copy: TLEN read back, duration displayed by the app and observable playback result. Check units and file identity first, then consider possible factors such as tag editor, file structure or app version. Without direct evidence, do not attribute a difference to a specific internal algorithm. Display precision and manual observation error can also cause differences. One result cannot establish behaviour for other files, sources or versions.

Clean up and restore

Preserve the original and practice record; do not publish B with its intentionally incorrect TLEN as a formal file. If removing test entries, first identify them as these copies; leave uncertain items alone. Record app version and incomplete steps but do not publish private paths or recording contents. This guide uses public format and store information and does not claim step-by-step tests on a personal device or private server.
