If you already manage a WebDAV service, you can use a dedicated folder for ManYue sync data. It handles reading history, favorites, settings, and similar state; comic files still follow local-import or remote-library workflows. Starting with creation of the sync folder, this tutorial focuses on whether to upload or download first and how to confirm that the configuration really works.

Prepare the sync folder and appropriate permissions

Create a separate folder on your WebDAV service, such as manyue-sync, separate from the folder containing comic originals. The example address https://dav.example.com/manyue-sync/ shows only the structure; the service administrator must provide the actual values. Confirm that the account can read, write, and manage sync files in the folder. An account that only has read access to comics may be unsuitable here.

Prepare the service address, account, and password, then check the device's network connection and sync entitlements. If the two devices already contain different reading data, export a backup from each first. Choose the device with more complete data for the initial upload and let the other receive it first. Write down this order so that the new device's limited data is not mistakenly treated as the sole source.

Complete the form through Data Sync

Open Data Sync and then WebDAV sync settings. Enter the folder URL, username, and password as requested. The URL should lead directly to the prepared sync folder. Put real credentials only in their corresponding fields. In your own configuration notes, label it “Personal Sync” and record the folder's purpose for future maintenance.

If optional fields for skipping settings appear, keep the defaults initially and complete basic sync first. These options refine the data scope; they are not arbitrary fixes for a failed connection. Confirm the automatic-sync switch and initial direction, then save. If saving or transfer fails, address the message rather than assuming success because the form closed.

Upload once from the source device

Before the initial upload, check that the source device has the important bookshelves and recent reading state. Choose Upload, wait for the result, and check for a new success time in the Sync Center. Pause bookshelf organization on the other device during transfer so that this change has a clear boundary.

If the server allows you to inspect the folder, you can confirm that sync files were created, but routine use does not require manually editing their names or contents. These files have version relationships; arbitrary renaming, overwriting, or clearing can disrupt later decisions. Once the folder's role is established, let the app manage its files and use the server for normal storage and necessary backups.

Choose Download on the second device

Use the same sync folder and corresponding account on the second device, choosing Download for its first operation. Afterward, check the agreed test group, book title, and reading position, then restore access to the comic content. If the service folder has no successfully uploaded data yet, finish the upload on the source device instead of repeatedly downloading an empty folder on the target.

Decide whether to enable automatic sync after the checks pass. Continue watching the latest success time and error state, especially after password changes, service migration, or folder-permission changes. One success does not remove the need to check later configuration changes, but you do not need to fill out the whole form again every time you open the app.

Example: synchronize one group and one reading position

Suppose the tablet is your main reading device and the phone will be used on the go. Confirm the “Reading This Week” group and the current chapter of a comic on the tablet, export a local backup, and upload to the dedicated WebDAV folder. After downloading on the phone, check that group and chapter record, then restore the comic files and inspect the actual pages.

Next make just one small change, such as reading several more pages normally. Wait for sync to succeed, then check the tablet. Keep other devices from modifying the same state during this test. If results differ, the sequence and times help locate the cause instead of leaving you to guess among many simultaneous changes.

After saving, leave the settings page and reopen it through the Data Sync Center to confirm that the folder and account still match what you entered. Repeat this check on the second device, especially folder names, capitalization, and subpaths. Two devices connected to the same server but different folders may see entirely different sync data.

Preserve the current state when sync fails

For an incorrect address, check the folder path. For authentication failures, check current credentials. If reading works but uploading does not, check write permissions and service capacity. If a conflict, newer version, or unverifiable result is reported, retain a local backup and pause repeated overwrites. Determine which device has the complete state before following the prompt.

Browsing files successfully in a WebDAV comic library does not prove that the sync folder has the same permissions. The two may use one server but different folders or accounts. Identify whether troubleshooting concerns comic reading or state uploading so that you inspect the right configuration. When changing services, retain the old folder and device data until a round-trip check of the new folder succeeds.

Can comics and sync backups share one folder?

Being technically able to store files does not make it a good organizational choice. A dedicated folder clarifies sync files, permissions, and backup scope and reduces the risk of touching sync data while organizing comics manually. A separate comic-library folder also makes finding and maintaining files easier.

After enabling automatic sync, do I still need to check the success time?

Yes. The switch describes the intended behavior, while success times and errors reflect actual results. After changing networks or passwords, or following server maintenance, check a test reading position to catch configuration changes promptly.
