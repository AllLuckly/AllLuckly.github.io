Check purpose, account and actual outcomes for book-library and reading-data destinations on one private service.

Prepare a recoverable book and one record

Choose a short EPUB you own or may use and confirm its original file is recoverable from a separate location. Record title, chapter and a nonprivate reading note, and verify both on the current device. Do not put a complete private book, account or server address in shared notes. If current reading data cannot be preserved, inspect only and do not change remote directories.

Label the two purposes

Book Isle’s public listing describes a WebDAV private library and WebDAV synchronization for reading progress, notes and other data. Label the book-file location A and the sync destination B. Even on one service, record them by purpose. Seeing a book in A does not prove B synced, and a completion message for B does not prove the EPUB was uploaded. This distinction does not imply that two accounts or servers are always required.

Check actual directories and accounts on the service

In an authorized service-management interface, inspect actual host, account, root path and permissions for A and B. Use only redacted labels in external records. If the provider specifies a WebDAV address, use its documentation and established configuration; a normal login page need not be the same entry. Nextcloud’s documentation describes its own WebDAV access and does not establish identical paths for all providers. Ask the maintainer if identity is unclear.

Inspect the original book in A first

Using the authorized Book Isle library connection, browse A and confirm the same EPUB’s title, format and recognizable chapter. Open or download it through the current interface, separately recording directory visibility, file acquisition and readable text. For an empty directory check account and path first; do not clear B as a repair. A cover or catalog entry does not establish that a complete local file was acquired.

Inspect sync conditions for B separately

In the sync settings actually offered by the installed version, inspect B’s service, path, account and interface description. If membership or configuration limits this feature, record the actual indication; readable A does not prove writable B. Perform synchronization only when current device and destination states are known, a recoverable backup exists and the prompts are understood. Pause for unclear configuration or conflicts.

Verify reading data instead of only the message

If synchronization was actually completed, use another authorized device or a result actually visible in the current interface to check the same book, chapter and note. Record separately whether the book file exists, reading data arrived and the original sentence can be located. Mark untested if no second device or confirmable sync result is available. A timestamp or success message does not establish that every note is complete.

Diagnose reading, writing and paths separately

If A reads while B fails, retain B’s redacted message and time and check destination path, account, network and write permission. If B writes but the book is missing, check A’s file and whether the target device has the actual book. Change one confirmed condition at a time. Do not delete remote directories, reinstall the app or overwrite another device’s records to force a pass.

List the two destinations in a scope table

Give A and B separate rows for redacted location, authorized account label, expected content and actual observation. For example, A may contain a self-made EPUB whose second chapter opens, while B’s settings show a destination path but no sync has been performed. Record “text observed” for A and “settings only, sync untested” for B rather than passing both. If another device displays a shelf entry but cannot open the book, check whether the actual file is available there instead of relying on a note or progress record. Even if A and B physically use the same path, preserve the distinct purposes and actual file scope; do not automatically move files.

A sync message does not resolve a conflict by itself

If B reports newer remote data or a conflict, stop and record each side’s visible time and sample note. With unconfirmed time zones or sync order, do not automatically choose the larger timestamp as the source that should overwrite the other. Confirm backups, destination and the recovery method stated by the interface before the user decides what to do. When uncertain, leave the test incomplete rather than repeatedly uploading different device states over one another.

Change one confirmed condition at a time

If B reports that an account cannot write, record the actual message and destination label and check that it is the intended account. Only after the user or service maintainer confirms authorization should their established process be considered. Read access to A is not proof of write access to B, and directory names differ among services. For a retry retain before-and-after states and the same test note. A later success covers this device, account and directory, not every book and device. Stop if backups or prompt scope are unclear, and provide only redacted configuration and failure stage in feedback.

Deliver results and protect existing data

Record A/B purposes, redacted identities, whether the sample was read, whether synchronization was performed, chapter and note outcomes and unfinished items. Confirm the original book and existing backups remain and restore usual connection settings. These sources support a self-directed verification procedure; no private-server connection, synchronization or device test is claimed.
