Uppercase labels on onscreen keys do not necessarily mean uppercase characters will be entered. Apple offers a system option to display only uppercase key labels, but that system documentation does not establish that a third-party keyboard follows it. Under settings you can restore, observe the system keyboard and Jianlai separately, then inspect the actual letters in an ordinary note.

Prepare a reversible comparison

On your own iPhone create a practice note titled “Lowercase key label observations”. Use non-private English practice text; do not test in password, payment or account fields. Verify the note can be saved and that both an English system keyboard and an English Jianlai layout are available. If the latter or the keyboard identity is uncertain, mark that observation pending rather than attributing another keyboard to Jianlai.

Record system and Jianlai versions, device orientation and layout. Prepare columns for system option, keyboard identity, key labels, action and actual characters. Preserve the original theme and accessibility settings. If changing the setting would interfere with daily needs, skip the comparison. Return to your usual keyboard after the exercise.

Find the system option and its original value

Apple’s iPhone guide describes turning off “Show Lowercase Keys” in the accessibility keyboard settings to show uppercase labels. The path and wording can change; use the options actually visible on your device. First record whether the option is on or off. If it cannot be found, record the version and where you looked; there is no need to reset or update the phone.

This is a device-level system setting, not a font toggle in Jianlai’s theme. Third-party keyboards may draw their own labels, and Apple’s system-keyboard documentation does not promise that Jianlai follows this setting. If you prefer not to change it, observe only the current condition and mark the other condition unperformed.

Observe the system keyboard first

Return to the note, select an ordinary text line and switch to the English system keyboard. Record the option’s current state and whether labels look uppercase, lowercase or unclear. Using the visible Shift state, enter three letters such as abc; inspect each committed character and record whether it says abc, Abc or something else. Seeing A on a key is not evidence that A was entered.

On another line use the visible Shift control to enter one uppercase and two lowercase letters; inspect the body. Automatic capitalization, host suggestions or a mistaken tap can affect the result. Record what actually occurred before correcting the practice copy. Do not assume all keyboards use identical actions to switch or lock Shift.

Repeat the check in Jianlai

On a new line in the same note, switch to Jianlai’s English layout and verify identity and layout against your record. Without changing the system option, observe labels and use the controls actually shown to enter the same three letters. Record appearance, resulting text and corrections; note separately whether candidates or host auto-correction participated.

The result may match the system keyboard or differ; neither observation alone proves the other is wrong. If the English layout is unavailable, the host switches to the system keyboard or identity is uncertain, stop and mark the row incomplete. Do not change themes or permissions to force a result. Change only keyboard identity between these rounds, keeping orientation and lighting stable.

Optionally compare the other system state

Only if the user wants to, knows the original value and can restore it, temporarily change “Show Lowercase Keys”. Return to the system English keyboard and Jianlai in the same order and enter one line with each. Record labels first, then Shift actions and committed text. Do not also change Jianlai’s theme, font size or host. If the option is unavailable or inappropriate to change, skip this round.

Record the two conditions separately. A change in the system keyboard’s appearance does not prove Jianlai changed; unchanged Jianlai labels do not prove output case was unchanged. Inspect each character and distinguish label presentation, current Shift state and committed text. Return to Settings, restore the original option, and ensure accessibility still suits the user.

Troubleshoot and deliver

If case is unexpected, first confirm the line, keyboard identity and visible Shift state, then inspect host capitalization at the start of a sentence. Work in the practice copy rather than repeatedly testing a real document, and distinguish a correction from the original observation. If the keyboard is hidden, check the cursor and active field; do not reinstall or reset all settings.

Deliver a table with the original setting, identity, display, actions and results for each round, noting skipped steps. Save and reopen the note to verify the lines and characters, and restore your original keyboard and theme. The exercise is designed from public sources; it does not claim a device test or generalize one observation to all third-party keyboards.
