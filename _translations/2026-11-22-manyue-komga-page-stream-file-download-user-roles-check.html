Use one authorized test comic to check Komga user roles and ManYue reading and download outcomes separately.

Prepare an authorized account and comic

Choose a nonprivate test comic on a Komga server you manage or may access, recording series, page count and first and last page markers. Preserve the original file. Use an account authorized for testing; without administrative rights ask for permission information rather than changing another account. Do not put server addresses, accounts or tokens in reports.

Understand server role scope

Komga’s user documentation distinguishes the Page Streaming role for reading individual pages from the File Download role for downloading a book file. Administrators can also restrict accessible libraries and content. Inspect actual roles and access on the current server. Do not assume one role implies the other or describe server user management as a ManYue feature.

Inspect existing access in Komga

Have an administrator inspect the test account’s library scope, page-streaming and download roles in the current user interface. Record original settings first; no change is needed for practice. Under that account check whether Komga lists the test book and opens pages. Test file download only if authorized and the interface offers it. Record library visibility, readable pages and file download separately.

Check the same source in ManYue

In ManYue enter the same Komga source and account and find the test book, comparing first and last page markers. If the interface offers download and the account permits it, perform one attempt and wait for its actual result. Mark a missing download entry or permission not observed or unperformed. The mapping between Komga roles and ManYue behavior depends on the actual environment; not every server option is guaranteed to appear in the client.

Separate permission from file problems

If the same account can see a library but cannot read pages on the server, have the administrator check the page-streaming role, content restrictions and actual error. If pages work but file download fails, inspect the download role and target file separately. If both work on the server but differ in ManYue, confirm the same book, account, versions and network and record a redacted error before changing broad library permissions. File corruption, permissions and network are distinct possibilities; symptoms alone do not select a cause.

Restore and document observations

If an administrator must adjust one role for the test account, first record original state and authorized scope, change one item at a time and restore afterwards. Do not delete the user: Komga warns deletion removes that user’s reading progress. Record both sides’ results, versions, time and untested items without exposing credentials or private comics. This article follows public documentation and claims no device or server testing.

Record operations in a matrix

For the test account use columns for server library visibility, server page reading, server file download and actual ManYue outcome. Enter success, failure or untested for each with an observation time. For example, an account with page-streaming access but no file-download role may show comic pages while download is refused; these outcomes are not contradictory. This is a conditional example, and the administrator must establish actual server settings.

If server page reading and download both succeed but ManYue only reads, first confirm that the client actually offers download, the same book is tested and the account is the same. Mark a missing entry not observed, not a fabricated status code; if an entry exists but fails, record its actual message. Conversely, if the same account cannot read pages on the server, investigate there first rather than switching to an administrator account as proof of the original account’s permissions.

Library scope, content restrictions and roles

Komga lets administrators restrict visible libraries and apply series-level age-rating or label restrictions. An administrator should check that the test series is within the account’s actual scope, then inspect page-streaming and download roles. A download role does not necessarily expose every library, and a visible list does not alone prove download rights. This does not require changing the user’s security settings.

If an administrator finds a role missing, first confirm whether the user is authorized to obtain that file. Only with clear authorization and understood effects should one setting on the test account be changed through the current server interface, then restored and rechecked. Do not grant administrator access without confirmation or delete and recreate the user to troubleshoot. Existing reading progress is user data that must be retained.

Verify an offline copy separately

After an actual download completes, locate the test content in ManYue and inspect first and last pages. Then test offline reading through your own device process. Mark it untested if download or network disconnection was not performed. Successful network page reading and a complete usable local file are different checks. On offline failure, inspect download state and actual file before drawing conclusions about server or client, and do not delete source material. Restore the network and confirm server books and original permissions remain.

Preserve unknowns in the handoff

Record app and server versions, test time, redacted account, whether the administrator confirmed roles and each side’s results. Mark inaccessible server settings unknown and downloads or offline tests not performed. Support feedback does not require passwords, complete addresses or another person’s comic.
