When individual book metadata becomes series information, fields can use different rules. Calculate and check each with three test books.

Separate book and series fields

Komga can import book and series metadata from ComicInfo.xml inside a CBZ. Its documentation says series Publisher uses the most frequent value across books, while Count uses the highest value. These aggregations differ and depend on library import options. Observe actual series information in Manyue+; Komga field rules do not establish that the app offers the same editing controls.

Prepare three authorized test books

An administrator prepares three self-made or authorized small CBZ copies A, B and C in an isolated test series, each with a distinguishable first page. Keep original archives and a database backup; do not edit production comics. The account must access the test series. Without a test library, backup or administrator permission, stop at preparation and mark unperformed. Do not disclose unauthorized comic images or private server addresses.

Build a field-value ledger

Have the administrator prepare Publisher and Count in each test copy’s ComicInfo.xml. For example, A has Atlas and 4, B has Atlas and 7, C has Birch and 5; publisher names are fictional markers. The documented candidates are Atlas, occurring twice, and Count 7, the maximum. Record each filename, first-page marker and fields on paper to avoid confusing similarly named files.

Confirm import conditions

The administrator checks that the test library permits importing the relevant ComicInfo.xml metadata, that the file is inside each CBZ and that XML parses. Record server version, library options and test-file identities. Check tag names, case and closure against current documentation and format. If import is disabled or another setting affects the fields, mark the condition unmet; do not change production library settings to force a prediction.

Run one controlled refresh

The administrator scans or refreshes test-series metadata through the current version’s normal procedure and waits for completion. Record whether the target is a book, series or entire test library and note completion time. Avoid blindly processing a production library. First confirm A, B and C belong to the same test series on the web, then inspect its publisher and total-book field. Record actual values, not predicted ones.

Check the two calculations

Count the publisher values: Atlas occurs twice and Birch once, making Atlas the candidate. Compare Count values 4, 7 and 5; the maximum is 7, not the most common number or the three files actually present. If server results differ, check recognition of all books, import options, field values and refresh status. This exercise does not assert how a tie for most frequent value is resolved; mark a tie pending.

Inspect the same series in Manyue+

Connect Manyue+ to the same Komga server and account. Enter the same test series and inspect any title, publisher or count actually shown by the installed interface. If a field is absent, record unavailable or not observed rather than declaring a failed import. If an old value appears, verify source, account and time, then re-enter using the app’s actual controls. A correct server value does not prove immediate client refresh.

Separate total count and actual books

Even if series Count displays 7, the test series contains only three books. That number is imported total-series metadata, not proof that seven files exist. Record actual entry counts on web and Manyue+ and whether A, B and C open to their first pages. Do not automatically add, delete or download files because numbers differ, or treat four absent books as proof of a scan failure.

Investigate content and refresh scope

If only two books are recognized, check folders, account and completed scanning first. If all three exist but metadata is old, the administrator can inspect ComicInfo.xml in the copies, import options, field locks and refresh scope. Keep previous observations and change one condition at a time instead of modifying all archives at once. Ask the administrator to confirm current lock behavior rather than bulk unlocking production entries.

Add checks between files and the interface

Have the administrator keep a short ledger outside the archive copies listing each filename, Publisher, Count and first-page marker. After preparing fields, reopen all three copies and verify each contains the intended ComicInfo.xml and test markers are not in another series. Unsaved editor contents do not prove an archive was updated. Use the administrator’s familiar archive tool without batch-overwriting originals.

Before aggregation, check the server identity of each book. If B was not scanned, its Count 7 cannot predict the current recognized series value. Wait for scanning and verify A, B and C are in the same series before comparing candidates. If differing Series fields alter grouping, record it and pause rather than changing every field in one operation.

Atlas and Birch are fictional test labels and the numbers are not real bibliographic facts. Do not present them as production metadata after removing the sample. For an actual series, verify each source and field first so duplicate files or different editions do not distort the calculation.

Restore and hand off

The administrator restores or cleans test copies under normal policy and verifies production books, metadata and database backups remain intact. Record three field sets, candidate calculations, actual web values, visible Manyue+ fields and unperformed steps. Exclude private accounts and comic text. This guide relies on public documentation and claims no private-server connection or physical-device test.
