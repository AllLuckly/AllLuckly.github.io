Use the published music-theme feature while checking selection, player appearance and track identity separately.

1. Separate the store release from the installed version

Public information on November 16 lists 1.0.1 and adds music themes, but a store release does not mean every device updated automatically. Record your installed version, working playback state and original theme/appearance. If an older version lacks the entry, preserve music/settings and resume after your normal store-update choice, rather than delete the app. Published information supplies no complete theme names, count or pricing conditions. Use actual available choices instead of treating older screenshots as a new-theme catalogue.

2. Fix a local track and inspection views

Choose one authorised imported playable track and verify title, artist, duration and opening sound. Retain queue, mode and volume. Inspect player, available lyrics and queue; missing lyrics remain missing without an unknown catalogue search. Change only the theme, leaving light/dark state and orientation fixed initially. Preserve artwork too, so a different cover’s colours are not mistaken for a theme effect. Each round should return to the same track and view for a meaningful comparison.

3. Record two choices from the actual theme entry

Open the installed music-theme controls, record the original selection and choose two distinguishable options actually available to you. Follow real names and selection actions without inventing a theme store, download or save button. Read any additional conditions and use another available choice instead of an unknown purchase. If only one choice is visible, retain the limitation. System dark mode is not automatically a second music theme; theme selection and system appearance need separate comparisons.

4. Inspect the first applied theme in the player

Select/apply the first choice through the actual flow, return to the same player and inspect background, text, controls and artwork surroundings. Separate preview from active playback; a selection marker does not prove every region changed. Listen briefly to verify the track and check pause/resume instead of using button colour as audio evidence. For no change, inspect preview versus application and identity before repeatedly selecting options. Preserve the round so later differences can be located rather than recalled as a vague preference.

5. Keep content fixed for the second theme

Save round one and change only to the second theme. Revisit the same track/views and inspect player, lyrics and queue. Readability, recognisable controls and artwork overlap are observable; improved speed or audio quality is not established without measurement. An unchanged area may retain shared styling and should be recorded honestly. If the track ends during switching, separate that new content and restore the sample before comparison. Different covers or lyrics cannot prove the theme changed all content.

6. Keep theme appearance within published scope

A theme changes presentation, not automatically equalisation, recording visualisation, playback speed or custom-image importing. Release notes establish multiple themes, not independent parameters, automatic day/night switching or cross-device synchronisation for each. Keep additional controls pending rather than interpret decoration as an audio function. Light/dark appearance and available space are separate lessons; retain them here instead of merging three changes into one result. External records suffice without an automatic theme report.

7. Diagnose entry, display and playback separately

For a missing entry, inspect installed version and availability. For an unchanged display, inspect preview/application. For changed appearance with silence, inspect pause, volume, output and track. These are distinct paths, not one theme failure or a reason to rebuild music. Restore one condition and compare the original theme. Record interruptions such as an update or automatic system appearance change, then establish a clear new round rather than treat ambiguous screenshots as evidence. Untested options remain unknown.

8. Restore the original and retain the comparison

Restore the recorded original or deliberately retain a chosen option, then verify appearance and sound on the same track. Deliver installed version, two real choices, preview/active differences, fixed-content conditions and restoration. Distinguish theme, artwork, light/dark state and audio identity instead of supplying attractive pictures alone. Recheck changed theme lists in later releases rather than freezing today’s count. No exhaustive device testing, unpublished audio processing or unverified purchasing entitlement is claimed.
