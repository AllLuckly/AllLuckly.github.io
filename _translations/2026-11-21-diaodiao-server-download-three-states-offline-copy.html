A server listing, a completed download and a copy audibly playable without a network are three distinct states. The public release notes for 调调 1.0.4 mention offline download improvements. This exercise observes one recording you are authorized to use.

Choose a controlled recording and source

Choose a recording on a compatible personal music server you manage or may access. Record its title, artist, album, duration and a recognizable opening cue. Confirm permission to save and use it offline and preserve the original master. Choose a small file that will not interfere with normal use. If server download permission is unclear, check it first. Do not download someone else’s private library for this exercise or publish passwords, tokens, internal addresses or playback history.

Record the state before downloading

Connect while the network is working, check account and service alias, find the target and play briefly. Record metadata, audible cue and source. Stop playback and check whether the actual interface offers a download action and whether a downloaded state already exists. Do not delete a pre-existing offline copy: choose another authorized recording without one. A distinct starting state is necessary to interpret change. If no download action is available or the server forbids it, mark the exercise not applicable or pending rather than inventing a button.

Plan a reversible network control

Record the current Wi-Fi, mobile data and conditions needed by the server. Consider a temporary disconnection only when it will not interrupt calls, work or other people. If turning off Wi-Fi also disrupts Bluetooth or a vehicle device, use the phone speaker instead and record that difference. Check the actual system network state and output. Do not weaken security settings. A connection type alone proves neither download completion nor later audibility.

Start one download and observe feedback

Use the target item’s download control if actually offered. Record start time and visible feedback. If progress or a completion mark appears, record appearance, changes and end separately; if completion cannot be identified, leave it pending. Do not disconnect immediately after tapping and declare success, or repeatedly trigger requests during a long wait. If an error appears, preserve a credential-free description, stop and do not delete the server original to retry.

Reopen and identify the specific item

Use the actual interface to find the downloaded item or offline entry and check title and duration against the target. A generic completion icon without an identifiable item supports only “completion notice observed, copy identity pending.” Leave the page and return once to observe whether the state remains. The display does not establish file format, storage path or an exportable filename without separate reliable evidence.

Play under reversible offline conditions

After a completion notice, temporarily disconnect the relevant networks only when safe and reversible; confirm the service cannot still be reached through another data connection. Select the target again from the identified offline entry and play enough to recognize the original cue, recording output, cue and player state. A recently buffered opening does not prove a complete download. If safe for user data, reopen the app or select an identifiable position away from the start, recording exactly what was observed. Do not claim the entire track or all caches were verified. If a cache and an offline copy cannot be distinguished, leave the outcome pending.

Restore network and troubleshoot

Write which condition changed, for example that cellular data as well as Wi-Fi was disconnected. If another connection cannot be paused, record that the control is invalid, restore settings and stop; do not change account or server security to manufacture an offline environment.

Restore the original network immediately and confirm normal connectivity. If a download entry is missing, check service permission, installed version and selected source. For failure, check connectivity and available space. If completion is displayed but offline playback fails, separately examine the selected item, device output, network change and actual offline entry. Change one condition per retry and preserve before/after records. Do not reinstall, reset the server or delete unrelated tracks as a first step. Service and interface differences mean not every source is guaranteed to support downloads.

Deliver and restore playback

Keep a credential-free record of track identity, starting state, download feedback, state after reopening, offline conditions, listening position and pending items. Restore volume and queue. You may decide whether to remove this test download after confirming originals and other copies are safe; retain it if identity is uncertain. A partial observation does not establish full-file validation, all-format support or cross-device synchronization. No private-server or device test is claimed.
