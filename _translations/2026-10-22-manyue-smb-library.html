If your home NAS already exposes SMB, choose its comic folder directly in ManYue. Follow host → share → folder → sample → local download. Start with a small directory before adding frequently used libraries for clearer browsing.

Separate host, share and subfolder before connecting

Ask the administrator for host, share, account, allowed directory and any required domain. The host provides the service; the share exposes an allowed file range; subfolders live beneath it. A management webpage, complete browser URL or local computer path is not an SMB host.

This article uses nas.example.com, Comics and reader_example are placeholder host, share and account values, not working services. Connect the device to a network reaching the NAS, not an isolated guest network. Check current purchase-page SMB requirements separately from legitimate server read permissions.

Choose SMB in remote libraries

Add a remote library, choose SMB and fill each connection field. Keep a recognisable purpose name in your own notes and credentials separately. Check host and account before connecting. Fill a domain only if the server requires it and the administrator supplies it; do not guess to populate every field.

After connecting, choose the share and then comic directory. Login and visibility of the target share are separate stages. If absent, ask the administrator to check assigned shares; shelf setup can wait until file listings work.

For initial setup, verify the administrator’s information step by step:

Location Information to use Common checks
Host field NAS hostname or address Whether the current network reaches this device
Account field An authorised share account and password Whether login succeeds
Domain field, if present Domain information actually required by the server whether it matches this account’s login method
Share selection The target share listed after login Whether the account can access this share
Folder selection The actual comic folder inside the share Whether the chosen sample can be found

After saving, return to the server list and reopen the SMB connection to verify repeatability. If the second attempt enters another folder, check saved server and library scope before importing.

Build a library from a small directory

Choose a library folder containing only a few comics. Match filenames to the NAS and use an ordinary CBZ or PDF sample. Do not scan the whole share containing work documents, backups and photos initially; a small scope makes failures easier to locate.

Refresh the relevant library after folder changes. Restore a sleeping NAS or disconnected network before judging files invalid. Temporary unavailability does not mean deletion, so do not immediately clear every unavailable record. Verify server online → share listed → file readable.

Choose online reading or local download

Open the sample and inspect distant pages to confirm real loading. Online reading depends on the current NAS connection; leaving Wi-Fi, leaving the network or NAS sleep changes access. Cached covers and read pages are not complete offline copies.

Use the item’s download action, wait for completion in download management and open it locally. Disconnect and inspect beginning, middle, end and intended chapters. Queue records, favourites and files serve different purposes; one checkmark or cover does not prove offline preparation is complete.

Example: weekly reading on a home NAS

Suppose your NAS has Comics share, containing ToRead and Archive. First connect through SMB and choose ToRead with your own short comic to verify online reading. Download two books for the week and test without networking. Browse the share remotely day to day, and open these two locally when commuting.

Working on home Wi-Fi but failing on cellular first indicates a changed access path, not corrupt files. Retain the working local connection and use offline copies outside. If remote access is needed, use your own managed network solution; this tutorial does not recommend exposing SMB ports publicly for the example.

Final checks and permission limits

Reopen the saved connection, enter the correct share, read the sample and complete needed downloads. Before clearing local files, confirm NAS originals and account access remain. Removing an app connection is not deleting the server library; retaining its name cannot restore moved remote files.

Why does NAS web login work but SMB fail?

Web administration and file-share permissions may differ. Check SMB activation, account access to the share and network reachability. A temporary webpage session is not an SMB credential; administrator webpage access does not grant every protocol permission.

Is WebDAV or SMB always better?

There is no universal answer. Choose a correctly configured, stable method whose permissions you understand. Test reading and downloading the same sample, then decide for your network. One speed result does not apply to every NAS or file.
