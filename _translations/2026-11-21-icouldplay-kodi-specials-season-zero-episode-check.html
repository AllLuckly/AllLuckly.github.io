In your own Kodi television library, compare one regular episode and one special across server classification, iCouldPlay's list and actual playback. Kodi's documentation normally numbers specials in season zero. Whether iCouldPlay exposes a separate special group depends on the actual connection. The goal is to identify two videos, without assuming a client control can change grouping or rename them.

Prepare two distinguishable owned videos

Use an accessible Kodi library you control and an authorized regular test video and special. Give each a non-private identifying cue, such as an original opening frame reading “regular test” or “special test.” Back up originals and existing naming and library settings. Do not upload private films or publish a server address. Never delete real episodes or overwrite existing media for this exercise. If no test copy exists, observe authorized material and stop before any rename until recovery is understood.

Establish classification in Kodi

In Kodi, find the same series and record the regular episode's season and episode, the special's location and name, and each file identity or opening cue. Kodi's naming documentation uses S01E01 for season one episode one and commonly names specials S00E01; actual special numbers depend on the information provider and existing library. Do not apply the examples blindly to another work. If no special exists, an independent test library can be prepared using Kodi documentation without changing the original. Without permission or willingness to add one, mark the baseline pending and stop later conclusions.

Record connection conditions

In iCouldPlay use an already configured Kodi source. If it does not connect, follow the Kodi connection guide to check a trusted network, service address and existing account permissions. Server season numbers form the baseline; do not publish account names, tokens or full private paths. Open the Kodi source and confirm the series identity, recording device, confirmable iCouldPlay version and network. If the source cannot open, resolve connectivity first rather than treating that as a missing special.

Find and play the regular episode

Enter the series list actually displayed, find the regular test episode through its available season or episode view, and record client title, season and number. Play it and verify its opening matches the regular cue. If no season number appears, retain visible title and list position rather than filling in what you expected. Return to the list and confirm the source is unchanged. If playback does not match the title, preserve the initial observation and check source-file mapping before changing a name.

Find the special and observe presentation

Return to the actual season or episode list and look for specials or season zero; if there is no separate grouping, inspect other entries actually offered. Record whether it appears, where and under what name; play it and verify the special's opening cue. Absence of a separate group does not by itself prove the file cannot play: a list can be merged, hidden or not yet updated. If it cannot be found or played, stop at the evidence, retaining client display and server baseline instead of inventing a menu or asserting that all specials are unsupported.

Separate server classification from client result

Make a two-row table with content identity, Kodi season and episode, iCouldPlay position, playback cue and pending checks. Mark each playback successful only when that specific video opens and matches. Identical titles do not replace opening-cue checks. If Kodi classifies correctly but the client places an item differently, record the display difference. If Kodi itself is wrong, address that baseline before attributing anything to iCouldPlay. Do not delete media or reset the library because an entry is temporarily missing.

Troubleshoot and retain a recoverable record

Check the intended Kodi source, account visibility, the two server records and whether client display has updated. Change one observable condition at a time and record before and after. If refreshing or reconnecting is necessary, use only a method actually offered; do not assume a refresh button. If an entry plays the wrong cue, inspect server mapping and file. If listed but unplayable, follow the connection and media-path guide. Do not disable access protection or publish credentials while troubleshooting.

Observe one return to the series

Exit playback, return to the series entry and follow the original path to both test items again, checking list names and openings separately. If only one appears, verify the same season or filter scope. When no season number is shown, record the actual navigation path rather than guessing from the title. This checks visibility on this re-entry, not automatic appearance of every future special.

Deliver and restore

Deliver a two-row table without private addresses, identities of the two test videos and source links. Restore the original source and viewing state. If using an independent test library, confirm the original library and backups remain intact. Record actually completed playback, unavailable controls and pending work. No physical-device, private Kodi server or exhaustive version-combination test is claimed.
