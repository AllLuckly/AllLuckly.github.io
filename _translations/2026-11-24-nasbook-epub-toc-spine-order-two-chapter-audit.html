Compare the EPUB navigation and default reading order in an authorized two-chapter sample.

Identify two orders

EPUB 3.3 defines the spine as the default reading order, while the navigation document supplies global contents links. A visible label, link target and reading sequence are different facts. Do not infer the first default chapter solely from the first contents entry. This exercise uses a self-made or authorized two-chapter sample to observe contents navigation and sequential reading in Book Isle without assuming it exposes technical fields.

Prepare a sample and backup

Back up an owned original or create a short test EPUB with two distinct chapter titles and opening sentences, such as chapter A and chapter B. Give the test a clearly different filename so it does not overwrite existing reading history. Do not unpack protected purchases or bypass restrictions for the exercise. Without an authorized editable sample, make a paper table and mark the test unperformed.

Record default sequence

In an EPUB editor inspect the package manifest and spine: confirm both chapter files are listed, then record the first and second primary reading entries. If the editor presents a graphical sequence, record the corresponding filenames as well as labels. Do not treat an auxiliary item outside primary reading order as an ordinary chapter or alter encryption for the test.

Record labels and targets

Inspect the navigation document or contents editor and record the displayed label, linked file and any fragment for each chapter. Verify both links point to the intended existing targets; identical labels do not prove identical targets. Use separate columns for displayed contents order, link targets and spine order. Fill in expectations before judging Book Isle behavior.

Validate and save a working copy

Use the editor’s EPUB check or a trusted validator for missing resources, links and package structure, and save the working copy separately. The specification recommends that contents entries follow spine content order. If a diagnostic sample deliberately differs, record that it departs from the recommendation rather than presenting it as preferred layout. Validation alone does not guarantee identical display in every reader.

Import and identify the book

Use Book Isle’s currently available file import method to add the test copy, then check title, chapter text and cover so it is not confused with an older copy. Record actual prompts and incomplete steps if interface, file access or format support differ. Do not clear the shelf or delete the original to troubleshoot. Note the initial reading position and return to the contents if needed.

Follow contents links

Open the contents actually offered by Book Isle and select chapters A and B in turn, recording each label and the opening sentence reached. If contents are absent or a link does not respond, record unavailable or failed; a manually searched passage is not a substitute for a contents click. Use the interface’s actual return method and stop if the state is unclear.

Compare sequential reading

Starting at the confirmed opening of chapter A, read sequentially using the method currently supported by Book Isle and observe the next chapter. Do not assume one gesture works in all settings. Compare the actual sequence with the spine record and keep contents-link results separate. If the chapter boundary was not reached, mark it unknown rather than inferring from the contents.

Diagnose a wrong mapping

If chapter A’s link opens B, inspect its navigation file and fragment, whether chapter contents were swapped, and whether the device opened the latest copy. If sequential reading differs, inspect primary spine entries and validation results. Change one item at a time, save separately, validate and import the new copy. Do not attribute an unchecked mismatch directly to a reader.

Record and retain originals

The table should include contents label, expected file, actual opening sentence, spine order, sequential result and reasons for unperformed steps. Add a row for another device or version rather than rewriting the first observation. Do not share private library paths or unauthorized text. Identify the test copy before deciding whether to remove it; retain original and backup. No device or private-library test is claimed.

Verify a fragment within a chapter

If chapter A has a subsection, give it a unique target in the authorized copy and point a corresponding contents entry to that fragment. Record the full relative path and fragment name, then select it and observe whether it lands near that subsection. It remains part of the chapter A document and does not automatically become a separate spine item. If the reader does not scroll precisely to it, check that the fragment exists and the path resolves relative to the navigation document, then record the actual landing point; do not infer a missing resource from scroll position alone.

Separate repair from retesting

Correcting contents labels does not require changing reading order. Inspect the spine separately in an editable working copy only if the default order also differs from the intended sequence. Give each copy a distinct version marker and repeat both contents selections and the sequential reading comparison, recording the results before and after the change. If the app still shows an old result, first confirm that the newly imported copy is open; do not start by clearing reading data.
