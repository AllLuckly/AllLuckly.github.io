Both discs of a two-disc album can have a “track 1.” ID3's set-part number and track number are separate fields. Whether 调调 displays a disc number, groups entries or sorts by it must be observed in the installed version; matching track numbers alone do not make recordings duplicates.

Prepare distinct authorized samples

Choose two different MP3 recordings you own or may use, to represent track 1 on disc 1 and track 1 on disc 2 of a fictional album. Keep a different recognizable opening cue and duration for each. They need not come from a real release, and you need not supply every other track. Preserve originals and backups, then make working copies and a sanitized table of file alias, sound cue, album, disc and track number. Do not expose private files or overwrite the only original for this exercise.

Separate disc count from track count

In ID3v2.4, TALB is the album title, TPOS identifies the part of a multi-part set, and TRCK identifies a track's position in the original recording. Either number may include a slash and total. For example, the first file may have TPOS=1/2, TRCK=1/3, and the second TPOS=2/2, TRCK=1/4. The fictional set has two discs of three and four tracks, while this exercise supplies only two tracks. 2/2 is neither track 2 nor duration, and 1/4 is not disc 4.

Inspect working copies in an external tool

Use a trusted local tag tool to inspect each copy's album, disc number, track number and tag version. If safe editing is available and you understand its effects, set the example values on working copies only. If the tool is unavailable, unfamiliar or may re-encode media, use already tagged authorized files and record their real values. After saving, reopen and check both file identities and fields. If the tool shows split disc-number and total fields only, record those fields rather than claiming you saw the raw TPOS text. External tool capability is not an in-app tag editor.

Use separate columns to avoid a duplicate assumption

Write disc and track columns as 1/2, 1/3 and 2/2, 1/4, with separate sound-cue and file-alias columns. Both track numbers are 1 but disc numbers differ, so the matching track number does not prove duplication. Different disc numbers likewise do not prove different audio: check the actual sounds. Record album names as the tool displays them. If one differs, preserve that difference rather than predeclaring that the app has one album.

Import and inspect visible information

Use a file-import entry actually visible in 调调 to select the authorized working copies, recording the selection count and feedback. Find visible items and compare each title, album, duration and other fields actually shown. If disc number is absent, mark it invisible; neither infer the app did not read it nor claim it grouped by disc. If only one item appears, inspect import feedback, file identity and the current view first. Do not delete your existing library or modify private data to force two entries.

Play each entry to confirm identity

At a suitable volume, play the first visible item's opening and compare it with the first reference cue. Return to the actual visible list, play the other and compare its cue. Record the selected item, playhead, audible cue and whether the wrong item may have been selected. If the second is not visible, mark it pending. Similar titles or durations do not replace separate audio checks. Hearing an opening does not establish byte identity of the whole file or which ID3 frame the app read.

Treat grouping and order as observations

If the version provides album browsing, record whether both items appear together or separately and whether any disc title is actually visible. Mark absent entries and unseen flags unknown. Even if disc 1 appears before disc 2, this only records the order in this run and does not establish a TPOS-based sorting algorithm. Matching external album names do not prove 调调 will merge albums, expand by disc or present the same structure in the car.

Understand the missing-disc-number boundary

Add a hypothetical table row: if each track is known only as TRCK=1 and TPOS is unknown, the disc identity cannot be determined. Do not infer disc number from the slash's track total or infer identical files from identical titles. To actually test missing-tag presentation, prepare independent copies and first understand import and deduplication behavior. Otherwise keep this a theoretical control, not a measured result. Never overwrite originals or bulk-edit the library for an experiment.

Preserve the source of each observation

Give the external tool and 调调 separate columns in the table and record observation time. If the tool is upgraded, files are reimported or new entries appear, add a new row instead of combining different rounds into one observation. If a working-copy title changes unexpectedly, return to the untouched backup and confirm the file and sound cue; do not guess its disc from the title. Keep originals separately and leave every unperformed step pending.

Troubleshoot and deliver

For unexpected presentation, separately check file aliases, sound, the two fields shown externally, the app's current source and import feedback, changing one reversible condition at a time. Deliver a sanitized two-field comparison, actual sound observations, app-visible result and pending items; restore prior volume and queue. Before removing a practice entry, verify independent backups and the app's deletion scope. This guide claims no physical-device, ID3 compatibility or disc-sort test in 调调.
