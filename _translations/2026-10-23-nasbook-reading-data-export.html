Reading notes deserve a format that opens outside the app. Book Isle's Data Export organizes statistics, notes, and highlights into Markdown or CSV. This guide starts with one test note, then exports, saves, reopens, and checks it so opening Share is not mistaken for actually retaining a file.

Specify which information you want to save

First decide whether to export reading statistics, notes, or highlights. Notes commonly include your comments and selected text; highlights primarily retain marked passages; statistics record reading activity. Their purposes differ, so there is no need to generate many duplicate files every time for “completeness.” Verify one type first, then establish a regular saving habit.

Prepare a clear test note, such as “Export check: retain the original text and my explanation” in chapter two of a practice book. Note the title and chapter so you can find it in the output. Book content and reading information are different: exporting notes does not automatically package the entire EPUB, PDF, or audio file.

Choose a type and format in settings

Open “Settings” → “Data Export” and inspect the available type and format combinations. Start with notes in Markdown for direct reading and text editing, or CSV for sorting and summarizing in a spreadsheet. The interface may combine type and format into an option such as “Notes Markdown”; use the actual choices shown.

After choosing, wait for file generation and then enter the system share sheet. Do not rush to leave the app; generating many notes may take time. If an error appears, retain its message, check device storage, and test a simpler data type. Repeated tapping may only generate several same-named results rather than diagnose the failure.

Choose the save location explicitly

In the system share sheet, choose “Save to Files” or your actual destination, using a clear folder such as “Reading Materials/2026-10.” Filenames can include date, type, and scope, such as “2026-10-23-notes.md.” If a same-named file exists, decide whether to keep historical versions before saving to avoid accidentally overwriting last week's records.

After the final save confirmation, open system Files and locate the output. Saving is complete only when you can see and reopen it at the destination. A share sheet, file preview, or selected folder may still require a final confirmation. Complete the entire process the first time so later results are easier to judge.

Check content and sources in Markdown

Open the Markdown file and search for the distinctive phrase in your test note. Check for the book title, chapter, selected text, and your explanation, comparing them with the original record in Book Isle. Markdown is readable text whose appearance depends on the viewing tool. Visible hash marks or list symbols are not necessarily errors or evidence of damaged content.

Also inspect a note with punctuation, line breaks, or a longer quotation for understandable order. An export lets information leave its original interface and remain useful elsewhere. Check text and provenance rather than expecting another tool to reproduce the app's card appearance exactly. For an attractive sharing image, use the separate quote-card workflow.

Check columns before working with CSV

Open CSV in a spreadsheet tool that supports it. First check column headings and Chinese text, then whether a record falls into the correct columns. Notes may contain commas, quotation marks, or line breaks, so counting visible commas is not a reliable column count. Incorrect character encoding or delimiter settings can make text appear garbled or squeeze an entire row into one cell.

Statistics exports may cover today, this week, or a month. Before comparing, confirm scope and units, such as whether duration is in seconds, before calculating or plotting. Do not directly compare a cumulative value with a daily value or heavily modify data before retaining the original CSV. Keeping the original output makes review easier.

Plan exports separately from backups

Markdown and CSV support reading, searching, and further organization, and can be archived as independent files. They cannot restore the entire Book Isle state in one step. They do not automatically contain all original books, cover caches, remote accounts, or settings. For device migration, separately prepare ebook sources and handle reading data within the sync feature's scope.

A lightweight routine could be to export notes after every important book and save statistics at month end, while managing original books through your own file-backup method. Dated versions help recover text from before accidental deletion or editing. Real-time sync often propagates the latest change and cannot replace every need for historical archives.

Frequently asked questions

Why is the exported notes file so small? Text records may naturally be small. File size does not establish completeness. Spot-check a test phrase, title, and record count rather than judging only a few KB. Highlights and notes are different export types, so confirm that you chose the intended one.

Why is the saved file not visible on another device? It may have been saved locally rather than to the expected cloud folder, or the external file service may not have uploaded it yet. Check the destination path and file-service status first. This is a separate workflow from Book Isle's WebDAV reading-data synchronization.

Can I import CSV back into Book Isle to restore all progress? CSV is an export for viewing and organizing information, not a replacement for the Book Isle database or a one-click way to restore all records. Use actually supported sync and import methods for restoration or migration. An editable spreadsheet is not an app database backup.

Next steps
