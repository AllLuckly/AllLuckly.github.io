A first screen of covers establishes only partial catalogue visibility. Large services may require more pages, nested navigation or indexing. Use known reference items to separate account scope, incomplete loading and filtering, while keeping the limits of sampling explicit.

Build a same-account reference

Using the same reader account, choose three to five clearly identified items across the catalogue. Record title, library and edition rather than vague page positions. Do not compare a reader with an administrator total. Note indexing/maintenance and avoid a changing baseline; a small private reference list is sufficient.

Clear filtering and fix the connection

Select the intended connection and scope, clear old queries and inspect refresh/error state. A multi-service home view is not necessarily the full server catalogue. Wait for visible loading to settle and keep connection and account fixed while locating reference items.

Locate known items across the range

Locate and open each reference item. Missing late items are an observation, not proof of an undocumented fixed limit. Check loading, nested organisation and connection identity. Reconfirm missing entries in the same-account server view to exclude recent moves or visibility changes.

Separate filtering from catalogue retrieval

Determine whether the entry filters loaded fields or uses a source-specific remote query. Verify a known simple title and clear it again. Local filtering cannot discover items absent from the loaded snapshot, and server syntax may not apply. Label search context before changing metadata or diagnosing matching.

Check changes during multi-page loading

Wait for server maintenance to stabilise before one normal refresh. Record repeated items, missing references or explicit errors without deleting archives. Provide sample identities and timing to the maintainer, including concurrent catalogue changes. No guessed page sizes or manual internal-file edits are needed.

Compare a smaller supported scope

Use a smaller supported feed or library scope only if the service actually offers one and permissions allow it. Preserve the original connection and label the comparison. Do not guess paths or reorganise all server files merely to test. Small-scope success narrows the issue without proving large-catalogue completeness.

Inspect actual reading as another layer

After locating references, inspect body pages and sample a middle/end too. Catalogue presence, file readability and offline availability are separate results. Record each layer explicitly and leave untested checks blank. A page failure calls for its own permission/file investigation rather than erasing the catalogue observation.

Acceptance and sampling limits

Finish with understood account scope, located references, explainable refresh/filter results and recorded page samples. Neither the list bottom nor a few passes proves the entire library intact. Keep date, connection and missing-reference notes for later checks without publishing private catalogues or rebuilding everything.
