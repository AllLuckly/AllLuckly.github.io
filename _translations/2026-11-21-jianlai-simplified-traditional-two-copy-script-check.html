A Chinese title may need simplified and traditional drafts. Interface language, active keyboard scheme, candidates and committed characters are separate facts. Specify both targets first and inspect the methods actually available; do not assume Jianlai has a particular conversion button.

Prepare two invented titles

Keep a nonprivate reference card in an ordinary note: simplified “学习记录” and traditional “學習記錄.” Each has four Han characters, with corresponding positions 学／學, 习／習, 记／記 and 录／錄. Preserve the card and create a separate practice copy; do not edit or publish real documents. Meaning only supplies a character exercise here: one example does not establish that all simplified and traditional words map one character at a time.

Confirm the available keyboard and scheme

Confirm Jianlai was added and actually selected in the ordinary field. Record device, system, host, Jianlai version and scheme shown. Public information describes multilingual input but does not establish a fixed traditional switch, automatic conversion process or identical candidate order on every layout or device. Use only actual visible language and input controls. If a route is unavailable, leave that draft pending; you may paste trusted reference text for later character checks, clearly labelled as pasted rather than directly entered with Jianlai.

Complete the simplified draft first

On the first line enter “学习记录” using an available scheme. If candidates appear, verify the user actually selected the target; if committed directly, record that. Inspect the ordinary document for 学, 习, 记, 录 without extra space or punctuation. If the first result differs, preserve it and correct a separate line. A correct candidate or key label does not establish committed text.

Complete the traditional draft separately

On a second real line enter “學習記錄” with the actual scheme and candidate controls. Do not require changing interface language or assume a specific encoding. If needed characters are unavailable, record conditions and leave the draft pending; a separately labelled pasted reference can support later character observation. Record unconfirmed composition, confirmation and focus changes. Prediction or preview is not committed document text.

Compare both drafts position by position

Use a four-position card: the simplified draft should be 学, 习, 记, 录 and the traditional draft 學, 習, 記, 錄. Record expected and actual values in each position. If one differs, do not vaguely call the whole result a font issue. The same character can appear differently in different fonts; visual similarity does not establish identical code points. When needed use a trusted local tool, validating both the tool and copy process with known references. Mark uncertainty pending.

Compare input scheme and interface labels

With a local tool that retains raw text, the simplified code points are U+5B66, U+4E60, U+8BB0 and U+5F55; the traditional points are U+5B78, U+7FD2, U+8A18 and U+9304. Each is one character in this example; font appearance or count alone does not prove the full text. Validate a tool with known reference cards and record if copying may transform text. Without a trustworthy tool retain visual comparison and mark code points pending; private drafts need not be uploaded.

Record each of the four positions in each draft. For example, if the third is “记” when the target is “記,” mark that position wrong even when the other three are correct. Make any correction in another copy, keeping the first result for review.

Record interface language, selected keyboard, input scheme and final text separately. An English interface does not automatically prevent Chinese input, and a scheme labelled Chinese does not guarantee the target traditional character appears. If switching schemes changes the first draft, record timing and host feedback and repeat in a separate copy; do not assume automatic conversion of existing text. Save both drafts separately instead of overwriting one to demonstrate the other.

Troubleshoot missing or mismatched characters

If a target character is absent, check scheme, entry and visible candidate range. If a box appears, inspect device font and display separately rather than immediately declaring the character lost. If displayed characters differ from the card, keep the first result and correct independently. If a change occurs only after synchronization or copying, inspect host and handoff. Change one condition per trial. Not all simplified and traditional expressions permit character-by-character substitution; do not use this exercise as formal translation.

Restore and deliver

Restore your usual keyboard and input scheme and confirm the reference and practice drafts remain. Deliver target card, available scheme, candidate confirmation, position-by-position comparison and pending items. Disclose pasted text and unverified code points. One observation does not establish compatibility for all Han characters, languages or hosts. Public multilingual information and Unicode charts inform this exercise; no physical simplified/traditional input or font compatibility test is claimed.

Record the actual observation date and app version; after updates preserve a separate trial for comparison.
