The English name of 云映 is iCouldPlay. It plays local videos and connects to file servers and media servers. For a first session, importing a one- or two-minute video you shot yourself makes the different entry points easier to understand than immediately connecting an entire NAS. This article completes a small loop: bring a file into the app, find it in the library, play it, exit, and reopen it.

Prepare a video that is easy to verify

Prepare an MP4 or MOV in the system Files app. Its filename could be FamilyWalk-2026-10.mp4. Confirm that it is fully downloaded to the device and can open in the system, rather than merely showing a cloud placeholder. Ideally, use a video with both picture and sound, about two minutes long and a few dozen megabytes, so import problems are easy to distinguish from playback problems.

Record the original filename, duration, and location. Importing saves a video copy in the app's local directory, so free storage is required. It does not turn a cloud link into a space-free bookmark. Keep the original until verification is complete, then decide how to manage copies. Do not casually delete the only file while importing.

Select a file through the import entry point

Open iCouldPlay, find Import Video in the Library, and choose Import from Files App. If your version reaches local storage through Sources, it also presents the local-video selection flow. In the system file picker, find the prepared video and confirm. Picker appearance differs across system versions; the key is selecting the actual video file rather than its containing folder.

Select only one file for this first exercise. Wait for the import result before leaving, and compare the success count with the number selected. Large or cloud-hosted files may need downloading before copying; the wait alone does not mean the app has frozen. Canceling the system picker creates no new entry when you return to iCouldPlay. Simply open the picker again.

Verify the entry in the local source

Return to the library, switch the source to local videos or the corresponding local storage, and select All first. Find an entry with the relevant filename and check its duration and picture. A personal video normally has no movie poster or plot synopsis. Do not randomly match it to a film merely to make the card attractive. Library-card information and the video file itself are separate and can be handled separately later.

If the entry is missing, first check whether the source filter remains on a network server, then whether the category shows only movies or shows. Do not import the same filename ten times in succession. The current import flow checks for existing files with the same name, so selecting it again may not add another card. Give two different clips with the same name clear, distinct names at the source first.

Check only three positions on the first playback

Open the video and watch the first ten seconds, checking picture orientation and sound. Seek to the middle, then check again near the end. All three positions playing correctly gives better evidence of completeness than the first frame alone. If the image is cropped, check the player's aspect-ratio or fit-to-screen option before assuming the import changed the video's dimensions.

Keep system volume audible during testing and confirm that sound is not routed to Bluetooth headphones or another audio device. If there is picture but no sound, compare a known-good short video first, then see Audio-track selection and sound troubleshooting. A successful import only means the file reached the local directory; it does not guarantee compatibility with every codec combination.

Check viewing progress after exiting

Play the two-minute video to about forty seconds, return normally to the library, then reopen the same entry. Observe whether it prompts you or resumes at the previous position. Playback settings may affect whether it starts from the beginning. One restart from the beginning does not establish file loss. First confirm that you opened the same source and entry rather than another copy with the same name.

Progress is viewing state, not a shortened video. The original content remains when you return to the beginning. After this check, close the playback page, visit another page, and find the video again in the library. This separates 'where the file is' from 'where I stopped watching' and prepares you for multiple sources later.

Handle import failures without deleting the original

If importing fails, first check in the system Files app that the file is complete and readable, then check available device storage. Files from third-party cloud drives may need downloading or authorization first; iCouldPlay cannot supply content missing from the file provider. Place the same small file in a local device location and retry to see whether the problem is limited to one cloud location.

Read the confirmation carefully when deleting local videos. Deleting from the library may also delete the video file inside the app; do not assume it only hides a card. Understand the relationship between the original and app copy beforehand. Keep an independent backup of important family videos before organizing app content. Do not uninstall the app as a routine refresh method, because its local data may be removed too.

Final checks and next steps

After this exercise, you should be able to identify where the original is stored, which iCouldPlay source contains it, whether the beginning, middle, and end play correctly, and whether viewing progress follows the current settings. Record these facts in one line of notes; that is more useful than a screenshot showing only Import Successful. Next, see Import videos from Photos, or go straight to Connect a home SMB share.

Will importing automatically upload it to the cloud? This operation saves the selected file in the app's local directory and adds it to the library; it does not establish a cloud backup. Any system backup, file-provider synchronization, or other service depends on its own settings. Do not interpret the name iCouldPlay as a promise of automatic uploading.

Why is there no poster? Videos you shoot yourself usually are not in a movie database and can play normally with their filenames. Organize content and sources clearly first. Poster matching applies to films or shows with corresponding database entries; it cannot establish a video's origin or authenticity.
