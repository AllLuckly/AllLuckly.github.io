For someone operating a device with an adaptive switch, a usable keyboard requires more than its appearance: system scanning must reach a target and the host must receive text after a selection. This exercise is for someone already familiar with Switch Control and tries the short word ok in an ordinary note. Switch Control is an iPhone accessibility feature, not a feature exclusive to 键来. Compatibility with this keyboard and host must be observed on the device; it is not promised here.

Establish a way back first

Read Apple’s setup guide and operation guide. Apple warns that standard touchscreen gestures cannot be used to exit Switch Control once it is enabled. Confirm that you have a working switch, a known exit method and someone who can assist if needed. If unfamiliar with the feature, do not enable it just for this exercise without help. Preserve any switch configuration, scan speed and combination of accessibility settings that you rely on; record the starting values rather than replacing them with a suggested preset.

Prepare a local plain-text note, avoiding payments, passwords, secure entry and forms that could send immediately. ok contains no private information. Record device model, OS and 键来 versions, host and whether you use automatic scanning or another actual configuration. Do not record passwords, camera images or another person’s assistive-device identity.

Establish an input baseline

Use your existing accessible input method to open a new note and confirm focus is in the body. Select 键来, observe that the keyboard actually appears, type ok and check that both characters are in the body. If your everyday method is unavailable or the active keyboard cannot be identified, stop and mark the baseline unavailable; do not mistake the system keyboard for 键来. Preserve that baseline and use a new line for the next round.

The baseline establishes only that the method actually used produced this text in this host and configuration. It does not establish behavior in other apps, layouts or scanning styles. If you normally use Switch Control, your baseline is simply the result of your existing setup; there is no need to disable an accessibility feature you depend on to manufacture a conventional comparison.

Observe the scan’s reach

Using your existing Switch Control configuration, enter the keyboard area on the new line. Observe which groups or items are actually highlighted, including whether the scan reaches the keyboard, the region containing a target letter and any selectable items within it. Apple explains that item mode can scan items or groups and select an item after a group; exact grouping and labels depend on the current system and keyboard. If only the whole keyboard is highlighted or the targets cannot be distinguished, do not assume individual keys are exposed. Record exactly where progress stopped.

If selecting an item opens the system scanner menu, inspect available actions using your familiar method. Menus can differ by OS and configuration. Do not invent an action merely to match the exercise. If you cannot continue, use the previously established exit method or request assistance; preserve the notes and do not delete the keyboard or reset all accessibility settings.

Select twice and inspect committed text

With your existing configuration, attempt to reach lowercase o and perform the selection or tap action actually offered. Pause and check whether the note body contains o. Then attempt k, recording highlight, activation feedback and resulting text. A highlighted key is not proof that text was committed. Record reachability, feedback after the action and the resulting character separately. If text repeats or case differs, do not immediately attribute it to 键来: record scan style, number of activations, case state and any host processing.

If the keyboard has an uncommitted composition or candidate, verify it was actually committed before continuing. If a target cannot be selected or the text remains unchanged, stop the round and return to your everyday keyboard using a known method. Do not change security settings to force completion. Do not claim 键来 provides its own dedicated Switch Control settings or guarantees every key can be scanned.

Retry after one system change

Only if the user wants to and can reliably restore the configuration, consider changing one understood system setting such as automatic scan time. Record the old and new values and the scan style. Keep the host, keyboard layout and short word fixed, start a new line and repeat. Compare reachability and committed text rather than speed alone. If adjustment is not appropriate, keep the first result and mark the comparison untested, not failed.

Do not change switch hardware, scanning style and keyboard theme at once. Restore the user’s original value afterward and check that familiar operations still work. Menu options, grouping, activation and key recognition may vary by system, device, switch and keyboard version. One success cannot establish behavior across all third-party keyboards and hosts.

Troubleshoot by layer and preserve the result

First confirm note focus, active keyboard and whether the switch works in another known interface. Next check whether the scan reaches the keyboard; finally check whether the host receives a character after selection. A reachable baseline with no scan access differs from a selectable item that produces no text. Record each symptom separately. If another host behaves differently, record it as a separate comparison, not proof of a system-wide fault. For support, provide versions, scanning style, steps and privacy-safe observations; share necessary assistive-device information only with the user’s explicit consent.

Deliver an observation table covering the baseline, scan reach, two selections, resulting text, actual changed conditions and outstanding items. Restore the previous accessibility configuration and keyboard and keep the original note. This procedure is designed from public documentation; no device or adaptive-switch test is claimed.
