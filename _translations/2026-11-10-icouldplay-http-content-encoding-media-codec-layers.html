A gzip response field and an H.264 stream label need not conflict: they describe different layers. Establish each field’s role before inspecting the received file rather than mixing HTTP compression with media compatibility. Use your own small file and trusted records without an in-app packet inspector or a gzip decoder switch.

Fix request and file identity

Choose an authorized small media file and record local name, size, source alias and date, preserving original and downloaded copy separately. Obtain headers only through familiar tools or service records, keeping private addresses and tokens private. Otherwise use the paper example. Do not modify production settings or disable TLS checks to expose fields. Bind a request to its dated representation rather than applying old logs to a changed same-named file or generalizing across sources.

Record media type and content coding separately

This original response excerpt is not a real request result. Content-Type identifies the media type after listed content codings are removed; Content-Encoding lists HTTP content coding. Here gzip is not an MP4 video-track codec. Content-Length in this example counts the gzip-coded representation, not the decoded local file. Record field, layer and observed status separately. An absent Content-Encoding does not establish uncompressed video.

Content-Type: video/mp4
Content-Encoding: gzip
Content-Length: 1200

Separate two compression layers on paper

Use RFC 9110 content-coding guidance to draw HTTP decoding before media data inspection. In the invented example, a 1,200-byte coded representation yields a 2,000-byte MP4 whose stream may still be H.264. The 2,000 is supplied, not derivable from these headers. Different lengths do not prove loss. Already compressed media may gain little or grow with gzip; this exercise does not recommend enabling it for a video service.

Establish whether the tool already decoded content

Check the actual downloader’s documentation and options to establish whether its saved bytes are coded or decoded. Automatic decoding can coexist with preserved original headers, so explain that distinction before comparing lengths. Do not rename an already decoded MP4 to .gz and decompress it again or cycle through extensions. If behavior is unknown, leave the layer unresolved and compare a known-good local sample. Documentation of possible decoding is not evidence that you inspected this transfer.

Compare size and hashes at the same layer

For copy verification, establish that both sides are complete decoded media files, then compare size and SHA-256 through familiar tools. A coded HTTP representation and local MP4 are different byte objects; differing hashes do not immediately mean corruption. Names do not replace bytes. Exclude partial range responses and unfinished downloads from whole-file checks. Keep actual results without invented hashes. Without an original, record the copy’s identity while leaving transfer equivalence unverified.

Retain playback separately from header inspection

Open the identified local copy in iCouldPlay and record startup, picture and sound, then compare its remote path. Plausible headers do not guarantee playable media; local success does not verify remote authorization, content decoding or range behavior. Change only local versus remote access, keeping captions, orientation and speed fixed. Preserve differences without diagnosing a missing video decoder from gzip or universal compatibility from H.264. Record actual controls and errors.

Inspect actual content for pages and incomplete files

A login page or error text remains wrong content even behind .mp4 and is outside the two-layer media example. If trusted decoding fails despite a gzip claim, a maintainer must inspect header/byte consistency; changing a copied header is no repair. Resolve incomplete retrieval before codec compatibility, without masking it through posters or captions. Reports should use redacted fields, an original small sample and clear steps, preserving records and excluding token-bearing private URLs.

Finish field-layer and readable-copy records

Reopen the identified local file and confirm name and content anchor, retaining remote tests separately. Identify evidence for media type, HTTP coding, container and video codec, distinguishing supplied examples from observations. The invented 1,200/2,000-byte values are not a measured compression report. Leave uninspected fields and devices untested, restore settings, and preserve originals, copies, logs and notes separately. Completion aligns findings with byte layers rather than assigning every compression issue to one player failure.
