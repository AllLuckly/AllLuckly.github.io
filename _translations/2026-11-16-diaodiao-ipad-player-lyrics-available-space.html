Hold track and appearance fixed while checking placement, content and return paths in two actual space states on one iPad.

1. Separate device support from current available space

调调 publishes iPhone/iPad support and player/lyric adaptation to available space; an official tablet screenshot shows a large-screen arrangement. It promises neither identical columns everywhere nor a fixed breakpoint for this lesson. Record version, orientation and opening state on your own iPad, preserving its original window state. Without a tablet, review the method but do not borrow a screenshot as performed evidence. Device model, pixel resolution and current app area are different quantities; inspect the actual layout.

2. Fix track, lyric source and theme

Choose an authorised playable track with available lyrics, recording title, artist, edition, sound, theme and light/dark state. Without lyrics, check only player/missing-data presentation instead of interpreting blankness as text hidden by narrow space. Retain source and queue without switching servers while resizing. Preserve artwork/data: changing space affects presentation, not automatically regenerated metadata or timed lyrics. Stable content is necessary before attributing positional differences.

3. Choose two space states the device actually permits

Choose two reversible states actually supported by your device, such as permitted orientations or already available window widths. Name A/B without prescribing identical Split View, Stage Manager or external-display capabilities on every iPad. If the current environment prevents change, retain it as pending instead of resetting the system. Change one space condition while fixing theme and other appearance. Use identifiable state names without invented logical-pixel measurements or a guaranteed two-column threshold.

4. Record regions and access paths in state A

In A, record artwork, track information, controls and lyrics: what is simultaneously visible and what needs navigation. The official wide example is not a mandatory template for this device. Read a short lyric passage and verify track identity, then check pause/resume. Keep an external location record without an in-app ruler or automatic layout report. Title, lyric and sound establish content; region dimensions describe only this presentation state.

5. Inspect rearrangement in state B rather than reuse coordinates

Save A, establish B, wait for a stable interface and locate the same track, lyric passage and controls again. Do not blindly reuse A’s screen coordinates after rearrangement, narrowing or changed navigation. Record moved regions separately from retained content. Lyric wrapping is not rewritten source text, and scaled artwork is not proof of a new download. Restore the sample after a natural transition. Observe actual state instead of requiring every window to copy the reference’s side-by-side layout.

6. Check that needed actions remain reachable

In B, use identifiable controls for pause/resume and return to lyrics/player, checking the same small task as A. A moved but reachable control is not a missing function; screenshot area alone cannot establish feature loss. For a changed lyric highlight, inspect playback position/timing data before inferring a synchronisation change. Preserve queue and accessories. Untested queue actions, long playback and gestures remain pending rather than certification of every large-screen interaction from two taps.

7. Diagnose data, space and controls separately

For absent lyrics, inspect source/navigation. For unchanged regions, establish whether available space changed. For an unfound control, inspect current navigation. These are not all adaptation failures, and deleting/reimporting the library is unnecessary. Restore one condition, return to A if useful and preserve both rounds. Record interruption or unclear dimensions as limited scope instead of generalising one screenshot to every iPad. Unpublished layout locks, freely draggable panes or custom breakpoints are not repair instructions.

8. Return to A and verify content and paths

Return to the original space state and verify track, lyrics, theme and everyday window arrangement. Save A, B and return-to-A records, explaining content identity, regional rearrangement and reachable actions separately. More space does not add a lyric provider or independent player. State the actual final condition if exact restoration is unavailable. Re-identify layouts after device/system/app changes. This is not a physical-device matrix across every width/orientation or professional display/accessibility certification.
