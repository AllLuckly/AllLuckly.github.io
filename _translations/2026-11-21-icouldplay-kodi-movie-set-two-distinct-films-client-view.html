Compare a Kodi movie set containing two authorized films with what iCouldPlay actually displays. First identify a set of different movies; do not confuse it with two versions of the same movie.

Prepare an existing movie set

Choose an authorized Kodi movie library containing two different movies A and B. In Kodi itself confirm they are separate titles with distinguishable names, durations and opening scenes. If an existing movie set contains both, record its actual name. If not, stop at inspection: this exercise does not require creating, editing or deleting server metadata. Preserve the media originals and library backup. Your own family clips can supply private examples without publishing real titles.

Distinguish sets and versions on the server

Kodi describes a Movie Set as a collection of related movies; Video Versions instead associates different versions of one movie. Record each of A and B, any set membership and the way Kodi actually presents it. Different edits of A are another layer and are not the two films in the set. This comparison concerns two distinct entries and does not require changing a Kodi default version, scraper or grouping setting.

Kodi documents that a movie can belong to only one Movie Set at a time; tags and other organizational methods are different relationships. If the films merely share a tag rather than membership in the same server-side set, record the prerequisite as unmet. A tag page, file folder or matching poster does not establish set membership, and this exercise does not require changing existing membership.

Write identifying content markers

Play the opening seconds of A and B in Kodi and record a recognizable scene or sound and approximate duration for each. A seaside opening and a mountain road are illustrative only; use actual details from your material. If names or artwork look similar, use duration and content to distinguish them. Different posters do not prove different underlying files. If even the content cannot be distinguished, mark identity pending before drawing conclusions about a client.

Open the same Kodi source in iCouldPlay

Open an existing authorized Kodi source in iCouldPlay and confirm that its server and library are the ones inspected above. Record whether A and B appear, and whether the client offers a set entry, separate cards or another presentation. A Kodi setting does not establish that every client exposes a matching set view. Follow only controls actually visible in iCouldPlay; if no set control appears, do not invent one or change server settings merely to produce an entry.

Check identity and playback separately

Open A using an entry actually visible in iCouldPlay. Record its displayed title, visible duration, playback response and opening marker; return and repeat for B. Keep “found in list,” “title matches server,” “playback starts” and “content matches marker” as separate checks. Even when both cards appear, play a short portion of each. If one has no sound or fails, preserve that feedback without assuming the other will behave the same way.

After checking the second film, return to the first and confirm it still matches the original marker. If list order changes, use the recorded name and content rather than treating the previous screen position as a stable identifier. When only one entry appears you can still check that entry separately, but mark the other row absent or unperformed. If names and durations match, use the previously observed visual distinction; stop if identity remains uncertain.

Separate grouping and sorting from content

If iCouldPlay lists the two films separately yet both are findable and play the expected scenes, record “content accessible; set grouping not observed”; this does not mean the Kodi set was lost. If a set entry appears, open it and check both members, any additional items, titles and order. Different order alone does not establish a file mismatch. Server grouping, client grouping, ordering and content identity are separate observations and can have different outcomes.

Investigate an absent item or playback failure

Check the Kodi server, selected library, login and network first; a same-named film on another server is not evidence about this one. Confirm the targets still exist on Kodi itself, then inspect the iCouldPlay list again. If Kodi has both but the client shows only A, preserve the time, screen and target information for follow-up instead of rebuilding the whole library. If B is listed but fails to play, provide the server administrator with the observed error and check path access and media state. Do not disable a firewall or broaden access as a generic fix.

Deliver the comparison and keep the original library

Make a two-row table with server-side identity, set membership, client entry, duration, opening marker, playback result and pending items. Record only grouping and messages actually seen. Redact server addresses, accounts and private content before sharing. Confirm both original files and the existing Kodi settings remain. This exercise does not change or rebuild the library and claims no physical-device, private-server, all-version or universal client grouping test.
