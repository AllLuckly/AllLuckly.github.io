1. Notification

Apple has continually refined Notification since its introduction, but earlier changes were modest. iOS 10 brings a substantial redesign, making UserNotifications easier to use and much more capable.

Notifications before iOS 9

1. Some notification methods are difficult to distinguish and easy to confuse, frustrating developers.

2. Notifications follow different delivery paths depending on whether the application is running.

3. An app in the foreground cannot display remote notifications directly; additional handling is required.

4. Delivered notifications cannot be updated, their contents cannot be changed after sending, and presentation is limited to plain text, offering little extensibility.

Notifications from iOS 10 onward

1. Notification-related functionality is unified in UserNotifications.framework.

2. Notifications can now be revoked or updated, and their contents modified in transit.

3. Notifications are no longer limited to plain text: they can include video, images, and custom presentation.

4. iOS 10 notifications are easier to use and manage, with substantial improvements for developers.

5. iOS 10 simplifies permission requests by combining local and remote notification authorization in one method.

2. ATS issues

iOS 9 discourages HTTP by default, although NSAllowsArbitraryLoads can be set to YES to disable ATS. For iOS 10, Apple will no longer allow this ATS bypass from 2017-1-1, effectively requiring HTTPS; otherwise, an App may be rejected. NSExceptionDomains can still allow HTTP for specific domains and help the app pass review.

7. New UIColor methods in iOS 10

The official documentation states:

Most graphics frameworks throughout the system, including Core Graphics, Core Image, Metal, and AVFoundation, have substantially improved support for extended-range pixel formats and wide-gamut color spaces. By extending this behavior throughout the entire graphics stack, it is easier than ever to support devices with a wide color display. In addition, UIKit standardizes on working in a new extended sRGB color space, making it easy to mix sRGB colors with colors in other, wider color gamuts without a significant performance penalty.

Here are some best practices to adopt as you start working with Wide Color.

In iOS 10, the UIColor class uses the extended sRGB color space and its initializers no longer clamp raw component values to between 0.0 and 1.0. If your app relies on UIKit to clamp component values (whether you’re creating a color or asking a color for its component values), you need to change your app’s behavior when you link against iOS 10.
When performing custom drawing in a UIView on an iPad Pro (9.7 inch), the underlying drawing environment is configured with an extended sRGB color space.
If your app renders custom image objects, use the new UIGraphicsImageRenderer class to control whether the destination bitmap is created using an extended-range or standard-range format.
If you are performing your own image processing on wide-gamut devices using a lower level API, such as Core Graphics or Metal, you should use an extended range color space and a pixel format that supports 16-bit floating-point component values. When clamping of color values is necessary, you should do so explicitly.
Core Graphics, Core Image, and Metal Performance Shaders provide new options for easily converting colors and images between color spaces.

Previously, we used RGB to define colors, with relatively limited variety. The new methods seem intended to improve this. In iOS 10, Apple recommends sRGB for better performance and richer colors. If you have a UIColor category, consider adapting it to sRGB. UIColor adds these two Api methods:

+ (UIColor *)colorWithDisplayP3Red:(CGFloat)displayP3Red green:(CGFloat)green blue:(CGFloat)blue alpha:(CGFloat)alpha NS_AVAILABLE_IOS(10_0);

- (UIColor *)initWithDisplayP3Red:(CGFloat)displayP3Red green:(CGFloat)green blue:(CGFloat)blue alpha:(CGFloat)alpha NS_AVAILABLE_IOS(10_0);
## 8.iOS 10 UITextContentType
// The textContentType property is to provide the keyboard with extra information about the semantic intent of the text document.

@property(nonatomic,copy) UITextContentType textContentType NS_AVAILABLE_IOS(10_0); // default is nil

In iOS 10, UITextField adds textContentType to indicate the expected semantic meaning of input.

This property tells the keyboard and system what kind of content the user is expected to enter. For example, identify an email-address field with uitextcontenttypeemailaddress. Providing this semantic information lets the system sometimes choose an appropriate keyboard automatically and improve correction and proactive integration with other text-entry opportunities.

11. Checking the system version correctly in iOS 10

Checking the system version is common, especially when adapting to iOS 10. But an issue appears, as shown below:


The answer is:

//值为 1
[[[[UIDevice currentDevice] systemVersion] substringToIndex:1] integerValue]
//值为10.000000
[[UIDevice currentDevice] systemVersion].floatValue,
//值为10.0
[[UIDevice currentDevice] systemVersion]

Use one of the latter two methods to check the system version. I forgot to mention that [[UIDevice currentDevice] systemVersion].floatValue is unreliable too. I vaguely remember 8.3 producing 8.2; regardless, it was unreliable. I recommend [[UIDevice currentDevice] systemVersion].

In Swift, check as follows:

if #available(iOS 10.0, *) { // iOS 10.0 print(“iOS 10.0”); } else { }

14. The Xib awakeFromNib warning in Xcode 8

Updated: 2016-09-18. Before Xcode 8, writing - (void)awakeFromNib {} for Xib initialization this way caused no issue. Xcode 8, however, produces this warning:


To remove the warning, explicitly add [super awakeFromNib];. Here is the official explanation:

You must call the super implementation of awakeFromNib to give parent classes the opportunity to perform any additional initialization they require. Although the default implementation of this method does nothing, many UIKit classes provide non-empty implementations. You may call the super implementation at any point during your own awakeFromNib method.

16. ImagePickerController.cameraViewTransform issues in iOS 10

Updated: 2016-09-21. Many developers report problems with custom cameras and cameraViewTransform no longer working. Information online is limited; here is a reference approach:

Resolve it by observing AVCaptureSessionDidStartRunningNotification.

  //#import <AVFoundation/AVFoundation.h>
  //监听
   [[NSNotificationCenter defaultCenter] addObserver:self selector:@selector(cameraNotification:) name:AVCaptureSessionDidStartRunningNotification object:nil];
  //监听方法
  - (void)cameraNotification:(NSNotification *)notification {
    dispatch_async(dispatch_get_main_queue(), ^{
          // 这里实现
          imagePickerController.cameraViewTransform = CGAffineTransformMakeTranslation(50,  50);
      });
  }
  • Use AVFoundation

UIImagePickerController appears unsuitable for iOS 10, so AVFoundation may solve the problem. References follow: UIImagePickerController’s cameraViewTransform
