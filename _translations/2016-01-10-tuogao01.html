The runtime refers to mechanisms that operate while a program is running. In iOS development, runtime features give oc its distinctive appeal.
For C and C++, the methods a class object can call and the operations it can perform are determined when the program is compiled. The runtime mechanism allows
oc can dynamically create classes, perform black-box testing, extend properties, and more at runtime, greatly increasing its flexibility. Today, using some runtime mechanisms,
let's discuss properties and variables in oc. (This is the first article in my runtime series. If you disagree with any of the points raised, please join the
comments to discuss them with me.)

property and ivar


First, properties (property) and member variables (ivar) are different things. In oc, the distinction is as follows:

  • Member variables
    Member variables are usually declared in a class declaration's@interface or class implementation@implementation variables declared in the braces that follow,
    Their default visibility is@protected protected visibility (inaccessible outside the file), as well as@public public visibility,@private
    private visibility and@package package visibility


  • Properties

Compared with a variable, a property involves several compiler operations: 1. Use @synthesize to generate its corresponding ivar, usually named 下划线+属性名. 2. Generate a setter to set the ivar. 3. Generate a getter to retrieve it.

In a sense, a property wraps a member variable, adding setter and getter methods to make it
better suited to object-oriented programming. (If you do not understand why setters and getters are needed, see this article:
What getter and setter methods are for)

  • Question two: How are address offsets calculated?

A pointer occupies 8bit on a 64-bit system, but char uses only one bit, so why is the offset also 8 here? Is it calculated like a structure's address offset? This brings us to class_addIvar(const char *, NSUInteger *, NSUInteger *), a function for adding a variable to a class. Its final parameter specifies the variable's memory alignment. Apple explains that parameter as follows:

The instance variable’s minimum alignment in bytes is 1«align. The minimum alignment of an instance variable depends on the ivar’s type and the machine architecture. For variables of any pointer type, pass log2(sizeof(pointer_type)).

This states that alignment is the variable's minimum alignment in bytes, but it does not explain exactly how the alignment works. In
objc-runtime-new.mm
contains code that calculates address offsets. Looking at that code makes this clearer:

In brief, Apple specifies a default variable offset of 1 << alignment, which in this context is the pointer length. Thus Objective-C class-structure offsets differ from ordinary struct offsets: anything shorter than 8bit is assigned an 8bit offset.

As discussed earlier, a property declared with @property automatically receives an underscore-prefixed ivar and associated setter and getter during compilation, allowing _property access within the class. The offset output shows that property-generated variables follow the member variables. How does that happen?   • Question four: What exactly does @synthesize do?

This question may seem surprising. From the preceding code and discussion, @synthesize clearly generates and binds variable memory. In the Person class, for example, declaring the abc property makes the compiler automatically generate @synthesize abc = _abc;, which means we can write it ourselves. What if we bind the property to an existing member variable instead, using @synthesize abc = _name? What addresses will be printed afterward?

Adding this custom binding causes an error in the original code. Binding the abc property to _name means the compiler no longer generates _abc, so that variable cannot be found in the class. After creating a Person instance, the console's address output remains unchanged, still differing by 0x8.

If found, it generates a getter and setter to access that memory. Otherwise, it creates a new member variable and then binds the accessors. Thus @synthesize does more than simply call class_addIvar() when adding a variable; it also traverses the variable list.


Just as black has its opposite in white, @synthesize has a counterpart. In Objective-C, @dynamic propertyName prevents the compiler from binding variable storage and generating setters and getters for the property, leaving us to provide these methods at runtime. The runtime messaging article will explain this.
