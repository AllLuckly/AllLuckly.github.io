“Care Data is a purely object-oriented framework for persisting entities and the relationships between them—what we usually call data persistence.”

1. Principles

Care Data is a purely object-oriented framework for persisting entities and their relationships. Care Data can use a SQLite database, an XML document, or even memory as its underlying store. The central concept in Care Data is an entity: a model object managed by Care Data, which must be an instance of NSManagedObject or one of its subclasses. Entities can have 1-1, 1-N and N-N relationships. All the entities and their relationships together form the managed object model, NSManagedObiectModel. The core object in Care Data is the managed object context, NSManagedObjectContext, which manages all entities. Every create, delete, fetch or update operation in a Care Data application must go through this context. Applications use NSMannagedObjectContext to perform these operations; NSMannagedObjectContext connects to the persistent store coordinator, which manages the underlying storage format, such as SQLite. The main Care Data objects and API are described below.

Managed object model, NSManagedObiectModel: manages every entity and the relationships between them. After designing those relationships in the Xcode graphical interface, use this object to load and manage the application's model.


Persistent store coordinator, NSPeristentStoreCoordinator: manages the underlying storage files, such as SQLite databases.


Managed object context, NSManagedObjectContext: the core object in Care Data. Every operation that creates, deletes, fetches or updates an entity must go through this object.


Entity description, NSEntityDescription: describes an entity and can be viewed as an abstraction of it. The description defines its name and implementation class, and uses a collection to define all its attributes.


Fetch request, NSFetchRequest: encapsulates which entities to query, the conditions and the sort rules. It specifies an entity name and expresses the query conditions using NSPredicate来表示. An NSArray collection defines the sort rules.


With these concepts in place, the basic Core Data persistence workflow is as follows.

  • Create an NSManagedObiectModel object to load and manage the application's model.
  • Using NSManagedObiectModel as the basis, create an NSPeristentStoreCoordinator object as required. It determines the underlying storage format used by Core Data.
  • Using NSManagedObiectModel as the basis, create NSMannagedObjectContext, the core object through which Core Data performs persistent access.
  • For ordinary create, delete, fetch and update operations, first create, delete or modify the relevant entity. Then call the NSMannagedObjectContext object's save: method to save the changes to the underlying store.
  • To query entities, first create an NSFetchRequest object. Then call the NSMannagedObjectContext object's executeFetchRequest:error method. The result is an NSArray containing all matching entities.
