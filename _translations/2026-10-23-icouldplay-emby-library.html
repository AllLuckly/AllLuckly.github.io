When Emby already manages posters, movie information, and user permissions, iCouldPlay can connect as a viewing interface. This differs from SMB: you sign in as a media-server user and see libraries supplied by the server rather than browsing every NAS share directly. This article verifies an existing library first, then checks movie details, actual playback, and the user's visible scope.

Get the correct connection details from Emby

First confirm in Emby's website or client that the server is running, using the same user intended for iCouldPlay. Record the server address, port, and protocol, not merely the NAS administration address. Emby's official guidance recommends obtaining the LAN address from the server dashboard. You can also verify reachability in a browser on another device on the same network.Connection documentation

The tutorial example can use the host 192.168.1.30, port 8096, but these are not fixed values for every installation. Use the actual configuration if the administrator provides HTTPS or a custom port. Prepare a movie already displayed correctly and playable in Emby, preferably with an easily checked duration and file location. Avoid beginning with a large collection containing several mixed versions.

Add a media server rather than a file source

Open Sources in iCouldPlay, choose to add a media server, and select Emby. A name such as Home Emby is suitable. Enter the prepared server address and port, with HTTPS matching the actual service. Do not put a movie file path, browser details page, or link full of query parameters in the host field. It needs the server entry point, not a particular film's webpage.

Use the Emby user's username and password. These may differ from the NAS SMB account and need not be the administration account. Start with an ordinary viewing user. If someone else manages the service, confirm the assigned account and library access with the administrator rather than trying passwords from your other websites. The source name is only for local identification and does not rename the server.

Check what the user can see after login

After testing and saving successfully, open the server's library list and compare its names with Emby's own client. If the user should see Movies and Family Videos, verify those two first. Do not conclude that iCouldPlay has omitted a library merely because an administrator also sees Work Materials. Library visibility follows the current user's permissions; the client cannot automatically bypass them.

Open a small library and check several posters and titles. Verify metadata supplied by the server on the server first instead of applying a file-source scan and matching everything again. If the library is completely empty, return to Emby's original entry point with the same account to distinguish lack of user permission from iCouldPlay failing to retrieve the list.

Use the details page to rule out a same-title mismatch

Choose a movie and check its year, duration, synopsis, and version clues. Films with the same title, remakes, and different cuts may have similar covers; do not start playback based only on poster color. If the server's own details are wrong, correct them in Emby first. iCouldPlay may need a refresh before showing the update.

Personal family videos may have no movie metadata. Keeping filenames or server-defined titles still allows normal browsing. Judge movie metadata separately from the actual file contents. For titles sharing a name and for year organization, see Movie naming and matching, but do not treat that article's file-source steps as server-management buttons.

Check both server and client during playback

Open the verified movie, watch a short section, then jump to the middle and check sound and subtitles. A poster only confirms that the metadata interface works. The video may use a different data path and still needs a separate test. If the list works but playback fails, play the same item in Emby's own client first to confirm that the server can read the media file.

If Emby's own client works but iCouldPlay does not, record the movie name, container, audio/video information, and exact failure stage. The server may provide different playback methods according to client capabilities, so one working client does not guarantee identical results elsewhere. Do not change transcoding, network, and subtitle settings all at once without understanding the cause. Keep the same file for comparison first.

Distinguish home and away connections

A LAN address working at home does not mean it is reachable over a mobile network. Before going out, use the remote entry point already configured by the administrator and confirm that the current user is allowed remote access. Give the two entry points different names to avoid using the home address externally. Do not open server ports or disable authentication just for a first test; this article covers connecting to an existing working service.

If the remote address remains slow after returning home, compare the LAN source, first confirming that both connect to the same server and user. Verify matching progress by exiting and reopening instead of assuming unconditional instant synchronization across clients. To investigate waiting and buffering, see Network buffering troubleshooting.

Common failures and completion criteria

Login succeeds but no libraries appear. Should I rescan the NAS? Not yet. Emby manages its own libraries. The signed-in user may lack access, or the server may not have finished organizing them. Checking through the original entry point with the same account is the most direct test. Continue investigating the client's list retrieval only after confirming that the library exists on the server.

Why does adding the server fail when the full URL opens? A full URL may contain a web-interface path, reverse-proxy subpath, or login-page parameters that the current form cannot process like a browser. Ask the administrator for a direct service address suitable for clients. If access uses a reverse proxy with a subpath, separately check whether the client can connect.

When finished, the same account should show the expected libraries, provide details for one verified movie, play and seek successfully, and work again after returning to the server list and reopening it. Keep track of the server name and usable network so later additions do not blur file sources, media servers, and user permissions together.
