Use an authorized EPUB sample to compare base text, ruby annotation and readability after a size change.

Understand ruby and base text

Ruby is short text associated with a base run, often used for pronunciation or brief annotations in East Asian writing. HTML uses elements such as ruby and rt to represent the relationship. Markup describes structure; actual rendering depends on the reader and layout. This guide does not assume Book Isle supports every ruby layout or treat system speech or translation as book-supplied annotation.

Choose an authorized sample

Choose an EPUB you created or are authorized to read, preferably with a publisher-identified short ruby example. Record title, edition, source and original file location. Choose a short self-made example and note base text and annotation without publishing copyrighted text. Preserve a backup. If protection or license terms prohibit inspecting internal structure, observe only the reading interface and do not bypass protection.

Establish a reading baseline

Open the original sample in Book Isle and locate the target paragraph using available contents, search or page navigation. Record whether base text is readable, whether the short annotation is visible, their relative positions, current font size and orientation. If the book will not open, first check download completeness and format recognition; do not attribute failure of the whole file to ruby markup. Preserve existing bookmarks and notes.

Inspect the marked relationship

When permitted and equipped with a suitable tool, inspect only the copied target XHTML section and identify the base text and rt annotation inside the ruby container; record any rp and its position as well. Compare both text runs with publisher information. Another file may contain the same words, so a whole-book search hit alone does not identify the target paragraph. Mark this step skipped if permission is unavailable.

Change one reading condition

Change font size once using the controls actually available in Book Isle, keeping the same book, orientation and target paragraph. Find the same base text again and record annotation size, line breaks, overlap and whether the relationship remains readable. If the app or book offers no size control, record it as unavailable; do not change original book styles or invent a control.

Check line breaks and neighboring text

Compare line breaks before and after the change. Check whether the annotation remains near the correct base text and whether punctuation or the next line is obscured. A line wrap does not necessarily mean content was lost; inspect the surrounding passage for completeness. If both runs exist but their association is unclear, record the observation without guessing an internal layout-engine error.

Observe assistive reading only when available

If the device offers system speech or magnification, use it only when the user wants to and understands the settings, recording their original state first. Observe the base text and annotation separately where possible. System voice, language and reading order can differ, so automatic distinction is not guaranteed. Mark the step untested if not used or uncertain; do not present an operating-system feature as exclusive to Book Isle.

Separate missing text from display differences

If the annotation is not visible, verify the paragraph, whether the sample actually includes it and whether the current font or size affects legibility. Structure inspection shows what the publication contains, not how the app processed it. Another reader can serve as an independent control, but its success does not prove identical support in Book Isle. Change one condition at a time rather than editing the file and device settings together.

Record findings and preserve the original

Record the publisher-provided base and annotation, whether structure inspection was performed, observations at each size, assistive-reading status and unresolved questions separately. Do not publish private files, account details or substantial unauthorized text. Restore original font size and assistive settings and confirm the original file, bookmarks and notes remain. This guide relies on public standards and app information and does not claim device testing.

Distinguish inline ruby from other notes

A title, footnote or glossary may explain a pronunciation, but that is not the same as ruby beside the target text. Record the visible target passage and other explanations in separate columns. If only a glossary is found, do not record inline ruby as displayed. If publisher information is missing, mark the expectation unknown rather than substituting personal knowledge for evidence about the file.

Preserve the comparison conditions

For an independent reader comparison, record its name, version, device and font size, and confirm the same file and passage. Default fonts, direction and available width can differ, so position alone does not establish a parsing error. Record the actual display; do not install unfamiliar software or change system security settings merely to create a difference. Leave this step untested if no control is available.

A reproducible self-made sample

A self-made section can use <ruby>山<rt>やま</rt></ruby>: the base is 山 and the annotation is やま. First verify both text runs and ruby/rt boundaries in the authorized copy, then observe whether Book Isle shows the annotation recognizably adjacent to the base. Record absence or different placement as observed. This illustrates structure; it neither guarantees Book Isle support nor claims a device test.
