If a controller works but confirm and cancel seem reversed, first establish the relationship between physical positions and the original console's buttons. A stick that keeps moving after release is a separate problem requiring different treatment. This guide uses an input table to relate button positions, game actions and stick behavior.

Build a table of actual responses first

Choose a working game and a menu you can revisit. On paper or in Notes, list up, down, left, right, lower button, right-hand button, left-hand button, upper button, shoulder button and Start, leaving space beside each for its game action. Avoid A, B, X and Y labels at first so different brands' layouts do not confuse your records.

Press and release each button separately, observe the cursor or character, then fill in the table. Holding a button and tapping it once may produce different results, so start with brief presses. If a game uses only two action buttons, the other two face buttons doing nothing does not necessarily indicate an app fault. Test within the buttons that platform actually uses.

Distinguish layout differences from incorrect input

Modern controllers and emulated platforms may label their face buttons differently. Yearn passes input to the emulator according to physical button position, so the letters printed on the controller alone cannot establish the expected game action. Check what the lower button actually triggers, then compare it with the game's settings or instructions.

If two games use opposite confirm conventions, the difference may be in the games themselves. Compare settings by repeating tests with the same controller in the same game. Do not immediately remove pairing when letter labels differ: pairing again will not usually change what the game designed each button to do.

Use the directional pad to check the basic input path

Test the four directions using only the directional pad and see whether movement stops when you release it. Follow the same route with the left stick. If the pad works and the stick does not, the basic connection and game are probably receiving input. Focus the investigation on stick settings and hardware condition.

If none of the four directions works, return to the title screen or another interactive page and check whether the current scene accepts input. If touch works but the controller does nothing, revisit controller connection checks. If neither input works, check for a paused game, stalled loading or demonstration mode instead.

Adjust the deadzone in small steps

In controller settings, find the stick deadzone: the range of input around the center that is ignored. Record the current value, raise it one step, and return to the same scene with the stick released. If unwanted movement decreases, also test whether a gentle push still responds promptly.

A larger deadzone is not always better. Too much inactive range near the center forces you to push farther before movement begins and can reduce precision. Compare settings by checking for no drift during ten seconds after release and reliable movement when slowly pushing the stick. Then confirm the feel during actual play.

Check left-stick-as-directional-pad

Controller settings include an option to use the left stick as the directional pad. For older games mainly using digital directions, it determines whether the stick can perform the pad's role. Testing with it off helps distinguish converted stick input from a game's own analog input path.

Keep other settings unchanged during the test. If turning the option off leaves the directional pad working but stops the left stick from performing the same actions, record that. Platforms and games differ in their stick requirements; reuse the table to check again when changing content.

How to evaluate custom mapping controls

If changing a mapping does not change the actual buttons, record responses as described here and report them. Test the lower button, right-hand button and Start in the same menu, noting their actions before and after the change. This helps establish whether the setting affects the current game.

Before trying system-level controller customization, confirm that your iOS version and controller support it, and use the options actually provided. Return to the same game menu afterward and fill in the response table again; only a changed action confirms a result. Avoid changing app, system and game settings simultaneously, or the cause becomes difficult to trace.

Questions and information to include in feedback

What if one button never responds? First try a scene that clearly uses that button, then compare the same controller in another game known to accept input. If the same physical button consistently fails, consider hardware or connection problems.

Why does control still feel different after resetting defaults? Game state, portrait or landscape orientation, controller reconnection and system settings can all affect what you observe. Resetting app settings does not clear every system or game configuration. Check each layer against your notes for a more reliable diagnosis.

For feedback, provide the controller model, game platform, physical button position, expected action and actual action. A response table without personal information communicates the issue more clearly than simply saying the buttons are reversed, and helps identify the specific failure.

Record a repeatable pressing method

Complete two rounds using the same hand and menu. Fully release each brief press before trying the next button. If trouble appears only during rapid repeated input, record single presses and repeated presses separately. Note diagonal pad input too—for example, whether up-left activates both directions. These records distinguish button position, pressing rhythm and combined input, making the actual failure conditions clearer in feedback.
