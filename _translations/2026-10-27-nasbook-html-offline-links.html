An HTML file may contain text while images, styles and linked pages remain online. A Book Isle reading copy is not a complete browser page. Verify prose separately from offline dependencies before deciding whether a layout-preserving reference is also needed.

Identify what the saved file contains

Confirm the file is actual HTML rather than a URL shortcut or redirect. Inspect its title and prose boundaries in a local-page-capable tool and record source and date. Preserve any companion resource folder, without assuming the reader will load every dependency.

Choose three kinds of checkpoints

Mark a prose passage, meaningful link and essential image, noting their roles. Prefer a figure carrying instructions or data over decoration. Verify all three in both source and saved file before import so capture omissions are not confused with reader omissions.

Check text boundaries after local import

Import locally and inspect beginning, middle section and ending. Identify menus, recommendations or footers mixed into prose. They may not make the document unusable, but distinguish article text before extensive annotation. A title and short extract do not establish complete reading order.

Check link labels and destinations separately

A surviving link label may be plain extracted text. Test a visible link control only if the installed version provides it; otherwise verify the target in the source. Opening a target does not mean it was stored in the book. Record important full addresses and titles, especially ambiguous labels.

Verify images rather than placeholders

Determine whether the checkpoint image is rendered, replaced by alt text, a placeholder or nothing. Verify essential diagrams directly. Local HTML may still reference remote or relative resources. Do not improvise an ebook by renaming an archive; retain the original and record precise missing figures.

Reopen the document offline

After local import, disconnect and reopen from the shelf rather than staying on a cached page. Recheck prose and image checkpoints. An external link failing offline is not necessarily book damage. Record specific conclusions and compare after reconnection to distinguish network dependencies from extraction limitations.

Inspect tables, code and layout-dependent meaning

Check one table, indented code sample or side-by-side explanation for preserved meaning. Do not execute code copied from a layout-damaged rendering without verifying the original. Visible text does not guarantee preserved webpage layout, forms, scripts or dynamic interaction.

Record source and capture time

Keep a source note with title, complete URL, capture date and copy identity. Distinguish the saved edition from later online updates. Cite section and anchor text, verifying the live page when needed. This is manual provenance, not assumed automatic capture-version or update tracking.

Diagnose the saved file before the reader

Open the same saved file locally first. If it contains only a title, obtain a complete authorised copy rather than changing font size. Compare a simple self-authored HTML when the source is complete. Preserve a minimal sample and test separately from annotated items without destructive first steps.

Choose a copy that meets the offline goal

Use the verified reading copy for prose, and a separately checked reference when image placement or layout matters. Name variants clearly and return to the three checkpoints for explicit acceptance results. More formats do not replace verification of what is actually available offline.
