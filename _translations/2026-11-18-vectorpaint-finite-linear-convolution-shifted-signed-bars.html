Draw a shifted-sum diagram for discrete convolution: list each input sample’s contribution, then add contributions sharing an index. Keep negative bars below zero and all four output indices, including the last. This illustrates external mathematics rather than applying an image or audio filter.

Declare finite indices and zero extension

Let x[0..2]=(1,2,1), h[0..1]=(1,−1), with both zero outside their ranges. Define y[n]=Σ over integer k of x[k]h[n−k]; only finitely many terms are nonzero. The−1 is a signed value, not missing data or a magnitude needing an absolute value. Create input, shifted contribution, output bar, index and note layers, then save native work. Samples are dimensionless and indices discrete positions, not automatically seconds or pixels. Any sampling interval requires a separate declaration.

Determine the four output positions before drawing columns

The support runs from 0+0=0 through 2+1=3, so the complete linear output uses n=0,1,2,3: length 3+2−1=4. Keep an index even if its sum is zero. Draw four ledger columns before contributions so the last is not cropped. Convolution is not pointwise multiplication. A three-item answer(1,−2,1) neither handles the two-item h correctly nor implements the shifted sum.

Generate a weighted shifted row for each input sample

At k=0, weight 1 contributes(1,−1,0,0). At k=1, shift h right once and multiply both entries by 2, giving(0,2,−2,0). At k=2, shift twice with weight 1, giving(0,0,1,−1). Label k and x[k], align columns with pale boxes and retain explicit zeros. Weight 2 multiplies both signs, not just the positive bar. Blank positions are zero by extension, not extra ones or values to choose for visual balance.

Sum columns and spot-check the defining formula

Column sums give y=(1,1,−1,−1). Independently y[1]=x[0]h[1]+x[1]h[0]=−1+2=1, and y[2]=x[1]h[1]+x[2]h[0]=−2+1=−1. Out-of-range terms are zero; do not wrap h[−1] or h[2] to an endpoint. Show one output bar per column while retaining contribution layers. Adding absolute heights instead of signed values would compute a different quantity, not convolution. Because h=(1,−1), y[n]=x[n]−x[n−1]. Zero extension gives the first 1−0 and last 0−1, independently checking endpoints. The zero kernel sum also rules out dividing by that sum to create a normalized average.

Check externally through sums and polynomial multiplication

The output sum 1+1−1−1=0 equals input sum 4 times kernel sum 0. This is a useful necessary check, not proof that every column is right. Also expand(1+2z+z²)(1−z)=1+z−z²−z³; its four coefficients agree. Here z is formal, not the canvas vertical coordinate. Keep both side checks alongside the column calculation. A zero total cannot excuse swapped middle signs or other local index errors.

x[0..2]=(1,2,1); h[0..1]=(1,-1); zero elsewhere
y[n]=sum_k x[k]*h[n-k]
k=0: 1 -1  0  0
k=1: 0  2 -2  0

y:   1  1 -1 -1

Positive bars reach 1120 and negative bars 1480, inside the canvas; label signed values. Put input/contribution tables above without hiding the baseline. Distinguish circular folding and overlap averaging

Under a separately defined length 3 circular convolution, fold linear y[3]=−1 into index 0 to obtain(0,1,−1). This changes the boundary rule; it is not a correction to the four-column linear result. Dividing each sum by overlap count likewise defines another averaging operation absent here. Diagnose linear/circular rules, extension and index direction before signs/weights. Save explicitly named controls instead of hiding changed definitions behind an alleged software-display difference.
