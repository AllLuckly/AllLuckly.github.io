Type three explicit ASCII scientific-notation strings and convert them to decimal externally to check signs and scale. Separate keyboard entry, host formatting and mathematical interpretation. Here e is neither a unit nor Euler’s constant, and normalized display does not establish exact source text.

Preserve three targets in a plain-text environment

Create an owned English/numeric draft with Jianlai and the host identified, preserving appearance/input state. Targets are 3.20e-4, 3.20e+4 and -3.20e-4 on separate lines, using ASCII dots, e and signs without spaces, units or labels. Keep the external source separate from decimal calculations instead of replacing targets with answers. These are text/math exercises, not measurements, money or experimental parameters. If the host evaluates or reformats them, preserve its response and use an existing plain-text field rather than invent a Jianlai scientific calculator or precision setting.

Type in portions and distinguish the two sign positions

For line one enter 3.20, lowercase e, ASCII minus and 4. Line two has an explicit plus before the exponent. Line three adds a leading minus while retaining the exponent’s minus. Inspect committed text, not keycaps or preview. The two minuses on line three have different roles: the leading sign controls the whole value, while the exponent sign controls the power of ten. They do not cancel merely because both are minus signs. Use actual newlines and record pasted/other-keyboard portions separately from manual Jianlai entry.

3.20e-4
3.20e+4
-3.20e-4

Recover all three values using powers of ten

In this notation e means multiplying the preceding decimal coefficient by ten to an integer power. 3.20e-4 is 3.20 times ten to minus four, giving 0.000320. The next values are 32000 and -0.000320. Minus four neither subtracts four from 3.20 nor raises 3.20 to minus four. Write the power-of-ten layer before checking decimal positions; a negative exponent does not make the first value negative. e is notation here, not a physical unit, variable or Euler’s constant. Other formula environments require their own interpretation rules. An additional zero-exponent control, 3.20e0, still equals 3.20; zero is not an empty exponent. A bare 3.20e lacks its integer exponent and fails this complete form. Record the omission rather than borrow the previous line’s exponent. Save this control outside the three-line target. A negative-zero exponent in 3.20e-0 also gives 3.20; do not move the exponent minus to the coefficient.

Check sign and scale before trailing zeros

The second value divided by the first is ten to the eighth, or one hundred million. The third has the first’s magnitude with the opposite sign. These expose exponent-sign or leading-sign mistakes; shared digits 3 and 2 do not establish equality. Exact decimal values 0.000320 and 0.00032 agree, while text and trailing zeros differ. Preserve the target’s zero rather than treating normalized output as identical input. Some measurement reports assign significance to zeros, but this exercise supplies no measurements and establishes no precision, uncertainty or confidence interval.

Save value-equivalent but textually different controls

Externally change line one to 3.2e-4 and 3.20E-4. Under the Python Decimal rules used here, both have the same value but differ character by character from 3.20e-4. One drops a coefficient zero and one changes case. Parser acceptance does not establish source equality. A human-readable expression 3.20×10⁻⁴ is another representation, not the ASCII target or an automatically valid input to the same numeric-string parser. Label controls without requiring every variant to be typed. Separate exact text, meaning and actual acceptance, retaining manual predictions for unexecuted cases.

Use Decimal externally for the specified strings

With an existing Python installation, use the standard-library example in a separate practice file and record version/output. Construct Decimal directly from strings, avoiding an intermediate binary float that would introduce another representation. It only prints fixed-point text and changes no app data. Expected lines are 0.000320, 32000 and -0.000320, but actual execution is separate evidence. Fixed-point display differs from the scientific source, so retain entered strings too. Neither keyboard entry nor external calculation establishes exact host persistence automatically.

from decimal import Decimal
for text in ("3.20e-4", "3.20e+4", "-3.20e-4"):
    print(format(Decimal(text), "f"))

Troubleshoot ASCII signs and host rewriting

A hundred-millionfold discrepancy suggests the exponent sign. Correct magnitude with wrong sign suggests the leading minus. Parse failure calls for inspecting Unicode minus, full-width dots, spaces or a written multiplication expression. This target requires ASCII without claiming every numeric tool accepts only ASCII or rejects all Unicode digits. Follow actual documentation/results. Repair one condition and preserve the initial draft instead of normalizing away evidence. If a host changes 3.20 to 3.2, retain both: equal value and changed text are different findings, not increased keyboard precision.
